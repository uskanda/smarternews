# Proposal

## Why

いまのsmarternewsで登録できる語は、配信記事を隠すためのストップワードだけである。気になる語を含む記事を一覧で見つけ、本文の中でその語の位置を追う手段がない。
GitHubのissueの54番は、Inoreaderの「Spotlights」に当たる、登録した語を一覧と本文で色付けする機能を求めている。Inoreaderから乗り換えるために洗い出した機能の1つである。

## What Changes

- 語のまとまりを足す。まとまりは名前と色を持ち、色付けの語を束ねる。まとまりの数は制限せず、複数のまとまりが同じ色を選べる。
- 色は `DESIGN.md` に4色を足し、配色ごとに値を決める。`pnpm run tokens` でWebのCSSとアプリの定数に反映する。
- 語の照合は、ストップワードと同じく、大文字と小文字、全角と半角を区別しない部分一致にする。照合の処理はプログラムで書き、LLMは呼ばない。
- 生成記事と配信記事の両方で、一覧の行の見出しと抜粋、本文のペインの見出しと本文を色付けする。訳したタイトル、訳した本文、要約の区画も色付けする。
- 色と一緒に下線を引き、色を見分けにくい利用者にも一致した箇所が分かるようにする。
- 一覧の行の端に、一致したまとまりの名前を印として出す。
- 1つの箇所が2つのまとまりの語に一致したときは、設定の画面で上に並ぶまとまりの色を使う。
- Webの設定の画面に「語の色付け」の区画を作り、購読フィードとストップワードの区画の隣に置く。まとまりと語の追加、変更、削除、まとまりの並べ替えをここで行う。
- Androidアプリでも、一覧と本文を色付けし、一覧の印を出す。編集はWebの画面だけで行う。
- 語とまとまりを、設定ファイルの書き出しと読み込みの対象にする。
- APIに、語のまとまりと色付けの語の操作を足す。
- まとまりに一致した記事だけを一覧に出す絞り込みは、今回は入れない。全文検索（#47）で代わりに探せる。

## Capabilities

### New Capabilities

- `term-highlights`: 語のまとまりと色付けの語の登録、変更、削除、まとまりの並び順、選べる色、照合の方法、重なる一致の扱いを定める

### Modified Capabilities

- `http-api`: 語のまとまりと色付けの語の操作、まとまりを動かす操作を足す
- `settings`: 設定ファイルでの語のまとまりの書き出し、読み込み、往復を足す
- `web-reader`: 一覧と本文での色付け、色以外の手がかり、一覧の行の印を足す
- `web-settings`: 設定の画面の「語の色付け」の区画と、まとまりと語の編集、並べ替えの画面を足す
- `mobile-reader`: 一覧と本文での色付け、色以外の手がかり、一覧の行の印を足す

## Impact

- `packages/core`: 移行で、語のまとまりと色付けの語の表を足す。登録、変更、削除、並べ替え、設定ファイルの読み書きを足す。ストップワードの照合の形への変換を、ブラウザーとアプリからも使える場所へ移す。
- `packages/client`: 文字列の中で語に一致した範囲を求め、重なる一致を解く処理を足す。APIの呼び出しを足す。
- `apps/server`: 語のまとまりと色付けの語のAPIのルートを足す。
- `apps/web`: 一覧の行、本文、訳、要約の区画に色付けを足す。一覧の行に印を足す。設定の画面に区画と編集の画面を足す。
- `apps/mobile`: 一覧の行、本文、訳、要約の区画に色付けを足す。一覧の行に印を足す。
- `DESIGN.md`: 色付けの4色の値と、使い方の説明を足す。「目立つ色は重要度の印だけ」の方針に、利用者が選んだ色付けを例外として書き足す。
- `docs/api.md`、`examples/settings.example.yaml`: 新しいAPIと設定ファイルの項目の例を足す。
- LLMの呼び出し、取得、翻訳の回数は変わらない。照合は画面の側でプログラムが行う。
