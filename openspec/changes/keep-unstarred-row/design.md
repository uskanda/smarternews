# Design

## Context

動機は `proposal.md` のWhyに書いた。

- 未読の一覧と最近読んだ記事の一覧は、その訪問で読んだ行を `kept` に持ち、`mergeKept` でサーバーの一覧に重ねて残す。`kept` は一覧を見分ける鍵（listKey）が変わるか、更新を選ぶと空になる。listKeyは並び順を含まない。
- スターの切り替えは `setStar` が担う。いまは `kept` の行のスターを書き換えるだけで、スターの一覧の行を残さない。
- `j` と `k` の `move` は、選んでいる記事が一覧にないとき、先頭か末尾へ移る。

## Goals / Non-Goals

**Goals:**

- スターの一覧でスターを外しても、読んでいた位置から `j` と `k` で移れるようにする。

**Non-Goals:**

- Androidアプリの「スター」の一覧。
- ほかの一覧でのスターの切り替え。
- 一覧から外れた記事の直前の位置を覚える仕組み。

## Decisions

### 外した行を `kept` に足す

表示中の一覧がスターの一覧（`target?.type === "starred"`）で、スターを外すときの処理を `setStar` に足す。
`items` からその行の要約を取り、`{ ...summary, starred: false }` を `kept` に足す。`showRead` が未読の一覧で読んだ行を残すのと同じ形である。
行が `items` に残るので、`move` はその位置から隣へ移る。残す期間も未読の一覧と同じになる。

直前の位置を覚える案は採らない。行を残す仕組みはすでにある。それに乗せれば、挙動はほかの一覧とそろい、変更も小さい。

### 付け直しと失敗

残った行でスターを付け直すと、`setStar` の既存の処理が `kept` の行を `starred: true` に書き換える。サーバーの一覧に戻っても、`mergeKept` はidで1つにまとめるので、行は重ならない。
送信に失敗したときは、既存の `flagFailed` が `kept` の行のスターを戻す。追加の処理はいらない。

## Risks / Trade-offs

- 残った行は、サーバーがもう返さない行である。スターの一覧は更新の新しい順で並び、`mergeKept` も同じ鍵で並べるため、行は元の位置に残る。
- 残った行は更新を選ぶまで消えない。外した記事を一覧から消したいときは、更新を選ぶ。
