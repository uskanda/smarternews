# Proposal

## Why

スターのある記事は保存期間で消えないので、増え続ける。
スターを付けた時刻を保存しておらず、「スター」の一覧は記事の日時の順に並ぶ。3週間前の記事にいまスターを付けると、一覧の3週間前の位置に入る。
検索の結果をスターで絞ることもできない（Issue #217）。

## What Changes

- スターを付けた時刻を保存する。付けるとその時刻を入れ、外すと消す。すでにスターのある記事に付け直しても、時刻は変えない。
- 移行の前からあるスターには、記事の日時（最終更新の時刻）を付けた時刻として入れる。
- 記事の一覧のAPIに、並び順「スターを付けた順」を足す。スターを指定した一覧でだけ受け付ける。
- 記事の要約に、スターを付けた時刻を足す。
- 「スター」の一覧の並び順のメニューに、3つ目の選択肢「スターを付けた順」を足す（Webとアプリ）。既定は「新しい順」のままで、選んだ値はほかの並び順と同じくサーバーに保存し、設定ファイルに書き出す。
- 検索の操作に「スターだけ」の絞り込みを足し、Webとアプリの検索の結果の画面に「スターだけ」の切り替えを足す。隠した重複も、スターがあれば出す。
- タグは扱わない。LLMは呼ばない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `http-api`：スターを付けた時刻の保存と返却、スターを付けた順の一覧と続きの値、表示の設定の並び順の値を足す。
- `article-search`：スターだけの検索と、その検索での重複の扱いを足す。
- `web-reader`：「スター」の一覧の並び順のメニューの選択肢と、検索の結果の「スターだけ」の表示を足す。
- `mobile-reader`：Webと同じく、並び順の選択肢と検索の結果の「スターだけ」の表示を足す。
- `settings`：「スター」の項目にだけ保存できる並び順と、設定ファイルでの扱いを足す。

## Impact

- `packages/core/src/db/migrations/033_starred_at.sql`（新規）：記事の表の `starred_at` の列と索引、`list_views` の作り直し
- `packages/core/src/api.ts`：並び順の値、記事の要約、検索の条件
- `packages/core/src/db/articles.ts`：一覧、続きの値、スターの変更、検索
- `packages/core/src/db/list-views.ts`：「スターを付けた順」を保存できる項目の検査
- `packages/client`：一覧の絞り込み、項目ごとの並び順、一覧の並びの時刻、検索の条件
- `apps/web`：並び順のメニュー、検索の結果の切り替え
- `apps/mobile`：並び順の選択肢、検索の結果の切り替え
- `docs/api.md`：一覧の並び順、検索の条件、記事の要約、表示の設定の説明
