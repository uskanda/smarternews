# grilling 記録: add-starred-order

Issue #217「スターを整理する手段（付けた順、スターの中の検索）」の計画の記録である。
計画の段階で、Issueに4つの質問を出した。利用者は4つとも推奨の案を選んだ。
そのあとに出した計画を、利用者はそのまま承認した（`/ok`）。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 「スターを付けた順」の出し方 | 「スター」の一覧の並び順のメニューにだけ、3つ目の選択肢として足す。既定は「新しい順」のままで、選んだ値はほかの並び順と同じくサーバーに保存し、Webとアプリで共有する | 第1ラウンド Q1（A） |
| いまあるスターの時刻 | 移行で、記事の日時（最終更新の時刻）を付けた時刻として入れる。いまあるスターは今日と同じ順に並び、これから付けるスターがその上に来る | 第1ラウンド Q2（A） |
| アプリも対象にするか | Webとアプリの両方に入れる | 第1ラウンド Q3（A） |
| 「スターだけ」の検索での重複 | 隠した重複も、スターがあれば出す。「スター」の一覧と同じ範囲を探す | 第1ラウンド Q4（A） |
| スターの時刻の保存 | 付けるとその時刻を保存し、外すと消す。すでにスターのある記事に付け直しても、時刻は変えない | 第1ラウンドの前提（質問によらず決まったこと） |
| 外したスターを「元に戻す」 | 付け直した時刻になり、一覧の先頭へ移る。元の時刻へ戻す仕組みは足さない | 第1ラウンドの前提 |
| タグ | 扱わない。次の段階とする | Issue #217の本文、第1ラウンドの前提 |
| LLMの呼び出し | 呼ばない | Issue #217の本文 |
| トピックの書き直しの提案に渡す材料 | 変えない。スターの時刻を使えるようになるが、LLMに渡す材料を変えることになるので別の話とする | 計画（`/ok` で承認） |
| 計画の承認 | 上の判断に沿った計画を、そのまま承認 | Issue #217への返答（`/ok`） |

## 後回しにしたもの

- タグ。add-mentionsでも後回しにしており、入れない決定はない
- トピックの書き直しの提案で、スターを付けた時刻を使うこと
- Androidの実機とエミュレーターでの確認。テストで代える
