# grilling 記録: show-nav-fetch-failures

Issue #211（カテゴリの取得が失敗したとき、左のペインに失敗と再試行が出ない件）で、計画についての質問に答えてもらった。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 本文側の「読み込み中…」の扱い | A：カテゴリや購読フィードの一覧のURLでその一覧の取得が失敗したら、本文側に失敗と再試行のボタンを出す。再試行は、失敗した問い合わせを取り直す | Issue #211 Q1 |
| 左のペインでの出し方 | A：失敗したものの名前を並べた1行と、再試行のボタン1つを出す。ボタンは失敗したものをまとめて取り直す | Issue #211 Q2 |
| 左のペインでの位置 | A：検索欄のすぐ下、固定の項目の上 | Issue #211 Q3 |
| 「読み直す」で取り直す範囲 | A：カテゴリと購読フィードは、失敗しているときだけ取り直す | Issue #211 Q4 |
| 計画の承認 | 上の4つの答えに沿った計画を承認 | Issue #211への返答（`/ok`） |

## 選ばなかった案

- 本文側を変えず、左のペインと「読み直す」だけで直す案。狭い画面では左のペインが隠れていて、理由の分からない `読み込み中…` が残る
- 失敗した問い合わせごとに1行とボタンを出す案。サーバーが止まると同じような行が3つ並び、狭いペインを埋める
- 失敗の行を、本来カテゴリが並ぶ位置に置く案。件数や購読フィードの失敗とは場所が合わない
- 「読み直す」で、カテゴリと購読フィードを毎回取り直す案。押すたびに問い合わせが2つ増え、左のペインが組み直されることもある

## 前提にした既存の決定

- `r` で購読フィードの取得を始めてはならない（web-shellの要件「キーボードでの一覧の再取得」）。これはサーバーへの取得の指示のことで、`["feeds"]` の問い合わせを取り直すことは当たらない

frontierは空。共有理解に到達した。利用者はQ1からQ4に答え、続く計画を承認した。
