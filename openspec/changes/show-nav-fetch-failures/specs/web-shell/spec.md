# Spec Delta

## MODIFIED Requirements

### Requirement: 手動の更新

利用者が更新を選んだとき、画面は件数と表示中の一覧をすぐに取得し直さなければならない（MUST）。
このとき、カテゴリと購読フィードの一覧の取得が失敗している間は、それらも取得し直さなければならない（MUST）。

#### Scenario: 更新のボタンを押す

- **WHEN** 一覧の更新のボタンを押す
- **THEN** 60秒を待たずに一覧が取得し直される

#### Scenario: 失敗していたカテゴリを取り直す

- **WHEN** カテゴリの取得が失敗した状態で、一覧の更新のボタンを押す
- **THEN** カテゴリが取得し直され、左のペインに並ぶ

#### Scenario: 成功しているカテゴリは取り直さない

- **WHEN** カテゴリと購読フィードの取得が成功している状態で、一覧の更新のボタンを押す
- **THEN** カテゴリと購読フィードの一覧は取得し直されない

### Requirement: 失敗の表示

APIの呼び出しが失敗したとき、画面は、何ができなかったかと、利用者が次にできることを表示しなければならない（MUST）。
左のペインのカテゴリ、購読フィード、件数の取得が失敗し、そのデータを持っていない間、左のペインは検索欄のすぐ下に1行を表示しなければならない（MUST）。
その1行は、読み込めなかったものを並べ、それらを取得し直すボタンを1つ置く。

#### Scenario: サーバーに届かない

- **WHEN** サーバーが止まっている状態で一覧を取得する
- **THEN** サーバーに接続できないことと、「もう一度試す」のボタンが表示される

#### Scenario: 入力の誤り

- **WHEN** カテゴリの最低重要度に範囲外の値を保存しようとする
- **THEN** その入力欄の近くに、誤りの理由が表示される

#### Scenario: 左のペインのカテゴリが取得できない

- **WHEN** 画面を開いたときにカテゴリの取得だけが失敗する
- **THEN** 左のペインの検索欄の下に「カテゴリを読み込めませんでした」と「もう一度試す」のボタンが表示され、ボタンを押すとカテゴリが並び、その1行は消える

#### Scenario: 複数が取得できない

- **WHEN** 画面を開いたときにカテゴリと件数の取得が失敗する
- **THEN** 左のペインには「カテゴリと件数を読み込めませんでした」の1行と、「もう一度試す」のボタンが1つだけ表示される

#### Scenario: 取り直しだけが失敗する

- **WHEN** カテゴリを一度取得したあと、取り直しが失敗する
- **THEN** 左のペインは前のカテゴリを並べたままで、失敗の1行は表示されない

#### Scenario: 開いているカテゴリの一覧が分からない

- **WHEN** カテゴリの取得が失敗した状態で、カテゴリの一覧のURLを開く
- **THEN** 本文側に `読み込み中…` ではなく、失敗と「もう一度試す」のボタンが表示される。購読フィードの一覧のURLで購読フィードの取得が失敗したときも同じである

### Requirement: キーボードでの一覧の再取得

記事の一覧が表示されている間、`r` が押されたとき、画面は一覧の更新のボタンを押したときと同じく、件数と表示中の一覧をすぐに取得し直さなければならない（MUST）。取得が失敗しているカテゴリと購読フィードの一覧も、同じく取得し直さなければならない（MUST）。
注釈の一覧が表示されている間、`r` が押されたとき、画面は件数と注釈の一覧をすぐに取得し直さなければならない（MUST）。
画面は、このキーで購読フィードの取得を始めてはならない（MUST NOT）。
利用者が更新のボタンか `r` で始めた取り直しの間、画面はボタンを「読み直し中…」と表示して押せなくし、`r` を無視しなければならない（MUST）。
取り直しが終わったとき、画面は、新しく一覧に入った記事の数を表示しなければならない（MUST）。
数えるのは、取り直す前の画面になかった記事である。読み込んでいなかったページから繰り上がった記事は、この数に含めない。
取り直しに失敗したとき、「すべて既読にする」のあとの取り直し、60秒ごとの自動の取り直しでは、画面はこの数を表示してはならない（MUST NOT）。

#### Scenario: キーで一覧を読み直す

- **WHEN** 未読の一覧を開いたまま、サーバーで新しい記事が作られ、60秒を待たずに `r` を押す
- **THEN** 一覧に新しい記事が現れ、左のペインの未読数が増える

#### Scenario: キーで注釈の一覧を読み直す

- **WHEN** 注釈の一覧を開いたまま、サーバーで注釈が作られ、`r` を押す
- **THEN** 注釈の一覧に、その注釈の行が現れる

#### Scenario: 購読フィードを取得しない

- **WHEN** 購読フィードの一覧で `r` を押す
- **THEN** その購読フィードの取得は始まらない

#### Scenario: 取り直している間

- **WHEN** 一覧の「読み直す」を押し、取り直しがまだ終わっていない
- **THEN** ボタンは「読み直し中…」と表示されて押せず、`r` を押しても次の取り直しは始まらない

#### Scenario: 新しい記事がある

- **WHEN** サーバーで新しい記事が2件作られたあとで、「読み直す」を押す
- **THEN** 取り直しが終わると、「新しい記事が2件あります」と表示される

#### Scenario: 新しい記事がない

- **WHEN** 新しい記事がないときに `r` を押す
- **THEN** 取り直しが終わると、「新しい記事はありませんでした」と表示される

#### Scenario: 取り直しに失敗する

- **WHEN** サーバーに届かない状態で、一覧の「読み直す」を押す
- **THEN** 新しい記事の数は表示されず、一覧の上のエラーの表示が失敗を知らせる

#### Scenario: すべて既読にしたあとの取り直し

- **WHEN** 一覧の「すべて既読にする」を押す
- **THEN** 既読にした件数だけが表示され、新しい記事の数は表示されない

#### Scenario: キーで失敗していたカテゴリを取り直す

- **WHEN** カテゴリの取得が失敗した状態で、カテゴリの一覧のURLを開き `r` を押す
- **THEN** カテゴリが取得し直され、その一覧の記事が表示される
