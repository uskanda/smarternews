# grilling 記録: disable-actions-while-pending

GitHubのissueの96番のコメントで、1ラウンドの質問に答えた記録である。
issueは、2026-11-06のWeb UIの監査（監査ID：B-10）で見つけた項目である。
要求の応答を待つ間も押せるボタンがあり、続けて押すと同じ操作を二重に送る。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 直す範囲 | サーバーのデータを変える要求を送るボタンを、Webの全体で直す。issueが挙げた削除、追加、「すべて既読にする」、ハイライトの作成に加えて、各設定の「保存する」、読み込み、切り替え、版を戻す操作、並べ替えも入れる（C）。書き出しと、楽観的に更新する操作（スター、既読の印）は入れない | 第1ラウンド Q1 |
| 作り方 | 購読フィードの登録の解除（`removing`）に揃える。状態を1つ持ち、処理の入口で二重の呼び出しを捨て、ボタンに `disabled` を付ける。共通の小さなフック `usePending` にまとめる | 計画の承認で確認 |
| 1つのダイアログに要求を送るボタンが2つあるとき | どちらの要求の間も、両方を止める | 計画の承認で確認 |
| キーとメニュー | Shift+AとHのキーは要求の間は捨て、右クリックのメニューの項目は止める | 計画の承認で確認 |
| ボタンの名前と「やめる」 | ボタンの名前は要求の間も変えない。「やめる」は押せるままにする | 計画の承認で確認 |
| すでに守られている所 | 購読フィードの追加、フィルターのフォーム、トピックを足すダイアログ、メモのダイアログ、「いま取得」などはそのままにし、フックへの書き換えもしない | 計画の承認で確認 |
| Androidアプリ | 対象にしない。Web UIの監査の項目のため | 計画の承認で確認 |

## 後回しにしたもの

- すでに守られている所を、共通のフックに書き換えること
