# Spec Delta

## ADDED Requirements

### Requirement: 要求の間の操作の無効化

利用者の操作でサーバーのデータを変える要求を送ったとき、画面はその応答が届くまで、同じ要求を送るボタンとメニューの項目を無効にしなければならない（MUST）。
同じ要求を送るキーは、応答が届くまで何もしてはならない（MUST NOT）。
応答が届いたあとは、成否によらず、ボタン、メニューの項目、キーを元に戻さなければならない（MUST）。
1つのダイアログに要求を送るボタンが複数あるときは、どれかの要求の間、そのすべてを無効にする。
要求の間もボタンの名前は変えず、要求を送らない「やめる」は押せるままにする。
対象は、削除の確認、追加のフォーム、一括の既読、ハイライトの作成、設定の保存、OPMLと設定ファイルの読み込みである。
フィルターの有効と無効の切り替え、トピックの版に戻す操作、語のまとまりの並べ替えも対象にする。
押した直後に画面を変え、失敗したら元に戻す操作（スター、既読の印、左のペインの並べ替え）は対象にしない。
データを変えない操作（書き出し）も対象にしない。

#### Scenario: 削除の確認を続けて押す

- **WHEN** トピックの削除の確認で「削除する」を押し、応答が届く前にもう一度押す
- **THEN** 削除の要求は1回だけ送られ、応答が届くまで「削除する」は無効で、届いたあと「トピックを削除しました」と知らせる

#### Scenario: 追加を続けて押す

- **WHEN** 新しいトピックを書いて「トピックを追加」を押し、応答が届く前にもう一度押す
- **THEN** トピックは1件だけ作られる

#### Scenario: 一括の既読をボタンとキーで続ける

- **WHEN** 一覧で「すべて既読にする」を押し、応答が届く前にもう一度押し、`Shift+A` も押す
- **THEN** 一括の既読の要求は1回だけ送られ、知らせには最初の操作の件数と取り消す手段が残る

#### Scenario: ハイライトを続けて作る

- **WHEN** 選んだ文字列の下に出るボタンの「ハイライト」を押し、応答が届く前に `H` を押し、右クリックのメニューを開く
- **THEN** ハイライトは1件だけ作られ、応答が届くまでボタンの「ハイライト」とメニューの「ハイライト」は無効である

#### Scenario: ダイアログの2つのボタン

- **WHEN** カテゴリの削除の確認で「無効にする」を押し、応答が届く前に「削除する」を押す
- **THEN** 確認の「削除する」は無効で、要求は「無効にする」の1回だけ送られる

#### Scenario: 失敗のあと

- **WHEN** 設定の保存の要求が失敗する
- **THEN** 設定の「保存する」は押せる状態に戻り、もう一度保存できる
