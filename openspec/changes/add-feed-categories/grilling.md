# grilling 記録: add-feed-categories

GitHubのissueの218番のコメントで、1ラウンドの質問（Q1〜Q6）に答えた記録である。
issueは、Web UIの監査の項目（R-08）である。購読フィードのパーサーは、項目の分類（RSSの `category` と `dc:subject`、Atomの `category`）を読んでいない。
1つのフィードに複数の分類を混ぜて配信するサイトで、分類を条件にしたフィルターを書けない。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 用語集に載せる名前 | 「配信元の分類」（en: feed category、APIの欄は `feedCategories`）。フィルターの欄の見出しは「分類」（A） | 第1ラウンド Q1 |
| 複数の値と条件の照合 | 値を1つずつ照合し、どれか1つが合えば欄が合ったとみなす。正規表現の `^Tech$` で1つの値に完全一致できる（A） | 第1ラウンド Q2 |
| 本文に出す画面 | Webとアプリの両方で、著者の横に小さく出す（A） | 第1ラウンド Q3 |
| 読む要素の範囲 | RSSの `category` と `dc:subject`、Atomの `category`（`label` があれば `label`、なければ `term`）、JSON Feedの `tags` を読む（A） | 第1ラウンド Q4 |
| 値の整え方と上限 | 前後の空白を除いてプレーンテキストにし、空の値と重複は保存しない。1件に20個まで、1つの値は100文字までで保存する（A） | 第1ラウンド Q5 |
| 保存済みの配信記事 | 書き換えの比較に分類を足す。フィードに残っている項目は次の取得で埋まり、照合し直される。消えた項目は空のまま（A） | 第1ラウンド Q6 |

## 計画で決めたこと

承認を求めた計画（issueのコメント）で、次を決めた。利用者は変更なしで承認した。

| 決定 | 選択 |
|---|---|
| 保存の列 | `articles` の `feed_categories`（JSONの配列、NULLは「なし」） |
| 分類だけが変わったとき | 列を書き換え、フィルターを照合し直す。翻訳は消さない |
| フィルターの欄の値 | `filter_conditions` の欄はJSONの文字列なので、移行はいらない |
| 生成記事と読めない値 | APIでは空の配列にする |
| JSON Feedの `tags` | `add-json-feed` で「読まない」と決めたことを、この変更で改める |

## 後回しにしたもの

- 変更の前に保存し、配信元のフィードからもう消えた記事の分類を埋めること
