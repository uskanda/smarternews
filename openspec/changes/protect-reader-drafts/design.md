# Design

## Context

読む画面のダイアログは6つある。購読フィードの追加、購読フィードの設定、トピックを足すの3つは `ui/FormDialog.tsx` を使う。ハイライト、メモを書いてハイライトする、隠すフィルターを作るの3つは、Radixのダイアログを直に使う。どれもRadixの既定で、外を押すと閉じる。入力の状態はダイアログの中の部品が持つので、閉じると消える。

設定の画面には `settings/unsaved.tsx` の `UnsavedGuard` があり、`useUnsaved(label, dirty)` で各部品が保存していない変更を知らせる。`AddFeedForm` と `FilterForm` は、すでにこのフックを呼んでいる。ダイアログの中では文脈がなく、何もしない。

`ReaderPage.tsx` は記事の画面に `key={articleId}` を付けている。記事を切り替えると記事へのメモの欄は作り直され、書きかけは消える。

`add-feed-from-category/design.md` は、「閉じれば値は捨てられ、次に開いたときは初期の値から始まる」と決めた。当時は、外を押す誤操作を検討していなかった。この変更は、閉じたら捨てることは保ったまま、閉じる前に確認を挟む。

`add-feed-from-category` は、まだarchiveしていない。この変更の `web-reader` の差分は、その変更の要件「ダイアログの取りやめ」と「購読フィードの設定の取りやめ」を書き換える。このため、archiveは `add-feed-from-category` のあとに行う。

## Goals / Non-Goals

**Goals:**

- 6つのダイアログの閉じ方を、1か所の部品でそろえる。
- 記事へのメモの書きかけを、別の記事へ移るときと再読み込みで失わない。

**Non-Goals:**

- 読む画面に、ページを移る前や再読み込みの前の確認を足すこと。記事へのメモはタブの中に覚え、ダイアログは開いている間だけ守る。
- ハイライトのメモの書きかけを覚えること。ダイアログが閉じなければ消えない。
- 設定の画面の振る舞いを変えること。

## Decisions

### 守りの文脈を `ui/` へ移す

`settings/unsaved.tsx` を `ui/unsaved.tsx` へ移し、文脈 `UnsavedContext` を外に出す。`FormDialog` はこの文脈を自分で用意し、中の部品が `useUnsaved` で知らせた変更を集める。
こうすると、`AddFeedForm` と `FilterForm` がすでに出している知らせを、ダイアログがそのまま使える。ダイアログの中で、別のフックやpropsを通す必要がない。
設定の画面の中にダイアログを置いた場合は、ダイアログの文脈が内側になり、ページの守りには届かない。ダイアログは開いている間、外を押しても閉じないので、ページを移る操作に届かない。

別案は、各ダイアログに `dirty` のpropsを渡すことだった。入力の状態はフォームの中にあるので、状態を外へ持ち上げる変更が4つの部品に要る。採らない。

### 閉じ方の守り

`FormDialog` は、集めた変更が1つでもある間、次のようにする。

- `onInteractOutside` で `preventDefault` する。外を押しても、フォーカスが外へ出ても閉じない。
- Radixの `onOpenChange(false)`（Escapeと `Dialog.Close`）を受けたら、閉じずに確認を開く。
- 「やめる」のように、フォームが親から受けた閉じる関数を直に呼ぶボタンは、`useDialogCancel(fallback)` を使う。`FormDialog` の中では、確認を挟む閉じ方を返す。外では `fallback` を返す。

入力がなければ、どれもこれまでどおり閉じる。保存できたときや「登録を解除」「ほかの設定」は、親の閉じる関数を直に呼ぶので、確認を通らない。

応答を待つ間は、各部品が `useUnsaved` の `dirty` に待っていることを含める。購読フィードの追加は、URLが空でないので、候補と登録を待つ間も守られる。

### 確認の見た目とフォーカス

確認は `ConfirmDialog` を使い、題を「保存していない変更があります」、操作を「破棄して閉じる」と「編集を続ける」にする。トピックの編集と同じである。
「破棄して閉じる」では、確認を先に閉じ、次の描画でダイアログを閉じる。Radixはフォーカスを戻す処理を閉じた順に行うので、最後にダイアログの開いた元（ボタンやハイライト）へフォーカスが戻る。

### 3つのダイアログを `FormDialog` に移す

ハイライト、メモを書いてハイライトする、隠すフィルターを作るの3つは、`FormDialog` を使う。見た目を変えないため、`FormDialog` にダイアログの幅と間隔の指定と、閉じたときのフォーカスの戻り先 `returnFocus` を足す。

### 何を「入力がある」とみなすか

- 購読フィードの追加：URLが空でない（いまのまま）。
- 購読フィードの設定：3つの切り替えのどれかが購読フィードの値から変わったか、保存を待っている。
- トピックを足す：文章が開いたときの値と違うか、カテゴリを別のものに選び直したか、追加を待っている。
- 隠すフィルターを作る：`FilterForm` に `initial` が渡されたとき、それと比べて変わった。設定の画面の新しいフィルター（`initial` なし）は、いまのまま値が書かれたかで決める。
- メモの欄（`NoteForm`）：書きかけが保存済みの値と違うか、保存を待っている。

### メモの欄の「やめる」

`NoteForm` は、書きかけがあるとき「やめる」で自分の確認を出す。ダイアログの外の記事へのメモでも、ハイライトのダイアログの中でも、同じ振る舞いにするためである。破棄を選ぶと、親の `onCancel` を呼ぶ。

### 記事へのメモの書きかけ

`sessionStorage` に、`smarternews.noteDraft.<記事のID>` のキーで覚える。読み書きは `lib/note-drafts.ts` にまとめる。

- `NoteForm` は、入力が変わるたびに `onDraftChange` で書きかけを知らせる。保存済みのメモと同じなら消し、違えば書く。
- 保存できたとき、確認で破棄したとき、入力がないまま「やめる」で閉じたときは消す。
- `ArticleNoteSection` は作られるときに覚えた書きかけを読み、保存済みのメモと違えば、入力欄を開いてそれを入れる。このときは `autoFocus` を付けない。ボタンから開いたときは、これまでどおりフォーカスを移す。
- 保存領域が使えないブラウザー（プライベートの設定など）では、読み書きの例外を無視し、覚えない。

別案のlocalStorageは、ブラウザーを閉じても残る代わりに、古い書きかけを消す決まりとほかのタブとの食い違いを決める必要がある。grillingのQ1で採らなかった。

## Risks / Trade-offs

- 危険：記事へのメモの書きかけは、保存済みのメモがほかの端末で変わっても、そのまま入力欄に戻る。対策：書きかけは利用者が書いたものなので、捨てずに見せる。保存すれば、書きかけの内容で上書きする。
- 危険：ダイアログに入力があると、外を押しても何も起きない。対策：閉じるにはEscapeか「やめる」を使う。確認で破棄を選べば閉じる。
- 危険：ハイライトのダイアログでメモを書きかけたまま、ほかのタブで記事が消える。対策：ダイアログは開いたままで、保存は失敗を知らせる。いまと同じである。
