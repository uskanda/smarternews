# Design

## Context

一覧の画面のパスは `/c/<slug>`（「AI生成」は `/c/<slug>/generated`）、カテゴリの設定の画面のパスは `/settings/categories/<id>` である。
記事の一覧の上部は、見出しと「すべて既読にする」「読み直す」の行と、その下の切り替えの行から成る。購読フィードの一覧の「購読フィードの設定」や、カテゴリの一覧の「購読フィードの追加」は、下の行に並ぶ。
イベントのカテゴリの一覧は別の部品（`EventList`）が描き、上部には見出しだけがある。
カテゴリの設定の画面は `UnsavedGuard` の中にあり、画面の中のリンクで離れるときも、保存していない変更の確認が働く。
左のペインのメニュー（`EntryMenu`）は、動かせる項目（カテゴリと購読フィード）にだけ出る。

## Goals / Non-Goals

**Goals:**

- 1つのカテゴリの一覧と、そのカテゴリの設定の画面を、1回の操作で行き来できるようにする。

**Non-Goals:**

- Androidアプリでの同じ入口。
- 「AI生成」の行や「未分類」にメニューを出すこと。
- 購読フィードの行のメニューの変更。

## Decisions

### 一覧の上部のリンク

記事の一覧では、切り替えが並ぶ行の末尾に、文字のリンク「カテゴリの設定」を置く。見出しの横に3つ目のボタンを置くと、一覧の名前の幅がなくなるためである。
出すのは、表示がカテゴリの一覧か「AI生成」の一覧で、パスの `<slug>` に合うカテゴリが見つかったときである。
イベントの一覧では、見出しの下に1行を足して同じリンクを置く。`EventList` は設定の画面のパスを引数で受け取る。
リンクの部品 `CategorySettingsLink` は `EventList.tsx` に置き、`ReaderPage` からも使う。
見た目は、設定の画面の「設定へ戻る」と同じ `type-label-sm` の `primary` の色の下線付きにする。

### 設定の画面のリンク

見出しの下に `/c/<slug>` へのリンクを置く。文言は `kind` で「記事の一覧」と「イベントの一覧」に分ける。
無効のカテゴリにも出す。無効にしても記事は残り、カテゴリごとに読む入口はほかにないためである。
リンクで進んだ先が無効のカテゴリの一覧なら、左のペインのどの項目も選択中にならない。

### 左のペインのメニュー

カテゴリのメニューでは、「上へ移動」「下へ移動」の下に区切り線を引き、「カテゴリの設定」を置く。選ぶと設定の画面へ移る。
購読フィードの「登録を解除」と同じ位置であり、移動の操作とほかの操作を区切る。

### パスの関数

設定の画面のパスは `lib/paths.ts` の `categorySettingsPath` にまとめ、既存の `topicEditPath` と `topicStatsPath` もこれを使う。

## Risks / Trade-offs

- カテゴリのメニューの項目が増え、キーボードでの移動の順が変わる。「下へ移動」が最後の項目でなくなる。既存のキーボードのテストは、最後の項目から1つ上を選ぶ形に直す。
