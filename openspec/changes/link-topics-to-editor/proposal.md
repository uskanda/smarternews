# Proposal

## Why

外れた記事を見つけても、その記事を選んだトピックの編集へ移る道がない。記事のAPIは当てはまったトピックを返すが、本文の画面には出ていない。直すには設定の画面からトピックの編集まで4回移り、どのトピックを直すかは推測するしかない。実行の詳細の「このトピックを直す」も、カテゴリの画面の先頭へ移るだけである。

## What Changes

- 生成記事の本文の画面で、補足の行のすぐ下に「トピック」の行を出し、当てはまったトピックをリンクで並べる。トピックのない記事では出さない。
- カテゴリの画面を `#topic-<id>` 付きで開くと、そのトピックまでスクロールし、編集を開いて、文章の欄にフォーカスを移す。
- 実行の詳細では、トピックごとにまとめたときの「このトピックを直す」と、まとめないときのトピック名の両方を、同じ遷移先へのリンクにする。
- APIとデータベースは変えない。モバイルアプリは対象外とする。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `web-reader`: 生成記事の本文に、当てはまったトピックをトピックの編集へのリンクとして表示する。
- `web-runs`: 除外した候補のトピックから、そのトピックの編集を開いた状態へ進める。
- `web-settings`: カテゴリの画面を、特定のトピックの編集を開いた状態で開ける。

## Impact
