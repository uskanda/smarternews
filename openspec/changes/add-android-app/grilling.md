# grilling 記録: add-android-app

Androidアプリの要件と設計を決めた2ラウンドの質問をまとめたものである。
対象をAndroidだけにすること、ストアを通さずAPKで入れること、端末に記事を保存しないことは、最初のchangeのgrillingで決まっている。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 範囲 | 読むことを中心にする。記事の一覧と本文、既読、スター、重要度での絞り込み、イベント、読み手情報の編集、即時の実行と直近の実行の状態。カテゴリとトピックの編集、設定ファイル、除外した候補はWebに任せ、アプリからWebの画面を開けるようにする | 第1ラウンド Q3 |
| APKのビルドと配布 | GitHub Actionsが署名済みのAPKを作り、GitHub Releasesに添付する。APKには特定の利用者の情報を入れない | 第1ラウンド Q4 |
| 開発中の確かめ方 | 開発用のマシンにJDKとAndroid SDKを入れ、エミュレーターで実際に動かして確かめる | 第1ラウンド Q5 |
| 通知 | 端末が定期的にサーバーを確かめ、新着があれば端末の中で通知を出す。外部のサービスは使わない。既定は重要度5の新着だけで、「新着すべて」と「出さない」を選べる | 第1ラウンド Q6 |
| サーバーへの接続の設定 | Webの設定の画面にQRコードを出し、アプリのカメラで読む。手での入力もできる。トークンは端末の暗号化された保存領域に置く | 第1ラウンド Q7 |
| 画面の構成 | 一覧から本文へ進む2段。項目の切り替えは左から出る引き出しで、並びはWebと同じ。一覧は引いて更新し、本文は左右に払って前後の記事へ移る | 第1ラウンド Q8 |
| 見た目 | `DESIGN.md` の配色、間隔、書体をそのまま使い、明朝とゴシックの2書体を同梱する | 第1ラウンド Q9 |
| 名前と識別子 | 名前は `smarternews`、識別子は `io.github.uskanda.smarternews`。アイコンは藍色の地に黄色の印 | 第1ラウンド Q10 |
| 署名の鍵 | 開発者が鍵を作ってリポジトリの外に置き、GitHubのsecretに登録する | 第2ラウンド Q2 |
| APKを作る契機 | リリースのタグを打ったときと、手動で起動したときだけ。毎回のPRの検査には入れない | 第2ラウンド Q3 |
| 通知の形 | 記事ごとに通知し、押すとその記事を開く。1回の確認で4件以上あれば1つにまとめ、押すと未読の一覧を開く | 第2ラウンド Q4 |
| 一覧の行を払う操作 | 左へ払うと既読と未読を切り替える。スターは本文の画面と、行の長押しで付ける。右へ払う操作は、引き出しを開く操作とぶつかるので置かない | 第2ラウンド Q5 |
| 画面の向き | 縦向きだけ。タブレット向けの配置は作らない | 第2ラウンド Q6 |
| 出典の開き方 | アプリ内のブラウザーで開く | 第2ラウンド Q6 |
| 実行の操作の場所 | 即時の実行と直近の実行の状態は、設定の画面にカテゴリごとに並べる | 第2ラウンド Q6 |
| QRコードの出し方 | Webの設定の画面でボタンを押したときだけ出す。中身は、そのときブラウザーが開いているサーバーのURLとトークン | 第2ラウンド Q6 |
| テスト | Jestで、Webと同じく実物のAPIに対して画面を動かす | 第2ラウンド Q6 |
