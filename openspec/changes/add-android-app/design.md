# Design

## Context

サーバーは `/api/v1` のAPIと、ビルド済みのWebの画面を配る。Webの画面は `apps/web` にあり、APIの型とスキーマを `packages/core` と共有している。
APIの呼び出し、日時の整形、イベントのまとめ方、再取得の結果と読んだ記事を合わせる処理は、いま `apps/web` の中にある。どれも画面の部品に依存しない。
サーバーにはTLSがなく、到達経路は自宅のLANとTailscaleである。アプリは `http` のURLへ接続する。
開発用のマシンは画面を持たない。Androidの道具は、利用者の領域に入れて使う。

## Goals / Non-Goals

**Goals:**

- Webと同じAPIだけで動く、読むためのアプリを作る。
- 画面に依存しない処理を、Webとアプリで1つにする。
- 見た目の値を `DESIGN.md` から取り、Webと同じ印象にする。
- 誰が入れても同じAPKを、リポジトリのタグから再現できる形で作る。

**Non-Goals:**

- 端末への記事の保存と、圏外での閲覧。
- カテゴリとトピックの編集、設定ファイルの操作、除外した候補の表示。
- iOS、タブレット向けの配置、横向きの表示。
- サーバーの側から通知を送る仕組み。

## Decisions

### D1. 構成

`apps/mobile` に、ExpoのSDK 57とReact Native 0.86で作る。画面の遷移は `expo-router` を使い、引き出しの中に一覧、その上に本文と設定の画面を重ねる。
Expo Goは使わない。通知の定期的な確認とカメラがExpo Goで動かないためである。開発用のビルドとリリース用のビルドを、どちらも `expo prebuild` で作る。
`android` のディレクトリは生成物としてコミットしない。設定は `app.config.ts` と設定用のプラグインに書く。

### D2. 共有する処理

新しいパッケージ `packages/client` を作り、次のものを `apps/web` から移す。テストも一緒に移す。

- APIの呼び出しと、失敗の種類の区別
- 日時の整形
- イベントを開催日ごとにまとめる処理
- 再取得の結果と、読んだ記事を合わせる処理
- 実行の状態と失敗の内容を言葉にする処理

APIの呼び出しには、サーバーのURLを渡せるようにする。Webは空のまま使い、アプリは接続中のサーバーのURLを渡す。
移すのは置き場所だけで、Webの振る舞いは変えない。Webのテストがそのまま通ることで確かめる。

### D3. 接続の設定

QRコードの中身は、次の形のURLとする。

```
smarternews://connect?v=1&url=<サーバーのURL>&token=<トークン>
```

- アプリは、方式が `smarternews`、`v` が1、`url` が `http` か `https` のURLであることを確かめる。当てはまらないものは、接続用でないQRコードとして扱う。
- 読み取りと手入力は、同じ確認を通す。`/api/v1/settings` を呼び、成功したら保存する。
- トークンは `expo-secure-store` で保存する。Androidでは、端末の鍵で暗号化された領域に入る。サーバーのURLと通知の設定は秘密ではないので、通常の保存領域に置く。
- 暗号化なしの通信は、`expo-build-properties` でアプリ全体に許可する。宛先を利用者が決めるので、宛先ごとの許可は書けない。
- Webの側は、設定の画面のトークンの区画にボタンを足す。押すとダイアログが開き、`location.origin` と保存中のトークンから上の形のURLを作ってQRコードにする。QRコードはSVGの四角を並べて描く。

### D4. 一覧と本文

- 一覧は、仮想化された一覧の部品で作る。末尾で続きを読み込み、先頭で引くと取得し直す。
- 取得と更新には、Webと同じくTanStack Queryを使う。未読数と一覧は、アプリが前面に戻ったとき取得し直す。前面にある間は60秒ごとに取得し直す。
- 行を払う操作と長押しは、`react-native-gesture-handler` で作る。払う操作を使えない利用者のために、同じ操作を長押しの一覧と本文の画面にも置く。
- 本文の画面は、一覧の記事を横に並べたページの集まりとして作る。ページが見えたら既読にする。一覧へ戻ると、見ていた記事の位置へ移る。
- 読んだ記事を一覧に残す動きは、Webと同じ処理（D2）を使う。
- 本文のMarkdownは、HTMLを解釈しない設定の部品で描く。リンクは `http` と `https` だけを開く。出典と本文のリンクは `expo-web-browser` で開く。

### D5. 見た目

- `scripts/` のトークンの変換に、アプリ向けの出力を足す。配色、間隔、角の丸み、文字の大きさと行間を、明るい配色と暗い配色の2組として `apps/mobile` に出力する。出力はコミットし、`make verify` でずれを検出する。
- 書体は、Webと同じ2つを、ビルドのときにAPKへ埋め込む。明朝は太さ500と700、ゴシックは400と600を入れる。
- 押せる部品の大きさは、Androidの目安に合わせて48dpとする。`DESIGN.md` に、アプリ向けの値として足す。
- 影は使わない。重なりは色の差と罫線で示す。引き出しとダイアログだけは、背後を暗くする。
- アイコンは、藍色の地に、黄色の印を重ねた見出しの線を置く。SVGで描き、必要な大きさの画像へ変換する。

### D6. 通知

- 定期的な確認には `expo-background-task` を使う。Androidの仕組みの都合で、間隔は15分以上になり、時刻はOSが決める。
- 確認の処理は、保存したURLとトークンを読み、未読の記事の一覧を、通知の設定に当たる重要度の下限つきで取得する。
- 端末には「ここまで確認した」という時刻を持つ。記事の最終更新がその時刻より後のものを通知の対象にし、成功した確認のあとで時刻を進める。失敗した確認では進めない。
- 通知の設定を「出さない」からほかの値へ変えたときは、その時点を確認した時刻にする。
- 何を通知するかを決める処理は、記事の一覧、確認した時刻、通知の設定から結果を返す関数にする。端末の機能を呼ぶ部分と分けて、関数だけをテストする。
- 通知を出すのは `expo-notifications` の、端末の中で完結する通知である。記事の通知には記事の番号を持たせ、押されたらその記事の画面へ移る。
- 通知の許可は、利用者が通知を出す設定を選んだときに求める。接続を設定した直後にも1度だけ求める。既定が「重要度5だけ」だからである。

### D7. 設定の画面

- 読み手情報は、複数行の入力欄で編集する。保存していない変更があるときは、戻る操作で確認を出す。
- カテゴリごとに、直近の実行の状態と「いま実行」を1行に並べる。待ちか実行中の間は3秒ごとに取得し直す。
- 接続の解除は、確認のあとで、保存したURL、トークン、通知の設定、確認した時刻を消す。定期的な確認の登録も外す。

### D8. テスト

- 画面のテストは、Jest、`jest-expo`、React Native Testing Libraryで書く。APIは、Webのテストと同じく実物を使い、偽の応答は書かない。
- サーバーの部品はNodeの機能に依存する。Jestの中で直接読み込めない場合は、テストの前に別のプロセスとして起動し、HTTPで呼ぶ。最初の作業で確かめた結果、別のプロセスの形を採った（「実装で分かったこと」）。
- 画面に依存しない処理（D2、D6の関数）は、いまと同じVitestで確かめる。
- Jestで確かめられないものは、エミュレーターで確かめ、内容を記録する。操作では、カメラでの読み取り、定期的な確認と通知、払う操作を見る。表示では、暗い配色と読み上げを見る。APKの上書きの更新も確かめる。
- 完成した画面に、Impeccableのネイティブ向けの `audit` をかける。

### D9. ビルドと配布

- GitHub Actionsに、APKを作るワークフローを足す。リリースのタグ（`v` で始まる日付の形式）のpushと、手動の起動で動く。PRに `apk` のラベルを付けたときも動く。
- 手順は、依存の導入、`expo prebuild`、Gradleでのリリース用のビルド、APKの添付である。タグで動いたときはリリースに添付し、手動のときは実行の成果物にする。
- 版の名前はタグから取る。版の番号は、ワークフローの実行の番号を使う。実行のたびに1つ増えるので、後のリリースほど大きくなる。
- 署名の鍵は、secretから読んでビルドの間だけファイルに戻す。鍵の場所と合言葉は、設定用のプラグインが環境変数からGradleの設定へ渡す。
- 鍵がないとき（フォークしたリポジトリなど）は、ビルドを失敗させ、必要なsecretの名前を示す。
- `make verify` の個人情報の検査に、鍵の形式のファイルを拒否する検査を足す。
- 開発用のマシンでも、同じ手順でAPKを作れるようにする。JDKとAndroid SDKは利用者の領域に入れる。

### D10. 検証とCI

`make verify` と、いまのCIの `verify` に、アプリの静的な検査、型の検査、Jestのテストを足す。APKのビルドは足さない。10分ほどかかり、毎回のPRには重いためである。

## Risks / Trade-offs

- 定期的な確認は、OSの省電力の仕組みで遅れたり止まったりする。→ 通知は補助として扱い、アプリを開けば必ず最新を表示する。遅れることと、端末の省電力の設定は、READMEで説明する。
- Tailscaleが切れている間は、確認が届かない。→ 確認した時刻を進めないので、経路が戻ったあとの確認で通知される。
- pnpmで複数のパッケージを持つ構成とReact Nativeの組み合わせで、依存の解決に失敗することがある。→ 最初の作業で、空のアプリのビルドとテストが通ることを確かめる。通らなければ、`apps/mobile` だけ依存の置き方を変える。
- サーバーの部品をJestから直接読み込めないことがある。→ D8のとおり、別のプロセスとして起動する形に切り替える。
- 書体の同梱で、APKが20MBほど大きくなる。→ 受け入れる。大きさを計って記録する。
- 暗号化なしの通信を全体に許可する。→ 宛先は利用者が設定した1つのサーバーだけである。出典はアプリ内のブラウザーが開き、アプリ自身は通信しない。
- QRコードはトークンを含む。→ ボタンを押したときだけ表示し、画面にその旨を書く。
- 署名の鍵をなくすと、上書きの更新ができなくなる。→ 鍵の控えを取る手順を文書に書く。

## Migration Plan

1. `packages/client` への移動を先に入れ、Webのテストが通ることを確かめる。
2. アプリを作り、手動のビルドでAPKを確かめる。
3. `main` へ入れてリリースのタグを打ち、APKがリリースに添付されることを確かめる。

サーバーとDBの変更はない。Webの変更は、QRコードの表示の追加だけである。

## 実装で分かったこと

### 依存の置き方

pnpmの既定の置き方では、React Nativeの部品が、依存の組み合わせごとに複数入った。同じ部品が2つあると、テストとアプリのどちらも動かない。
リポジトリ全体を、依存を平らに置く設定（`nodeLinker: hoisted`）に変えた。あわせて、WebのReactを、Expoが指定する版にそろえた。Webのテストとビルドは変更なしで通っている。

### テストの中のAPI

サーバーの部品は、Jestの中で直接は読み込めなかった。JestがReact Native向けに依存を解決するため、サーバーの依存がブラウザー向けのものに差し替わる。
D8のもう1つの形を採った。`apps/server` にテスト用のプロセスを足し、Jestが始まるときに1つ起動する。テストごとに、メモリ上のDBを持つサーバーを1つ作らせ、ループバックのHTTPで呼ぶ。データの投入と時計の操作も、そのプロセスへの依頼で行う。

- `expo-router` のテスト用の関数は、偽の時計に切り替えてから描画する。偽の時計のままでは、実際の通信の応答を待てなかった。同じ描画を、時計を切り替えずに自前で行っている。
- サーバーの状態を確かめる待ち合わせは、画面の待ち合わせとは別の関数にした。

### 通知

- 確認した時刻の初めの値は、空の文字列ではなく、どの記事よりも前の日時にした。空の文字列は、保存領域によって値なしと区別できないためである。
- アプリの一覧に表示された記事は、通知の対象から外す。確認した時刻を、一覧の中で最も新しい記事の更新日時まで進める。仕様に要件を1つ足した。
- 通知の設定は、起動のときの処理と設定の画面の両方が使う。値を1か所で持ち、許可を断られて「出さない」へ戻った結果を、すぐ設定の画面に出す。

### 画面

- 本文の左右の移動は、ページ単位で止まる横方向のスクロールで作った。表示中のページと両隣だけを描く。ページの並びは、記事を開いた時点の一覧で固定する。裏での再取得で、読んでいる記事が動かないようにするためである。
- 通知やリンクから直接開いた画面には、戻る先がない。戻るボタンは、その場合、未読の一覧か設定の画面へ移る。
- 記事を既読にするのは、一覧の取得が済んでからにした。直接開いた記事も、読んだあと一覧に残せる。
- カメラの許可についての説明は、読み取りを試して断られたあとにだけ出す。エミュレーターで、初回の起動から説明が出ているのを見つけて直した。

### ビルド

- 開発用のマシンには、JDK 17をmiseで、Android SDKを利用者の領域に入れた。エミュレーターは、画面なしで起動し、画面の画像を `adb` で取る。起動にはKVMを使うので、利用者に `kvm` の権限を与えておく。
- 対象のCPUの種類を絞らないAPKは130MBあった。リリースでは、端末向けの `arm64-v8a` と、エミュレーター向けの `x86_64` の2つに絞る。
- 手動の起動は、ワークフローが既定のブランチに入るまで使えない。PRに `apk` のラベルを付けたときにもビルドするようにした。毎回のPRでは動かない。
- Expoの公式のスキルは、`skills-lock.json` だけをリポジトリに置く。中身は他者の著作物で、静的な検査にも通らないため、置かない。

### 利用の記録の送信

QRコードの読み取りには、Expoのカメラの部品が使うGoogleのML Kitが入る。ML Kitは、利用の統計をGoogleへ送るライブラリーを連れてくる。エミュレーターで、アプリの名前で送信の予定が登録されているのを見つけた。
外部へ何も送らない方針に反するので、送信先を担う部分をビルドから外す設定用のプラグインを足した。送信先がなければ、ライブラリーは集めた記録を捨てる。読み取りそのものは変わらない。仕様に要件を1つ足した。

### エミュレーターで確かめたこと

署名済みのAPKをAndroid 15のエミュレーターに入れ、テスト用のサーバーにつないで確かめた。

| 確かめたこと | 結果 |
|---|---|
| `http` のURLとトークンを入力して接続する | 未読の一覧が出た。接続の直後に、通知の許可をたずねられた |
| 一覧の表示 | 同梱した2つの書体で表示された。重要度の印、「未確認」と「更新」の印、全体設定のタイムゾーンの時刻が出た |
| 本文を開く | 明朝の見出しと本文、読み手への影響、出典が出た。本文の中のタグは文字として出た。サーバーの側で既読になった |
| 本文を左右に払う | 隣の記事へ移り、位置の表示が変わった |
| 行を左へ払う、行を長く押す | 開かずに既読になった。長く押すと操作の一覧が出た |
| 引き出し | ボタンと、端から少し内側を払う操作で開いた。システムの戻る操作で閉じた。閉じている間は、読み上げの対象から外れていた |
| イベントの一覧、設定の画面 | 開催日ごとにまとまった。設定には、実行の状態、通知の設定、接続先、版が出た |
| 読み手情報の編集 | 入力中も、入力欄と保存のボタンがキーボードに隠れなかった。保存せずにシステムの戻る操作をすると、確認が出た |
| 暗い配色 | 端末の設定を切り替えると、その場で切り替わった |
| 通知 | アプリを閉じた状態で定期的な確認を強制的に走らせた。重要度5の新着だけが、見出しとカテゴリ名つきで出た。新着がなければ出なかった。通知を押すと、その記事が開いた |
| 上書きの更新 | 版を上げたAPKを上から入れると、接続の設定を保ったまま更新された。別の鍵のAPKと、古い版のAPKは拒否された |
| 接続の解除 | 確認のあと、接続の設定の画面に戻った |
| システムの戻る操作 | 未読の一覧ではアプリを出た。カテゴリの一覧では未読の一覧へ移った。引き出しは閉じた |
| 文字の大きさを2倍にする | 一覧と引き出しは、折り返して全体が表示された。欠けと重なりはなかった |
| 求める権限 | カメラ、通知、通信など、使うものの8つだけになった |
| 利用の記録の送信 | 送信先がないという記録が出て、送信は起きなかった。読み取りの画面とアプリは動いた |

エミュレーターで見つけて直したものは、次の5つである。

- カメラの許可についての説明が、読み取りを試す前から出ていた。
- 時刻の「時」が1桁で出た。Androidは、Nodeと違って0を補わない。終日のイベントの判定にも影響するので、共有する処理の側で補う。
- 引き出しを開く払う操作が、端ではシステムの戻る操作に取られた。受け付ける幅を広げた。
- 閉じた引き出しの項目が、読み上げの対象に残っていた。
- 一覧の行の読み上げで、句点が重なっていた。

### 画面の点検（audit）

Impeccableのネイティブ向けの手順で、実装した本人とは別の担当が、コードと画面の画像から点検した。点数は20点中13点で、内訳は次のとおりである。

| 観点 | 点 | 主な指摘 |
|---|---|---|
| 読み上げと操作のしやすさ | 3 | 本文の移動が払う操作だけ。暗い配色で1か所のコントラスト不足 |
| 速さ | 2 | 一覧の行ごとに日時の整形の部品を作り直す。行をむだに描き直す |
| 配色と値 | 3 | 値を直接書いた箇所が少し残る |
| Androidらしさ | 2 | 一覧でシステムの戻る操作がアプリを閉じない。一覧の下端に余白がない |
| 画面の大きさへの対応 | 3 | 大きな文字での表示が未確認 |

直したものは次のとおりである。

- 一覧でシステムの戻る操作をしても、アプリが閉じなかった。最初の画面への転送を引き出しの外へ出した。未読の一覧で戻ればアプリを出る。ほかの一覧で戻れば未読の一覧へ移る。
- 日時の整形の部品を、タイムゾーンごとに1つだけ作って使い回す。一覧の行と本文のページは、自分の記事が変わったときだけ描き直す。
- 一覧と読み手情報の画面の下端に、システムの操作の帯の分の余白を足した。
- 本文の移動を、払う操作のほかに、読み上げの操作として「次の記事」「前の記事」でもできるようにした。表示中のページは、スクロールが止まった位置から決める。位置の表示は、変わったときに読み上げる。
- 引き出しの外側の部分の読み上げが英語だった。日本語の名前を付けた。引き出しの角の丸みと幅も、設計の値に合わせた。

直さずに残したものは次のとおりである。

- 戻る操作の予告の動き（predictive back）は有効にしていない。有効にするには、保存していない変更の確認の作り方を変える必要がある。
- 細かい値を直接書いた箇所が残る。2dpの間隔、通知の選択の丸の大きさ、等幅の書体の指定である。
- 押せる部品に、キーボードのフォーカスを示す枠がない。入力欄にはある。
- カメラを開いている間のシステムの戻る操作は、読み取りをやめずに画面を離れる。
- 実物の読み上げ（TalkBack）での確認はしていない。名前、役割、状態は、テストと画面の構造の出力で確かめた。

`git status --short -- DESIGN.md .impeccable` で確かめたところ、Impeccableが書いたファイルはない。`DESIGN.md` の変更は、このchangeで足した値と説明だけである。
