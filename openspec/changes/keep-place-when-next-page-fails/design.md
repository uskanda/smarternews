# Design

## Context

`moveOn`は、読み込み済みの最後の記事から先へ進むとき、`fetchNextPage`で次のページを取得し、最後のページの先頭の記事を開く。TanStack Queryの`fetchNextPage`は、失敗しても例外を投げず、前のままのページとエラーを返す。動機は`proposal.md`の「Why」を参照する。

## Goals / Non-Goals

**Goals:**

- ページが増えたときだけ次の記事へ移る。
- 失敗を知らせる。
- 待つ間に一覧や記事が変わったら、遅れて届いた結果で画面を動かさない。

**Non-Goals:**

- 「さらに読み込む」のボタンの失敗の知らせ（`grilling.md`の後回しにしたもの）。
- 仕様の変更。

## Decisions

### 覚えたページ数の位置のページを開く

取得の前に`pages.length`を覚える。取得のあとのページ数がそれより多ければ、覚えた数の位置のページの先頭を開く。最後のページではなく位置で選ぶのは、増えなかったときに古いページを開かないためである。

### 失敗は結果のエラーと例外の両方で知らせる

結果の`isError`が真のときと、`fetchNextPage`が例外を投げたときに、`useToast`で知らせる。文言は`続きを読み込めませんでした。もう一度試してください。`とし、同じ画面の既読の失敗の文言に合わせる。開いている記事は残るので、もう一度`j`か`Space`を押せば取得をやり直せる。

### 最新の一覧と記事は ref で読む

押した時点の`listKey`と`articleId`を覚える。取得のあとに、描画のたびに更新するrefから最新の値を読み、比べる。どちらかが変わっていれば、何もしない。同じ一覧の別の記事をクリックで開いた場合も、読み手が選んだ記事を残す。

## Risks / Trade-offs

- 取得は成功したが新しいページが空のとき、記事は開かず、知らせも出ない。サーバーが空のページを返すのは続きがないときだけなので、起きることはまれである。
