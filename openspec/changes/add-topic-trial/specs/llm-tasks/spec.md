# Spec Delta

## ADDED Requirements

### Requirement: 試しの判定を呼ぶ時点

サーバーは、利用者がトピックの試しを求めたときにだけ、試しのために解釈と判定のタスクを呼び出さなければならない（MUST）。
1回の試しでは、解釈のタスクを1回、判定のタスクを試す候補の組の数だけ呼び出す。組の大きさは、実行の判定の組の大きさと同じとする。

#### Scenario: 60件の候補で試す

- **WHEN** 判定の組の大きさが30件で、60件の候補で試しを1回求め、どのタスクの1回目の出力も正しい
- **THEN** 解釈のタスクの呼び出しは1回、判定のタスクの呼び出しは2回である

### Requirement: 試しの1日の上限

その日の試しの呼び出し回数が試しの1日の上限に達している間、サーバーは試しのためにLLMを呼び出してはならない（MUST NOT）。
試しの呼び出し回数は、やり直しを含めて数える。試しの1日の上限の既定は30回とし、設定で変えられる。0のとき、試しは使えない。
試しを始める前に、その日の残りの回数が試し1回に要る回数より少なければ、サーバーは試しを始めずに断らなければならない（MUST）。

#### Scenario: 残りが足りない

- **WHEN** 試しの1日の上限が30回で、その日の試しの呼び出しが28回ある状態で、3回を要する試しを求める
- **THEN** LLMは呼び出されず、サーバーは上限を理由に断る

#### Scenario: 既定の上限

- **WHEN** `config.yaml` に試しの1日の上限を書かずにサーバーを起動する
- **THEN** 試しの1日の上限は30回になる

#### Scenario: 試しの上限に達しても実行は止まらない

- **WHEN** その日の試しの呼び出しが試しの1日の上限に達し、1日あたりの呼び出し回数には余裕がある状態で、実行が始まる
- **THEN** 実行はLLMを呼び出す

### Requirement: 1日あたりの上限への試しの計数

サーバーは、試しの呼び出しを、1日あたりの呼び出し回数にも数えなければならない（MUST）。
その日の呼び出し回数が1日の上限に達している間、サーバーは試しのためにLLMを呼び出してはならない（MUST NOT）。

#### Scenario: 試しのあとの呼び出し回数

- **WHEN** その日の呼び出し回数が10回の状態で、3回の呼び出しで終わる試しをする
- **THEN** その日の呼び出し回数は13回になる

### Requirement: 予算への試しの計数

サーバーは、試しの呼び出しの金額を、月の予算に数えなければならない（MUST）。
予算の期間の合計が月の予算に達している間、サーバーは、試しのために `anthropic` のプロバイダーを呼び出してはならない（MUST NOT）。

#### Scenario: 予算に達した状態で試す

- **WHEN** 解釈のタスクに `anthropic` のプロバイダーを割り当て、予算の期間の合計が月の予算に達した状態で、試しを求める
- **THEN** LLMは呼び出されず、サーバーは予算を理由に断る

### Requirement: 試しの呼び出しの記録

サーバーは、試しの呼び出しを記録するとき、実行の呼び出しと見分けられるようにしなければならない（MUST）。

#### Scenario: 試しのあとで確かめる

- **WHEN** 試しを1回したあとで、呼び出しの記録を読む
- **THEN** 試しの解釈と判定の呼び出しは、試しの用途として記録されており、どの実行にも属さない

## MODIFIED Requirements

### Requirement: 1日あたりの呼び出し回数の上限の既定

サーバーは、1日あたりの呼び出し回数の上限の既定を380回にしなければならない（MUST）。
既定の値は、セレクターの提案の1日の上限の既定である50回と、試しの1日の上限の既定である30回を含む。

#### Scenario: 上限を書かない設定

- **WHEN** `config.yaml` に1日あたりの呼び出し回数の上限を書かずにサーバーを起動する
- **THEN** 1日あたりの呼び出し回数の上限は380回になる
