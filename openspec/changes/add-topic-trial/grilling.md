# grilling 記録: add-topic-trial

Issue #140（監査ID F-05）のコメントで、7つの質問と推奨の答えを出した。Issueのオーナーは7つとも推奨の答えを選び、そのあと計画を`/ok`で承認した。承認に追加の変更の指示はなかった。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 試しの対象にする候補 | B：そのトピックに結び付いた候補を、「判定では採用」の側と「判定では除外」の側から新しい順に30件ずつ取る。片方が足りなければ、もう片方で埋める。合計は判定2回分（`judgeBatchSize`×2、既定で60件）まで。「公開日時が不明」で除外した候補は対象にしない | 第1ラウンド Q1 |
| 「入れ替わり」を何と比べるか | A：判定の結論どうしで比べる。採用待ちと採用済みの候補、プログラムの理由（重要度が基準未満、件数上限、開催日が対象期間の外、開催日を確認できない）で除外した候補を「判定では採用」、それ以外の除外を「判定では除外」とする。画面では、新しい重要度がカテゴリの最低を下回ることも添える | 第1ラウンド Q2 |
| ほかのトピックにも当たった候補 | A：実行と同じく、候補が当たったトピックをすべて渡す。試すトピックだけを、新しい文章と新しい判定基準に差し替える | 第1ラウンド Q3 |
| 判定に渡す「現在時刻」 | B：候補を作った時刻の順に並べて組に分け、組ごとに、組の中で最も新しい候補を作った時刻を渡す | 第1ラウンド Q4 |
| 試しの1日の上限の数え方と既定の値 | A：呼び出しの回数（やり直しを含む）で数え、既定は30回。`llmCallsPerDay` にも数え、その既定を350回から380回に上げる。月の予算にも数える。設定は `limits.topicTrialsPerDay` で、0なら試しは使えない。残りの回数が試し1回に要る回数より少なければ、始めずに断る | 第1ラウンド Q5 |
| 結果の返し方 | B：受け付けたらすぐに試しの識別子を返し、画面が数秒ごとに結果を問い合わせる。結果はサーバーのメモリーにだけ置く。同時に動く試しは1つまで | 第1ラウンド Q6 |
| 試したあとに保存したときの解釈 | A：試しの結果は保存に使わない | 第1ラウンド Q7 |
| 計画 | 承認。追加の変更の指示はなし | 会話中に確認（Issueのコメントの`/ok`） |
