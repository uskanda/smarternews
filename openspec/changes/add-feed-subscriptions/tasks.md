# Tasks

どの作業も、失敗するテストを先に書いてから実装する。テストは実際のサイトとLLMを呼ばず、記録済みの応答で動かす。

## 1. データベースと型

- [x] 1.1 `packages/core` では、移行の仕組みに、外部キーの検査を止めて流す移行と、その前のファイルの複製を足す。違反のある移行が取り消されることと、複製ができることをテストで確かめる
- [x] 1.2 `packages/core` では、移行 `002_feeds.sql` を書く。記事の表を作り直して由来と購読フィードの列を足し、購読フィード、ストップワード、見た項目の表と、基本の取得周期の列を足す。古い形のデータを入れたデータベースを移して、記事、出典、トピックとの対応、候補からの参照が残ることをテストで確かめる
- [x] 1.3 `packages/core/src/api.ts` に、記事の由来と購読フィードと著者、購読フィード、ストップワード、件数の内訳、OPMLの結果のスキーマを足す。型の検査が通ることを確かめる
- [x] 1.4 `packages/core` では、生成記事だけを読む問い合わせ（続報の判定、イベントの重複、RSS、180日の削除）に由来の条件を足す。配信記事を混ぜた状態で、既存の実行のテストとRSSのテストが通ることを確かめる

## 2. フィードの解析と内容の変換

- [x] 2.1 `packages/core` では、フィードの解析を広げ、項目の識別子、著者、内容のHTMLを読む。RSS 2.0、RSS 1.0、Atomの記録済みの文書で、それぞれの値が取れることをテストで確かめる。候補を集める既存の経路のテストが変わらず通ることも確かめる
- [x] 2.2 `packages/core` では、内容のHTMLをMarkdownに変換する処理を書く。スクリプトと埋め込みが消えることと、`http:` の画像が消えることをテストで確かめる。リンク、画像、見出し、リストが残ることと、10万文字で切ることも確かめる
- [x] 2.3 `packages/core` では、内容から照合用の文章を作る処理を書く。リンクのURLが含まれないことをテストで確かめる
- [x] 2.4 `packages/core` では、取得の部品に、応答のヘッダーを返すことと、304の応答を成功として返すことを足す。既存の取得のテストが通ることを確かめる

## 3. 購読フィードの保存と取得

- [x] 3.1 `feed-subscriptions` では、購読フィードの登録、変更、削除を書く。URLの正規化と重複の拒否、イベントのカテゴリの拒否、取得周期の範囲、500件の上限、カテゴリを移したときの配信記事のカテゴリの書き換えをテストで確かめる
- [x] 3.2 1つの購読フィードを取得して配信記事を保存する処理を書く。新しい項目だけが未読で入ること、識別子で見分けること、書き換えで既読が保たれること、並びの時刻、90日より古い項目の除外、200件の上限をテストで確かめる
- [x] 3.3 `feed-subscriptions` では、見た項目の記憶を書く。保存期間で消した項目が再び配信記事にならないことと、90日見ていない識別子が消えることをテストで確かめる
- [x] 3.4 `feed-subscriptions` では、取得の列を書く。時計を差し替えたテストで、取得周期と個別の値、無効な購読フィードの除外、直列の取得、即時の取得を確かめる。失敗のたびに間隔が2倍になり24時間で止まることと、成功で元に戻ることも確かめる。1つの失敗が他の取得を止めないことも確かめる
- [x] 3.5 `feed-subscriptions` では、条件付きの要求を足す。`ETag` と `Last-Modified` を送ることと、304で配信記事が増えず成功として記録されることをテストで確かめる
- [x] 3.6 `feed-subscriptions` では、ページからフィードを探す処理を書く。複数のフィードの指定、フィードそのもののURL、指定のないページをテストで確かめる
- [x] 3.7 `runs` では、保存期間の削除に、配信記事の90日を足す。スターのある配信記事が残ることと、生成記事の180日が変わらないことをテストで確かめる
- [x] 3.8 `runs` では、スケジュールの確認で、有効なトピックのないカテゴリを飛ばす。実行が始まらないことと、手動の実行は受け付けることをテストで確かめる
- [x] 3.9 `settings` では、カテゴリの削除で、購読フィードと配信記事をカテゴリなしに移す。既読とスターが保たれることをテストで確かめる
- [x] 3.10 `feed-subscriptions` では、取得の列を、サーバーの起動と停止に組み込む。購読フィードを取得しても、LLMの呼び出し回数と実行履歴が増えないことを、サーバーを通したテストで確かめる

## 4. ストップワード

- [x] 4.1 `stop-words` では、ストップワードの登録、変更、削除と、照合の処理を書く。部分一致、大文字と小文字、全角と半角、記号をそのまま比べること、対象の違いをテストで確かめる
- [x] 4.2 `stop-words` では、配信記事の保存と書き換えのときに判定する。登録、変更、削除のときに保存済みの配信記事を計算し直す。あとから足した語で隠れること、外すと既読とスターを保って戻ること、ほかの語に当たる記事は戻らないことをテストで確かめる
- [x] 4.3 `stop-words` では、一覧、件数、一括の既読から、隠した配信記事を除く。スターのある配信記事は隠さないことと、生成記事には適用しないことをテストで確かめる
- [x] 4.4 `stop-words` では、語ごとの隠している件数を返す。10万件の配信記事を入れた状態で語を足し、かかった時間を測る。`design.md` の見込みの数秒と比べた結果をPRに書く
