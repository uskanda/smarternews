# Spec Delta

## ADDED Requirements

### Requirement: 検索の試行の記録

実行がニュース検索かLLM検索を1回試したとき、サーバーは、その試行のトピック、取得元、検索先、検索語、エラーで終わったかどうか、返った結果の数を記録しなければならない（MUST）。
ニュース検索の検索先と検索語の組ごとに1回、LLM検索のトピックごとに1回と数える。LLM検索の検索語は、トピックの文とする。
返った結果の数は、判定済みのURLを除く前の数とする。Google Newsの試行では、転送用URLの解決を試した数と、解決できなかった数も記録する。
トピックに書いたフィードの取得は記録しない。

#### Scenario: 判定済みの結果だけが返る

- **WHEN** Google Newsの検索が3件を返し、3件とも判定済みのURLである
- **THEN** その試行の返った結果の数は3と記録され、候補は1件も増えない

#### Scenario: エラーで終わった試行

- **WHEN** Bing Newsの検索が応答しない
- **THEN** その試行はエラーで終わったものとして記録される

#### Scenario: フィードの取得

- **WHEN** トピックに書いたフィードを取得する
- **THEN** 検索の試行は記録されない

### Requirement: 検索の試行の保存期間

検索の試行の記録が作られてから30日が過ぎたとき、サーバーはその記録を削除しなければならない（MUST）。
その試行を含む実行が削除されたときも、サーバーはその記録を削除しなければならない（MUST）。

#### Scenario: 古い試行

- **WHEN** 試行から31日が過ぎる
- **THEN** その試行の記録は残っていない

### Requirement: 失敗したカテゴリの注意

有効なカテゴリの最新の定時の実行（やり直しを含む）が、やり直しの予定のない失敗か、上限での停止で終わったとき、サーバーは、そのカテゴリとその実行を指す注意の項目を作らなければならない（MUST）。
その実行のあとに、同じカテゴリの実行が成功か一部失敗で終わったとき、サーバーはその項目を作ってはならない（MUST NOT）。手動の実行でも同じである。
最新の定時の実行が待機中か実行中の間と、一部失敗で終わったとき、サーバーはその項目を作ってはならない（MUST NOT）。

#### Scenario: やり直しを使い切った

- **WHEN** 定時の実行が失敗し、3回のやり直しもすべて失敗する
- **THEN** 注意の一覧に、そのカテゴリと最後のやり直しの実行を指す項目がある

#### Scenario: やり直しを待っている

- **WHEN** 定時の実行が失敗し、やり直しの予定がある
- **THEN** 注意の一覧に、そのカテゴリの失敗の項目はない

#### Scenario: 手動の実行で直った

- **WHEN** 上限で止まった定時の実行のあとに、手動の実行が成功で終わる
- **THEN** 注意の一覧に、そのカテゴリの失敗の項目はない

#### Scenario: 無効のカテゴリ

- **WHEN** 定時の実行が失敗したあとに、そのカテゴリを無効にする
- **THEN** 注意の一覧に、そのカテゴリの失敗の項目はない

### Requirement: 解釈が未了のトピックの注意

有効なカテゴリの有効なトピックが解釈未了の間、そのカテゴリの最新の終わった実行がそのトピックの解釈に失敗していたとき、サーバーは、そのトピックを指す注意の項目を作らなければならない（MUST）。

#### Scenario: 解釈に失敗したトピック

- **WHEN** 実行がトピックTの解釈に失敗して終わる
- **THEN** 注意の一覧に、トピックTの解釈が未了であることを示す項目がある

#### Scenario: まだ実行していないトピック

- **WHEN** トピックを足したあと、まだ実行していない
- **THEN** 注意の一覧に、そのトピックの解釈の項目はない

### Requirement: 0件が続く検索の注意

有効なカテゴリの有効なトピックのニュース検索の検索先と検索語の組と、LLM検索のトピックについて、エラーで終わった試行を除いた直近3回の試行の返った結果の数がどれも0のとき、サーバーは、その組を指す注意の項目を作らなければならない（MUST）。
その検索語がトピックから外れたとき、またはトピックのニュース検索かLLM検索が無効になったとき、サーバーはその項目を作ってはならない（MUST NOT）。

#### Scenario: 3回続けて0件

- **WHEN** トピックTの検索語「q」のBing Newsの検索が、3回の実行で続けて0件を返す
- **THEN** 注意の一覧に、トピックT、Bing News、「q」を指す項目がある

#### Scenario: エラーがはさまる

- **WHEN** 0件、エラー、0件、0件の順に試行が終わる
- **THEN** 注意の一覧に、その組の項目がある

#### Scenario: 1回だけ結果があった

- **WHEN** 直近3回の試行が0件、2件、0件である
- **THEN** 注意の一覧に、その組の項目はない

### Requirement: 採用のないトピックの注意

有効なカテゴリの有効なトピックが作られてから14日以上たち、直近14日に、そのトピックに結び付いた記事が作られても更新されてもいないとき、サーバーは、そのトピックを指す注意の項目を作らなければならない（MUST）。

#### Scenario: 14日間記事がない

- **WHEN** 20日前に作ったトピックの最後の記事が、16日前に更新されたきりである
- **THEN** 注意の一覧に、そのトピックの採用がないことを示す項目がある

#### Scenario: 作ったばかりのトピック

- **WHEN** 5日前に作ったトピックに、まだ記事がない
- **THEN** 注意の一覧に、そのトピックの採用の項目はない

### Requirement: Google Newsの解決の失敗の注意

Google Newsの転送用URLの解決を1件以上試した直近3回の実行で、どの回も解決が1件も成功していないとき、サーバーは、そのことを示す注意の項目を作らなければならない（MUST）。

#### Scenario: 3回続けて解決できない

- **WHEN** Google Newsの結果があった3回の実行で、どの転送用URLも解決できない
- **THEN** 注意の一覧に、Google Newsの転送用URLを解決できないことを示す項目がある

#### Scenario: 1件でも解決できた

- **WHEN** 直近3回のうち1回で、転送用URLが1件だけ解決できた
- **THEN** 注意の一覧に、その項目はない

### Requirement: 確認した注意の項目

利用者が注意の項目を確認したとき、サーバーは、その項目のきっかけが変わるまで、その項目を注意の一覧から除かなければならない（MUST）。
きっかけは、失敗した実行、解釈に失敗した実行、0件が続き始めた試行、最後に記事を作るか更新した日時、解決できなくなり始めた実行とする。
確認の記録は30日で削除する。

#### Scenario: 確認した項目

- **WHEN** 0件が続く検索の項目を確認し、そのあとの実行でもその組が0件を返す
- **THEN** 注意の一覧に、その項目はない

#### Scenario: 別の実行でまた失敗した

- **WHEN** 失敗したカテゴリの項目を確認したあと、次の定時の実行もやり直しを使い切って失敗する
- **THEN** 注意の一覧に、そのカテゴリと新しい実行を指す項目がある
