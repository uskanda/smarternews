# grilling 記録: add-run-attention

Issue #141（監査ID F-06）のコメントで、7つの質問と推奨の答えを出した。Issueのオーナーは7つとも推奨の案を選び、続く計画を`/ok`で承認した。

この変更は、最初のgrilling（`archive/2026-10-10-add-crawler-api-rss`の第2ラウンドQ12）の「実行履歴をAPIで見せる。通知は初版では出さない」を決め直す。決め直すのはWebの画面の中だけである。Androidアプリへの通知と、サーバーから外への知らせは、今までどおり出さない。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 「通知を出さない」をどこまで決め直すか | A：Webの画面の中だけで知らせる。左のペインの印と「注意」の一覧を置く。Androidの通知や、メールなどの外への通知は出さない | 第1ラウンド Q1 |
| 「注意」の一覧を置く場所 | A：実行履歴の画面の先頭に「注意」の区画を置き、その下に今の履歴を続ける | 第1ラウンド Q2 |
| 注意の項目を消す方法 | B：項目ごとに「確認した」を置き、サーバーに保存して隠す。同じ対象でも、状態が変わって新しく条件を満たしたら、また出す。保存するのは項目の種類、対象、きっかけからなる鍵だけにする | 第1ラウンド Q3 |
| カテゴリの失敗と上限での停止を、いつ注意にし、いつ消すか | B：定時の実行（やり直しを含む）で注意にし、そのあとに成功か一部失敗で終わった実行があれば、手動の実行でも消す。無効のカテゴリと、一部失敗の実行は対象にしない | 第1ラウンド Q4 |
| 0件が続く検索の対象と数え方 | B：ニュース検索（検索先と検索語の組）とLLM検索（トピック）を対象にする。トピックに書いたフィードは対象にしない。判定済みのURLを除く前の結果の数を数え、エラーを除いた直近3回の試行が0件なら注意にする | 第1ラウンド Q5 |
| 採用が0件のトピックの条件 | A：直近14日に、トピックに結び付いた記事が作られても更新されてもいない。作ってから14日未満のトピックと、無効のトピックとカテゴリは除く | 第1ラウンド Q6 |
| Google Newsの転送用URLの解決失敗を検知するか | A：5つ目の項目にする。Google Newsの結果が1件以上あった直近3回の実行で、どの回も解決が1件も成功しなかったら注意にする | 第1ラウンド Q7 |
| 計画 | 承認。追加の変更の指示はなし | 会話中に確認（Issueのコメントの`/ok`） |
