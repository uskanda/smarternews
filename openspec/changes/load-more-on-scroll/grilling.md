# grilling 記録: load-more-on-scroll

GitHubのissueの188番のコメントで、1ラウンドの質問（Q1〜Q5）に答えた記録である。
issueは、2026-11-13のWeb UIの監査の項目B-06である。仕様の「続きの読み込み」は一覧の末尾までスクロールしたときに続きを読み込むことを求めているが、実装は「さらに読み込む」のボタンだけだった。スクロールで既読にする設定が有効なときは、ボタンの下に一覧の高さの余白があり、スクロールの終わりはボタンより下になる。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| ボタンを出す場面 | 失敗のときだけ「さらに読み込む」のボタンを出し、読み込みの間は「読み込み中…」を出す。仕様の2か所と、ボタンを押す既存のテスト3件を書き直す（A） | 第1ラウンド Q1 |
| 失敗の知らせ方 | 末尾のボタンの上に「続きを読み込めませんでした」と出し、続きの失敗では一覧の先頭の知らせを出さない（A） | 第1ラウンド Q2 |
| 対象にする一覧 | 記事の一覧（項目、検索の結果、名前の記事）と注釈の一覧。注釈の一覧の要件を仕様に足す（B） | 第1ラウンド Q3 |
| 読み込みを始める位置 | 一覧の高さ1つ分ほど手前で始める（A） | 第1ラウンド Q4 |
| 失敗のあとの自動の読み込み | ボタンが押されるか、一覧が読み直されるか、別の一覧に変わるまで、自動では読み込まない（A） | 第1ラウンド Q5 |

## 計画で決めたこと

承認を求めた計画（issueのコメント）で、次を決めた。利用者は変更なしで承認した。

| 決定 | 選択 |
|---|---|
| 部品 | 一覧の末尾に置く共通の部品 `LoadMore` を作り、記事の一覧と注釈の一覧で使う |
| 見張り方 | 目印を `IntersectionObserver` で見張る。`root` はスクロールする要素、`rootMargin` は `0px 0px 100% 0px` |
| 見張りの付け直し | 読み込んだページの数とエラーの状態が変わるたびに付け直す。50件を読み込んでも目印がまだ範囲の中にあるときや、読み直しでエラーが消えたときにも続けて読み込むためである |
| 目印の位置 | 記事の一覧では、行の直後、スクロールで既読にするときの余白より上に置く |
| `j` での続きの読み込み | 今のままにする。失敗したときは、同じく末尾の知らせとボタンが出る |
| テスト | 交差を起こせる `IntersectionObserver` の代用品をテストの道具に足す。何もしない代用品は既定のまま残す |
