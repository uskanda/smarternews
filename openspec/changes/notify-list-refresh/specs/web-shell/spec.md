## MODIFIED Requirements

### Requirement: キーボードでの一覧の再取得

記事の一覧が表示されている間、`r` が押されたとき、画面は一覧の更新のボタンを押したときと同じく、件数と表示中の一覧をすぐに取得し直さなければならない（MUST）。
画面は、このキーで購読フィードの取得を始めてはならない（MUST NOT）。
利用者が更新のボタンか `r` で始めた取り直しの間、画面はボタンを「読み直し中…」と表示して押せなくし、`r` を無視しなければならない（MUST）。
取り直しが終わったとき、画面は、取り直す前に画面にあった行になく、新しく一覧に入った記事の数をトーストで知らせなければならない（MUST）。
読み込んでいなかったページから繰り上がった記事は、この数に含めない。
取り直しに失敗したとき、「すべて既読にする」のあとの取り直し、60秒ごとの自動の取り直しでは、画面はこのトーストを出してはならない（MUST NOT）。

#### Scenario: キーで一覧を読み直す

- **WHEN** 未読の一覧を開いたまま、サーバーで新しい記事が作られ、60秒を待たずに `r` を押す
- **THEN** 一覧に新しい記事が現れ、左のペインの未読数が増える

#### Scenario: 購読フィードを取得しない

- **WHEN** 購読フィードの一覧で `r` を押す
- **THEN** その購読フィードの取得は始まらない

#### Scenario: 取り直している間

- **WHEN** 「読み直す」を押し、取り直しがまだ終わっていない
- **THEN** ボタンは「読み直し中…」と表示されて押せず、`r` を押しても次の取り直しは始まらない

#### Scenario: 新しい記事がある

- **WHEN** サーバーで新しい記事が2件作られたあとで、「読み直す」を押す
- **THEN** 取り直しが終わると、トーストで「新しい記事が2件あります」と知らされる

#### Scenario: 新しい記事がない

- **WHEN** 新しい記事がないときに `r` を押す
- **THEN** 取り直しが終わると、トーストで「新しい記事はありませんでした」と知らされる

#### Scenario: 取り直しに失敗する

- **WHEN** サーバーに届かないときに「読み直す」を押す
- **THEN** 読み直しのトーストは出ず、一覧の上のエラーの表示が失敗を知らせる

#### Scenario: すべて既読にしたあとの取り直し

- **WHEN** 「すべて既読にする」を押す
- **THEN** 既読にした件数のトーストだけが出て、読み直しのトーストは出ない
