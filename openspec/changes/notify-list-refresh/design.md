# Design

## Context

`ReaderPage.tsx` の `refresh` は、この訪問で既読にして残している行（`kept`）を捨て、`["articles"]` と `["counts"]` の問い合わせを無効にするだけで、取り直しの完了を待たず、状態も持たない。
「すべて既読にする」（`markAllRead`）も `refresh` を呼び、自分のトーストを出す。
記事の要約には作成日時がなく、サーバーは前回から何件増えたかを返さない。
未読の一覧では、取り直すと既読の行が消え、読み込んでいなかったページの記事が下から繰り上がる。
取り直しの失敗は、一覧の上の `ErrorNotice` がすでに知らせる。

## Goals / Non-Goals

**Goals:**

- 利用者が始めた取り直しの間、進んでいることを見せる。
- 取り直しが終わったら、新しく一覧に入った記事の数を知らせる。

**Non-Goals:**

- サーバーのAPIの変更
- 注釈の一覧の「読み直す」
- 「すべて既読にする」と60秒ごとの自動の取り直しの知らせ

## Decisions

- 件数は純粋な関数 `countNewArticles(before, after)` で数える。`before` は取り直す前に画面にあった行のID、`after` は取り直したあとの一覧である。`after` のうち `before` になかった記事を数える。ただし、`before` の行のうち `after` で最後に現れる位置より後ろの記事は、読み込んでいなかったページからの繰り上がりとみなし、数えない。`before` の行が `after` に1つもないときは、前に何もなかったときを除いて0件とする。
- `refresh` は今の動きのまま内側の処理として残し、`markAllRead` はそれを呼ぶ。利用者の操作からは `refreshByUser` を呼ぶ。
- `refreshByUser` は `refreshing` の状態を立て、`fetched` と `kept` のIDを控えてから `refresh` と同じ無効化を `await` する。終わったら、表示中の一覧の問い合わせ（一覧、検索、名前の記事のいずれか）を `client.getQueryState` で読み、失敗の状態ならトーストを出さない。成功していれば、ページの行を並べて件数を数え、トーストを出す。
- 取り直し中は、ボタンを「読み直し中…」と表示して `disabled` にし、`r` の処理は何もしない。
- 文言は `fetch-now.ts` の0件の文言「新しい記事はありませんでした」にそろえる。

## Risks / Trade-offs

- 古い順の一覧で、新しい記事が読み込み済みの範囲の後ろに入ると、その記事は数えない。→ Q1で受け入れた弱点である。
- 取り直しの間に一覧を切り替えると、前の一覧の結果を知らせることがある。→ 取り直しは短く、知らせるのは件数だけなので受け入れる。
