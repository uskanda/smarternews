# grilling 記録: notify-list-refresh

GitHubのissueの203番のコメントで、1ラウンドの質問（Q1とQ2）に答えた記録である。
issueは、2026-11-13のWeb UIの監査の項目U-10である。新しい記事がないとき、「読み直す」を押しても `r` を押しても画面は変わらず、取り直した結果が0件だったのか、押せていないのかを見分けられない。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 「一覧に入った記事の数」の数え方 | 画面にあった行と比べ、取り直した一覧に新しく現れた記事を数える。前からあった行の最後より後ろに繰り上がった記事は数えない。Webだけの変更とする（A） | 第1ラウンド Q1 |
| 知らせ方と文言 | 「いま取得」と同じ画面の下の知らせで「新しい記事がN件あります」、0件のとき「新しい記事はありませんでした」と知らせる。失敗のときは知らせない（A） | 第1ラウンド Q2 |

## 計画で決めたこと

承認を求めた計画（issueのコメント）で、次を決めた。利用者は変更なしで承認した。

| 決定 | 選択 |
|---|---|
| 知らせる取り直し | 利用者が「読み直す」か `r` で始めた取り直しだけを知らせる。「すべて既読にする」のあとの取り直しと、60秒ごとの自動の取り直しでは知らせない |
| 取り直し中の表示 | ボタンを「読み直し中…」にして押せなくし、`r` も無視する |
| 比べる前の行 | 取得した行と、この訪問で既読にして一覧に残している行の両方 |
| 対象の範囲 | 注釈の一覧の中の「読み直す」は変えない。`fetch-now.ts` も変えず、0件の文言だけをそろえる |
