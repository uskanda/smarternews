# Design

## Context

`apps/web/src/reader/ReaderPage.tsx` は、狭い画面（`useLayout()` が `narrow`）で記事を開くと、一覧のペインを描かない（`showList` が偽）。一覧の要素が外れるので、スクロール位置は失われる。
`/unread` と `/unread/:id` は同じ `ReaderPage` を描くので、本文を開いても `ReaderPage` の状態は残る。
行の選択の印（`aria-current`）と `j`・`k` の起点は、URLの記事の番号（`articleId`）だけで決まる。一覧へ戻るとURLから番号が消え、印と起点が失われる。
「スクロールで既読にする」（`useScrollToRead`）は、狭い画面で本文を開いている間は止まり、一覧に戻ると動き出す。動き出すときの `useLayoutEffect` で最初の位置を測り、そこからスクロールで上を通り過ぎた行を既読にする。
`move` は、読み込んだ最後の記事から先へは進まない。

## Goals / Non-Goals

**Goals:**

- 狭い画面で戻ったとき、一覧の位置、選択、フォーカスを戻す。戻し方の違い（リンクとブラウザーの戻る操作）で振る舞いを変えない。
- 戻すスクロールで既読にしない。
- 狭い画面で、一覧へ戻らずに隣の記事へ移れるようにする。
- ページの境目で `j`、`Space`、「次の記事」が止まらないようにする。

**Non-Goals:**

- 再読み込みのあとに位置と選択を戻すこと。スクロール位置も再読み込みで消えるので、それに合わせる。
- 広い画面の見た目を変えること。
- Androidアプリの振る舞いを変えること。

## Decisions

### スクロール位置を一覧ごとに覚える

一覧の要素はこれまでどおり外す。一覧のスクロール要素（`data-list-scroll`）の `onScroll` で、`positions`（refの `Map`、`listKey` から `scrollTop`）に書く。
要素を `display:none` で隠す案は採らない。隠した要素のスクロール位置がブラウザーによって0に戻り、隠れた一覧を描き続けるからである。

### 最後に開いた記事を覚える

`{ key: listKey, id }` を状態に持ち、`articleId` が決まるたびに更新する。`listKey` が違うものは使わない。
`current = articleId ?? 覚えた番号` を、行の `selected`、`move` の起点、`index` に使う。広い画面でも同じに働くが、広い画面ではURLの番号がふつう残るので、違いが出るのは一覧へ戻るリンクがある狭い画面である。
戻り先のURLに番号を付ける案は採らない。ブラウザーの戻る操作では付かず、2つの戻り方で振る舞いが分かれるからである。

### 戻ったときの処理

一覧が描き直された（`showList` が偽から真になった）ときに、`useLayoutEffect` で次の順に処理する。

1. 覚えた `scrollTop` を戻す。
2. 直前の行が表示範囲の外にあれば、`followScroll` で表示範囲の中に入るまで送る。
3. その行のリンクにフォーカスを置く（`preventScroll`）。本文を開いたときに見出しへフォーカスを移すのと対になる。

### 戻すスクロールで既読にしない

上のeffectを `useScrollToRead` の呼び出しより前に宣言する。同じ部品の `useLayoutEffect` は宣言の順に走るので、`useScrollToRead` は戻したあとの位置を最初の位置として測る。戻すスクロールで上を通り過ぎた行は、最初の位置より上にあるので既読にならない。`scroll-read.ts` は変えない。

### ページの境目での移動

`move` は、`active.hasNextPage` があって読み込んだ最後の行から先へ進むとき、`fetchNextPage()` を待ってから新しいページの最初の記事へ移る。`page`（`Space`）は `move` を通るので同じ扱いになる。
読み込みの途中に重ねて押されたときは何もしない。

### 本文の末尾の「前の記事」「次の記事」

`ReaderPage` は、狭い画面のときだけ、隣の記事を `neighbors`（前と次のそれぞれ `{ title, to }`、または次のページの読み込み）として `ArticleView` に渡す。広い画面では渡さない。
`ArticleView` は、スター・既読のボタンの下に `nav aria-label="記事の移動"` を置き、「前の記事」「次の記事」の `Link` を並べる。それぞれに見出しを1行で示し（`truncate`、全体は `title` 属性）、`tap` で指で押せる高さを確保する。
読み込んだ最後の記事で続きのページがあるときは、次の記事の見出しが分からない。そこで、リンクと同じ見た目のボタンを置き、「次の記事」の語と、続きを読み込んで開くことを示す文を出す。
「この話題の前の記事」（続報の元の記事）は、名前と動きを今のまま残す。「この話題の」の前置きで見分けられる。

## Risks / Trade-offs

- 戻ったときの行のフォーカスで、読み上げの道具は一覧の見出しではなく行を読み上げる → 本文を開いたときに見出しへフォーカスを移すのと対で、どこに戻ったかが分かる。
- 次のページの読み込みが失敗したとき、`j` は何もしない → 一覧には今までどおり読み込みの失敗が出る。
