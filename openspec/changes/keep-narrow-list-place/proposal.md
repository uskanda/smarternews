# Proposal

## Why

幅719px以下の画面で本文から一覧へ戻ると、一覧は先頭から表示され、直前に読んだ行の印も消える（issue #112）。
一覧の要素は本文を開くと外れ、戻り先のURLに記事の番号がないためである。また、本文の画面には次の記事へ移る手段がなく、1件読むたびに一覧へ戻って探し直すことになる。

## What Changes

- 狭い画面で一覧へ戻ったとき、一覧は離れたときのスクロール位置から表示する。位置は一覧ごとに覚える。
- 戻ったとき、直前に開いた記事の行を選んだ状態にし、その行が表示範囲の中に入るまで一覧を送り、フォーカスをその行のリンクに置く。`j` と `k` はその行から動く。「一覧へ戻る」とブラウザーの戻る操作のどちらでも同じに働く。
- 戻すときのスクロールでは、上を通り過ぎた行を既読にしない。「スクロールで既読にする」を有効にしていても同じである。
- 狭い画面の本文の末尾、スター・既読のボタンの下に「前の記事」と「次の記事」を置く。それぞれ隣の記事の見出しを1行で示し、隣がない側は出さない。広い画面には出さない。
- 読み込んだ最後の記事で続きのページがあるとき、`j`、`Space`、「次の記事」は、次のページを読み込んでから、その最初の記事を開く。広い画面の `j` と `Space` にも及ぶ。
- 「この話題の前の記事」は今のまま残す。Androidアプリは変えない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `web-shell`: 要件「狭い画面での切り替え」へ、戻ったときの位置と選択、本文の末尾の「次の記事」「前の記事」、位置を戻すスクロールで既読にしないことのシナリオを足す。要件「キーボードでの記事の移動」と「本文の端での記事の移動」へ、続きのページがあるときのシナリオを足す

## Impact

- `apps/web/src/reader/ReaderPage.tsx`：一覧ごとのスクロール位置と最後に開いた記事の記録、戻ったときの処理、ページの境目での移動、隣の記事の受け渡し。
- `apps/web/src/reader/ArticleView.tsx`：本文の末尾の「前の記事」「次の記事」。
- サーバー、API、`packages/client`、Androidアプリに変更はない。
