# grilling 記録: add-web-app

Webの画面の要件と設計を決めた2ラウンドの質問をまとめたものである。
見た目の方向は、見本のページを見ながら第2ラウンドで確認した。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 配信方法 | いまのサーバーがWebのビルド結果を `/` で配る。開発中だけ、開発用のサーバーからAPIへ中継する | 第1ラウンド Q1 |
| トークンの渡し方 | 最初にAPIのトークンを貼り付ける画面を出し、ブラウザーに保存する。外部のスクリプトはContent-Security-Policyで禁じる | 第1ラウンド Q2 |
| 画面の構成 | カテゴリ、記事の一覧、本文の3ペイン。狭い画面では1ペインずつ切り替える | 第1ラウンド Q3 |
| 既読の付け方 | 記事を開いたら既読にする。一覧は既定で未読だけを出す。一括の既読は一覧を読み込んだ時刻までを対象にする | 第1ラウンド Q4 |
| キーボード操作 | 前後の記事、スター、既読の切り替え、出典を開く、の基本の組を入れる | 第1ラウンド Q5 |
| 携帯端末のブラウザー | 狭い画面でも使えるようにする。PWAにはしない | 第1ラウンド Q6 |
| 範囲 | APIでできることをすべて画面にする。読む、設定、実行の3群に分ける | 第1ラウンド Q7 |
| 未読数 | カテゴリごとの未読数とスターの数を返す操作をAPIに足す。60秒ごとの再取得と手動の更新で反映する | 第1ラウンド Q8 |
| 検索 | 入れない | 第1ラウンド Q9 |
| 見た目の方向 | 一覧は密度を高く、本文は読みやすい幅と行間にする。明るい配色と暗い配色の両方を作り、端末の設定に従う | 第1ラウンド Q10 |
| スタイルの作り方 | Tailwind v4。`DESIGN.md` の値を取り込む。ダイアログなどはRadixの部品を使う | 第1ラウンド Q11 |
| イベントの見せ方 | 開催日ごとにまとめた一覧 | 第1ラウンド Q12 |
| テスト | VitestとTesting Libraryで、実物のAPIに対して画面を動かす。完成時に実際のブラウザーで確かめる | 第1ラウンド Q13 |
| 配色と形 | 地は青みのある薄い灰色、文字は青みのある黒、操作とリンクは藍色。目立たせるのは重要度を示す黄色の印だけ。角の丸みは小さく、影は使わず、一覧は罫線で区切る | 第2ラウンド Q1 |
| 本文の書体 | 本文と記事の見出しは明朝、一覧と操作はゴシック。書体はアプリに同梱する | 第2ラウンド Q2 |
| 一覧の1行の情報 | 見出し、要約1行、カテゴリ、時刻、出典の件数、「更新」と「未確認」の印 | 第2ラウンド Q3 |
| 重要度での絞り込み | 重要度4以上だけを見る切り替えを置く。APIの記事の一覧に重要度の下限の指定を足す | 第2ラウンド Q4 |
| 左のペインの項目 | 「未読」「すべて」「スター」、カテゴリの一覧（未読数つき）、「設定」「実行履歴」。最初に開くのは「未読」 | 第2ラウンド Q5 |
| 日時の表示 | 全体設定のタイムゾーンで表示する | 第2ラウンド Q6 |
| カテゴリの削除 | 確認のダイアログに消える件数を出す。名前の入力は求めない。同じダイアログで無効化も選べる | 第2ラウンド Q7 |
| トピックを追加したあと | 次の実行で解釈されることを示し、同じ画面に即時の実行のボタンを置く。自動では実行しない | 第2ラウンド Q8 |

## 後回しにしたもの

- 記事の検索。スターで足りるかを使ってから判断する。
- PWAと圏外での閲覧。
- サーバーからの通知による即時の反映。
- イベントを月の暦の形で見せる表示。
- UIの多言語化。
- 実際のブラウザーを使う自動テストをCIに入れること。
