# Design

## Context

`RunPage`、`DigestPage`、`FiltersPage` は、それぞれ `overflow-y-auto` の要素の中でスクロールする。ブラウザーが戻すのは文書のスクロール位置だけなので、別の画面から戻ると、これらの要素は先頭から表示される。
「トピックごとにまとめる」（`grouped`）と開いた「隠している記事」（`showing`）は `useState` に持つので、画面を離れると消える。
ルーターは `createBrowserRouter`（テストでは `createMemoryRouter`）で、履歴の項目ごとに `location.key` が付く。戻る操作では、離れたときと同じ `key` に戻る。新しく開いた項目には新しい `key` が付く。
前例として、`ReaderPage` は一覧ごとのscrollTopをrefの `Map` に覚えて戻している（keep-narrow-list-place）。`RunsPage` は、カテゴリの絞り込みをURLのパラメーターに `replace: true` で書いている。

## Goals / Non-Goals

**Goals:**

- 3つの画面で、戻る操作で戻ったときに位置と表示を戻す。同じ画面を新しく開いたときは先頭から表示する。
- 位置を覚えて戻す処理を1つにまとめ、3つの画面から使う。

**Non-Goals:**

- 再読み込みのあとに位置を戻すこと（grilling Q2）。
- `ReaderPage` の一覧の位置の扱いを、この仕組みへ移すこと。一覧は `location.key` ではなく一覧ごとに位置を覚え、本文の開閉でも戻すので、要件が違う。
- Androidアプリの振る舞いを変えること。

## Decisions

### 記憶の置き場所とキー

モジュールの `Map` に、`location.key` と領域の名前の組をキーとして `scrollTop` を覚える。画面の部品は戻るまでに外れるので、部品のrefには置けない。
`location.key` を使うので、戻る操作では覚えた位置が見つかり、リンクで新しく開いたときは見つからずに先頭から表示される。パスをキーにする案は採らない。同じパスをリンクで開き直したときにも位置が戻ってしまうからである。
sessionStorageに置く案は採らない（grilling Q2）。`Map` の項目には上限（200件）を付け、古いものから捨てる。

### フックの形

`useScrollMemory(name, ready)` は、スクロール領域の要素に付けるcallback refを返す。
画面によっては、領域の要素が読み込みの後に現れたり（`RunPage` は読み込み中に別の表示を返す）、幅で入れ替わったり（`DigestPage`）するので、refのオブジェクトとeffectより、要素が付いた時点で呼ばれるcallback refのほうが確実に拾える。

- 要素が付いたとき、覚えた位置があれば、戻すまで待つ印を立てる。`ready` が真なら、その場で `scrollTop` に戻す。
- 覚えた位置がなければ、要素のその時点の `scrollTop` を覚える。新しく開いた画面では0になる。
- `ready` が偽から真になったとき、戻すまで待っていれば `scrollTop` に戻す。
- 要素の `scroll` イベントのたびに位置を書く。ただし、戻すまで待つ間は書かない。読み込み中の短い内容で起きたスクロールが、覚えた位置を0で上書きしないためである。

### `replace` でキーが変わることへの対処

URLのパラメーターを `replace: true` で書き換えても、`location.key` は新しくなる。callback refは `key` が変わると付け直されるので、そのとき新しい `key` に覚えた位置はなく、上の規則で、その時点の `scrollTop` が新しい `key` に写る。
これがないと、切り替えたあとスクロールせずに離れたとき、戻っても位置が見つからない。

### `ready` の決め方

戻す位置まで内容が届かないうちに戻すと、位置が切り詰められる。そこで、画面ごとに、内容がそろったときを `ready` として渡す。

- 実行の詳細：実行と、除外した候補の両方を読み込めたとき。
- ダイジェスト：一覧と、表示するダイジェストを読み込めたとき。ないダイジェストや読み込みの失敗も、それ以上は変わらないので `ready` とする。
- フィルター：フィルターの一覧を読み込めたとき。開いた「隠している記事」は、React Queryのキャッシュに残っていればすぐに出る。キャッシュになく内容が短いときは、届く範囲までしか戻らない。

### 状態をURLに持つ

- 実行の詳細の「トピックごとにまとめる」は `?group=topic`。切っているときはパラメーターを消す（grilling Q3）。
- フィルターの「隠している記事」は `?shown=3,5`。開閉のたびに番号を足し引きし、空になればパラメーターを消す（grilling Q1）。数でない番号は読み飛ばす。ないフィルターの番号は、行がないので何も起こさない。無効のフィルターは今と同じく一覧を出さない。

どちらも `setSearchParams` を関数で呼び、ほかのパラメーターを残し、`replace: true` で履歴を増やさない。

## Risks / Trade-offs

- [`?shown=` に残った番号のフィルターを、あとで有効に戻すと一覧が開く] → 無効の間は一覧を出さず、ボタンの `aria-expanded` も同じ状態を示すので、開いていることは分かる。
- [隠している記事のキャッシュが消えた後に戻ると、届く範囲までしか位置が戻らない] → 戻らなかった分は、画面の内容が読み込まれた位置から利用者が送ればよい。前例と同じく、完全には追わない。
- [位置の記憶はタブを閉じるか再読み込みで消える] → grilling Q2で受け入れた。
