# grilling 記録: show-followup-changes

GitHubのissueの139番のコメントで、1ラウンドの質問（Q1〜Q5）に答えた記録である。
issueは、2026-11-06のWeb UIの監査の項目F-04である。続報で書き直された記事は未読に戻り「更新」の印と回数が出るだけで、加わった内容を知るには本文を読み直すしかない。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 「今回加わったこと」を出す続報の種類 | 既存の記事を書き直す続報（72時間以内）のときだけ出す。新しい記事を作る続報（72時間を過ぎたもの）では出さない。入力は増えない（A） | 第1ラウンド Q1 |
| 「今回加わったこと」が説明する範囲 | 最新の書き直し1回分だけを書かせる。見出しは「今回の更新で加わったこと」にする。前回読んでから重なった分は「新しい出典」の印で見分ける（A） | 第1ラウンド Q2 |
| 一覧の行での表示 | 「今回加わったこと」のある記事では、要約の1行の代わりに「更新：」で始まる1行を出す。既読でも未読でも同じにする。検索の結果では抜粋を優先する（A） | 第1ラウンド Q3 |
| 前の記事の連なりの向き | 前の記事の方向だけにする。サーバーが前の記事への参照をたどり、新しい順に最大20件を返す（A） | 第1ラウンド Q4 |
| 変更の範囲 | Webの画面だけを変える。AndroidアプリとRSSの出力は別のissueにする。APIには項目を足すだけにする（A） | 第1ラウンド Q5 |

## 計画で決めたこと

承認を求めた計画（issueのコメント）で、次を決めた。利用者は変更なしで承認した。

| 決定 | 選択 |
|---|---|
| 前回読んだ時刻の保持 | 書き直すときに、その時点の既読の時刻を新しい列に写す。未読のまま2回目の書き直しが来たときは、前の値を残す |
| 一度も読まれていない記事 | 基準の時刻がないので、どの出典にも「新しい出典」の印を付けない |
| 出典に加わった時刻 | 出典に加わった時刻の列を足す。今ある出典は空のままにし、新しくない出典として扱う |
| 書き直したのに「今回加わったこと」がないとき | 前の文を残さず空に戻す。同じイベントを別の見出しで見つけて生成のあとで書き直しに切り替わった場合も、既存の記事を入力に渡していないので空にする |
| 不正な「今回加わったこと」 | 文字列でない、空、300文字を超えるときは無いものとして扱い、問い直さず、記事は保存する |
| 前の記事の連なりの終わり | 輪になっていたらそこで止める。削除された記事で切れたら、そこまでを返す。前の記事への参照の項目は互換のために残す |
