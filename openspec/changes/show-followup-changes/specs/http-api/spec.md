## ADDED Requirements

### Requirement: 今回加わったことの提供

APIは、記事の一覧、記事の詳細、検索の結果の各記事に、今回加わったことを返さなければならない（MUST）。
今回加わったことのない記事では、その項目は空である。

#### Scenario: 続報で書き直された記事の一覧

- **WHEN** 今回加わったことを持つ記事を含む一覧を要求する
- **THEN** その記事の項目に、今回加わったことの文が含まれる

#### Scenario: 配信記事

- **WHEN** 配信記事の詳細を要求する
- **THEN** 応答の今回加わったことは空である

### Requirement: 新しい出典かどうかの提供

APIは、記事の詳細の各出典に、新しい出典かどうかを返さなければならない（MUST）。
出典が新しいのは、その出典を加えた時刻が、記事の書き直す前に読んだ時刻より後のときである。
書き直す前に読んだ時刻のない記事と、加えた時刻のない出典では、出典は新しくない。

#### Scenario: 読んだあとに加わった出典

- **WHEN** 出典Aを持つ記事を読み、そのあとの続報で出典Bが加わり、記事の詳細を要求する
- **THEN** 出典Bは新しく、出典Aは新しくない

#### Scenario: 記事を開いたあと

- **WHEN** 出典Bが加わった記事を開いて既読にし、もう一度記事の詳細を要求する
- **THEN** 出典Bは新しいままである

#### Scenario: 一度も読まれていない記事

- **WHEN** 一度も既読にされないまま続報で更新された記事の詳細を要求する
- **THEN** どの出典も新しくない

### Requirement: 前の記事の連なりの提供

APIは、記事の詳細に、前の記事への参照をたどった記事の連なりを、新しい順に最大20件返さなければならない（MUST）。
連なりの各記事は、識別子、タイトル、最初の公開日時を持つ。
たどる途中で同じ記事に戻ったとき、または参照先の記事がないとき、APIはそこで連なりを終える。

#### Scenario: 3つの記事の連なり

- **WHEN** 記事Cが記事Bを、記事Bが記事Aを前の記事として参照し、記事Cの詳細を要求する
- **THEN** 応答の前の記事の連なりは、記事B、記事Aの順である

#### Scenario: 25件の連なり

- **WHEN** 前の記事を25件たどれる記事の詳細を要求する
- **THEN** 応答の前の記事の連なりは、近い順に20件である

#### Scenario: 輪になった参照

- **WHEN** 記事Aと記事Bが互いを前の記事として参照し、記事Aの詳細を要求する
- **THEN** 応答の前の記事の連なりは記事Bだけである

## MODIFIED Requirements

### Requirement: 記事の詳細

記事の詳細の要求を受けたとき、APIは、タイトル、要約、本文、重要度、出典、当たったトピック、読み手への影響、未確認の印、更新回数、前の記事への参照を返さなければならない（MUST）。
APIは、前の記事への参照を、前の記事の連なりとは別の項目として返し続ける。

#### Scenario: 更新された記事を開く

- **WHEN** 続報で1回更新された記事の詳細を要求する
- **THEN** 応答には、更新回数1と、更新後の本文と、すべての出典が含まれる
