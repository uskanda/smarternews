## ADDED Requirements

### Requirement: 本文の生成のタスクの今回加わったこと

既存の記事を書き直すとき、本文の生成のタスクは、既存の記事になく新しい出典で加わったことを、全体設定の出力言語の1〜2文で、今回加わったこととして出力しなければならない（MUST）。
加わったことがないときは、今回加わったことを空にする。
既存の記事を渡さずに新しい記事を書くとき、本文の生成のタスクは今回加わったことを空にする。
今回加わったことのために、呼び出しの回数を増やしてはならない。

#### Scenario: 続報で記事を書き直す

- **WHEN** 既存の記事と、価格を発表した新しい出典を渡して、本文の生成のタスクで記事を書き直す
- **THEN** 出力の今回加わったことは、価格の発表を伝える1〜2文である

#### Scenario: 新しい記事を書く

- **WHEN** 既存の記事を渡さずに、本文の生成のタスクで記事を書く
- **THEN** 出力の今回加わったことは空である

#### Scenario: 呼び出しの回数

- **WHEN** 既存の記事を1つ書き直す実行が終わる
- **THEN** 呼び出しの記録に、その記事のための本文の生成の行は1件だけである

### Requirement: 今回加わったことだけが不正な出力

今回加わったことを除いた部分がスキーマに合い、今回加わったことがスキーマに合わないとき、サーバーは今回加わったことを空として扱わなければならない（MUST）。
今回加わったことを除いた部分は、今回加わったことのない出力として保存し、問い直さない。
今回加わったことがスキーマに合わないのは、文字列でないとき、前後の空白を除いて空のとき、300文字を超えるときである。

#### Scenario: 今回加わったことが数値

- **WHEN** 本文の生成のタスクの出力で、タイトル、要約、本文は正しく、今回加わったことが数値である
- **THEN** 記事は書き直され、その記事の今回加わったことは空であり、本文の生成の呼び出しは1回だけである

#### Scenario: 今回加わったことが長すぎる

- **WHEN** 本文の生成のタスクの出力で、今回加わったことが301文字である
- **THEN** その出力の今回加わったことは空として扱われる
