# Spec Delta

## ADDED Requirements

### Requirement: LLM検索の判定済みのURLの除外

検索のタスクが判定済みのURLを返したとき、クローラーはそのページを取得してはならない（MUST NOT）。
実行あたりのページ数の上限は、判定済みでないページの取得にだけ使う。

#### Scenario: 判定済みのページを返す

- **WHEN** 検索のタスクが3件のURLを返し、うち2件が判定済みである
- **THEN** 取得されるのは残りの1件だけで、使ったページ数は1増える

### Requirement: 空振りが続くLLM検索の減らし方

トピックのLLM検索が減らした状態の間、クローラーは、設定の時間帯の同じ日付に、そのトピックのLLM検索を2回以上行ってはならない（MUST NOT）。
エラーで終わった試行は、その日の1回に数えない。定時の実行と手動の実行を同じに扱う。省いた検索は、検索の試行として記録しない。
減らした状態とは、エラーで終わった試行を除いた直近3回のLLM検索の試行で、新しい候補の数がどれも0である状態である。数えるのは、検索語が今のトピックの文と一致し、最後に元に戻した時点よりあとの試行だけとする。

#### Scenario: 同じ日の2回目の実行

- **WHEN** LLM検索を減らしたトピックで、06:00の実行がLLM検索を行い、同じ日の18:00に実行する
- **THEN** 18:00の実行は、そのトピックの検索のタスクを呼ばない

#### Scenario: 日付が変わった

- **WHEN** LLM検索を減らしたトピックで、前の日の18:00の実行がLLM検索を行い、翌日の06:00に実行する
- **THEN** 06:00の実行は、そのトピックのLLM検索を行う

#### Scenario: 手動の実行

- **WHEN** LLM検索を減らしたトピックで、その日の定時の実行がLLM検索を行ったあと、手動で実行する
- **THEN** 手動の実行は、そのトピックの検索のタスクを呼ばない

#### Scenario: その日の検索がエラーだった

- **WHEN** LLM検索を減らしたトピックで、その日の06:00のLLM検索がエラーで終わり、18:00に実行する
- **THEN** 18:00の実行は、そのトピックのLLM検索を行う

### Requirement: 新しい候補による自動の戻し

LLM検索の試行で新しい候補が1件以上あったとき、クローラーは、次の実行からそのトピックのLLM検索を毎回行わなければならない（MUST）。

#### Scenario: 減らしたあとに新しい候補が出る

- **WHEN** LLM検索を減らしたトピックで、その日の1回のLLM検索が新しい候補を2件見つける
- **THEN** 同じ日の次の実行でも、そのトピックのLLM検索が行われる

### Requirement: 元に戻したあとの数え直し

利用者がトピックのLLM検索を元に戻したとき、クローラーは、そのあとの試行だけで減らした状態かどうかを判断しなければならない（MUST）。

#### Scenario: 元に戻す

- **WHEN** LLM検索を減らしたトピックを元に戻し、同じ日にもう一度実行する
- **THEN** その実行は、そのトピックのLLM検索を行う

#### Scenario: 元に戻したあとも空振りが続く

- **WHEN** 元に戻したあと、そのトピックのLLM検索が3回続けて新しい候補を0件で終える
- **THEN** そのトピックのLLM検索は、また減らした状態になる

### Requirement: トピックの文の書き換えでの数え直し

トピックの文を書き換えたとき、クローラーは、書き換える前の文で行った試行を、減らした状態かどうかの判断に数えてはならない（MUST NOT）。

#### Scenario: 文を書き換える

- **WHEN** LLM検索を減らしたトピックの文を書き換え、同じ日にもう一度実行する
- **THEN** その実行は、そのトピックのLLM検索を行う
