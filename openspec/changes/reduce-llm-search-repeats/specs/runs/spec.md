# Spec Delta

## ADDED Requirements

### Requirement: LLM検索の試行で数える結果

LLM検索の試行を記録するとき、サーバーは、返った結果の数として新しい候補の数を記録しなければならない（MUST）。
新しい候補は、判定済みでなく、取得でき、対象期間に収まるページである。検索のタスクが何も返さないときは0とする。
この数え方は、LLM検索についてだけ、add-run-attentionで決めた「判定済みのURLを除く前の数」に代わる。ニュース検索の数え方は変えない。

#### Scenario: 判定済みのページだけが返る

- **WHEN** 検索のタスクが3件を返し、3件とも判定済みのURLである
- **THEN** その試行の返った結果の数は0と記録される

#### Scenario: 新しいページがある

- **WHEN** 検索のタスクが3件を返し、うち1件が判定済みで、2件を取得できる
- **THEN** その試行の返った結果の数は2と記録される

### Requirement: 空振りが続くLLM検索の注意

有効なカテゴリの有効なトピックのLLM検索が減らした状態の間、サーバーは、そのトピックを指す注意の項目を作らなければならない（MUST）。
項目は、新しい候補が3回続けて0件であることと、そのトピックのLLM検索を1日1回に減らしていることを示す。項目のきっかけは、0件が続き始めた試行とする。
LLM検索について、サーバーは、ほかに0件が続く検索の注意の項目を作ってはならない（MUST NOT）。

#### Scenario: 3回続けて新しい候補がない

- **WHEN** トピックTのLLM検索が、3回の実行で続けて判定済みのページだけを返す
- **THEN** 注意の一覧に、トピックTのLLM検索を1日1回に減らしていることを示す項目がある

#### Scenario: 新しい候補が出る

- **WHEN** 減らした状態のトピックTのLLM検索が、新しい候補を1件見つける
- **THEN** 注意の一覧に、トピックTのLLM検索の項目はない

#### Scenario: 元に戻す

- **WHEN** トピックTのLLM検索を元に戻す
- **THEN** 注意の一覧に、トピックTのLLM検索の項目はない

#### Scenario: 元に戻したあとにまた続く

- **WHEN** トピックTのLLM検索を元に戻したあと、3回続けて新しい候補が0件になる
- **THEN** 注意の一覧に、トピックTのLLM検索の項目が、前とは別のきっかけで現れる

### Requirement: 元に戻した記録

利用者がトピックのLLM検索を元に戻したとき、サーバーは、その時点で最後のそのトピックの検索の試行を記録しなければならない（MUST）。
トピックを削除したとき、サーバーはその記録も削除する。記録は、設定ファイルにもトピックの履歴にも含めない。

#### Scenario: トピックを削除する

- **WHEN** 元に戻したことのあるトピックを削除する
- **THEN** そのトピックの元に戻した記録は残っていない
