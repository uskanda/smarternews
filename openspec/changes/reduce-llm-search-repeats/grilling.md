# grilling 記録: reduce-llm-search-repeats

Issue #234（監査ID F-12）のコメントで、6つの質問と推奨の答えを出した。Issueのオーナーは6つとも推奨の案を選び、続く計画を`/ok`で承認した。承認に追加の変更の指示はなかった。

この変更は、add-run-attention（Issue #141）の第1ラウンドQ5の「0件は、判定済みのURLを除く前の結果の数で数える」を、LLM検索についてだけ決め直す。LLM検索では「新しい候補の数」を数える。ニュース検索の数え方は変えない。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 「元に戻す」のあとの扱い | A：数え直す。元に戻すと毎回の検索に戻り、そこからまた3回続けて新しい候補が0件なら、もう一度減らして注意の項目を出す | 第1ラウンド Q1 |
| 減らしている状態を見せる場所 | B：注意の項目に「元に戻す」を足し、トピックの編集の「LLM検索」の近くにも、減らしていることと「元に戻す」を出す | 第1ラウンド Q2 |
| 新しい候補が出たときに自動で戻すか | A：自動で戻す。新しい候補が1件でも出たら、次の実行から毎回の検索に戻り、注意の項目も消える | 第1ラウンド Q3 |
| LLM検索の0件の項目を置き換えるか | A：置き換える。LLM検索の項目は「新しい候補が3回続けて0件。1日1回に減らしています」の1つにし、検索が何も返さない場合も含める | 第1ラウンド Q4 |
| 「1日1回」の区切り | A：設定の時間帯の日付で区切る。その日にまだ成功したLLM検索がないトピックだけ検索する | 第1ラウンド Q5 |
| 手動の実行での扱い | A：定時の実行と同じに扱う。手動の実行でも、その日にもう検索したトピックのLLM検索は省く | 第1ラウンド Q6 |
| 渡す見出し | そのトピックに結び付いた生成記事を、最後に書いたか更新した順に10件まで。期間では絞らない。配信記事は除く | 会話中に確認（計画の承認） |
| エラーになったLLM検索 | 「0件」にも「その日の1回」にも数えない | 会話中に確認（計画の承認） |
| トピックの文を書き換えたとき | 数え直す。数えるのは、検索語が今の文と一致する試行だけにする | 会話中に確認（計画の承認） |
| 「元に戻す」の記録 | 実行の記録として別の表に置く。トピックの列、設定ファイル、トピックの履歴には入れない | 会話中に確認（計画の承認） |
| 計画 | 承認。追加の変更の指示はなし | 会話中に確認（Issueのコメントの`/ok`） |
