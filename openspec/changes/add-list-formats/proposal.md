# Proposal

## Why

Webの記事の一覧は、3段の行と本文のペインを並べる1つの形しかない。Inoreaderからの乗り換えでは、見出しだけを素早く選ぶ読み方と、本文をスクロールで続けて読む読み方の両方が要る（issue #49）。

## What Changes

- 項目ごとの表示の設定に、一覧の形式を足す。値は「標準」「タイトルのみ」「展開」の3つで、既定は今と同じ「標準」とする。並び順と同じく、サーバーに保存し、設定ファイルで書き出しと読み込みができる
- Webの一覧の上部の並び順のメニューの隣に、形式のメニュー「表示」を置く。並び順のメニューを出す項目にだけ出す
- 「タイトルのみ」では、記事の一覧の1行に、見出し、購読フィードかカテゴリの名前、時刻と、行を選ぶ判断に使う印だけを出す
- 「展開」では本文のペインを閉じ、記事ごとに本文のペインと同じ内容を一覧へ続けて並べる。記事は10件ずつ読み込む。記事の取得と、それに続く要約、翻訳、全文の取得、開いた記録は、表示範囲へ入った記事だけで走らせる。キー操作は、表示範囲の上端の記事に働く
- Androidアプリは見せ方を変えない。ただし、並び順を変えたときに、Webで選んだ形式を消さないようにする

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `settings`: 項目ごとの表示の設定に、一覧の形式を足す。設定ファイルの書き出し、読み込み、往復も扱う
- `http-api`: 表示の設定の読み出しと変更に、一覧の形式を足す
- `web-reader`: 形式のメニューと、「タイトルのみ」と「展開」の一覧の振る舞いを足す
- `web-shell`: 形式が「展開」のときのペインの構成とキー操作を足す
- `mobile-reader`: アプリで並び順を変えても、Webで選んだ形式を残す

## Impact

- core：移行041（`list_views` に `format` 列）、`api.ts` の表示の設定と設定ファイルのスキーマ、`list-views.ts`、`settings-file.ts`
- client：形式の名前と既定、変更を画面へ先に反映するための関数
- Web：`ReaderPage`、`ArticleRow`、`ArticleView`、並び順のメニューの共通化、展開の形式の記事の部品、一覧の取得の件数
- アプリ：並び順の変更を画面へ先に反映する処理
- 文書：`docs/api.md`、`README.md`、`README.ja.md`、`examples/settings.example.yaml`、`DESIGN.md`
- APIの応答に `format` が加わる。古いアプリは知らない項目として読み飛ばすので、そのまま動く
