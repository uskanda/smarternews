# Proposal

## Why

設定の画面で設定ファイルを読み込んだあと、読み手情報と全体設定の入力欄は読み込む前の値を表示したままになる。
この状態で全体設定を保存すると、全体設定の保存はすべての項目を送るので、読み込んだタイムゾーンなどが読み込む前の値に戻る。
別の端末で変えた値があとから届いたときも、同じことが起きる。
これは2026-11-06のWeb UIの監査が見つけた項目である（監査ID B-06）。GitHubのissueの92番で扱う。

## What Changes

- 設定の画面の読み手情報と全体設定の欄は、その欄が表示する設定の値が変わったとき、入力値を新しい値に置き換える。
- 置き換えるとき、保存していない入力と、入力の誤りと保存の失敗の表示は消える。読み込みの確認のダイアログの文は変えない。
- 欄は作り直さないので、保存のあともフォーカスは「保存する」のボタンに残る。
- 購読フィードの設定の画面にある基本の取得周期の欄は変えない。
- サーバー、API、Androidアプリは変えない。LLMは呼ばない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `web-settings`: 読み手情報と全体設定の欄が、届いた設定の値に入力値を合わせる要件を足す

## Impact

- `apps/web/src/settings/SettingsPage.tsx`：`ReaderInfo` と `GlobalSettings` が、設定の値が変わったときに入力値を置き換える
- `apps/web/src/settings/settings.test.tsx`：読み込みのあとの表示と保存、保存していない入力、保存のあとのフォーカスのテストを足す
