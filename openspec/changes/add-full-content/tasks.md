# Tasks

どの作業も、失敗するテストを先に書いてから実装する。テストはLLMと外部のサイトを呼ばず、差し替えた取得元と記録済みのページで動かす。
要約だけの取得で得た本文を保存しないこと、自動の取得をやり直さないこと、開いた記事の全文を画面が頼むことは、grilling.mdのround 3 Q4からQ6で決めた。

## 1. 保存と取り出し

- [ ] 1.1 `packages/core/src/db/migrations` に移行を足し、`feeds` と `articles` に設計の列を足す。番号は、そのときの最後の番号の次にする。既存の購読フィードで全文の自動の取得が無効なこと、既存の記事の状態が空なことを、移行のテストで確かめる
- [ ] 1.2 `packages/core/src/db/feeds.ts` の登録と変更で、全文の自動の取得の設定を保存する。有効にした時刻が入ること、無効にすると空になることをテストで確かめる
- [ ] 1.3 `packages/core/src/db/articles.ts` に、全文を待つ記事を1件取る問い合わせを足す。由来の条件 `a.origin = 'feed'` を付ける。設定を入れる前の記事、既読の記事、状態のある記事、隠れた記事、無効な購読フィードの記事が外れること、新しい順であることをテストで確かめる
- [ ] 1.4 `packages/core/src/db/articles.ts` に、全文の保存と失敗の記録を足す。全文の保存が同じトランザクションで本文の訳を消し、タイトルの訳を残すことをテストで確かめる
- [ ] 1.5 `packages/core/src/sources/extract.ts` の `extractArticle` が、本文のHTMLも返すようにする。記録済みのページで、本文のHTMLが段落を含むことと、いまの文字列の結果が変わらないことをテストで確かめる
- [ ] 1.6 `packages/core/src/fetch` の `FetchError` と `PageResult` で、取得先の制限と時間切れを別の理由として返す。どちらも別の理由になることをテストで確かめる

## 2. 全文の取得の処理

- [ ] 2.1 `packages/core/src/feeds/full-content.ts` に、1件の記事の全文を取得し、変換して保存する処理を足す。保存、`no-url`、`robots`、`http`、`not-html`、`no-content`、`shorter` の各場合と、配信された内容が空の記事の場合をテストで確かめる
- [ ] 2.2 `full-content.ts` の全文の変換が、配信された内容と同じ規則に従うことを確かめる。スクリプトと `http:` の画像が消え、`https:` の画像と段落が残ることをテストで確かめる
- [ ] 2.3 `full-content.ts` に `FullContentWorker` を足す。1件ずつ取得すること、頼まれた記事が取得中の1件の直後に割り込むこと、同じ記事の二重の依頼が1回の取得になること、時間切れとHTTPの5xxで失敗した記事を自動で取得し直さないことをテストで確かめる
- [ ] 2.4 `FullContentWorker` のテストで、全文の取得がLLMを呼ばないこと、1件の失敗がほかの記事の取得を止めないこと、1日の回数で止まらないことを確かめる
- [ ] 2.5 `packages/core/src/feeds/ingest.ts` の項目の書き換えが、全文の列に触れないことと、ストップワードの判定が全文を見ないことをテストで確かめる

## 3. 要約と翻訳の入力

- [ ] 3.1 `packages/core/src/feeds/summarize.ts` の入力の選び方を、設計の順に変え、`SummaryWorker` に `FullContentWorker` を渡す。全文のある記事でページを取得しないこと、失敗した記事で配信された内容を使うこと、両方が有効な購読フィードでページの要求が1回であることをテストで確かめる
- [ ] 3.2 `summarize.ts` のテストで、全文の自動の取得が無効な購読フィードでは、要約のための取得が全文を保存しないことを確かめる
- [ ] 3.3 `packages/core/src/translation/service.ts` の `translateArticle` が、全文があれば全文を訳すようにする。全文から段落が作られること、20,000文字の上限が当たること、訳の途中で全文が保存されたときに訳を保存しないことをテストで確かめる

- [ ] 4.2 `apps/server` の記事の詳細に `fullContent`、`fullContentStatus`、`fullContentError` を足す。全文のある配信記事、待っている配信記事、失敗した配信記事、生成記事をテストで確かめる
- [ ] 4.3 `apps/server` に `POST /api/v1/articles/:id/full-content` を足す。取得、失敗、保存済みの記事、生成記事の400、存在しない記事の404をテストで確かめる
- [ ] 4.4 `apps/server/src/runtime.ts` で `FullContentWorker` を起動し、停止で止める。起動と停止をテストで確かめる
- [ ] 4.5 `packages/core/src/settings-file.ts` で、全文の自動の取得の設定を書き出し、読み込む。往復、書いていない購読フィードの扱い、読み込みで既存の記事の全文を取得しないこと、全文が設定ファイルに出ないことをテストで確かめる
