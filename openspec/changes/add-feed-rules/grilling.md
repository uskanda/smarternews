# grilling 記録: add-feed-rules

Issue #59「ルール（条件に合う記事への自動の操作）」の計画の記録である。
第1ラウンド（Issueのコメント）の8問には答えがなかったため、コードと仕様を調べたうえで、第2ラウンドで5問、第3ラウンドで9問を聞き直した。
利用者は第2ラウンドと第3ラウンドのすべての問いに答え、そのあとの計画を変更なしで承認した（`/ok`）。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 操作の種類 | スター、既読、通知、要約の4つ。webhookは別のIssueへ分ける | 第2ラウンド Q1（B） |
| 適用する時点 | 新しく保存する配信記事にだけ適用する。設定の画面に、保存済みの記事に当てて一致する件数を確かめる操作を置く | 第2ラウンド Q2（A） |
| 対象の記事 | 配信記事だけ | 第2ラウンド Q3（A） |
| 条件の形 | 条件も適用する範囲（全体・カテゴリ・購読フィード）も、フィルターと同じ | 第2ラウンド Q4（A） |
| フィルターとの順序 | フィルターで隠れた配信記事には適用しない。フィルターのあとにルールを適用する | 第2ラウンド Q5（A） |
| ルールの通知と通知の設定 | アプリの通知の設定が「出さない」以外のときに出す。「重要度5だけ」でも出す | 第3ラウンド Q6（A） |
| 1つのルールの操作の数 | 複数を選べる | 第3ラウンド Q7（A） |
| ルールの要約の順番 | 開いて頼んだ記事の次、ほかの自動の要約より先 | 第3ラウンド Q8（A） |
| 要約の1日の上限 | 数える。超えた分は翌日へ回る | 第3ラウンド Q9（A） |
| 自動の要約をしない購読フィード | ルールで頼めば要約する。AGENTS.mdの規則に、ルールで頼んだ記事を足す | 第3ラウンド Q10（A） |
| 既読との組み合わせ | ルールで既読にした記事は通知しない。要約は、ルールで頼んだものなら既読でも作る | 第3ラウンド Q11（A） |
| 適用する記事の範囲 | 初めて保存した、隠れていない配信記事だけ。重複として隠した記事と、再取得で書き換わった記事には適用しない | 第3ラウンド Q12（A） |
| ルールの設定の画面 | Webの設定の画面にだけ置く。フィルターの画面の部品を使う | 第3ラウンド Q13（A） |
| ルールの通知の内容 | 見出しと購読フィードの名前を出す。生成記事と合わせて数え、4件以上なら1つにまとめる | 第3ラウンド Q14（A） |
| 有効と無効の切り替え | フィルターと同じく、ルールを消さずに止める切り替えを置く | 計画（コードの慣例から決定。`/ok` で承認） |
| 設定ファイル | フィルターと同じく、設定ファイルの書き出しと読み込みでルールも扱う。範囲は識別名とURLで書く | 計画（コードの慣例から決定。`/ok` で承認） |
| 計画の承認 | 上の判断に沿った計画を、変更なしで承認 | Issue #59への返答（`/ok`） |
