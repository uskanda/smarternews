## ADDED Requirements

### Requirement: ルールの操作

APIは、ルールについて、次の操作を提供しなければならない（MUST）。

- 一覧、登録、変更、削除
- 有効と無効の切り替え
- 保存の前の件数の確認

一覧、登録、変更の応答は、ルールごとに次を含む。適用する範囲、条件、操作、有効と無効の別である。

#### Scenario: 操作を変える

- **WHEN** スターを付けるルールを、スターを付けて既読にするルールに変更する
- **THEN** APIは、2つの操作を持つルールを返す

#### Scenario: 件数を確かめる

- **WHEN** 保存済みの配信記事2件に合う条件で、保存の前の件数の確認を要求する
- **THEN** APIは件数2を返し、ルールの一覧は変わらない

### Requirement: ルールの入力の拒否

ルールの登録、変更、件数の確認の要求に、誤った正規表現の条件、ないカテゴリか購読フィードを指す範囲、操作のない内容が含まれるとき、APIはHTTPステータス400を返し、不正な箇所を示さなければならない（MUST）。
条件、範囲、操作の同じルールが登録済みのときの登録と変更には、HTTPステータス409を返す。存在しないルールを指定した要求には、HTTPステータス404を返す。

#### Scenario: 操作のないルール

- **WHEN** 操作を空にしたルールの登録を要求する
- **THEN** APIはHTTPステータス400を返し、不正な箇所として操作を示す

#### Scenario: 削除したルールを指定する

- **WHEN** 削除したルールの変更を要求する
- **THEN** APIはHTTPステータス404を返す

### Requirement: ルールの通知の対象の一覧

ルールの通知の対象の一覧の要求を受けたとき、APIは、ルールで通知の対象になった未読の配信記事を、対象になった時刻の新しい順に返さなければならない（MUST）。
項目ごとに、通知の対象になった時刻、購読フィードの名前、記事の一覧と同じ形の記事を含める。時刻を指定した要求には、その時刻より後に対象になった記事だけを返す。フィルターで隠れた配信記事は含めない。

#### Scenario: 指定した時刻より後

- **WHEN** 時刻Tの前と後に1件ずつ通知の対象になった配信記事がある状態で、Tを指定して一覧を要求する
- **THEN** APIは、Tの後に対象になった1件だけを、購読フィードの名前とともに返す

#### Scenario: 既読にした記事

- **WHEN** 通知の対象になった配信記事を既読にしてから、一覧を要求する
- **THEN** その記事は一覧に含まれない
