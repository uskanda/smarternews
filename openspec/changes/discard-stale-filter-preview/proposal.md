# Proposal

## Why

フィルターの入力欄で隠れる件数の確認を選び、応答が届く前に条件を変えると、変える前の条件の件数が表示される（Issue #99）。
条件を変えると確認の結果は消えるが、そのあとで届いた古い応答が、消えた結果の欄に件数を書き込むためである。
誤りの応答でも同じで、古い条件に対する誤りが新しい条件の横に出る。

## What Changes

- 件数の確認の応答が届いたとき、問い合わせたあとで条件が変わっていれば、その応答を捨てる。件数と誤りのどちらも表示しない。
- 確認のボタンは、応答を捨てたときも、応答が届けば押せるように戻す。
- 保存の応答は今のまま扱う。
- サーバーとAndroidアプリには手を入れない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `web-settings`：要件「古い条件の確認の結果を出さない」を足す。確認の応答を待つ間に条件を変えたときの扱いである。

## Impact

- `apps/web/src/settings/FilterForm.tsx`：下書きの版と、件数の確認の古い応答を捨てる処理
- `apps/web/src/settings/filters.test.tsx`：応答を待つ間に条件を変えるテスト
- APIとサーバー：変えない
