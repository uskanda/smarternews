# Design

## Context

`convertContent`（`packages/core/src/feeds/content.ts`）は、中身ごと捨てる要素の集合 `DROPPED` に `IFRAME`、`VIDEO`、`AUDIO` を持つ。`source` の子も一緒に消える。
同じ関数は、配信の内容（`ingest.ts`）、全文の取得（`full-content.ts`）、翻訳の答えの読み取り（`translation/google.ts`）の3か所から呼ばれる。
変換は同じ要素を2回たどる。1回はMarkdownを作り、もう1回は照合用の `text`（plainモード）を作る。

## Goals / Non-Goals

**Goals:**

- 配信の内容と全文の変換で、埋め込みを元のアドレスへのリンクとして残す。

**Non-Goals:**

- 枠や再生の部品を画面に出すこと。画面は変えない。
- 表の変換（別のissue）。
- `object` と `embed` の扱いを変えること。

## Decisions

### オプションで有効にする

`convertContent` の4つめの引数にオプション `{ embeds?: boolean }` を足す。省略したときは今までどおり捨てる。`ingest.ts` と `full-content.ts` だけが有効にする。

- 代わりの案：常に有効にする。翻訳の答えに紛れ込んだ `iframe` がリンクとして残り、既存のテスト「drops a tag the answer slipped in」が崩れる。翻訳の答えは原文の段落の訳で、新しいリンクを足す理由がない。

### 前後の文章とは別の段落にする

埋め込みは、`inline` の中でリンクの文字を返すのではなく、`blocksOf` で区切りとして扱う。段落の途中にあっても、それまでの文章を1つの段落にまとめ、リンクだけの段落を足し、続く文章を新しい段落にする。
`blocksOf` は子を順にたどるので、埋め込みが `p` などの中にあっても、その `p` の `blocksOf` で同じく区切られる。`span` や `a` などの文中の要素の中にある埋め込みは、`inline` が文字を返さず、今までどおり消える。

- 代わりの案：文中のリンクとして文章に混ぜる。翻訳の区切りで、文章とリンクが同じ区切りになり、リンクの文字を翻訳に送ってしまう。

### リンク先と文言

リンク先は、要素の `src` を、項目のページを基準にhttp(s)の絶対のアドレスに直したものである。`src` がない `video` と `audio` は、子の `source` を順に見て、http(s)に直せる最初の `src` を使う。
文字は、出力言語が `ja` で始まるときは `埋め込み（ホスト名）`、それ以外は `Embedded content (host)` にする。ホスト名は直したアドレスの `host` を使い、Markdownの記号を含めない形でエスケープする。
幅か高さが0か1の要素は、計測用の画像と同じ判定（`isTrackingPixel`）で捨てる。

### 照合用の文章

plainモードでは、埋め込みは何も返さない。画像とリンク先を入れないのと同じ扱いで、ストップワードの照合と、全文と配信された内容の長さの比較に影響しない。

### 翻訳の区切り

`segments.ts` の `hasWords` で、`[埋め込み（…）](…)` と `[Embedded content (…)](…)` の形だけの区切りを、文字のない区切りとして扱う。画像だけの区切りと同じく、翻訳には送らない。判定はリンクの文字の形とリンク先がhttp(s)であることで行う。

## Risks / Trade-offs

- 保存済みの記事の書き換え：埋め込みを含む記事は、次の取得で内容が変わったとみなされ、本文の翻訳が消える → issueに書かれた想定どおり。LLMは使わない。
- 文言と同じ形の文章：記事の中に、たまたま同じ形のリンクだけの段落があると、翻訳に送られない → リンクだけの段落は訳す語がほとんどなく、影響は小さい。
