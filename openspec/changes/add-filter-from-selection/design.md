# Design

## Context

動機は `proposal.md` の「Why」を見よ。ここでは、設計を決める今の作りだけを書く。

- 本文の選択は `apps/web/src/reader/Annotations.tsx` の `AnnotatedBody` が見ている。`selectionchange` のたびに `selectionIn` が選択を原文の文字列の位置に直し、ハイライトと重なる選択は捨てる。全文のある記事で配信された内容を表示している間は、`enabled` が偽になり、選択を見ない。
- 原文の部分には `SEGMENT_ATTRIBUTE` の属性が付いている。訳がなければ本文の全体が1つの部分で、訳があれば段落ごとの原文が部分になる。要約、訳、タイトルは部分の外にある。
- フィルターの入力欄 `FilterForm` は `apps/web/src/settings/FiltersPage.tsx` の中にあり、追加と編集の両方で使う。保存の前の件数は `api.previewFilter` で確かめる。保存のあと `useRefresh` が、フィルター、隠した記事、記事の一覧、件数の問い合わせを読み直させる。
- 開いている記事は `["article", id]` の問い合わせで読み、一覧の問い合わせとは別である。一覧から消えても、記事の表示は残る。
- 左のペインの項目の右クリックのメニューは、`apps/web/src/shell/order.tsx` の `EntryMenu` が `@radix-ui/react-context-menu` で作っている。キーボードからは、メニューのキーと `Shift+F10` で、`contextmenu` の出来事を送って開く。

## Goals / Non-Goals

**Goals:**

- 選んだ文字列を、フィルターの設定の画面と同じ検証と件数の確認を通して、隠すフィルターにする。
- ブラウザーの標準の右クリックのメニューは、操作できる選択がないときに残す。
- フィルターの設定の画面の見た目と動きを変えない。

**Non-Goals:**

- Androidアプリでの操作（grillingのQ5）。
- フィルターの照合の規則、API、サーバーの変更。

## Decisions

### 選択の判定を、ハイライトとフィルターに分ける

`selectionIn` は、選んだ文字列と画面の位置を返す。ハイライトを付けられるときはハイライトの位置を、フィルターを作れるときはそのことを加える。
ハイライトと重なる選択と、配信された内容を表示している間の選択は、捨てずにハイライトの位置だけを持たない。
フィルターを作れるのは、次をすべて満たすときである。

- 配信記事である
- 選択が、原文の部分か原文のタイトルの中に収まり、両端が同じ段落にある
- 前後の空白を除いた値が1〜200文字で、改行を含まない

200文字は、条件の値の上限 `MAX_FILTER_VALUE_CHARS` である。

代わりに、フィルターの判定を別のフックに分ける案もあった。選択の出来事と画面の位置を2か所で扱うことになるので、1つの判定にまとめた。

### 原文のタイトルの印と、選択を見る範囲

`ArticleView.tsx` で、原文のタイトルの要素に属性 `FILTER_SOURCE_ATTRIBUTE` を付ける。訳したタイトルがあるときは下の原文の行、ないときは見出しである。
`AnnotatedBody` は、記事の要素を受け取り、その中の選択を見る。ハイライトの判定は、これまでどおり本文の要素の中だけで行う。

### 右クリックのメニュー

記事の要素の `contextmenu` の出来事で、操作できる選択があるときだけ既定の動きを止める。
そのうえで、見えない `ContextMenu.Trigger` に同じ位置の出来事を送り、`@radix-ui/react-context-menu` のメニューを開く。
メニューの部品と見た目は `order.tsx` と同じものにし、キーボードからもメニューのキーと `Shift+F10` で開ける。
項目は、文字を選んだときのメニューと同じ操作に「コピー」を加える。コピーは、ブラウザーのコピーと同じく、選んだ文字列を写し取る。

記事の要素の全体を `ContextMenu.Trigger` にする案もあった。タイトルと本文の両方を包むには、`ArticleView` と `AnnotatedBody` の間で選択の状態を受け渡す必要がある。見えない起点に出来事を送る形なら、変更が `AnnotatedBody` の中に収まる。

### 入力欄の共有

`FilterForm` と関連の関数を `apps/web/src/settings/FilterForm.tsx` へ移す。propsを3つ足す。

- `initial`：種類、範囲、条件の初期値
- `preferred`：範囲の選択肢で、「全体」の次に「この記事」のまとまりとして並べる範囲。ほかのまとまりからは除く
- `onCreated`：追加のあとの処理。指定がないときは、いまと同じく下書きを空に戻して知らせを出す

### 保存のあと

ダイアログを閉じ、選択を外す。隠すフィルターを追加したことと隠した件数を知らせ、「取り消す」の操作を出す。
取り消すと `api.deleteFilter` を呼び、一覧と件数を読み直させ、取り消したことを知らせる。
開いている記事は閉じず、次の記事へも進まない。

## Risks / Trade-offs

- 全文の語が配信された内容にないとき、全文から作ったフィルターはその記事に当たらない → ダイアログの件数の確認で見分けられる。
- 見えない起点に出来事を送る形は、Radixの内部の動きに頼る → `order.tsx` の `openEntryMenu` と同じ使い方で、テストで開くことを確かめる。
