# Proposal

## Why

いまのsmarternewsで、配信記事の語から隠すフィルターを作るには、フィルターの設定の画面を開き、語を書き写す必要がある。
GitHubのissueの80番は、本文の文字を選んで右クリックし、そこからフィルターやストップワードを指定したいと求めている。
ストップワードは全体の隠すフィルターに統合済みである。

## What Changes

- Webの本文のペインで、配信記事の文字を選ぶと、隠すフィルターを作る操作を出す。文字を選んだときのメニューと、右クリックのメニューの両方に置く。
- 操作を出すのは、配信記事のタイトルの原文と本文の原文である。全文と配信された内容のどちらを表示している間も出す。訳、要約、生成記事では出さない。200文字を超える選択と、段落をまたぐ選択でも出さない。
- ハイライトと重なる範囲と、全文のある記事で配信された内容を表示している間は、ハイライトの操作を出さず、フィルターを作る操作だけを出す。
- 右クリックで独自のメニューを出すのは、操作できる選択があるときだけにする。それ以外では、ブラウザーの標準のメニューのままにする。独自のメニューには「コピー」も置く。
- 操作を選ぶとダイアログを開く。フィルターの設定の画面と同じ入力欄に、選んだ文字列を値として入れる。既定値は、隠すフィルター、範囲は全体、欄はタイトルと内容、方法は部分一致である。範囲の選択肢では、開いている記事の購読フィードとカテゴリを先頭のほうに並べる。
- 保存しても、開いている記事の表示はそのまま残す。一覧と件数だけを読み直す。隠した件数と取り消しの操作を知らせ、取り消すと作ったフィルターを削除する。
- サーバー、API、フィルターの照合の規則、Androidアプリは変えない。LLMは呼ばない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `web-reader`: 選んだ文字列から隠すフィルターを作る操作、本文での右クリックのメニュー、ダイアログの既定値、保存のあとの表示と取り消しを足す。文字を選んだときのメニューの出し方を変える

## Impact

- `apps/web/src/reader/Annotations.tsx`：選択の判定を、ハイライトとフィルターに分ける。右クリックのメニューを足す
- `apps/web/src/reader/ArticleView.tsx`：原文のタイトルに印を付け、選択を見る範囲を記事全体に広げる
- `apps/web/src/settings/FilterForm.tsx`（新規）：フィルターの入力欄を、設定の画面とダイアログで共有する
- `apps/web/src/settings/FiltersPage.tsx`：共有にした入力欄を使う。見た目と動きは変えない
