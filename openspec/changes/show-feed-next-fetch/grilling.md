# grilling 記録: show-feed-next-fetch

Issue #127（購読フィードの次の取得と、連続した失敗の回数が画面にない件）で、計画についての質問に答えてもらった。
APIは `failureCount`（続けて失敗した回数）と `nextFetchAt`（次の取得の時刻）をすでに返している。この変更は画面だけを変える。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 失敗の回数を出す条件 | A：2回目の失敗から「n回続けて失敗」と出す。1回目は今の印と理由だけ | Issue #127 第1ラウンド Q1 |
| 過ぎた次の取得の時刻 | A：「次の取得 まもなく」と出す | Issue #127 第1ラウンド Q2 |
| 次の取得を出す行 | A：一時停止していない、すべての購読フィードの行に出す。一時停止中は出さない | Issue #127 第1ラウンド Q3 |
| 仕様と記録の残し方 | A：小さなOpenSpecの変更を作り、web-settings の要件「購読フィードの一覧」に場面を2つ足す。回答は grilling.md に記録する | Issue #127 第1ラウンド Q4 |
| 計画の承認 | 上の4つの答えに沿った計画を承認 | Issue #127への返答（`/ok`） |

## 選ばなかった案

- 1回目の失敗から「1回続けて失敗」と出す案。日本語として不自然で、1回目の失敗は今の印と理由で伝わる
- 1回目と2回目以降で文言を変え、2回目から「n回続けて失敗」と言い分ける案。文言が2種類に増える
- 過ぎた時刻をそのまま「次の取得」として出す案。登録した直後のフィードにまで過去の時刻が出て、取得が止まったように見える
- 取得に失敗している行にだけ次の取得を出す案。問題のないフィードでも、次の取得の時刻を知る意味はある
- OpenSpecの変更を作らず、画面とテストだけを変える案

## 前提にした既存の決定

- 取得の状態の表示と「いま取得」の共通化は、変更 `show-feed-fetch-state`（Issue #117）で入っている。この変更とは重ならない
- 一時停止している購読フィードでは、APIの `nextFetchAt` は `null` である。まだ取得していない購読フィードでは登録の時刻である
