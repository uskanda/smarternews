# grilling 記録: add-article-misses

GitHubのissueの137番のコメントで、1ラウンドの質問（Q1〜Q8）に答えた記録である。
issueは、生成記事に「外れ」の印を付ける操作を足し、印を付けた記事をトピックの修正の材料として集めたいという要望である。
第2段階として、最近の外れの見出しを解釈のタスクの入力に足し、判定基準に「除くもの」を書かせることも求めている。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 第2段階を含めるか | 第1段階（記録）と第2段階（解釈への反映）を1つの変更にまとめる（A） | 第1ラウンド Q1 |
| 置く画面 | Webの画面とAPIだけに置く。Androidアプリは別のissueにする（A） | 第1ラウンド Q2 |
| 操作のキー | `x`（A） | 第1ラウンド Q3 |
| 取り消しの方法 | もう一度押すと印だけが外れる。押したときに「取り消し」付きの知らせを出し、取り消すと印が外れ、既読も押す前の状態に戻る（C） | 第1ラウンド Q4 |
| 記録の保持期間 | 期間を決めず、カテゴリが消えるまで残す。記事が消えたときは記事のIDだけを空にし、トピックが消えたときはそのトピックとのつながりだけを外す（A） | 第1ラウンド Q5 |
| 一覧での扱い | 一覧の表示は変えない。既読になるだけで、印は本文のペインのボタンの状態で分かる（A） | 第1ラウンド Q6 |
| 解釈に反映する時機 | もともと起きる解釈と、利用者が選んだ再解釈のときだけ反映する。呼び出しは増やさない。トピックの編集の画面に「前の解釈のあとに外れがN件ある」と出す（A） | 第1ラウンド Q7 |
| 解釈に渡す範囲 | そのトピックの外れのうち、直近90日の新しいものから20件まで。見出しは `<material>` で包む（A） | 第1ラウンド Q8 |

## 計画で決めたこと

承認を求めた計画（issueのコメント）で、次を決めた。利用者は変更なしで承認した。

| 決定 | 選択 |
|---|---|
| 対象 | 印を付けられるのは生成記事だけ。配信記事には操作を出さず、APIも400で拒否する |
| 記事の保持 | 印を付けても、記事の保持（180日の削除、スターと注釈がある記事は残す）は変えない |
| 記録の形 | 外れの表に、記事のID、カテゴリ、印を付けた時点の見出し、印を付けた時刻を持たせる。トピックは、印を付けた時点の記事のトピックを別の表に写す。同じ記事に印を付けられるのは1回だけ |
| 解釈の時刻 | トピックに解釈の時刻を足し、解釈のタスクが成功したときに記録する。今ある解釈済みのトピックは値なしのままにし、値なしは「すべての外れが前の解釈のあと」として数える |
| APIの形 | `PATCH /api/v1/articles/:id` に `missed` を足す。`true` は記録を作って既読にし、`false` は記録を消す。同じ要求に `isRead` があれば、それを優先する。記事の詳細に `missed`、トピックに `missesSinceInterpretation` を足す |
| 解釈のタスクの出力 | 出力のスキーマは変えない。外れが1件以上あるときだけ、見出しを渡し、判定基準に除くものを書くよう指示する |
| 他の変更との衝突 | add-digestsもllm-tasksを変えているので、差分は解釈のタスクの要件だけに絞る |
