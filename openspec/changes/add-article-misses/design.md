# Design

## Context

動機はproposal.mdの「Why」を参照する。生成記事と配信記事は `articles` の同じ表に入り、生成記事は180日で消える（スターと注釈がある記事は残す）。トピックの解釈は、トピックが未了のときだけ実行の最初に走る。未了になるのは、登録したとき、文章を変えたとき、`POST /api/v1/topics/:id/interpret` を呼んだときである。WebにはまだWebから再解釈を求める操作がない。

## Goals / Non-Goals

**Goals:**

- 外れの記録を、記事が消えても見出しとトピックで読めるように残す
- 解釈の呼び出しの回数を変えずに、外れを判定基準に返す

**Non-Goals:**

- Androidアプリの操作。応答に項目が増えるだけで、アプリの読み取りは変えない
- 外れの集計の画面（#138）
- 外れの数に応じた自動の再解釈

## Decisions

### 記録は記事と別の表に写して持つ

`misses` に記事のID（記事を消したら値なし）、カテゴリ（カテゴリを消したら一緒に消える）、印を付けた時点の見出し、印を付けた時刻を置く。トピックは `miss_topics` に、印を付けた時点の `article_topics` を写す。記事の行に印の列を足す案は、記事が消えると記録も消えるので採らない。記事のIDには `article_id IS NOT NULL` の部分一意索引を置き、同じ記事の2回目の印は最初の記録を残す。

### 記事の保持は変えない

外れの印は、`keptByReader` の条件（スターと注釈）に加えない。外れの記事を残す理由はなく、記録は別の表にあるからである。

### APIは記事のフラグの更新に足す

`PATCH /api/v1/articles/:id` の `articleUpdateSchema` に `missed` を足し、`setArticleFlags` の1つの取引の中で記録と既読を変える。専用の端点を作る案もあるが、既読とスターと同じ要求で扱えば、取り消しを1回の要求（`{"missed":false,"isRead":false}`）で送れる。`isRead` が同じ要求にあれば優先する。配信記事は、何かを変える前に400で拒否する。

### 件数はトピックの取得のときに数える

`topics` に `interpreted_at` を足し、実行前の解釈が成功したときに実行の開始時刻を書く。`missesSinceInterpretation` は、トピックを読む問い合わせの副問い合わせで数える。値なしのトピック（この移行より前に解釈したもの）は、すべての外れを数える。設定ファイルの読み込みで解釈を写すときは、時刻を変えない。読み込んだ解釈は外れを読んでいないからである。

### 解釈のタスクは入力だけを変える

`InterpretInput` に省略できる `misses` を足す。1件以上あるときだけ、見出しを1つの `<material>` の区画に1行ずつ入れ、判定基準に除くものを書く指示を足す。見出しをそのまま判定基準に写さず、記事の種類として書くよう指示する。出力のスキーマは変えないので、add-digestsのタスクの限定の要件とは衝突しない。範囲（90日、20件）は `recentMissTitles` で決める。

### Webの操作

本文のペインの、スターと既読のボタンの横に置く。ラベルはスターと同じ形で、「外れの印を付ける」と「外れの印を外す」を切り替え、`aria-pressed` で押された状態を示す。配信記事では表示しない。`x` のキーは、生成記事の本文が表示されている間だけ動く。

記事を開くと既読になるので、押したときにはたいてい既読である。既読の状態は、変わるときだけ要求に含める。失敗したときに、画面が変えた分だけを戻すためである。知らせの文は、既読にしたかどうかで「外れの印を付けました」と「外れの印を付けて、既読にしました」を分ける。取り消しは、印を付ける前に未読だったときだけ未読に戻す。

一覧の行には印を出さない（Q6）。外れの印は記事の詳細にだけあり、一覧の要約には含めない。

### 設定の画面に「解釈し直す」を置く

計画では件数と「再解釈で反映される」ことを出すとしたが、Webには再解釈を求める操作がない。件数の横に「解釈し直す」のボタンを置き、既存の `POST /api/v1/topics/:id/interpret` を呼ぶ。新しいAPIは足さず、解釈はこれまでどおり次の実行の最初に走るので、呼び出しの回数の規則（Q7）は変わらない。

## Risks / Trade-offs

- ［外れの見出しが判定基準をゆがめる］→見出しは `<material>` で包み、指示として扱わせない。件数は20件までにする。
- ［解釈し直すまで、外れは判定基準に入らない］→件数を設定の画面に出し、解釈し直す操作を同じ場所に置く。
- ［記録が増え続ける］→利用者は1人で、1件は見出しの1行程度である。必要になったら期間を足す。

## Migration Plan

移行の022で、表を2つと列を1つ足す。既存の行は変えない。戻すときは、表と列が残っていても前の版のコードは読まないので、そのままでよい。
