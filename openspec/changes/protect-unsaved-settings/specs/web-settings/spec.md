# Spec Delta

## MODIFIED Requirements

### Requirement: 保存していない変更の保護

設定の画面に保存していない変更がある間、利用者が別の画面へ移ろうとしたとき、画面は変更を破棄してよいかを確認しなければならない（MUST）。
設定の画面は、設定、カテゴリの編集、購読フィード、フィルター、語の色付けの各画面である。
別の画面へ移る操作には、リンク、左のペインの項目、`Shift+J` などのキー操作を含む。

#### Scenario: 保存を忘れて移動する

- **WHEN** カテゴリの名前を書き換え、保存せずに記事の一覧へ移ろうとする
- **THEN** 変更を破棄するかどうかの確認が表示され、取り消すと編集の画面に留まる

#### Scenario: トピックの文章を書き換えてキーで移る

- **WHEN** トピックの文章を書き換え、保存せずに `Shift+J` を押す
- **THEN** 確認が表示され、「編集を続ける」を選ぶと、書き換えた文章のまま編集の画面に留まる

#### Scenario: 変更を破棄して移る

- **WHEN** 全体設定のタイムゾーンを書き換え、左のペインの項目を選び、確認で「破棄して移動」を選ぶ
- **THEN** 選んだ項目の画面へ移り、タイムゾーンは保存されていない

#### Scenario: 保存したあとに移る

- **WHEN** 読み手情報を書き換えて保存し、左のペインの項目を選ぶ
- **THEN** 確認は表示されず、選んだ項目の画面へ移る

## ADDED Requirements

### Requirement: 未保存とみなす入力

画面は、保存済みの値と異なる編集の欄を、保存していない変更とみなさなければならない（MUST）。
画面は、空白でない文字があって、まだ追加していない追加の欄も、保存していない変更とみなさなければならない（MUST）。
追加の欄は、新しいトピック、新しいカテゴリの名前、購読フィードのURL、新しいフィルターの条件の値、語のまとまりの名前、まとまりに足す語である。

#### Scenario: 新しいフィルターの条件を書いて移る

- **WHEN** フィルターの画面で、新しいフィルターの条件の値を書き、追加せずに左のペインの項目を選ぶ
- **THEN** 確認が表示される

#### Scenario: 空の追加の欄

- **WHEN** 新しいトピックの欄に空白だけを書き、左のペインの項目を選ぶ
- **THEN** 確認は表示されず、選んだ項目の画面へ移る

#### Scenario: 追加したあとの移動

- **WHEN** 新しいカテゴリの名前を書いて追加する
- **THEN** 確認は表示されず、作ったカテゴリの編集の画面へ移る

### Requirement: 確認の対象にしない入力

利用者が「この端末の設定」、ファイルの選択、記事の画面のダイアログで入力したとき、画面はその入力を保存していない変更とみなしてはならない（MUST NOT）。
ファイルの選択は、設定ファイルとOPMLの読み込みに使う欄である。記事の画面のダイアログは、購読フィードの追加と、選択範囲からフィルターを作るダイアログである。

#### Scenario: 配色を変えて移る

- **WHEN** 区画「この端末の設定」で配色を変え、左のペインの項目を選ぶ
- **THEN** 確認は表示されず、選んだ項目の画面へ移る

#### Scenario: 選択範囲からフィルターを作るダイアログ

- **WHEN** 記事の画面で、選択範囲からフィルターを作るダイアログを開き、条件の値を書き換える
- **THEN** 再読み込みやタブを閉じる操作で、ブラウザーの確認は表示されない

### Requirement: 確認に並べる欄の名前

移動の確認を表示するとき、画面は、変更のある欄の名前をすべて並べなければならない（MUST）。
確認の操作は「破棄して移動」と「編集を続ける」の2つである。

#### Scenario: 2つの欄に変更がある

- **WHEN** カテゴリの設定とトピック「ransomware」の両方を書き換え、左のペインの項目を選ぶ
- **THEN** 確認に「カテゴリの設定」と「トピック『ransomware』の編集」の両方が表示される

### Requirement: ページを離れる前の確認

設定の画面に保存していない変更がある間、利用者が再読み込みやタブを閉じる操作をしたとき、画面はブラウザーの確認を表示させなければならない（MUST）。
保存していない変更がない間、画面はブラウザーの確認を表示させてはならない（MUST NOT）。

#### Scenario: 変更のある画面を再読み込みする

- **WHEN** 購読フィードの編集で名前を書き換え、保存せずにページを再読み込みしようとする
- **THEN** ブラウザーが、ページを離れてよいかを確認する

#### Scenario: 変更のない画面を閉じる

- **WHEN** 設定の画面を開いただけで、タブを閉じる
- **THEN** ブラウザーの確認は表示されない

### Requirement: トピックの「閉じる」の確認

トピックの編集に保存していない変更がある間、利用者が「閉じる」を選んだとき、画面は変更を破棄してよいかを確認しなければならない（MUST）。
確認の操作は「破棄して閉じる」と「編集を続ける」の2つである。

#### Scenario: 変更のないトピックを閉じる

- **WHEN** トピックの編集を開き、何も変えずに「閉じる」を選ぶ
- **THEN** 確認は表示されず、編集の欄が閉じる

#### Scenario: 変更のあるトピックを閉じる

- **WHEN** トピックの文章を書き換えて「閉じる」を選び、確認で「編集を続ける」を選ぶ
- **THEN** 編集の欄は開いたまま、書き換えた文章が残る

### Requirement: 「やめる」での破棄

利用者が購読フィード、フィルター、語のまとまりの編集で「やめる」を選んだとき、画面は確認を表示せずに変更を破棄しなければならない（MUST）。

#### Scenario: 購読フィードの編集をやめる

- **WHEN** 購読フィードの名前を書き換えて「やめる」を選ぶ
- **THEN** 確認は表示されず、編集の欄が閉じ、名前は保存されていない
