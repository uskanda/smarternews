# Design

## Context

動機は `proposal.md` の「Why」を見よ。ここでは、設計を決める今の作りだけを書く。

- 確認を出しているのは `CategoryPage.tsx` だけである。`CategoryForm` が `onDirty` で変更の有無を親へ渡し、親が `useBlocker` で移動を止め、`ConfirmDialog` で確かめる。カテゴリを削除したあとは、`leaving` の参照を立てて確認を出さない。
- 左のペインのクリックと `Shift+J` は、どちらも `react-router` による移動である。画面ごとの `useBlocker` で止められる。
- `react-router` は、同時に1つの `useBlocker` しか扱えない。欄ごとに置くことはできない。
- `FilterForm` と `AddFeedForm` は、設定の画面のほかに、記事の画面のダイアログでも使われる。ダイアログでの入力は確認の対象にしない（grillingのQ1）。

## Goals / Non-Goals

**Goals:**

- 未保存の変更を、画面ごとに1か所へ集める。移動の確認とページを離れる前の確認は、集めた結果だけを見る。
- 欄の側は、名前と変更の有無を渡すだけにする。

**Non-Goals:**

- 「やめる」での確認（grillingのQ2）。
- サーバー、API、Androidアプリの変更。

## Decisions

### 画面ごとの範囲と、欄からの登録

`apps/web/src/settings/unsaved.tsx` に、次の3つを置く。

- `UnsavedGuard`：画面ごとの範囲である。登録された欄のうち、変更のあるものを、欄の識別子と名前の対で持つ。`useBlocker` を1つだけ置き、変更のある欄が1つでもあれば、パスの変わる移動を止める。確認には、今の `ConfirmDialog` を使い、本文に欄の名前を「、」でつないで並べる。
- `useUnsaved(label, dirty)`：欄から登録するフックである。`dirty` が真の間だけ登録し、消えるときに外す。`UnsavedGuard` の外では何もしない。
- `useUnsavedLeaving()`：確認を出さずに移るための関数を返す。カテゴリを削除したあとと、新しいカテゴリを追加して作った画面へ移るときに使う。

`UnsavedGuard` の外では何もしないので、記事の画面のダイアログで使う `FilterForm` と `AddFeedForm` は、手を加えずに対象から外れる。

代わりに、各画面が今のカテゴリと同じく、変更の有無を親の状態に集める案もあった。画面ごとに `useBlocker` とダイアログを書き写すことになり、欄が増えるたびに親の状態も増える。登録の形なら、欄を足しても画面の側は変わらない。

### パスの変わらない移動は止めない

`/settings#providers` のように、同じ画面の中の位置だけを変える移動は止めない。編集中の値は消えないからである。

### ページを離れる前の確認

変更のある欄があるあいだだけ、`window` に `beforeunload` の処理を付ける。処理は既定の動作を止め、`returnValue` に空文字を入れる。文面はブラウザーが決める。

### トピックの「閉じる」

`TopicEditor` は、自分の変更の有無を見て、変更があるときだけ確認のダイアログを出す。

| 部分 | 文面 |
|---|---|
| 題 | 保存していない変更があります |
| 本文 | `このトピックに加えた変更は保存されません。` |
| 操作 | 「破棄して閉じる」と「編集を続ける」 |

保存に成功したあとで閉じるときは、確かめない。

### 変更の有無の判定

- 編集の欄は、初めの値と今の値を比べる。全体設定は、保存のときと同じく前後の空白を除き、実行時刻は区切りをそろえて比べる。保存したあとに値が同じになれば、変更はなくなる。
- 追加の欄は、空白でない文字があるかを見る。新しいフィルターは、条件の値のどれかに文字があるかを見る。

### 欄の名前

| 画面 | 欄 | 名前 |
|---|---|---|
| カテゴリの編集 | カテゴリの設定 | カテゴリの設定 |
| カテゴリの編集 | トピックの編集 | トピック『{文章}』の編集 |
| カテゴリの編集 | 新しいトピック | 新しいトピック |
| 設定 | カテゴリの名前 | 新しいカテゴリの名前 |
| 設定 | 読み手情報 | 読み手情報 |
| 設定 | 全体設定 | 全体設定 |
| 購読フィード | 追加 | 購読フィードの追加 |
| 購読フィード | 編集 | 購読フィード『{名前}』の編集 |
| 購読フィード | 基本の取得周期 | 基本の取得周期 |
| フィルター | 追加 | 新しいフィルター |
| フィルター | 編集 | フィルター『{種類と範囲}』の編集 |
| 語の色付け | まとまりの追加 | 語のまとまりの追加 |
| 語の色付け | まとまりの編集 | まとまり『{名前}』の編集 |
| 語の色付け | 語の追加 | まとまり『{名前}』への語の追加 |

## Risks / Trade-offs

- 欄が登録を忘れると、確認が黙って出ない → 欄ごとに、止まることをテストで確かめる。
- `beforeunload` の確認は、ブラウザーによっては、ページを操作したあとにしか出ない → ブラウザーの決まりなので受け入れる。テストでは、既定の動作を止めることだけを確かめる。
