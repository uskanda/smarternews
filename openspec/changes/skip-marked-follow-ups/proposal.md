# Proposal

## Why

外れの印を付けた生成記事に続報が来ると、実行は本文の生成のタスクを呼んで記事を書き直し、未読に戻す。利用者が要らないと伝えた話題が未読に戻り、LLMの呼び出しも使う。また「話題は合っているが、もう十分」を伝える印がない。

## What Changes

- 集約で既存の記事の続報と見なした話題について、その記事に外れの印か続報の停止の印があるとき、実行は本文の生成の前に候補を除外する。期間内の更新と、期間を過ぎた続報の新しい記事の両方を対象にする。基準未満と件数上限の判定より前に行う
- イベントの記事でも、本文の生成のあとで同じイベントの記事に印があると分かったときは、書き直さずに除外する
- 理由の種類を2つ足す。`missed-follow-up`（外れの印を付けた記事の続報）と `stopped-follow-up`（続報を止めた記事の続報）。理由の文には相手の記事の見出しを入れる
- 生成記事に「続報の停止」の印を足す。記事の表に保存し、`PATCH /api/v1/articles/:id` の `followUpsStopped` で変える。記事の詳細にも出す。既読と未読は変えず、解釈の入力にも入れない。配信記事への要求は400で拒否する
- Webの本文のペインに「この話題の続報を止める」のボタンを足す。キーは割り当てない
- トピックの成績に `rejectedByMark` を足し、2つの理由の除外をまとめて数える。設定の画面に行を1つ足す

## Capabilities

### New Capabilities

新しい能力はない。

### Modified Capabilities

- `article-pipeline`: 印のある記事の続報の除外と、その理由の記録
- `http-api`: 続報の停止の印の変更と提供、配信記事での拒否、トピックの成績の印による除外の数
- `web-reader`: 本文のペインの続報の停止の操作と、配信記事での非表示
- `web-settings`: トピックの成績の「印のある記事の続報」の行

## Impact

- 移行：`articles` に列を足し、`candidates` を作り直して理由の種類のCHECK制約に2つの値を足す
- `packages/core`：実行の処理、理由の文、候補と記事の保存、トピックの成績、APIのスキーマ
- `apps/web`：本文のペイン、記事の印の変更、トピックの成績
- `docs/api.md`
- LLMの呼び出しは減る。印のある記事の続報について、本文の生成のタスクを呼ばなくなる。イベントの記事で生成のあとに分かった場合だけは、呼んだうえで結果を捨てる
- Androidアプリは変えない
