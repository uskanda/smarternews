# grilling 記録: skip-marked-follow-ups

GitHubのissueの224番のコメントで、1ラウンドの質問（Q1〜Q6）に答えた記録である。
issueは、外れの印を付けた記事への続報を本文の生成の前に除外し、話題は合っているが続報は要らないことを伝える「この話題の続報を止める」の印を足すよう求めている。
質問のあとに計画を投稿し、利用者は変更なしで承認した（`/ok`）。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 止めた効果が続く期間 | 14日のまま。集約の入力は変えない。最後の更新から14日たつと、同じ話題が新しい記事として戻ることがある（A） | 第1ラウンド Q1 |
| 理由の種類の数 | 2つ足す。`missed-follow-up`（外れの印を付けた記事の続報）と `stopped-follow-up`（続報を止めた記事の続報）（A） | 第1ラウンド Q2 |
| 相手の記事の示し方 | 理由の文に相手の記事の見出しを入れる。APIと実行の詳細の画面の形は変えない（A） | 第1ラウンド Q3 |
| 止めた印の保存とAPI | 記事の表に列を足し、`PATCH /api/v1/articles/:id` に `followUpsStopped` を足す。記事の詳細にも出す。既読と未読は変えない（A） | 第1ラウンド Q4 |
| Androidアプリの扱い | Webだけに足す。アプリは変えない（A） | 第1ラウンド Q5 |
| トピックの成績での数え方 | 件数 `rejectedByMark` を1つ足し、2つの理由をまとめて数える。設定の画面に行を1つ足す（A） | 第1ラウンド Q6 |
| 除外の順序 | 基準未満と件数上限の判定より前に除外する。2つの印が両方あるときは外れを優先する | 会話中に確認（計画の承認） |
| イベントの記事 | 同じ規則を当てる。本文の生成のあとで同じイベントの記事に印があると分かった場合も、書き直さずに除外する | 会話中に確認（計画の承認） |
| 対象の続報 | 期間内の更新と、期間を過ぎた続報の新しい記事の両方 | 会話中に確認（計画の承認） |
| キー | 止める操作にキーは割り当てない | 会話中に確認（計画の承認） |
| 配信記事 | 止めた印は生成記事だけに付けられる。配信記事への要求は400（`not_allowed`）で拒否する | 会話中に確認（計画の承認） |

## 後回しにしたもの

- 印のある記事を14日より長く集約に渡し続けること（Q1のB、C）
- 除外した候補から相手の記事へのリンク（Q3のB）
- Androidアプリでの続報の停止の操作（Q5のB）
