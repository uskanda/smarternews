# Proposal

## Why

購読フィードを追加できるのは、設定の購読フィードの画面だけである。
カテゴリの記事を読んでいて、そのカテゴリにフィードを足したくなったとき、設定の画面へ移り、カテゴリを選び直し、読んでいた一覧へ戻る必要がある（issue #79）。
読んでいる一覧のまま、そのカテゴリへ追加できるようにする。
同じく、購読フィードの記事を読んでいて、そのフィードの要約や翻訳を切り替えたくなったときも、設定の画面で目当てのフィードを探す必要がある。読んでいる一覧のまま切り替えられるようにする。

## What Changes

- Webの画面で、ニュースのカテゴリの記事の一覧の上部に「フィードを追加」のボタンを置く。イベントのカテゴリ、カテゴリの「AI生成」の一覧、カテゴリ以外の一覧には置かない。
- ボタンを選ぶと、一覧の画面のままダイアログを開く。入力欄は設定の画面の追加の欄と同じで、カテゴリは開いていたカテゴリを選んだ状態にする。
- 追加できたら、ダイアログを閉じ、左のペインのそのカテゴリの下に購読フィードを加える。
- 購読フィードの記事の一覧の上部に「フィードの設定」のボタンを置く。選ぶとダイアログを開き、自動の要約、翻訳、全文の取得の3つを、いまの値と設定の画面と同じ説明とともに表示する。保存を選んだときだけ保存し、ほかの設定は変えない。
- ダイアログを開いている間は、1文字のキーによる操作を受け付けない。購読フィードの設定のダイアログ、キー操作の一覧、確認のダイアログにも同じ扱いが及ぶ。
- 設定の画面の追加と編集の振る舞いは変えない。Androidアプリ、サーバー、APIは変えない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `web-reader`: 2つの要件を足す。ニュースのカテゴリの記事の一覧から、ダイアログで購読フィードを追加する。購読フィードの記事の一覧から、ダイアログでそのフィードの要約、翻訳、全文の取得を切り替える
- `web-shell`: ダイアログを開いている間に、1文字のキーによる操作を受け付けない要件を足す

## Impact

- `apps/web`: 設定の画面の追加の欄と3つの切り替えを、ダイアログでも使える部品に切り出す。記事の一覧の上部に2つのボタンとダイアログを足す。キー操作の処理で、ダイアログの中のキーを無視する。
- 購読フィードの更新のAPIは、送った項目だけを変える。これをそのまま使うので、サーバー、API、`packages/client`、Androidアプリに変更はない。
- 画面の操作でLLMを呼ぶのは、これまでどおり、利用者がWebページの購読フィードのセレクターの候補を求めたときだけである。自動の要約を入れた購読フィードの記事は、これまでどおり、保存のあとの別の処理が要約する。
