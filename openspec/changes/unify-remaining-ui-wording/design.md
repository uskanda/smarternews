# Design

## Context

動機はproposal.mdのWhyにある。文言は`apps/web/src`の各画面に直接書かれ、テストはボタンやダイアログを支援技術に伝わる名前で探す。そのため文言を変えると、テストも変える必要がある。前回の`unify-ui-wording`（#121）と同じ形で、文言、テスト、要件の差分、文書を1つの変更で直す。DESIGN.mdは、操作の名前を押したあとの表示と同じ言葉にすると決めている。

## Goals / Non-Goals

**Goals:**

- 同じ種類の操作には、どの画面でも同じ名前を付ける。
- 設定の区画の名前から、アプリの接続を探せるようにする。

**Non-Goals:**

- 購読フィードの「いま取得」。DESIGN.mdとweb-settingsの要件が名前で書いており、そのまま使う。
- トピックの編集の「閉じる」（カテゴリの画面）。`protect-unsaved-settings`が、変更があれば確かめる動きと合わせて決めたものなので変えない。
- 入力のないダイアログ（接続用のQRコード、キー操作の一覧）の「閉じる」。
- Androidアプリ。対象の文言は「もう一度試す」だけで、Webの新しい名前と同じである。
- `README.ja.md`のCLIの説明の「いますぐ実行する」。ボタンの名前ではない。
- 進行中の変更の`grilling.md`。会話の記録なので直さない。

## Decisions

### すぐ始める操作

「いま実行」「いま作る」「いま取得」にそろえる。ダイジェストの画面の2つの説明文と、全体設定の「ダイジェストを作る時刻」の説明も「いま作る」にする。進行中の変更`add-digests`は、proposal、design、tasks、要件の差分の「今すぐ作る」を「いま作る」にする。要件名の「今すぐ作る操作」なども同じ語にする。

### 設定の区画「アプリの接続」

区画`#connect`を「利用量」のあと、「トークン」の前に置く。見出しは「アプリの接続」で、中身はQRコードの説明と表示のボタンである。「トークン」の名前と`#tokens`は変えないので、区画のリンクで「トークン」へ移る場面はそのまま使える。上部の区画のリンクは11個になる。進行中の変更`add-settings-shortcuts`の区画の一覧にも「アプリの接続」を足す。

### トピックの追加

読む画面の操作は「トピックを追加…」、ダイアログの見出しは「トピックを追加」にする。ダイアログの中の「追加する」「追加しました」、設定の画面の「トピックを追加」と同じ語になる。進行中の変更`add-topic-from-reader`の要件名の「〜からトピックを足す」は「〜からトピックを追加する」にする。

### 続きの読み込みのテスト

フィルターの画面の隠している記事は、1回に50件を読み込む。テストは51件を隠すフィルターを作り、「さらに読み込む」で残りの1件が出ることを確かめる。

## Risks / Trade-offs

- ［上部の区画のリンクが11個になり、折り返しが増える］→ リンクはもとから幅が足りなければ折り返す。「アプリの接続」は短い名前である。
- ［進行中の変更の要件名を変える］→ 主の要件にはまだ入っていないので、変更を閉じるときの差分の適用には影響しない。
