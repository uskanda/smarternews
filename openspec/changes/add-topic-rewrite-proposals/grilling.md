# grilling 記録: add-topic-rewrite-proposals

Issue #143（監査ID F-08）のコメントで、2つのラウンドの質問と推奨の答えを出した。
第1ラウンド（Q1〜Q6）は、外れの印（#137）がまだない時点で出した。そのあと#137がマージされ、Issueのオーナーが見直しを求めた。第2ラウンド（Q7〜Q12）は、第1ラウンドを#137のあとのコードに合わせて置き換えたものである。第1ラウンドには答えが付かず、第2ラウンドの答えで決まった。
オーナーはQ7〜Q12のすべてでAを選び、そのあと計画を`/ok`で承認した。承認に追加の変更の指示はなかった。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 外れの印（#137）がまだないときの扱い | 問いが要らなくなった。#137がマージされたので、外れの印を入力に入れる（Q7で範囲を決めた） | 第1ラウンド Q1（第2ラウンドで置き換え） |
| 外れの印を入力に入れる範囲 | A：解釈と同じく`recentMissTitles`を使う。90日以内の外れを新しい順に20件まで、見出しだけを`<material>`で包んで渡す | 第2ラウンド Q7（第1ラウンド Q1を置き換え） |
| 案で書き直すもの | A：案はトピックの文章だけにする。判定基準は、保存したあとに解釈が作り直す。変えた点の説明では、判定基準がどう変わるはずかも述べさせる | 第2ラウンド Q8（第1ラウンド Q2を置き換え） |
| 専用の1日の上限の既定 | A：`limits.topicRewritesPerDay`の既定を20回とし、0でこの機能を止める。1日の呼び出し回数（`llmCallsPerDay`）と月の予算にも数える。`llmCallsPerDay`の既定は変えず、既定の説明に「書き直しの案の20回も含む」と足す | 第2ラウンド Q9（第1ラウンド Q3を置き換え） |
| 割り当てがないときのプロバイダー | A：`smart`があればそれを使い、なければ既定のプロバイダーを使う（`CAPABLE_TASKS`に足す） | 第2ラウンド Q10（第1ラウンド Q4を置き換え） |
| 外れ以外の記事を渡す範囲と件数 | A：そのトピックの直近30日の分を渡す。開いた記事とスターの記事はそれぞれ新しい順に20件まで、タイトルと要約を渡す。除外は判定が関連なしとした候補を30件まで、タイトルと理由を渡す。機械的な理由の除外は入れない。件数と期間は定数にし、設定には出さない | 第2ラウンド Q11（第1ラウンド Q5を置き換え） |
| 画面での出し方と使い方 | A：Webのトピックの編集に「書き直しの案を出す」を置く。保存済みの文章と判定基準から案を求め、1〜2案を説明と一緒に並べる。「この案を使う」で編集欄の文章を置き換える（保存はしない）。案はデータベースに残さない。保存していない変更があるときは押せない。上限や予算、未解釈のときは、ボタンのそばに理由を出す | 第2ラウンド Q12（第1ラウンド Q6を置き換え） |
| 計画 | 承認。追加の変更の指示はなし | 会話中に確認（Issueのコメントの`/ok`） |
