# Design

## Context

`ArticleRow`はメモ化されていない。`ReaderPage`は行ごとに`now()`を呼んで新しい`Date`を渡すので、選択が1つ動くだけで一覧のすべての行を描き直す。
行は描くたびに`groupsIn`で見出しと要約を正規化し直す。`split`は文字列ごとに結果を覚えるが、`groupsIn`は覚えない。
動機は`proposal.md`の「Why」を参照する。

## Goals / Non-Goals

**Goals:**

- `j`や`k`で移ったとき、描き直す行を、選択が外れた行と選択された行の2つに減らす。
- 同じ文字列について、語のまとまりの判定をやり直さない。

**Non-Goals:**

- 日付の整形（`formatShort`）そのものの修正（`grilling.md`）。
- `AnnotationList`と`EventList`の行の修正。
- Androidアプリの画面の修正。すでにメモ化と分への丸めが入っている。

## Decisions

### groupsIn は文字列ごとに語のまとまりの位置を覚える

`groupsIn`は、文字列ごとに当たった語のまとまりの位置を`Map`に覚える。上限は`split`と同じ`KEPT_TEXTS`（2000件）で、古いものから捨てる。
覚えるのは位置なので、複数の文字列の結果を合わせても、語のまとまりの順序と重複のなさは今と同じになる。
`createTermMatcher`の結果は語のまとまりが変わると作り直すので、古い語のまとまりの結果が残ることはない。

### 行は memo で包み、現在時刻はミリ秒の数値で受け取る

`now`を`Date`から数値に変え、行の中で`new Date(now)`にする。数値なら、同じ分の間は同じ値なので、`memo`の浅い比較で同じと判定できる。Android側の行と同じ形である。

### 現在時刻は一覧で1回だけ分に丸める

`Math.floor(now().getTime() / 60_000) * 60_000`を一覧の描画で1回だけ求め、すべての行に渡す。
行の時刻は「今日の時刻」「昨日」「日付」のどれかで、分より細かい違いは表に出ない。丸めても表示は変わらない。

## Risks / Trade-offs

- 行に渡すほかの値（`to`、`sourceName`、`terms`など）は、文字列か、取得したデータの参照である。描画ごとに参照の変わる値を1つでも渡すと、また毎回すべての行を描き直す。テストで`formatToParts`の呼び出し回数を数え、描き直す行が少ないことを確かめる。
- 分が変わった直後の描き直しでは、すべての行を描き直す。1分に1回なので許容する。
