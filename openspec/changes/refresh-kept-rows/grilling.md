# grilling 記録: refresh-kept-rows

GitHubのissueの89番のコメントで、1ラウンドの質問（Q1、Q2）に答えた記録である。
issueは、2026-11-06のWeb UIの監査の項目B-03である。未読の一覧に残した行は既読にした時点の写しで、あとから届いた続報、翻訳の見出し、既読やスターの変更の失敗を反映しない。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 続報が届いた行の既読の見た目 | 取得した行の`updatedAt`が残した行より新しければ、取得した行をそのまま使う。続報は未読の見た目と新しい見出しで出る。更新の時刻が同じか古いときは、取得した行に残した行の`isRead`と`starred`だけを重ねる（A） | 第1ラウンド Q1 |
| Androidアプリを直す範囲 | Webとアプリの両方で、キャッシュの更新と失敗の巻き戻しを残した行へ届ける。アプリに失敗の知らせは足さない（A） | 第1ラウンド Q2 |
| 計画 | 承認。追加の変更の指示はなし | 会話中に確認（Issueのコメントの`/ok`） |

## 計画で決めたこと

承認を求めた計画（issueのコメント）で、次を決めた。利用者は変更なしで承認した。

| 決定 | 選択 |
|---|---|
| 取得した行にない記事 | これまでどおり残した行を使う。未読の一覧が返さなくなった既読の記事などである |
| 並べ替えの鍵 | 重ねたあとの行から取る。最近読んだ記事の一覧でも、取得した行にある記事は取得した行の`readAt`で並ぶ |
| キャッシュの更新を残した行へ届ける方法 | `patchArticle`がキャッシュに書いたあと、`QueryClient`ごとに登録した受け手へ`(id, patch)`を渡す。購読するフック`useArticlePatchListener`を足す。Webは`ReaderPage`、アプリは`ReaderSessionProvider`が受け取る |
| Webの`flagFailed`の手での巻き戻し | 受け手が同じことをするので消す。知らせと「もう一度試す」は残す |
| アプリの失敗の巻き戻し | `useArticleFlags`の`onError`を、送った変更の逆を当てる形にする。記事の詳細がキャッシュにない行でも戻る |
| Webのスクロールでの既読の写し方 | すでに残した行も、今の一覧の行から写し直す。アプリの`showRead`と`setRead`はすでに今の行を写しているので変えない |
| 仕様 | web-readerとmobile-readerに、続報、翻訳の見出し、失敗の巻き戻しのシナリオを足す |
