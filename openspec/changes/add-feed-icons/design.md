# Design

## Context

動機は `proposal.md` のWhyに、決定の経緯は `grilling.md` に書いた。

- 画像の中継（`packages/core/src/images/`）は、署名した中継のパスを受けて元のURLの画像を取得し、ディスクに置いて返す。形式は先頭のバイトで判別し、JPEG、PNG、GIF、WebP、AVIFだけを返す。SVGは拒む。
- APIは、配信記事の本文や添付の画像のURLを、署名した中継のパスに書き換えて返す（`rewrite.ts`）。画面はそのパスだけを読み込む。
- フィードを読むと `siteUrl` を取り出し、`feeds` の `site_url` に記録する。ページから作るフィードでは、そのページのURLである。
- 取得の後始末として、題名の翻訳がある。記事を保存したあとに呼び、失敗しても取得は成功のままである。
- `PageFetcher` は、robots.txtを守ってHTMLのページを取得する。購読フィードの取得は、取得器の `pageFetcher()` を共有する。

## Goals / Non-Goals

**Goals:**

- 左のペインの購読フィードを、名前を読まなくても見分けられる状態にする。
- アイコンの画像を、既存の中継の安全の仕組みだけで配る。

**Non-Goals:**

- 一覧の行（`ArticleRow`）の配信元の前に出すこと。行に記事の画像を出さない決定も変えない。
- Androidの引き出し。必要になれば別のissueにする。
- アイコンを利用者が選んだり差し替えたりすること。
- RSSの `<image>` と、`apple-touch-icon` などの `icon` 以外の `rel`。

## Decisions

### 記録するのは元のURLと探した時刻だけ

データベースの変更 `038_feed_icons.sql` で、`feeds` に2列を足す。

- `icon_url TEXT`：見つけたアイコンの元のURL。見つからなければNULL
- `icon_checked_at TEXT`：最後に探した時刻。まだ探していなければNULL

画像のバイト列は表に持たない。画面が中継のパスを求めたとき、中継が元のURLから取得してディスクに置く。
ディスクの保存（既定7日）が切れても、次に求められたときに取り直される。

### アイコンを探す順番

`packages/core/src/feeds/icon.ts` の `findFeedIcon` が、次の順に候補を作る。重なる候補は1度だけ試す。

1. フィードの記述：Atomの `<icon>`、JSON Feedの `favicon`。どちらもフィードのURLを基準に絶対URLへ直す
2. サイトのHTML：`site_url` のページを `PageFetcher` で1回取得し、`rel` に `icon` を含む `<link>` を文書の順に読む。`type` が `image/svg+xml` のものは飛ばす
3. `/favicon.ico`：`site_url`（なければフィードのURL）のオリジンの直下

`<link>` の読み取りは、`discover.ts` の `<link rel="alternate">` を読む処理と共有する。`pageLinks` として切り出す。

候補ごとに画像を取得し、`sniffImageType` が形式を判別できた最初の候補を採る。
取得は、取得器の制限（取得先の制限、ホストごとの間隔、User-Agent、時間の上限）の下で行う。大きさの上限は1MBとする。アイコンにそれより大きいものはまず無く、探すたびの通信を抑えるためである。
robots.txtが禁じるURLは取得しない。`PageFetcher` にrobots.txtの判断だけを返す `allows` を足して使う。
HTTPの失敗、判別できない中身、取得の失敗は、どれもその候補を飛ばす理由になる。

RSSとRDFのフィードでは、1の候補はない。RSSの `<image>` は横長のロゴが多く、文字の高さに縮めると読めないので使わない。

### 探す時機

`subscribe` と `fetchFeed` が記事を保存し終えたあとに、`icon_checked_at` がNULLか30日より前のときだけ探す。
内容が変わらなかったとき（304）にも、30日を過ぎていれば探す。
304ではフィードの記述が手元にない。そこで1の候補の代わりに、前に見つけたアイコンのURLを最初に試す。フィードの記述が名指すアイコンを、304のたびに失わないためである。
ページから作るフィードも同じ時機に探す。1の候補はない。
2の候補のページは、取得で手にしたページをそのまま読み、もう1度は取得しない。ページから作るフィードでは、`site_url` が取得したページそのものだからである。

探したら、見つかったかどうかによらず `icon_checked_at` を今の時刻にし、`icon_url` を結果で置き換える。
見つからなかったときは `icon_url` をNULLにする。以前のアイコンが消えたサイトで、古い画像を出し続けないためである。
探す処理が例外を投げても、取得の結果は変えない。題名の翻訳と同じ扱いである。このときは時刻を更新しないので、次の取得で探し直す。

### APIでの出し方

`feedSchema` に `iconUrl: string | null` を足す。
データベースから読んだ `Feed` は元のURLを持つ。サーバーが返す前に、`relayFeedIcon(feed, key)` が署名した中継のパスに置き換える。
`http:` か `https:` でないURLはNULLにする。
`Feed` を返すすべてのAPIで通す。一覧、1件、登録、編集、移動、即時の取得である。

### 中継でのICO

`sniffImageType` は、先頭の4バイトが `00 00 01 00` のものを `image/x-icon` と判別する。
ICOの中身はPNGかBMPで、SVGのようにスクリプトを含められない。記事の本文の画像も同じ判別で受け付ける。
種類の値が1でないものと、画像の数が0のものは判別しない。
中継が取得先に送る `Accept` にも `image/x-icon` を足す。SVGは今までどおり拒む。

### 左のペインの表示

`Shell.tsx` の `ListItem` に `icon` を渡せるようにし、購読フィードの項目にだけ渡す。

- 名前の前に、1em四方の枠を置く。名前と枠の間は `DESIGN.md` の `gap-sm` に揃える
- `iconUrl` があれば、枠に `<img>` を描く。`alt=""`、`referrerPolicy="no-referrer"`、`loading="lazy"` を付ける。名前は隣の文字で読み上げられるので、画像は読み上げない
- `iconUrl` がNULLのときと、読み込みに失敗したとき（`onError`）は、枠だけを残して何も描かない

カテゴリ、固定の項目、管理のページの行には枠を置かない。
`NavEntry` には足さない。Androidと共有する型で、Androidは今回アイコンを出さないためである。`Shell.tsx` が購読フィードの一覧からURLを引く。

## Risks / Trade-offs

- 1つのフィードでアイコンを探すと、取得が数回増える。探す間隔を30日として抑える。
- 登録の応答は、アイコンを探す分だけ遅くなる。HTMLと画像の取得は、どれも取得器の時間の上限の下にある。
- 判別に通ったICOでも、ブラウザーが描けない中身はありうる。`onError` で枠だけを残す。

## Migration Plan

- データベースの変更は列を足すだけで、既存の行は2列ともNULLになる。次の取得で探す。
- 戻すときは、2列を読まなくなるだけで害はない。
