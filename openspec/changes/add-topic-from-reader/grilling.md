# grilling 記録: add-topic-from-reader

GitHubのissueの144番のコメントで、1ラウンドの質問に答えた記録である。
issueは、記事を読みながら新しいトピックを足せるようにする提案である（Web UIの監査のF-09）。
入口は、名前の記事の一覧の上部と、文字を選んだときのメニューの2つである。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| add-mentionsで後回しにした「名前を追う機能」との関係 | トピックの形を採り、左のペインに名前の項目を並べる形は取り下げる。add-mentionsのgrillingの記録に、置き換えたことを書き足す（B） | 第1ラウンド Q1 |
| 文字を選んだときのメニューに出す記事と箇所 | 生成記事と配信記事のどちらでも、記事の要素の中の選択なら出す。タイトル、本文、訳、要約のどれでもよい。前後の空白を除いて1〜200文字の選択に限り、改行は空白に置き換えて下書きに入れる（A） | 第1ラウンド Q2 |
| ダイアログのカテゴリの初期値と選択肢 | 選択肢は種類がニュースかイベントのカテゴリ。初期値は開いている記事のカテゴリ（配信記事は購読フィードのカテゴリ）。決まらなければ左のペインの並びで先頭のカテゴリ。名前の記事の一覧では、本文のペインに残っている元の記事で決める（A） | 第1ラウンド Q3 |
| ダイアログで決める項目と、追加したあと | カテゴリと文章だけを決め、ほかは設定の画面と同じ既定値にする。追加したら`追加しました。次の実行で解釈されます。`と知らせ、トピックの編集へ移る操作を知らせに置く。開いている記事と一覧はそのまま残す（A） | 第1ラウンド Q4 |
| 同じカテゴリに同じ文章のトピックがあるとき | ダイアログに`同じ文章のトピックがあります`と出し、そのトピックの編集へのリンクを出す。追加は止めない（A） | 第1ラウンド Q5 |
| Androidアプリ | 今回はWebだけを変える（A） | 第1ラウンド Q6 |
| 実装の計画 | 2026-11-07に承認された計画のとおり（API、サーバー、coreは変えず、今ある `createTopic` と `listTopics` を使う） | 会話中に確認 |
