# Design

## Context

注釈の一覧は、50件ずつ読み込む無限の一覧で、注釈を付けた時刻の新しい順に並ぶ。
注釈を書き換えると、画面は一覧を取り直さずに、サーバーの返した内容をキャッシュの一覧へ書き込む。
記事全体へのメモの保存は、読み込み済みのページにそのメモの行がないと、新しいメモとみなして先頭に入れていた。
サーバーは、記事全体へのメモを書き直しても作成の時刻を保つ。そのため、まだ読み込んでいないページの古いメモは、続きを読み込むと元の位置にも現れ、行が2つになる。

`r` と一覧の更新のボタンは、記事と件数の問い合わせだけを無効にしていた。
購読フィードの登録の解除とカテゴリの削除も、注釈の一覧を無効にしていなかった。

## Goals / Non-Goals

**Goals:**

- 古い記事全体へのメモを書き直しても、注釈の一覧に同じ行が2つ出ないようにする。
- 注釈の画面の `r` で注釈を取り直す。
- 記事が消える削除のあとに、注釈の一覧を取り直す。

**Non-Goals:**

- 開いたままの本文のペインに残る、消えた記事の扱い。
- Androidアプリ。
- 設定ファイルの読み込み。記事を消さない。

## Decisions

### 古いメモの判定

保存の前に、記事のキャッシュにあるメモを控える。`deleteNote` と同じ読み方である。
返ってきたメモが同じIDなら、保存の前からあったメモとみなす。

- 読み込み済みのページに行があれば、いまと同じくその行の内容だけを書き換える。
- 行がなく、保存の前からあったメモなら、先頭に入れない。続きを読み込んだときに、作成の時刻の位置に新しい内容で現れる。
- そのうえで続きのページがもうないときは、一覧がメモより古いので、一覧を無効にして取り直す。
- 保存の前にメモがなかったときは、いまと同じく先頭に入れる。

`createdAt` と `updatedAt` の比較は使わない。作成の直後に書き直すと、同じ時刻になることがあるからである。

### `r` で注釈を取り直す

`refresh` は、注釈の画面のときだけ `["annotations"]` も無効にする。ほかの一覧では、注釈の一覧は表示されていない。
件数の取り直しはいまのまま残す。上部の「読み直す」のボタンは変えない。

### 削除のあとの無効化

`FeedDeletionDialog` で無効にするキーへ `annotations` を足す。左のペインのメニュー、設定の画面、購読フィードの設定のダイアログの3か所が、このダイアログを通る。
カテゴリの削除の `refreshLists` にも `["annotations"]` を足す。

## Risks / Trade-offs

- 記事のキャッシュがない記事のメモを書いた場合は、行を作れないので、いまと同じく一覧を取り直す。要求は1回増えるが、並びは正しい。
- 削除のたびに、表示していない注釈の一覧も無効になる。表示していなければ取り直しは次に開いたときだけなので、要求は増えない。
