# Design

## Context

動機はproposal.mdのWhyにある。左のペインの数は `Shell.tsx` の `ListItem` が出す。`実行履歴` の項目の注意の数は、すでに読み上げ用の「、注意N件」を置き、見える数字に `aria-hidden="true"` を付けている。待ちの文のうち、`読み込み中…` は `controls.tsx` の `Loading` が出す。`試しています…` は `TopicTrial.tsx`、`案を出しています…` は `TopicRewrite.tsx` が出す。OPMLの読み込みの結果は `role="status"` の段落である。

## Goals / Non-Goals

**Goals:**

- 左のペインの数が何を数えるかを、言葉で伝える。
- 待ちの文と、試しと書き直しの案が終わったことを知らせる。

**Non-Goals:**

- 見た目の変更。文の色、並び、余白は変えない。
- Androidアプリの読み上げ。
- 候補や案の一覧を読み上げること。長く、利用者が自分でたどるものだからである。

## Decisions

### 左のペインの数

`ListItem` に、数が何を数えるかを表す引数 `countKind`（`"unread"` か `"starred"`。既定は `"unread"`）を足す。数があるときは、読み上げ用の `<span className="sr-only">、未読N件</span>`（スターは「、スターN件」）と、`aria-hidden="true"` の見える数字を並べる。「、注意N件」と同じ形である。

`NavItem` の `count` は渡している呼び出し元がないので、引数ごと消す。

### `読み込み中…` と設定ファイルの結果

`Loading` の段落と、設定ファイルの読み込みの結果の段落に `role="status"` を付ける。結果の段落は、OPMLの結果と同じく、結果があるときだけ出す。

### 試しと書き直しの案の枠

`role="status"` の枠を、試しを始める前から置いておき、中の文だけを入れ替える。後から現れた枠の中身は、読み上げられないことがあるためである。

- 区画（`section`）は、idleのときは `contents` にして見た目から消す。枠はidleでも同じ位置に描く。Reactが同じ要素を使い続けるようにするためである。
- 枠に文がないとき（idleのときと、`ErrorNotice` を出すとき）は、枠に `sr-only` を付ける。`sr-only` は絶対配置なので、区画の縦の並びに加わらず、余白が増えない。`display: none` にしないのは、隠した枠に後から入った文は読み上げられないことがあるからである。
- 試しの結果では、注記と検索語と判定基準の表を枠の前に、入れ替わりがないことの文と候補の一覧を枠の後ろに置く。いまの並びと同じである。
- 書き直しの案では、「この案を使う」の説明を枠に入れ、案の一覧を枠の後ろに置く。
- `ErrorNotice` は `role="alert"` で読み上げられるので、枠の外に置く。2回読まれるのを避けるためである。

### 文書

`DESIGN.md` の `nav` の項に数の読み方を、Componentsに待ちの文と終わりの1文の知らせを足す。

## Risks / Trade-offs

- `role="status"` が増える。`findByRole("status")` で1つだけを探すテストは、`読み込み中…` が同時に出ていると失敗する。その場合は、区画や文で絞る形に直す。
