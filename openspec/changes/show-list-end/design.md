# Design

## Context

動機は `proposal.md` のWhyに書いた。

- `j` と `Space` の移動は `ReaderPage.tsx` の `move` が担う。最後の行で続きのページがあるときは、`moveOn` が次のページを読み込んでから進む（変更 `keep-narrow-list-place`）。次の行と続きのどちらもないときは、何もせずに戻る。
- 続きの読み込みは「さらに読み込む」のボタンだけである。web-readerの要件「続きの読み込み」は、末尾までのスクロールでの読み込みを求めている。
- 一括の既読のあとに次の項目を開く処理として、`openNext` がある。件数を取り直し、`nextTarget` で次の未読のある項目を決める。
- 画面下部の知らせは1度に1件で、一括の既読の「取り消す」が10秒間使う。
- web-shellの要件「キーボードでの記事の移動」は、まだ本体の仕様に反映していない2つの変更が書き換えている。`keep-narrow-list-place` と `replace-history-on-key-moves` である。

## Goals / Non-Goals

**Goals:**

- 一覧の末尾を、スクロール、キー、読み上げのどの使い方でも伝える。
- スクロールだけで、一覧のすべての記事を表示できるようにする。

**Non-Goals:**

- 末尾の `j` で次の項目へ移ること。末尾で止まる決定（`archive/2026-10-25-add-more-shortcuts/design.md`）は変えない。
- 注釈の一覧とイベントの一覧。別の部品であり、対象にしない。
- `k` で先頭に来たときの知らせ。

## Decisions

### 末尾の表示は一覧に常に置く

続きのページがなく、記事が1件以上あるとき、行の並びの下に、文言 `一覧の最後です` を置く。スクロールで既読にする設定の余白より上である。
画面下部の知らせで出す案は採らない。「取り消す」を押し出すためである（grilling.md）。

未読のある次の項目を開くボタンは、手元の件数で `nextTarget` を引いて、次の項目があるときだけ出す。
押したときは `openNext` を呼ぶ。キーとボタンで別の処理を作らない規則に沿い、一括の既読のあとと同じ処理を使う。
`openNext` は件数を取り直すので、手元の件数が古くて次の項目がもうないときは、何も開かない。取り直した件数でボタンは消える。
通信に失敗したときは、開けなかったことを画面下部の知らせで伝える。

### 末尾での `j` と `Space`

`move` は、進む向きで次の行も続きのページもないとき、末尾の表示が見える位置まで一覧を送る。
送る位置は、行の追従と同じ `followScroll` で決める。下端に合わせる向きで使う。
狭い画面で本文を表示しているときは一覧が見えないので、本文のペインを、本文の末尾の表示まで送る。

読み上げには、見えない `aria-live` の領域で伝える。押すたびに中の要素を入れ替え、同じ文でも繰り返し読ませる。
フォーカスは動かさない。記事や一覧が変わったら、領域を空に戻す。
画面下部の知らせと同じ `role="status"` は付けない。画面下部の知らせを役割で探す既存のテストと区別するためである。

### 狭い画面の本文の末尾

`ArticleNeighbors` に、末尾であることを表す `end` を足す。中身は次の項目を開く関数で、次の項目がなければnullである。
`NeighborLinks` は、次の記事も続きのページもなく `end` があるとき、「次の記事」の位置に文とボタンを出す。

### 見張りによる自動の読み込み

続きのページがある間、行の並びの下に見張りの要素を置く。`IntersectionObserver` で、一覧のスクロール領域に入ったかどうかを状態として持つ。
読み込むのは、次の条件がそろったときである。見張りが見えている。続きがある。読み込み中でない。直前の続きの読み込みが失敗していない。

ページが届くと見張りの位置は変わるので、届くたびに見張りを見直す。「見えている」という状態は、それを見たときの一覧とページ数に結び付けて持つ。
ページが届く前の「見えている」を使い回すと、1度のスクロールで2ページを読み込んでしまう。ブラウザーでの確認で見つけた。
見直しても見張りが見えたままのとき、つまり1ページが画面より短いときは、次のページを続けて読み込む。

失敗のあとは自動で繰り返さない。スクロールのたびに要求が出るのを避けるためである。
「さらに読み込む」のボタンは残し、失敗の文をその上に出す。押して読み込めれば、自動の読み込みも元に戻る。
読み込み中のボタンは押せない状態にし、文言を `読み込んでいます` に替える。

スクロールのイベントで位置を計算する案は採らない。見張りのほうが、スクロールで既読にする余白や一覧の高さの変化を自分で計算せずに済む。

### 続きの読み込みが失敗したときの `j`

`moveOn` は、読み込んだ結果の最後のページの先頭を開く。読み込みが失敗すると、最後のページは今のページのままなので、その先頭へ戻ってしまう。
ページが増えたときだけ進むようにする。自動の読み込みで失敗の場面が増えるので、あわせて直す。

### テストでの交差

jsdomには配置がないので、`testing/setup.ts` の `IntersectionObserver` の代用品を、テストから交差を起こせるものに替える。
ブラウザーと同じく、見張りを始めた時点で対象が見えていれば、そのことを伝える。

## Risks / Trade-offs

- 末尾の表示まで一覧を送ると、スクロールで既読にする設定では、上端を越えた行が既読になる → 行の追従のスクロールでも同じであり、既存の振る舞いに合わせる。
- 古い件数のせいで、次の項目がないのにボタンを出すことがある → 押したときに件数を取り直し、何も開かずにボタンが消える。
- 定期の読み直しの最中は、自動の読み込みを待つ → 読み直しが終わると、状態の変化で読み込む。
