# grilling 記録: show-list-end

Issue #108（50件目で `j` と `Space` が止まる件）で、計画についての質問に答えてもらった。
Issueの改善案のうち、最後の行の `j` と `Space` が次のページを読み込むことは、変更 `keep-narrow-list-place` ですでに入っている。
この変更は、残りの2つを扱う。本当の末尾の知らせと、スクロールでの続きの読み込みである。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 本当の末尾の知らせ方 | A：一覧の最後の行の下に、文と操作を常に置く。末尾で `j` を押すとそこまで一覧を送り、読み上げにも伝える。狭い画面では本文の末尾にも置く | Issue #108 第1ラウンド Q1 |
| スクロールでの続きの読み込み | A：末尾が見えたら自動で読み込む。読み込みに失敗したときのために、ボタンは再試行として残す。仕様の本文は変えない | Issue #108 第1ラウンド Q2 |
| 計画の承認 | 上の2つの答えに沿った計画を承認 | Issue #108への返答（`/ok`） |

## 選ばなかった案

- 末尾の知らせを画面下部の知らせで出す案。画面下部の知らせは1度に1件で、一括の既読の「取り消す」を押し出す
- 一覧の末尾と画面下部の知らせの両方に出す案。同じことを2か所で伝え、その欠点も残る
- 実装をボタンのままにして、仕様をボタン式に書き換える案。スクロールのたびにボタンを押す操作が残る

## 前提にした既存の決定

- 末尾で `j` を押しても、次の項目へは移らない（`openspec/changes/archive/2026-10-25-add-more-shortcuts/design.md`）
- キーとボタンで別の処理を作らない（同上）。次の項目へ移る操作は、一括の既読のあとと同じ処理を使う

frontierは空。共有理解に到達した。利用者はQ1とQ2に答え、続く計画を承認した。
