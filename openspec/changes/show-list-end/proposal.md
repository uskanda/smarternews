# Proposal

## Why

記事の一覧の本当の末尾で `j` や `Space` を押しても、画面は何も示さない。キーの入力が届いていないのか、読み終えたのかを区別できない。
また、仕様は末尾までのスクロールで続きを読み込むことを求めているが、画面は「さらに読み込む」のボタンを押すまで読み込まない（Issue #108）。

## What Changes

- 続きのない一覧の最後の行の下に、文言 `一覧の最後です` を置く。未読のある次の項目があるときは、そこへ移るボタンを並べる。
- 続きのない最後の記事で `j` や `Space` を押したとき、この表示まで一覧を送り、読み上げにも伝える。選んでいる記事は変えない。
- 狭い画面では、最後の記事の本文の末尾にも同じ文とボタンを置く。
- 一覧の末尾が表示範囲に入ったら、続きのページを自動で読み込む。「さらに読み込む」のボタンは、読み込みに失敗したときの再試行として残す。
- Androidアプリとサーバーには手を入れない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `web-reader`：一覧の末尾の表示の要件を足す。続きの読み込みの要件に、読み込みに失敗したときのシナリオを足す。

## Impact

- `apps/web/src/reader/ReaderPage.tsx`：末尾の表示、末尾での `j` と `Space`、末尾の見張りによる自動の読み込み
- `apps/web/src/reader/ArticleView.tsx`：狭い画面の本文の末尾の表示
- `apps/web/src/testing/setup.ts`：テストから交差を起こせる `IntersectionObserver` の代用品
- APIとサーバー：変えない
