# grilling 記録: add-content-selector

Issue #220「全文の取り出しを、購読フィードごとに直す」の計画の記録である。
計画の段階で、Issueに4つの問いを出した。利用者は、Q1だけを推奨と違う案で答え、残りは推奨どおりに答えた。
その答えに沿った計画を、利用者は直しの指示なしで承認した。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| セレクターに当たる要素がないページ | Readabilityの結果に戻す。失敗にはしない | 第1ラウンド Q1（B。推奨はA：既存の理由 `no-content` で失敗にする案） |
| 本文のセレクターを変えたときの保存済みの全文 | その購読フィードの未読の記事だけ、全文と失敗の記録を消して取得し直せるようにする。既読の記事は保存済みのまま残す | 第1ラウンド Q2（A） |
| 自動の要約が自分でページを読むときの取り出し | 要約の入力も、本文のセレクターで取り出す | 第1ラウンド Q3（A） |
| セレクターが複数の要素に当たるとき | 最初の要素だけを本文にする | 第1ラウンド Q4（A） |
| 設定する場所 | Webの設定の、購読フィードの編集のフォームだけ。3つの切り替えだけのダイアログとアプリには足さない | 第1ラウンドの前提（問いにしなかった点。計画の承認で確定） |
| 見本の出し方 | ボタンで試す。そのフィードのURLのある最新の記事1件のページを取得し、何も保存しない | 第1ラウンドの前提（同上） |
| 配信された内容より短いときの失敗（`shorter`） | セレクターを指定したときも残す | 第1ラウンドの前提（同上） |
| 設定ファイル | 指定があるときだけ書く。移行は `feeds` の表に列を1つ足すだけ | 第1ラウンドの前提（同上） |
| 生成記事の処理 | 変えない | 第1ラウンドの前提（同上） |
| LLMの呼び出し | 呼ばない | Issue #220の本文 |
| 計画の承認 | 上の判断に沿った計画を、変更なしで承認 | Issue #220への返答（`/ok`） |

## 後回しにしたもの

- 記事ごとに全文を取得し直す操作。Q2のDとして示したが、WebとアプリにUIが増え、規模がMを超えるため採らなかった
- 失敗の理由に、セレクターが当たらなかったことを示す新しい種類を足すこと。`articles` の表の作り直しが要るため採らなかった（Q1のC）
- アプリ（`apps/mobile`）での本文のセレクターの設定
