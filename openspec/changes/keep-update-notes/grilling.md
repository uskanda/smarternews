# grilling 記録: keep-update-notes

GitHubのissueの231番のコメントで、1ラウンドの質問（Q1〜Q5）に答えた記録である。
issueは、2026-11-13のWeb UIの監査の項目F-09である。書き直しは今回加わったことの文を上書きするので、利用者が読んだあとに2回書き直されると、1回目の文は消える。「新しい出典」の印は2回分に付くが、文は最後の1回分しか出ない。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 文のない書き直しの扱い | 表には文のある回だけを残す。前回読んでからの文はすべて出す。最新の回に文がなくても、前の回の文を「前回読んでから加わったこと」として時刻付きで出す（A） | 第1ラウンド Q1 |
| 一度も読まれていない記事 | 今のまま、最新の書き直し1回分の文だけを「今回の更新で加わったこと」として出す（A） | 第1ラウンド Q2 |
| 新しい表と今の列 | `articles.update_note`列は残し、書き直しのたびに今と同じく更新する。新しい表には文のある回を足し、今ある`update_note`は`updated_at`を時刻にして新しい表へ写す（A） | 第1ラウンド Q3 |
| APIでの渡し方と並べ方 | 記事の詳細に、前回読んでからの文と時刻を古い順で足す。どの文を返すかはサーバーで決める。画面は2件以上のとき「前回読んでから加わったこと」の見出しで時刻付きで並べ、1件のときは今の見出しのまま出す（A） | 第1ラウンド Q4 |
| 変更の範囲 | サーバー（保存とAPI）とWebの本文の画面だけを変える。AndroidアプリとRSSには触れない（A） | 第1ラウンド Q5 |

## 計画で決めたこと

承認を求めた計画（issueのコメント）で、次を決めた。利用者は変更なしで承認した。

| 決定 | 選択 |
|---|---|
| 新しい表 | `article_update_notes`（`id`、`article_id`、`note`、`created_at`）を032のmigrationで作る。記事を消すと行も消える |
| 返す文の基準 | 前回読んだ時刻があれば、その時刻より後の文をすべて返す。「新しい出典」と同じ基準にする。なければ、最新の書き直しの時刻の文だけを返す |
| 1件だが最新の回のものでないとき | 最新の回に文がなかった場合である。「前回読んでから加わったこと」の見出しで、時刻付きで並べる形で出す |
| 時刻の書式 | 同じ日に2回書き直されることがあるので、日付だけでなく時刻まで出す |
