# Spec Delta

## MODIFIED Requirements

### Requirement: 購読フィードの編集

購読フィードの変更を受けたとき、サーバーは、名前、属するカテゴリ、取得周期、有効と無効の別を保存しなければならない（MUST）。
変更がURLを含み、それが今のURLと違うときは、「購読フィードのURLの変更」に従う。

#### Scenario: 名前を付け直す

- **WHEN** 購読フィードの名前を書き換え、そのあとフィードのタイトルが変わる
- **THEN** 購読フィードの名前は、利用者が書いたもののままである

### Requirement: 取得の状況の記録

購読フィードの取得が終わったとき、サーバーは、取得の時刻、成功した時刻、失敗した場合の理由を、その購読フィードに保存しなければならない（MUST）。
恒久的な転送でURLを書き換えたときは、書き換える前のURLと書き換えた時刻も保存する。この記録は、次にURLが変わるまで残す。

#### Scenario: 応答しないフィード

- **WHEN** 購読フィードが時間内に応答しない
- **THEN** その購読フィードから、最後の取得の時刻と、時間内に応答しなかったという理由を読み出せる

#### Scenario: 失敗のあとに成功する

- **WHEN** 失敗が記録された購読フィードの次の取得が成功する
- **THEN** 失敗の理由は消え、最後に成功した時刻が更新される

#### Scenario: 転送でURLを書き換えた

- **WHEN** 購読フィードのURLが恒久的な転送で書き換わる
- **THEN** その購読フィードから、書き換える前のURLと書き換えた時刻を読み出せる

## ADDED Requirements

### Requirement: 購読フィードのURLの変更

購読フィードの変更が今と違うURLを含むとき、サーバーは、登録と同じ検査をしなければならない（MUST）。
検査は、URLの正規化、登録済みのURLの拒否、そのURLを取得してフィードとして読めること、Webページの購読フィードではセレクターで記事を1つ以上取り出せることである。
検査に通ったら、サーバーは、URLとほかの変更を保存し、取得した項目を配信記事として保存する。あわせて、条件付きの取得の値、失敗の記録、配信終了の記録、転送の数、転送による書き換えの記録を消す。
検査に通らなければ、サーバーは何も保存せず、URLの欄のエラーとして理由を返す。
配信記事は今までどおり購読フィードと項目の識別子で見分けるので、URLを変えた後も、保存済みの配信記事、スター、注釈、既読は残る。

#### Scenario: httpsのURLに変える

- **WHEN** スターと注釈のある配信記事を持つ購読フィードのURLを、同じ項目を配るhttpsのURLに変える
- **THEN** 購読フィードのURLは新しいURLになり、配信記事は増えず、スター、注釈、既読はそのまま残る

#### Scenario: フィードでないURLに変える

- **WHEN** 購読フィードのURLを、フィードの指定を持たないHTMLのページのURLに変え、名前も一緒に変える
- **THEN** サーバーは変更を拒否し、URLの欄のエラーとして理由を返し、URLも名前も変わらない

#### Scenario: 登録済みのURLに変える

- **WHEN** 購読フィードのURLを、ほかの購読フィードのURLに変える
- **THEN** サーバーは変更を拒否し、登録済みであることを返す

#### Scenario: 失敗の記録が消える

- **WHEN** 取得に失敗し続けている購読フィードのURLを、フィードを返すURLに変える
- **THEN** 失敗の理由と失敗の回数は消え、新しいURLにはETagとLast-Modifiedを送らずに次の取得をする

### Requirement: 恒久的な転送によるURLの書き換え

購読フィードの取得が恒久的な転送を受けて成功したとき、サーバーは、同じ行き先への転送を数え、続けて3回の取得で起きたら、購読フィードのURLを行き先に書き換えなければならない（MUST）。
行き先は、最初の要求から続く301と308の転送の最後の行き先とする。302、303、307の転送が挟まったら、その手前の行き先とする。
転送のない成功した取得では、数を0に戻す。行き先が数えている行き先と違うときは、新しい行き先で1から数え直す。
失敗した取得では、数を変えない。
行き先が、ほかの購読フィードとして登録済みのときは、書き換えず、数えない。
304の応答も成功した取得として数える。Webページの購読フィードは、セレクターで記事を取り出せた取得だけを数える。
書き換えは、項目の保存と同じトランザクションで行い、LLMは呼ばない。

#### Scenario: 3回続けて転送される

- **WHEN** 購読フィードの取得が、同じhttpsのURLへの301を受けて、3回続けて成功する
- **THEN** 3回目の取得のあと、購読フィードのURLはそのhttpsのURLになり、書き換える前のURLと時刻が記録される

#### Scenario: 2回で転送が止まる

- **WHEN** 購読フィードの取得が、301を受けて2回成功し、3回目は転送なしで成功する
- **THEN** 購読フィードのURLは変わらず、転送の数は0に戻る

#### Scenario: 一時的な転送が挟まる

- **WHEN** 購読フィードの取得が、301のあとに302を受ける転送で、3回続けて成功する
- **THEN** 購読フィードのURLは、302の手前の301の行き先になる

#### Scenario: 一時的な転送だけ

- **WHEN** 購読フィードの取得が、302を受けて3回続けて成功する
- **THEN** 購読フィードのURLは変わらない

#### Scenario: 失敗が挟まる

- **WHEN** 購読フィードの取得が、301を受けて2回成功し、次に失敗し、そのあと301を受けて1回成功する
- **THEN** 最後の取得のあと、購読フィードのURLは行き先に書き換わる

#### Scenario: 行き先が登録済み

- **WHEN** 購読フィードの取得が、ほかの購読フィードとして登録済みのURLへの301を受けて、3回続けて成功する
- **THEN** 購読フィードのURLは変わらず、取得は成功として記録される

#### Scenario: Webページの購読フィードで記事が見つからない

- **WHEN** Webページの購読フィードの取得が、301の行き先のページでセレクターが記事を取り出せずに終わる
- **THEN** その取得は転送の数に入らない
