# Proposal

## Why

Webのイベントの一覧には、記事の一覧にある表示と操作が欠けている（Issue #187）。
終了していないイベントが51件以上あると開催の近い50件だけが出て、切れていることが分からない。読み込み中も取得に失敗したときも「これから開催されるイベントはありません。」と出て、再試行の手段がない。「読み直す」と「すべて既読にする」もなく、`Shift+A` も働かないので、未読を0にするには1件ずつ開くことになる。
また、APIの一括の既読は終了したイベントも既読にするので、既読にした件数が一覧の未読と合わないことがある。

## What Changes

- Webのイベントの一覧に、記事の一覧と同じ読み込み中の表示、失敗の理由と再試行のボタン、「さらに読み込む」を出す。空の文は取得に成功したときだけ出す。
- 一覧の上部に「すべて既読にする」と「読み直す」を置き、`Shift+A` を働かせる。範囲はカテゴリで、取り消しと次の項目へ移る設定の扱いは記事の一覧と同じにする。「既読も表示」、重要度の絞り込み、並び順のメニューは出さない。
- APIの一括の既読は、終了したイベントを既読にしない。「未読」「すべて」など、どの一覧での一括の既読にも効く。
- Androidアプリの画面は変えない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `web-reader`：「イベントの一覧」の要件に、読み込み中、失敗と再試行、続きの読み込み、上部の操作を足す。
- `web-shell`：「キーボードでの一括の既読」のシナリオで、一括の既読を選べない一覧の例を最近読んだ記事の一覧に替え、イベントのカテゴリで `Shift+A` が働くシナリオを足す。
- `http-api`：「一括の既読」の要件に、終了したイベントを既読にしないことを足す。

## Impact

- `packages/core/src/db/articles.ts`：`markArticlesRead` の条件
- `docs/api.md`：`mark-read` の説明
- `apps/web/src/reader/EventList.tsx`、`apps/web/src/reader/ReaderPage.tsx`：イベントの一覧の表示と操作
- Androidアプリ：画面は変えない。一括の既読の件数は、終了したイベントを含まなくなる
- LLMは呼ばない
