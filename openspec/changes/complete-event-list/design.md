# Design

## Context

Webの一覧は `apps/web/src/reader/ReaderPage.tsx` が1つのページとして描く。
記事の一覧は、上部のボタン、読み込み中、失敗、「さらに読み込む」をこのページの中に持つ。イベントの一覧は `EventList.tsx` に分かれており、渡されたイベントを日ごとに描くだけである。
一覧の取得、続きの読み込み、`refresh`、`markAllRead` は、イベントのカテゴリでもすでに同じものが動いている。一覧はイベントについて `kind=event` を指定して取る。
一括の既読を出すかどうかは `canMarkAll` が決め、「未読」と「既読も表示」の切り替えのある一覧だけを通す。イベントの一覧にはこの切り替えがないので、ボタンも `Shift+A` もない。
サーバーの一覧と未読数は、終了したイベントを `(kind <> 'event' OR event_ends_at >= now)` で除く。`markArticlesRead` にはこの条件がない。

## Goals / Non-Goals

**Goals:**

- イベントの一覧の表示と操作を、記事の一覧と同じ部品と同じ処理でそろえる。
- 一括の既読の件数と取り消しの範囲を、画面に見えている未読と合わせる。

**Non-Goals:**

- Androidアプリの画面の変更。
- イベントの一覧の「既読も表示」、重要度の絞り込み、並び順のメニュー。

## Decisions

### 状態と操作は `ReaderPage` から渡す

`EventList` は取得をしない。`ReaderPage` が、上部のボタン（`actions`）、取得の状態（読み込み中、失敗とその理由、再試行）、続きの有無と続きを読み込む関数を渡す。
`EventList` で一覧を取り直す案もあったが、`Shift+A`、`j` での続きの読み込み、読んだ行を一覧に残す処理はページの側にあり、二重に持つことになる。

表示には記事の一覧と同じ `Loading`、`ErrorNotice`、`Button` を使う。上部は記事の一覧と同じく、見出しの右に「すべて既読にする」「読み直す」の順で並べる。

### `canMarkAll` にイベントのカテゴリを足す

条件を `view === "unread" || readToggle || isEvents` にする。未読のイベントが読み込んだ中にあるか、続きがあるときだけ通す点は変えない。
`markAllRead` はそのまま使う。範囲は `targetScope` でカテゴリになり、取り消しのトーストと次の項目へ移る設定もそのまま効く。

### 重要度の下限を送らない

`importantOnly` は、URLに `min=4` があると一括の既読に `minImportance: 4` を付ける。イベントの一覧では切り替えを出さないので、`!isEvents` を条件に足し、URLに残っていても送らない。

### 終了したイベントはサーバーで除く

`markArticlesRead` の条件に `(kind <> 'event' OR event_ends_at >= ?)` を足し、既読にする時刻 `now` を渡す。一覧と未読数と同じ形である。
画面の側で除く案は、範囲で既読にするAPIでは識別子を選べないため採らない。
これにより「未読」「すべて」などでの一括の既読でも、終了した未読のイベントは既読にならない。どの一覧にも未読数にも出ないものなので、利用者に見える変化は件数が合うことだけである。

## Risks / Trade-offs

- [終了した未読のイベントが既読にならずに残る] → どの一覧にも未読数にも出ないので、利用者には見えない。`includeEnded=true` の一覧では未読のまま出る。
- [Androidアプリの一括の既読の件数が変わる] → アプリの画面は変えないが、「未読」などでの件数は終了したイベントの分だけ減る。一覧の未読と合う方向の変化である。
