# grilling 記録: move-article-topics-down

Issue #202「本文の上部にトピックの区画があり、スターと既読の操作は末尾にしかない」の計画の記録である。
計画の段階で2つの質問を出し、利用者が答えた。そのあと、答えに沿った計画を利用者が変更なしで承認した。
計画で「前提にした決定」として並べたものも、この承認で確定した。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 末尾のスターと既読のボタンの扱い | 末尾にも残す。スターと既読は上部と末尾の両方から操作でき、末尾の並びは今のまま（スター、既読、外れの印）にする | Issue #202の計画の質問Q1（A） |
| 上部の小さなボタンの形 | 文字の小さなボタン。`label-sm` の文字の枠つきボタンを `DESIGN.md` に `button-small` として足す。「スターを付ける」「未読に戻す」のように書き、星の印は今のまま残す | Issue #202の計画の質問Q2（A） |
| トピックの区画の位置 | 出典の区画の下、末尾のボタンの並びの前。見出し、リンク、2行で切る表示、出さない条件は変えない | Issue #202の本文と計画の前提（`/ok` で承認） |
| 外れの印のボタン | 上部には置かず、末尾だけに残す。Issueが挙げているのはスターと既読だけである | Issue #202の計画の前提（`/ok` で承認） |
| 同じ名前のボタンの区別 | 末尾の並びを読み上げ名「記事の操作」のグループにする。名前でボタンを探す既存のテストは、どちらの並びかを指定するよう書き換え、意味は変えない | Issue #202の計画（`/ok` で承認） |
| 対象とする画面 | Webだけ。Androidアプリは上部にすでにアイコンのボタンがあり、トピックの区画もない | Issue #202の計画の前提（`/ok` で承認） |
| キーの操作 | 変えない | Issue #202の計画の前提（`/ok` で承認） |
| 元の要件の扱い | `link-topics-to-editor` の要件「当てはまったトピックの表示」をMODIFIEDで改める。`openspec archive` は `link-topics-to-editor` を先に行う | Issue #202の計画（`/ok` で承認） |
| 計画の承認 | 上の決定に沿った計画を、変更なしで承認 | Issue #202への返答（`/ok`） |
