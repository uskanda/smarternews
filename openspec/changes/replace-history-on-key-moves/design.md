# Design

## Context

動機は proposal.md の Why を参照する。
記事の一覧と注釈の一覧は、キーで移るたびに、開く記事のパスへ遷移する。遷移は履歴を足すので、移った回数だけ履歴が増える。
本文の端での `Space`・`Shift+Space` も、`j`・`k` と同じ移動の処理を通る。

## Goals / Non-Goals

**Goals:**
- キーで続けて記事を移っても、戻る操作1回で、記事を開く前の一覧へ戻れるようにする。

**Non-Goals:**
- 行を押したときとリンクでの移動の履歴は変えない（grilling.md の Q1）。

## Decisions

- **置き換えるかどうかは、記事が開いているかどうかで決める。** 記事の一覧では記事のIDがあるかどうか、注釈の一覧では選んだ注釈があるかどうかを見る。
  - 代わりに、一覧での位置が見つからないときに足す案を考えた。採らなかった。絞り込みで一覧から外れた記事を開いているときも、位置が見つからない。この場合は記事が開いているので、置き換えるのが正しい。
- **キーでの移動の処理1か所で決める。** `Space` も同じ処理を通るので、別に直す必要はない。
- **テストはブラウザーの履歴で描く。** テストの描画の道具に、メモリー上の履歴の代わりにブラウザーの履歴を使うオプションを足す。戻る操作で、どの記録へ戻るかを確かめるためである。

## Risks / Trade-offs

- [記事を開いたまま行を押すと、これまでどおり履歴が増える] → 行を押すのは読み手が選んだ1回の操作であり、キーのように積み上がりにくい。Q1 で受け入れた。
