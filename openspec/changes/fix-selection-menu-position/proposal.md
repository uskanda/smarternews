# Proposal

## Why

本文で行の右のほうの語を選ぶと、文字を選んだときのメニューが画面の外へはみ出す。
幅390pxの画面では、配信記事の右端の語を選ぶとメニューが69pxはみ出した。画面の下端にかかる文でも同じである。
また、文字を選んだあとに本文をスクロールしても、メニューは元の位置に残る。
位置は選択が変わったときだけ測り、右端と下端を確かめていないためである。2026-11-13のWeb UIの監査（U-06）で見つけ、#199として起票した。

## What Changes

- メニューが画面の右端からはみ出すときは、はみ出す分だけ左へずらす。
- メニューが画面の下端からはみ出すときは、選んだ範囲の上に出す。
- メニューの幅は画面の幅までにし、入りきらないボタンは折り返す。
- 本文のペインをスクロールしたときと、画面の大きさが変わったときも、位置を測り直す。
- 選んだ範囲が本文のペインの見える部分と少しも重ならなくなったら、メニューを隠す。範囲が戻ってきたら、また出す。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `web-reader`：「文字を選んだときのメニュー」に、画面の中に収めること、スクロールに付いていくこと、範囲が見えないときは隠すことを足す

## Impact

- `apps/web/src/reader/Annotations.tsx`: メニューの位置を決める関数を分け、スクロールと画面の大きさの変化で範囲の矩形を測り直す。範囲がペインの外にあるときはメニューを描かない。
- `apps/web/src/styles/app.css`: `.selection-menu` に折り返しと最大幅を足す。
- 右クリックとキーボードで開くメニューは変えない。キーボードで開くときは、測り直した位置を使う。
- サーバー、API、Androidアプリに変更はない。
