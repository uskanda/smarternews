# Proposal

## Why

購読フィードの設定の一覧は、最後に成功した時刻と失敗の理由しか出さない。取得には成功するのに新しい項目が届かなくなった購読フィードを、見分けられない。
また、購読フィードごとの数字（届いた数、読んだ数、隠した数）が分からない。購読を続けるかを、数字で判断できない（#64）。

## What Changes

- サーバーは、フィードに新しい項目が現れた最後の時刻を、購読フィードごとに記録する。古い項目の除外で保存しなかった項目も、新しい項目として数える。書き換えられた既知の項目は数えない。
- 有効な購読フィードで、最後に新しい項目が現れてから決まった日数が過ぎたとき、その購読フィードを「更新の止まった購読フィード」とみなす。日数は全体設定に持ち、既定は60日とする。自動では無効にしない。
- サーバーは、記事の本文を初めて表示した時刻を、開いた時刻として記事ごとに記録する。既読の時刻（#51）とは別に持ち、未読に戻しても消さない。一括の既読やスクロールで既読にする操作（#50）は、開いたことにならない。
- APIは、記事を開いたことを記録する操作と、購読フィードごとの直近30日の統計を提供する。統計は、届いた記事、開いた記事、スターを付けた記事、フィルターで隠した記事、重複の除去で隠した記事の数と、最後に新しい項目が現れた時刻である。
- 購読フィードの一覧のAPIは、更新が止まっているかどうか、直近30日に届いた記事の数、最後に新しい項目が現れた時刻を返す。
- Webの購読フィードの設定の一覧は、更新の止まった購読フィードに印を付け、届いた記事の数と最後に新しい項目が現れた日時を出す。止まった購読フィードと失敗している購読フィードを先頭へ並べる切り替えを置く。
- 購読フィードの編集の画面に統計の区画を置き、開いた記事とスターを付けた記事は、届いた記事に対する割合も出す。
- 全体設定の画面で、更新が止まったとみなす日数を変えられるようにする。設定ファイルの書き出しと読み込みも、この日数を扱う。
- Webの画面とアプリは、記事の本文を表示したときに、開いたことを記録する。アプリには統計と印を出さない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `feed-subscriptions`: 新しい項目が現れた時刻の記録、更新の止まった購読フィードの判定、止まっても無効にしないことを足す
- `settings`: 更新が止まったとみなす日数の保持と、設定ファイルでの扱いを足す
- `http-api`: 開いた時刻の記録と提供、記事を開いたことを記録する操作、購読フィードの一覧の項目、購読フィードの統計、日数の設定の提供を足す
- `web-settings`: 更新の止まった印、一覧の数字、問題のある購読フィードを先頭へ並べる切り替え、統計の区画、日数の編集を足す。設定の画面での並び順に、この切り替えの例外を足す
- `web-reader`: 本文を表示したときに開いたことを記録することを足す
- `mobile-reader`: 本文の画面で記事を表示したときに開いたことを記録することを足す

## Impact

- `packages/core`: 移行で3つの列を足す。記事の表の開いた時刻、購読フィードの表の最後に新しい項目が現れた時刻、全体設定の表の日数である。取得の処理で新しい項目を見分けて時刻を書く。統計の問い合わせを足す。
- `apps/server`: 記事を開いたことを記録する操作と、購読フィードの統計の操作を足す。
- `packages/client`: 2つの操作の呼び出しと、型を足す。
- `apps/web`: 購読フィードの設定の一覧と編集の画面、全体設定の画面、本文のペインを変える。
- `apps/mobile`: 本文の画面で、開いたことを記録する。
- `docs/api.md`: 操作、応答の項目、全体設定の項目を足す。
- LLMは呼ばない。翻訳のAPIも呼ばない。統計と判定は、保存済みの値からプログラムで数える。
- 開いた時刻は、関連度での並び（#60）でも使う見込みである。
