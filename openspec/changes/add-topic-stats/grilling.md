# grilling 記録: add-topic-stats

GitHubのissueの138番のコメントで、2ラウンドの質問（Q1〜Q6、Q7〜Q12）に答えた記録である。
issueは、トピックごとに直近30日の成績を出し、「問題のあるトピックを先頭へ」の切り替えを置く提案である。成績には、集めた候補と除外の数、作った記事とその行方、よく除外されるサイトを含める。

第1ラウンド（Q1〜Q6）は、#137（外れの印）がマージされる前に出した。利用者は「#137がマージされたので、それを踏まえて再度検討して」と答えたため、第1ラウンドの問いには回答がない。第2ラウンド（Q7〜Q12）は、#137 の misses と miss_topics の表を踏まえて同じ論点を問い直したもので、第1ラウンドの問いを置き換える。

## 計画で決めたこと

承認を求めた計画（issueのコメント）で、次を決めた。利用者は変更なしで承認した。

| 決定 | 選択 |
|---|---|
| LLM | 呼ばない。記事の数は、すべて生成記事（`origin = 'generated'`）に限って数える |
| 理由の種類の値 | `no-date`、`below-minimum`、`over-limit`、`event-outside-window`、`event-no-date` と、判定（モデル）による除外の NULL。文と種類の対応は reasons.ts の1か所に置く |
| 成績の項目 | 集めた候補（全体と取得元ごと）、判定での除外、基準未満、件数上限、日付で外れた数（日付による3種類の合計）、作った記事、更新した記事、開いた記事、スター、外れ、よく除外されるサイト |
| 更新した記事 | 版が1以上で、更新の時刻が期間内の生成記事 |
| 開いた記事、スター、外れ | 期間内に作った記事のうち、開いた時刻がある記事、今スターがある記事、このトピックの外れの印がある記事 |
| API | `GET /api/v1/categories/:id/topic-stats`。応答は期間の始まりと、トピックごとの項目の配列。存在しないカテゴリは404 |
| 並べ替えの切り替え | 外したときはトピックのIDの順、入れたときは上の並べ方。外れの割合は記事が0件なら0とし、最後はIDの順 |
| 行の印 | 各行に `id="topic-stats-<id>"` を付け、実行の詳細からのリンクは `/settings/categories/:id#topic-stats-<id>` にする |
| 変えないこと | Androidアプリ（トピックの設定の画面がない）、日ごとの集計の表、#137 の「解釈し直す」の文とボタン |
