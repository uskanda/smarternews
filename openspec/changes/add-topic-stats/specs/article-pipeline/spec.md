# Spec Delta

## ADDED Requirements

### Requirement: 除外の理由の種類の記録

プログラムが候補を除外したとき、クローラーは、除外の理由の文とともに理由の種類を保存しなければならない（MUST）。理由の種類は次の5つのいずれかとする。

- `no-date`：公開日時が不明
- `below-minimum`：重要度が基準未満
- `over-limit`：件数上限
- `event-outside-window`：開催日が対象期間の外
- `event-no-date`：開催日を確認できない

#### Scenario: 基準未満で除外した候補

- **WHEN** 最低重要度3のカテゴリで、重要度2の話題の候補を除外する
- **THEN** その候補は、理由の文「重要度が基準未満」と理由の種類 `below-minimum` とともに保存される

#### Scenario: 公開日時がない候補

- **WHEN** 公開日時のないニュースの候補を、判定の前に除外する
- **THEN** その候補は、理由の種類 `no-date` とともに保存される

#### Scenario: 開催日が対象期間の外のイベント

- **WHEN** 開催日が対象期間の外にあるイベントの候補を除外する
- **THEN** その候補は、理由の種類 `event-outside-window` とともに保存される

### Requirement: 判定による除外の理由の種類

判定のタスクが候補を関連なしとしたとき、クローラーは、その候補に理由の種類を保存してはならない（MUST NOT）。

#### Scenario: 関連がないと判定された候補

- **WHEN** 判定のタスクが、ある候補を理由「製品の宣伝で新しい情報がない」で関連なしとする
- **THEN** その候補は理由の文とともに保存され、理由の種類を持たない

### Requirement: 移行より前の候補の理由の種類

理由の種類を足す移行のとき、サーバーは、除外された候補のうち、理由の文がプログラムの日本語または英語の理由の文と一致するものに、その理由の種類を入れなければならない（MUST）。一致しない候補は、理由の種類を持たないままにする。

#### Scenario: 英語で書かれた件数上限の理由

- **WHEN** 移行より前に、理由の文「over the article limit of the run」で除外された候補がある状態で移行する
- **THEN** その候補の理由の種類は `over-limit` になる

#### Scenario: 判定の理由

- **WHEN** 移行より前に、理由の文「advertising」で除外された候補がある状態で移行する
- **THEN** その候補は理由の種類を持たない
