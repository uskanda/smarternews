# Tasks

どの作業も、失敗するテストを先に書いてから実装する。テストはLLMと外部のサイトを呼ばず、記録済みのフィードと差し替えた取得元で動かす。

## 1. 判定に使う値と設定（packages/core）

- [x] 1.1 `normalizeUrl` の隣に、タイトルの正規化の関数を足す。全角と半角、大文字と小文字、空白、記号の違いを無視し、10文字未満なら値なしを返すことを、先に書いた単体テストで確かめる
- [x] 1.2 `packages/core` に移行を足す。`articles` に `dedup_url`、`dedup_title`、`duplicate_of` と2つの索引を、`settings` に重複の除去の列（既定値1）を足す。番号は空いている次の番号にする。記事のある古いデータベースに当てて、既存の配信記事の値が空のままであることを `database.test.ts` で確かめる
- [x] 1.3 `articles` の削除のあとに動くトリガーを、同じ移行で作る。残した記事を消したとき、最も先に保存した重複を新しく残す記事にする。購読フィードの削除（外部キーの連鎖）と、保存期間での削除の両方で記録し直されることをテストで確かめる
- [x] 1.4 `api.ts` の全体設定のスキーマと保存に、重複の除去の真偽値を足す。初回の既定値が有効であること、無効が再起動で保たれること、更新した既存のデータベースで有効になることを `settings.test.ts` で確かめる
- [x] 1.5 `settings-file.ts` の書き出しと読み込みに、重複の除去の設定を足す。往復と、設定がないファイルで値が変わらないことを `settings-file.test.ts` で確かめる。`examples/settings.example.yaml` に例を足す

## 2. 保存のときの判定（packages/core）

- [x] 2.1 `storeItems` で、新しい配信記事に `dedup_url` と `dedup_title` を保存し、書き換えられた項目では新しい値に置き換える。`ingest.test.ts` で、記録済みのフィードを使って確かめる
- [x] 2.2 `storeItems` に重複の判定を足す。別の購読フィード、保存から7日以内、URLかタイトルの一致、残した記事への置き換え、最も先に保存した記事の選択を実装する。feed-subscriptionsの差分の各シナリオを `ingest.test.ts` のテストにして確かめる。LLMのアダプターを呼ばないことも、同じテストで確かめる。同じ購読フィードの中の項目同士を比べないことも確かめる
- [x] 2.3 `storeItems` が返す `titled` から、隠した重複を外す。新しい重複と書き換えられた重複のどちらも、取得のときにタイトルを翻訳せず、翻訳のAPIに送る文字数が増えないことを確かめる。テストは `ingest.test.ts` に書き、翻訳のアダプターを差し替える
- [x] 2.4 `articles.ts` に、隠した重複の条件（`duplicate_of` があり、全体設定で重複の除去が有効）を定数として置く。`WAITING_FOR_SUMMARY` の未読の側に、隠した重複でないことを足す。`articles.test.ts` で次を確かめる。自動の要約が有効な購読フィードの重複は、要約を待つ記事にならない。開いて要約を頼んだ重複は要約される。重複の除去を無効にすると、要約を待つ記事に戻る

## 3. 一覧、件数、詳細、設定のAPI（packages/core、apps/server）

- [x] 3.1 `listArticles` で、2.4で置いた条件を使い、購読フィードとスターのどちらも指定しない一覧から隠した重複を外す。全体、カテゴリ、カテゴリなし、購読フィード、スターの一覧のシナリオと、無効にすると記録済みの重複が並び、有効に戻すとまた隠れることを `articles.test.ts` で確かめる
- [x] 3.2 `getCounts` で、全体の未読数、カテゴリの未読数と総数、カテゴリなしの未読数から隠した重複を引き、購読フィードの未読数には含める。http-apiの差分のシナリオと、無効の間は引かないことを `articles.test.ts` で確かめる
- [x] 3.3 `setArticleFlags` と `markArticlesRead` で、残した記事を既読にするのと同じトランザクションで、隠した重複のうち未読のものを既読にする。`articles.test.ts` で次を確かめる。一括の既読が返す識別子に、連動した重複が含まれる。ストップワードで隠した重複は既読にならない。残した記事を未読に戻しても、重複は変わらない。無効の間は連動しない。重複を既読にしても、残した記事は変わらない
- [x] 3.4 `api.ts` の記事の詳細のスキーマに、ほかに配信した購読フィードの配列を足す。残した記事と重複のない記事の応答を `apps/server/src/articles.test.ts` で確かめる。`docs/api.md` に項目と、カテゴリの未読数が購読フィードの未読数の合計と合わないこと、残した記事を既読にすると重複も既読になることを書く
- [x] 3.5 `apps/server` の全体設定の取得と変更で、重複の除去の設定を扱う。`settings-api.test.ts` で確かめ、`docs/api.md` の全体設定の表に足す
