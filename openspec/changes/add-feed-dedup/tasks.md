# Tasks

どの作業も、失敗するテストを先に書いてから実装する。テストはLLMと外部のサイトを呼ばず、記録済みのフィードと差し替えた取得元で動かす。

## 1. 未決の問いの確定

- [ ] 1.1 `design.md` の「Open Questions」の4つを利用者に確かめ、答えをspecsとdesignに反映する。`openspec validate add-feed-dedup --strict` が通ることで確かめる

## 2. 判定に使う値と設定（packages/core）

- [ ] 2.1 `normalizeUrl` の隣に、タイトルの正規化の関数を足す。全角と半角、大文字と小文字、空白、記号の違いを無視し、10文字未満なら値なしを返すことを、先に書いた単体テストで確かめる
- [ ] 2.2 `packages/core` に移行を足す。`articles` に `dedup_url`、`dedup_title`、`duplicate_of` と2つの索引を、`settings` に重複の除去の列（既定値1）を足す。番号は空いている次の番号にする。記事のある古いデータベースに当てて、既存の配信記事の値が空のままであることを `database.test.ts` で確かめる
- [ ] 2.3 `articles` の削除のあとに動くトリガーを、同じ移行で作る。残した記事を消したとき、最も先に保存した重複を新しく残す記事にする。購読フィードの削除（外部キーの連鎖）と、保存期間での削除の両方で記録し直されることをテストで確かめる
- [ ] 2.4 `api.ts` の全体設定のスキーマと保存に、重複の除去の真偽値を足す。初回の既定値が有効であること、無効が再起動で保たれること、更新した既存のデータベースで有効になることを `settings.test.ts` で確かめる
- [ ] 2.5 `settings-file.ts` の書き出しと読み込みに、重複の除去の設定を足す。往復と、設定がないファイルで値が変わらないことを `settings-file.test.ts` で確かめる。`examples/settings.example.yaml` に例を足す

## 3. 保存のときの判定（packages/core）

- [ ] 3.1 `storeItems` で、新しい配信記事に `dedup_url` と `dedup_title` を保存し、書き換えられた項目では新しい値に置き換える。`ingest.test.ts` で、記録済みのフィードを使って確かめる
- [ ] 3.2 `storeItems` に重複の判定を足す。別の購読フィード、保存から7日以内、URLかタイトルの一致、残した記事への置き換え、最も先に保存した記事の選択を実装する。feed-subscriptionsの差分の各シナリオを `ingest.test.ts` のテストにして確かめる。LLMのアダプターを呼ばないことも、同じテストで確かめる

## 4. 一覧、件数、詳細、設定のAPI（packages/core、apps/server）

- [ ] 4.1 `listArticles` で、購読フィードとスターのどちらも指定しない一覧から重複を外す。全体、カテゴリ、カテゴリなし、購読フィード、スターの一覧のシナリオを `articles.test.ts` で確かめる
- [ ] 4.2 `getCounts` で、全体の未読数、カテゴリの未読数と総数、カテゴリなしの未読数から重複を引き、購読フィードの未読数には含める。http-apiの差分のシナリオを `articles.test.ts` で確かめる
- [ ] 4.3 `api.ts` の記事の詳細のスキーマに、ほかに配信した購読フィードの配列を足す。残した記事と重複のない記事の応答を `apps/server/src/articles.test.ts` で確かめる。`docs/api.md` に項目と、カテゴリの未読数が購読フィードの未読数の合計と合わないことを書く
- [ ] 4.4 `apps/server` の全体設定の取得と変更で、重複の除去の設定を扱う。`settings-api.test.ts` で確かめ、`docs/api.md` の全体設定の表に足す
