# Proposal

## Why

いまは、同じ購読フィードの中だけで、項目の識別子によって同じ記事を見分けている。別の購読フィードが同じ記事を配信すると、全体とカテゴリの一覧に2件の配信記事が並ぶ。
GitHubのissueの58番は、Inoreaderの「Duplicate filters」に当たる機能として、購読フィードをまたぐ重複を1件にまとめることを求めている。

## What Changes

- 配信記事を保存するとき、ほかの購読フィードが7日前までに配信した配信記事と比べる。正規化したURLか、正規化したタイトルが同じなら、重複とみなす。LLMは使わない。
- URLの正規化は、取得元で使っている正規化（追跡用のパラメーターと断片を取り除く）をそのまま使う。
- タイトルの正規化は、大文字と小文字、全角と半角、空白、記号の違いを無視する。正規化したあとで10文字未満のタイトルは、タイトルでは比べない。
- 重複とみなした配信記事は保存し、先に保存した配信記事の重複であることを記録する。全体とカテゴリの一覧からは隠す。購読フィードの一覧には出し、その購読フィードの未読の件数にも含める。
- 判定は保存のときに1度だけ行う。この機能を入れる前に保存した記事には適用しない。
- 残した配信記事の本文に、出典の下に「ほかに配信した購読フィード」の名前を並べる。名前を押すと、その購読フィードの同じ記事を開く。Webとアプリの両方に出す。
- 全体設定に、重複の除去の切り替えを足す。既定は有効とする。Webの全体設定の画面で切り替えられる。設定ファイルにも書き出す。
- 生成記事は比べない。生成記事の出典とも比べない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `feed-subscriptions`: 配信記事の保存のときの重複の判定と記録を足す。比べ方、比べる期間、残す記事、残した記事が消えたときの扱いも足す
- `settings`: 重複の除去の切り替えを全体設定として保持すること、設定ファイルでの扱いを足す
- `http-api`: 一覧と件数で重複を隠すこと、残した記事の詳細に「ほかに配信した購読フィード」を返すこと、全体設定で切り替えを扱うことを足す
- `web-reader`: 一覧で重複を隠すこと、本文の「ほかに配信した購読フィード」の表示と操作を足す
- `web-settings`: 全体設定の画面に、重複の除去の切り替えを足す
- `mobile-reader`: 一覧で重複を隠すこと、本文の「ほかに配信した購読フィード」の表示と操作を足す

## Impact

- `packages/core`: 移行で、記事の表に、重複の判定に使う値と、どの記事の重複かを記録する列を足す。全体設定の表に切り替えを足す。購読フィードの保存の処理、一覧と件数の問い合わせ、記事の詳細、設定と設定ファイルの読み書きを変える。
- `apps/server`: APIの応答に項目を足す。
- `packages/client`: 記事の詳細の型に、ほかに配信した購読フィードを足す。
- `apps/web`、`apps/mobile`: 本文の画面に「ほかに配信した購読フィード」を足す。Webの全体設定の画面に切り替えを足す。
- `docs/api.md`、`examples/settings.example.yaml`: 新しい項目と設定を足す。
- LLMの呼び出しと、外部への取得は増えない。判定は保存済みの記事との比較だけで行う。
