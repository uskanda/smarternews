# Design

## Context

スターと既読は`useArticleFlags`で送る。送る前に画面へ反映し、失敗したら戻す。ただし今は、開いた記事のキャッシュ（`["article", id]`）がないと戻さない。
未読の一覧と直近に読んだ一覧は、読んだ行を`kept`に残して表示する。この`kept`はキャッシュの外にあるので、失敗しても戻らない。
スクロールで既読にする処理は、失敗すると画面の下で知らせ、「もう一度試す」を置いている。今回はこれにそろえる。動機は`proposal.md`の「Why」を参照する。

## Goals / Non-Goals

**Goals:**

- スター、既読、一括の既読の取り消しの失敗を、どれも知らせる。
- 失敗したら、キャッシュと`kept`の印を元の値に戻す。

**Non-Goals:**

- アプリ（`apps/mobile`）の修正（`grilling.md`のQ1）。
- 仕様の変更（`grilling.md`のQ4）。

## Decisions

### 戻す値は送った値の反対にする

`isRead`を送ったなら`!isRead`に、`starred`を送ったなら`!starred`に戻す。`patchArticle`で、すべての一覧と記事のキャッシュに当てる。
開いた記事のキャッシュから前の値を読む今の方法では、一覧だけにある行が戻らない。送る前の値は、送った値の反対と同じである。`s`と`m`は反転して送り、自動の既読は未読のときだけ送るためである。

### 失敗は onFailed で画面に返す

`useArticleFlags`は`onFailed(change)`を受け取る。`useListSortChange`と同じ形である。`kept`と知らせを出す関数は`ReaderPage`にあるので、フックの中では扱わない。

### 最新の描画の関数を ref で呼ぶ

`onFailed`と「もう一度試す」は、要求を送ったときの描画ではなく、今の描画の`setRead`と`setStar`を呼ぶ。知らせが出ている間に一覧を移っても、古い一覧の`kept`で上書きしないためである。`useScrollToRead`の`latest`と同じ作りにする。

### スターは値を指定して設定する

`setStar(id, starred)`を足し、`toggleStar`はこれを呼ぶだけにする。「もう一度試す」で、反転ではなく同じ値を送れる。同じ理由で、`setRead`は記事ではなく`id`を受け取る。

### 一括の既読の取り消しを関数に分ける

`undoMarkAll(ids)`が失敗したら、同じ`ids`をもう一度送る「もう一度試す」を付けて知らせる。何度失敗しても同じように知らせる。

## Risks / Trade-offs

- 同じ記事に続けて2つの要求を送り、先の要求だけが失敗すると、後の要求の値を反対に戻してしまう。一覧は1分ごとに取得し直すので、いずれサーバーの値にそろう。すぐに直すなら、知らせの「もう一度試す」で送り直せる。利用者が1件ずつ操作するので、起きることはまれである。
