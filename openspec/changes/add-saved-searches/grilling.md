# grilling 記録: add-saved-searches

Issue #132「保存した検索」の計画の記録である。
計画の段階で、9つの質問をIssueに出した。利用者は9つともAを選んだ。
そのあとの計画で、経路、カテゴリやフィードを削除したときの扱い、同じ条件の二重の保存の3つを決めて確認を求めた。利用者は、変更を添えずに計画を承認した（`/ok`）。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 対象にする画面 | Webだけに出す。項目と件数はサーバーと共有のモデルに置き、Androidは別のissueで広げる | Issue #132 Q1（A） |
| 保存する条件 | 検索語と、カテゴリまたは購読フィードの絞り込みを保存する。未読だけかどうかは保存しない | Issue #132 Q2（A） |
| 保存先 | サーバーのデータベースに新しい表を作り、APIで読み書きする。設定ファイルにも書き出し、読み込む | Issue #132 Q3（A） |
| 項目を開いたときの表示 | 未読だけの表示で開く。画面の切り替えで既読も出せる | Issue #132 Q4（A） |
| 項目の名前 | 保存するときに名前を入力できる。既定は検索語で、あとから項目のメニューで変えられる | Issue #132 Q5（A） |
| 一括の既読 | 使えないままにする。記事を開くか、1件ずつ既読にする | Issue #132 Q6（A） |
| 左のペインでの置き場所 | 上の段（未読、すべて…ダイジェスト）と「カテゴリ」の間に、見出し「保存した検索」の区切りを作って並べる。1つもないときは区切りごと出さない | Issue #132 Q7（A） |
| 未読数の数え方 | 未読だけの表示で開いたときの結果の件数と同じにする（終了したイベントも含む）。件数のAPIの応答に検索ごとの数を足す | Issue #132 Q8（A） |
| 既存の操作との関係 | 他の記事の一覧と同じに扱う。Shift+J/Kで通り、隠す設定がオンなら未読0で隠れ（開いている項目は残す）、メニューで名前の変更、削除、上下の移動ができる | Issue #132 Q9（A） |
| 経路 | `/search` の画面を流用せず、`/s/:id` を新しく作る | Issue #132 計画（`/ok` で承認） |
| 絞り込みに使うカテゴリやフィードの削除 | 保存した検索も一緒に消す | Issue #132 計画（`/ok` で承認） |
| 同じ条件の二重の保存 | 拒まない | Issue #132 計画（`/ok` で承認） |
| LLMの呼び出し | 呼ばない。数えるのには全文検索の表を使う | Issue #132 の本文 |

## 後回しにしたもの

- Androidの引き出しへの表示と、結果の画面からの保存の操作（Q1）。共有のモデルと件数のAPIは用意しておく
- 保存した検索の結果での一括の既読（Q6）。使ってみて必要なら別のissueにする
