# Proposal

## Why

よく使う検索を、毎回検索欄に打ち直している。
今は検索の結果の画面のURLをブラウザーへ登録すれば代わりになるが、新しく一致した記事が何件あるかは開くまで分からない（Issue #132）。
保存した検索を左のペインに未読数つきで並べれば、カテゴリや購読フィードと同じように、新しい一致を読み進められる。

## What Changes

- サーバーに保存した検索を置く。1つの保存した検索は、名前、検索語、カテゴリまたは購読フィードの絞り込み（どちらか1つまで）を持ち、並び順を持つ。
- APIに、保存した検索の一覧、作成、名前の変更、削除、移動の操作を足す。
- 件数のAPIの応答に、保存した検索ごとの未読数を足す。数は、その検索を未読だけで開いたときの結果の件数と同じにする。終了したイベントも含める。全文検索の表で数え、LLMは呼ばない。
- 絞り込みに使っているカテゴリや購読フィードを削除したときは、その保存した検索も消す。
- 設定ファイルに保存した検索を書き出し、読み込む。
- Webの左のペインの上の段と「カテゴリ」の間に、見出し「保存した検索」の区切りを置き、項目を未読数つきで並べる。1つもないときは区切りごと出さない。
- 項目を開くと、保存した条件で、未読だけの表示の結果を出す。既読も表示する切り替えを持ち、一括の既読と並び順のメニューは持たない。
- Shift+JとShift+K、既読の項目を隠す設定、項目のメニュー（名前の変更、削除、上下の移動）を、保存した検索にも適用する。
- 検索の結果の画面に「検索を保存」のボタンを置く。名前の既定は検索語である。
- Androidの引き出しには出さない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `article-search`：保存した検索の保存、未読数、カテゴリや購読フィードの削除に伴う削除の要件を足す。
- `http-api`：保存した検索の操作と、件数の応答の保存した検索ごとの未読数の要件を足す。
- `settings`：設定ファイルでの保存した検索の往復の要件を足す。
- `web-shell`：左のペインの「保存した検索」の区切り、Shift+J/K、既読の項目を隠す設定、項目のメニューの要件を足す。
- `web-reader`：保存した検索の一覧と、検索の結果からの保存の要件を足す。
