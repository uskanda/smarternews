# grilling 記録: show-llm-usage

GitHubのissueの146番のコメントで、2ラウンドの質問に答えた記録である。
issueは、LLMの利用量を実行、カテゴリ、日ごとに分けて表示し、期末の見込みも出すという、Web UIの監査の項目（F-11）である。
設定の画面には今日の回数、予算の期間の合計、タスクごととプロバイダーごとの内訳がある。呼び出しの記録は実行と金額を持つが、実行のAPIは金額を返さない。

第1ラウンドはQ1〜Q7を聞いた。Q6には回答がなかったので、第2ラウンドで2問（Q8とQ9）に分けて聞き直した。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| カテゴリごと・日ごとの内訳を置く場所 | 設定の画面に区画「利用量」を新しく足し、「プロバイダー」の直後に置く。区画のリンクにも足す。サーバーには利用量のAPIを足す。対象はWebだけで、モバイルの設定の画面は変えない（A） | 第1ラウンド Q1 |
| 内訳を数える期間 | 今の予算の期間（初日から今まで）。月の予算と期末の見込みと同じ期間にする（A） | 第1ラウンド Q2 |
| 呼び出しの記録の保持期間と予算の期間のずれ | この変更で直す。呼び出しの記録を消す境目を、「30日前」と「今の予算の期間の始まり」の早いほうにする。実行の記録は今のとおり30日で消す（A） | 第1ラウンド Q3 |
| 「作った記事」と「開いた記事」の数え方 | 作った記事は、そのカテゴリの生成記事のうち、作った日時が期間内のもの。開いた記事は、そのうち開いた時刻のあるもの。1件あたりの金額は、カテゴリの金額 ÷ 開いた記事の数で、0件なら「—」を出す（A） | 第1ラウンド Q4 |
| 期末の見込みの「今の速さ」 | 期間の平均。今までの金額 ÷ 期間の始まりから経った時間 × 期間の長さ。予算を超える見込みのときは文で添え、上部の警告の帯は増やさない。見込みであることを明記する（A） | 第1ラウンド Q5 |
| 実行の一覧と詳細に出すもの | 一覧に「金額」の列を足す。詳細には、金額、金額のわからない呼び出しの数、タスクごとの回数と金額を出す。金額のかかる呼び出しがない実行では、金額に「—」を出す（A） | 第1ラウンド Q7 |
| 日ごとの推移の日の区切り | UTCの日で区切る。予算の期間と同じ区切りにし、日ごとの金額の和を期間の合計と一致させる（A） | 第2ラウンド Q8 |
| 日ごとの推移の見せ方 | 日、金額、回数の表にし、金額の列にCSSの横棒を添える。グラフのライブラリは足さない（A） | 第2ラウンド Q9 |

## 計画で決めたこと

承認を求めた計画（issueのコメント）で、次を決めた。利用者は変更なしで承認した（`/ok`）。

| 決定 | 選択 |
|---|---|
| 利用量のAPIのパス | `GET /api/v1/usage` |
| 実行に足す欄 | `costUsd`（金額のかかる呼び出しがなければ空）、`unknownCostCalls`、`callsByTask`（呼び出しのあったタスクだけ） |
| 実行に属さない呼び出し | 要約、翻訳、提案、ダイジェストなど、実行を持たない呼び出しを1行にまとめる |
| 金額と回数の数え方 | 金額は今の予算の判定と同じく、金額のかかる呼び出しのうち金額のわかるものの合計。回数は、金額のかからない呼び出しも含めた全部 |
| 金額のかかるプロバイダーがないとき | 利用量の区画の金額の列を「かからない」と出し、回数で見せる |
| 呼び出しの記録を消す境目の渡し方 | `purgeExpired` に残す期間の始まりを渡す。`Scheduler` が締め日から予算の期間の始まりを求めて渡す |
