# Proposal

## Why

設定の画面が示すのは、今日の呼び出しの回数、予算の期間の合計、タスクごととプロバイダーごとの金額だけである。どの実行やカテゴリでいくら使ったか、このままの速さで期末までにいくら使うかは、利用者から見えない（issueの146番、Web UIの監査のF-11）。
呼び出しの記録は実行と金額を持っているので、LLMを呼ばずに集計して見せられる。

また、呼び出しの記録は30日で消える。予算の期間が31日ある月の最後の日には、期間の最初の日の呼び出しが消えており、期間の合計と予算の判定がその分だけ少なくなっている。見込みも同じだけずれるので、ここで一緒に直す。

## What Changes

- 実行履歴の一覧に「金額」の列を足す。実行の詳細には、金額、金額のわからない呼び出しの数、タスクごとの回数と金額の表を足す。金額のかかる呼び出しがない実行では、金額に「—」を出す。
- 設定の画面に区画「利用量」を、「プロバイダー」の直後に足す。区画には、期末の見込みの文、カテゴリごとの利用量の表、日ごとの利用量の表を置く。
  - カテゴリごとの表は、回数と金額を出す。作った記事の数、開いた記事の数、開いた記事1件あたりの金額も出す。実行に属さない呼び出し（要約、翻訳、提案、ダイジェストなど）は、最後の1行にまとめる。
  - 日ごとの表は、予算の期間の初日から今日まで、UTCの日ごとに金額と回数を出す。金額の隣には、金額に比例した長さの横棒を描く。
  - 期末の見込みは、期間の平均の速さで期末まで進んだときの金額で、予算を超えそうなときはそのことも書く。
  - 金額のかかるプロバイダーがないときは、金額を「かからない」と出し、回数で見せる。
- APIの実行に、金額、金額のわからない呼び出しの数、タスクごとの回数と金額を足す。APIに利用量の内訳（`GET /api/v1/usage`）を足す。
- 呼び出しの記録を消す境目を、今から30日を引いた日時と、今の予算の期間の初日の早いほうにする。実行履歴は今のとおり30日で消す。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `http-api`: 実行ごとの金額と呼び出しの内訳、利用量の内訳の操作を足す
- `runs`: LLMの呼び出しの記録の保存期間を足す
- `web-runs`: 実行履歴の一覧の列に金額を足す。実行の詳細の金額とタスクごとの呼び出しの表示を足す
- `web-settings`: 区画「利用量」と、その中の期末の見込み、カテゴリごとの利用量、日ごとの利用量を足す

## Impact

- `packages/core`: `runSchema` に欄を足し、利用量の型（`usageSchema`）を足す。`db/runs.ts` が実行に呼び出しの集計を付ける。利用量の集計（`db/usage.ts`）と、`TaskRunner` の `usageStatus` を足す。`purgeExpired` と `Scheduler` が予算の期間の初日を受け取る。
- `apps/server`: `GET /api/v1/usage` を足す。`runtime.ts` が締め日を `Scheduler` に渡す。
- `packages/client`: APIの呼び出しに `usage()` を、表示の言葉にタスクの名前と見込みの文を足す。
- `apps/web`: 実行履歴の一覧と詳細、設定の画面の区画「利用量」。
- `docs/api.md`、`docs/providers.md`: 足した欄と操作、区画を書く。
- LLMは呼ばない。移行は要らない。Androidアプリは変えないが、APIの実行に欄が増えるだけなので、そのまま動く。
