# grilling 記録: add-digests

GitHubのissueの68番のコメントで、1ラウンドの質問（Q1〜Q10）に答えた記録である。
issueは、1日2回ほど、生成記事と配信記事のうち重要なものをLLMでまとめた文章を出したいという要望である。
全体をまとめたエグゼクティブサマリーと、カテゴリごとに3行程度のまとめを求めている。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| まとめの対象 | 生成記事と配信記事の両方。配信記事は、タイトルと、自動の要約があれば要約、なければ配信された内容の抜粋（1件300文字まで）だけを渡す。全文は使わない（B） | Q1 |
| 期間 | 前回のダイジェストの期間の終わりから今まで。初回と、前回から長く空いたときは、最大24時間に限る（A） | Q2 |
| 配信記事の重要さ | 同じ1回の呼び出しの中でLLMが判断する。生成記事は、重要度4以上を優先するよう指示する（A） | Q3 |
| カテゴリのない購読フィード | その配信記事は、エグゼクティブサマリーの入力にだけ使う。カテゴリの区画は作らない（C） | Q4 |
| 読む場所 | Webとアプリで読め、APIでも取れる。作られたらアプリに通知する。RSSには出さない（AとC） | Q5 |
| 保存 | 専用の表に保存し、180日で消す（A） | Q6 |
| 根拠の記事 | 各行が根拠の記事の識別子を持つ。入力になかった識別子は捨てる（A） | Q7 |
| 作る時刻 | 全体設定に作る時刻の一覧を置く（既定は7:00と19:00）。起動したとき、6時間以内に過ぎた回がまだ作られていなければ1回だけ作る。「今すぐ作る」も用意する。一覧が空なら、時刻でのダイジェストは作らない（A） | Q8 |
| 呼び出しと上限 | 1回のダイジェストにつき呼び出しは1回。専用の1日の上限（既定4回）を置き、実行の上限とは別に数える。月の予算はほかのタスクと同じく守る（C） | Q9 |
| 長さ | エグゼクティブサマリーは800文字以内の文章。カテゴリの区画は1区画3行程度、1行100文字程度まで（C） | Q10 |

## 計画で決めたこと

承認を求めた計画（issueのコメント）で、次を決めた。利用者は変更なしで承認した。

| 決定 | 選択 |
|---|---|
| 用語 | 「ダイジェスト」とする。既存の仕様の「通知のまとめ」「まとめた通知」と区別するためである。画面の表記も「ダイジェスト」にする |
| 入力の件数 | 200件まで。生成記事を重要度の高い順、同じ重要度なら新しい順に並べ、そのあとに配信記事を新しい順に並べて、先頭から選ぶ。期間内の記事が0件なら、LLMを呼ばず、ダイジェストも作らない |
| 失敗の扱い | 出力の検証はほかのタスクと同じ規則にする（2回とも不正なら破棄）。失敗も呼び出しの記録に残す。自動でのやり直しはしない。次の期間は、最後に成功したダイジェストの終わりから数える |
| アプリの通知 | 通知の設定が「出さない」以外のとき、ダイジェストができたら通知を1つ出す。内容は「ダイジェスト」とエグゼクティブサマリーの先頭である。記事の通知をまとめる件数には数えない。押すと、そのダイジェストを開く。通知の設定に新しい値は足さない |
| 時刻の編集 | Webの設定の画面で編集する。設定ファイルの書き出しと読み込みにも含める。アプリの設定の画面には足さない |
