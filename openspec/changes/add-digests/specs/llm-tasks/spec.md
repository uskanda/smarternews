# Spec Delta

## MODIFIED Requirements

### Requirement: タスクの限定

サーバーは、解釈、判定、集約、本文の生成、検索、要約、翻訳、セレクターの提案、ダイジェストの9つのタスク以外の目的でLLMを呼び出してはならない（MUST NOT）。

#### Scenario: フィードだけの実行

- **WHEN** 新しい候補が1件もない実行をする
- **THEN** その実行でLLMは1回も呼び出されない

## ADDED Requirements

### Requirement: ダイジェストのタスク

ダイジェストのタスクは、期間内の記事の一覧とカテゴリの一覧を入力とし、エグゼクティブサマリーとカテゴリの区画を出力しなければならない（MUST）。
エグゼクティブサマリーは、出力言語で書いた800文字以内の文章とする。
カテゴリの区画は、1区画3行程度、1行100文字程度とし、各行は根拠の記事の識別子を持つ。
生成記事では重要度4以上の記事を優先し、配信記事では重要さをLLMが判断する。
ダイジェストのタスクは、道具を使わない。

#### Scenario: 出力言語でのダイジェスト

- **WHEN** 出力言語が日本語の状態で、英語の配信記事だけを入力にダイジェストを作る
- **THEN** エグゼクティブサマリーとカテゴリの区画は日本語で書かれる

#### Scenario: 入力にないカテゴリの区画

- **WHEN** ダイジェストのタスクの1回目の出力に、入力のカテゴリの一覧にないカテゴリの区画があり、2回目の出力は正しい
- **THEN** サーバーは2回目の出力を採用する

### Requirement: ダイジェストの呼び出しの回数

サーバーは、1回のダイジェストのために、ダイジェストのタスクを1回だけ呼び出さなければならない（MUST）。
出力の検証に通らないときのやり直しは、ほかのタスクと同じく1回までとする。

#### Scenario: 3つのカテゴリのダイジェスト

- **WHEN** 3つのカテゴリに記事がある期間のダイジェストを作り、1回目の出力が正しい
- **THEN** 呼び出しの記録に、タスクがダイジェストの行が1件だけある

### Requirement: ダイジェストのタスクの割り当て

サーバーは、ダイジェストのタスクを、設定が割り当てたプロバイダーで実行しなければならない（MUST）。
割り当てがないとき、`smart` という名前のプロバイダーがあればそれを使い、なければ既定のプロバイダーを使う。

#### Scenario: 割り当てを変える

- **WHEN** `config.yaml` の `tasks` で `digest` に別のプロバイダーを割り当てて、サーバーを起動する
- **THEN** ダイジェストは、そのプロバイダーで作られる

### Requirement: ダイジェストの1日の上限

その日のダイジェストの呼び出し回数がダイジェストの1日の上限に達している間、サーバーはダイジェストのためにLLMを呼び出してはならない（MUST NOT）。
ダイジェストの呼び出しは、記事を書く実行の1日の上限には数えない。記事を書く実行の呼び出しも、ダイジェストの1日の上限には数えない。
ダイジェストの1日の上限の既定は4回とし、設定で変えられる。0にすると、ダイジェストは作られない。

#### Scenario: 上限に達した日

- **WHEN** ダイジェストの1日の上限が1回の状態で、その日に2回目のダイジェストを作る時刻が来る
- **THEN** LLMは呼び出されず、2回目のダイジェストは保存されない

#### Scenario: 実行の上限との分離

- **WHEN** 記事を書く実行の呼び出しがその日の上限に達した状態で、ダイジェストを作る時刻が来る
- **THEN** ダイジェストは作られる

### Requirement: 予算に達したときのダイジェスト

予算の期間に使った金額が月の予算に達している間、サーバーは、金額のかかるプロバイダーでダイジェストのタスクを呼び出してはならない（MUST NOT）。

#### Scenario: 予算に達した状態で時刻が来る

- **WHEN** ダイジェストのタスクを `anthropic` のプロバイダーに割り当て、月の予算に達した状態で、作る時刻が来る
- **THEN** LLMは呼び出されず、ダイジェストは保存されない

### Requirement: ダイジェストの呼び出しの記録

サーバーは、ダイジェストの呼び出しも、タスク、プロバイダー、所要時間、成否とともに記録しなければならない（MUST）。
失敗した呼び出しも記録する。

#### Scenario: 失敗したダイジェスト

- **WHEN** ダイジェストのタスクの出力が2回ともスキーマに合わない
- **THEN** 呼び出しの記録に、タスクがダイジェストで失敗の行が2件あり、ダイジェストは保存されない
