## ADDED Requirements

### Requirement: セレクターの候補を求める操作

APIは、ページのURLを受けてセレクターの候補を返す操作を提供しなければならない（MUST）。
応答は、候補ごとのセレクターの組と見本、候補にLLMの提案を使ったかどうかを含む。
上限に達してLLMを呼べないときと、LLMが失敗したときも、応答は成功とする。

#### Scenario: LLMの提案で候補を得る

- **WHEN** 記事の並ぶページのURLで、候補を求める操作を呼び、セレクターの提案のタスクが成功する
- **THEN** APIは、候補ごとのセレクターの組と見本を返し、LLMの提案を使ったことを示す

#### Scenario: 1日の上限に達している

- **WHEN** その日の呼び出し回数が1日の上限に達した状態で、候補を求める操作を呼ぶ
- **THEN** APIは成功の応答で、推定した候補と、LLMの提案を使わなかったことを返す

#### Scenario: 取得を禁じているページ

- **WHEN** `robots.txt` が取得を禁じているページのURLで、候補を求める操作を呼ぶ
- **THEN** APIは、入力が不正であることを示す応答と、`robots.txt` が禁じているという理由を返す

### Requirement: 見本を求める操作

APIは、ページのURLとセレクターの組を受けて見本を返す操作を提供しなければならない（MUST）。

#### Scenario: 見本を確かめる

- **WHEN** ページのURLとセレクターの組で、見本を求める操作を呼ぶ
- **THEN** APIは、抜き出せる記事の件数と、先頭から10件までの記事のタイトル、リンク、日時を返す

### Requirement: Webページの購読フィードの登録の操作

APIは、購読フィードの登録で、ページのURLとセレクターの組を受け、Webページの購読フィードを登録しなければならない（MUST）。
カテゴリ、取得周期、有効と無効の別、自動の要約、翻訳、全文の自動の取得の設定は、ほかの購読フィードと同じに受ける。

#### Scenario: 登録して確かめる

- **WHEN** ページのURLとセレクターの組で購読フィードを登録し、購読フィードの一覧を要求する
- **THEN** 登録した購読フィードが、Webページの購読フィードであることと、そのセレクターの組とともに返る

### Requirement: 種類とセレクターの組の提供

APIは、購読フィードの一覧と詳細で、購読フィードがWebページの購読フィードかどうかを返さなければならない（MUST）。
Webページの購読フィードには、セレクターの組も返す。

#### Scenario: 2種類の購読フィード

- **WHEN** Atomのフィードの購読フィードとWebページの購読フィードが1つずつある状態で、購読フィードの一覧を要求する
- **THEN** それぞれの種類が返り、セレクターの組はWebページの購読フィードにだけ含まれる

### Requirement: セレクターの組を変える操作

APIは、Webページの購読フィードの変更で、セレクターの組を受けて保存しなければならない（MUST）。

#### Scenario: 項目のセレクターを変える

- **WHEN** Webページの購読フィードの変更で、項目のセレクターを別の値にする
- **THEN** そのあとの購読フィードの詳細は、新しい項目のセレクターを返す

### Requirement: 不正なセレクターの入力の拒否

CSSセレクターとして読めないセレクターを含む入力を受けたとき、APIはHTTPステータス400と、誤っているセレクターの項目の名前を返さなければならない（MUST）。
登録、変更、見本を求める操作のどれでも、同じに拒否する。

#### Scenario: 閉じていない括弧

- **WHEN** 項目のセレクターに `div[` を指定して見本を求める操作を呼ぶ
- **THEN** APIはHTTPステータス400と、項目のセレクターが誤っていることを返し、ページへの要求は発生しない
