# Proposal

## Why

購読できるのは、RSSとAtomのフィードだけである。フィードを提供しないサイトの新しい記事は、smarternewsで追えない（#61）。
Inoreaderの「Web feeds」に当たる機能がないため、乗り換えのときに読めなくなるサイトが残る。

## What Changes

- 購読フィードに、フィードを持たないページを登録する種類を足す。この種類を「Webページの購読フィード」と呼ぶ。ページの中の記事を、CSSセレクターの組で抜き出す。カテゴリへの所属、取得周期、並べ替えは、ほかの購読フィードと同じに扱う。
- 登録のときに1回だけ、新しいタスク「セレクターの提案」でLLMを呼ぶ。LLMはページのHTMLからセレクターの候補を提案し、利用者は抜き出した結果の見本を見て1つを選ぶ。取得のたびにはLLMを呼ばない。
- LLMに送るHTMLは、スクリプト、スタイル、埋め込みを除き、5万文字までに切り詰める。
- セレクターの提案の1日の上限を `config.yaml` に足す。既定は50回とする。提案の呼び出しは、1日あたりの呼び出し回数の上限（`llmCallsPerDay`）にも数える。`llmCallsPerDay` の既定を300回から350回へ増やす。
- 上限に達したときとLLMが失敗したときは、エラーにしない。プログラムがリンクの多い領域から候補を推定して出す。それでも候補がないときは、セレクターを手で入れる欄を出す。どちらの場合も、LLMを使わなかったことを画面に一文で出す。
- セレクターの提案のタスクは、既定で `smart` のプロバイダーに割り当てる。ほかのタスクの割り当ては変えない。
- 一覧のページから得るのは、記事のタイトル、リンク、日時だけとする。本文は全文の取得（#52）で取る。日時がない記事は、初めて見つけた時刻で並べる。
- ページの取得には、`robots.txt` の順守を含め、全文の取得と同じ取得の作法を適用する。JavaScriptを実行しないと記事が出ないサイトは対象にしない。
- 設定ファイルには、Webページの購読フィードをセレクターの組とともに書き出す。OPMLには書き出さない。
- ページの構造が変わって記事が見つからなくなった取得は、失敗として記録し、購読フィードの一覧に失敗の理由を出す。自動では候補を出し直さない。この状態が続けば、更新の止まった購読フィードの印（#64）も付く。購読フィードの編集の画面に「候補を出し直す」操作を置く。
- AGENTS.mdの規則「購読フィードの取得…ではLLMを呼ばない」に、セレクターの提案のタスクだけを例外として書き足す。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `feed-subscriptions`: Webページの購読フィードの登録、セレクターの組での抜き出し、取得の作法、LLMを使わない取得、構造が変わったときの扱いを足す。OPMLの書き出しから、Webページの購読フィードを外す
- `llm-tasks`: セレクターの提案のタスク、その割り当て、送るHTML、1日の上限、使えないときの切り替え、`llmCallsPerDay` の既定を足す。タスクの限定に、このタスクを加える
- `settings`: 設定ファイルでのWebページの購読フィードとセレクターの組の扱いを足す
- `http-api`: セレクターの候補を求める操作、見本を求める操作、Webページの購読フィードの登録と変更、一覧での種類とセレクターの組の提供を足す
- `web-settings`: 購読フィードの追加の画面での候補と見本の表示、LLMを使わなかったことの表示、手で入れる欄、編集の画面での「候補を出し直す」操作を足す

## Impact

- `packages/core`: 移行で、購読フィードの表に種類とセレクターの組の列を足す。ページから記事を抜き出す処理と、候補を推定する処理を足す。セレクターの提案のタスクと、その1日の上限を足す。取得の処理は、種類に応じて抜き出しを切り替える。設定ファイルとOPMLの書き出しを変える。`config.ts` の `limits` と `tasks` を変える。
- `apps/server`: 候補を求める操作と見本を求める操作を足し、購読フィードの登録と変更で種類とセレクターの組を受ける。
- `packages/client`: 操作の呼び出しと型を足す。
- `apps/web`: 購読フィードの設定の画面の追加と編集を変える。
- `apps/mobile`: 変えない。Webページの購読フィードの配信記事は、ほかの配信記事と同じに表示する。
- 文書と例：操作、タスク、上限、既定の値を書き直す。対象は `docs/api.md`、`docs/providers.md`、`README.md`、`README.ja.md` と、`examples/config.example.yaml` である。
- `AGENTS.md`: LLMを呼ばない規則に、このタスクの例外を書き足す。
- LLMを呼ぶのは、登録の画面で候補を求めたときと、「候補を出し直す」を選んだときだけである。取得、保存、フィルターの判定では呼ばない。
