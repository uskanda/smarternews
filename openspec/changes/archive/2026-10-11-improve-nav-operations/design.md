# Design

## Context

カテゴリと購読フィードは、どちらもidの順に返している。並び順を持つ列はない。
左のペインと引き出しは、`packages/client` の `buildNav` が作る同じ構造を表示している。
Webにはドラッグの部品がなく、ペインの境目だけがポインターのイベントを自前で扱っている。
アプリには `react-native-gesture-handler` と `react-native-reanimated` が入っている。
仕様 `web-shell` は、すべての操作をキーボードだけで行えることを求めている。

## Goals / Non-Goals

**Goals:**

- 並び順をサーバーに1つだけ持ち、Web、アプリ、設定ファイル、OPMLが同じ順を使う。
- 次の項目を選ぶ規則と、動かす先を求める規則を、Webとアプリで1つの実装にする。
- ドラッグのできない利用者にも、Webで並べ替えと登録解除の手段を用意する。

**Non-Goals:**

- カテゴリの入れ子と、購読フィードが複数のカテゴリに属すること。
- アプリでの登録解除と、アプリの読み上げでの並べ替え。
- Webの、指で触れる操作でのドラッグ。指ではメニューの「上へ移動」「下へ移動」を使う。

## Decisions

### 並び順は整数の列で持ち、動かすたびに振り直す

`categories` と `feeds` に `position` の列を足す。既存の行にはidを入れるので、いまの順が保たれる。
一覧は `position`、idの順で並べる。
動かす処理は、対象の並びを読み、対象を指定の位置へ入れ直して、1から振り直す。途中で失敗したときは、すべてを元に戻す。
件数は多くて数百件で、振り直しの負荷は問題にならない。
小数や文字列で間の値を作る方式は、振り直しが要らない代わりに、値が尽きたときの処理が要る。件数が少ないので採らない。

購読フィードの `position` は、属するカテゴリの中での順を表す。カテゴリに属さない購読フィードも、1つの並びとして扱う。

### 動かす操作は「どれの前か」で指定する

APIは次の2つを足す。

- `POST /api/v1/categories/:id/move`。本文は `{ "before": <カテゴリのid> | null }`。
- `POST /api/v1/feeds/:id/move`。本文は `{ "categoryId": <カテゴリのid> | null, "before": <購読フィードのid> | null }`。

`before` が `null` のときは末尾に置く。応答は、動かしたあとの一覧とする。
全体の並びを送らせる方式は、画面が古い一覧を持っていたときに、あとから足された項目を消すおそれがある。
前に置く相手だけを送る方式なら、サーバーの持つ並びに対して1件だけを動かせる。
「上へ移動」は1つ前の項目の前へ、「下へ移動」は2つあとの項目の前（なければ末尾）へ動かす操作として呼ぶ。

購読フィードの所属の変更は、既存の変更の操作と同じ処理を通す。配信記事のカテゴリも、そこで付け替わる。

### 設定は全体設定の1項目にする

`settings` の表に `advance_after_mark_all` の列を足す。APIと設定ファイルでは `advanceAfterMarkAll` と書く。
設定ファイルにこのキーがないときは、読み込みで値を変えない。古いファイルを読んでも設定が戻らないようにするためである。

### 設定ファイルの読み込みは、ファイルの順を先頭に置く

読み込みのあと、ファイルにあるカテゴリをファイルの順に並べ、ファイルにないカテゴリをそのあとに元の順で置く。
購読フィードも、カテゴリごとに同じ規則で並べる。
OPMLの読み込みは、既存の並びを変えない。新しく登録した購読フィードだけを末尾に足す。

### 次の項目を選ぶ規則は `packages/client` に置く

`buildNav` の結果と、いまの項目を受け取り、移る先を返す関数を足す。

- カテゴリの全体と「未分類」は、同じ階層の並び（カテゴリと「未分類」）の中で、下にある未読ありの最初のものを返す。
- 購読フィードと各カテゴリの「AI生成」は、すべてのカテゴリの配下を上から順につないだ並びの中で探す。
- 上部の項目では、何も返さない。

画面は、一括の既読のあとに件数を取り直してから、この関数を呼ぶ。古い件数で選ぶと、いま既読にした項目を未読ありと見なすためである。
折りたたんだカテゴリの配下も対象にする。移る先が折りたたまれているときは、開く。

### Webのドラッグは、ポインターのイベントで自前に作る

HTMLのドラッグの仕組みは、0.5秒とどまる判定と、入る位置の線の表示を作りにくい。指での操作にも使えない。
ペインの境目と同じく、ポインターのイベントを自前で扱う。対象はマウスとペンに限る。

- 押してから4px動いたらドラッグを始める。それまでは通常のリンクとして働く。
- 動かしている間は、行の位置から「どれの前か」を求め、線を出す。この計算は `packages/client` に置き、アプリと共有する。
- 購読フィードは、元のカテゴリの中では待たずに置ける。別のカテゴリは、その範囲に0.5秒とどまってから置ける先になる。
- ドラッグのあとの離す操作では、リンクを開かない。Escapeで取りやめる。
- 離したら、画面の並びを先に変えてからAPIを呼ぶ。失敗したら、保存済みの順に戻して通知を出す。

### メニューは `@radix-ui/react-context-menu` を使う

右クリック、メニューを開くキー、`Shift+F10` での起動と、矢印キーでの移動、フォーカスの復帰を、この部品が受け持つ。
すでに `@radix-ui/react-dialog` を使っており、同じ系列の部品である。
自前で作ると、フォーカスの扱いと画面の端での位置合わせを作り直すことになる。
登録解除の確認は、設定の画面と同じ確認のダイアログの部品と文言を使う。

### アプリのドラッグは、既存のジェスチャーの部品で作る

行ごとに、長押し（0.4秒）で始まるパンのジェスチャーを付ける。短く押したときは、いまと同じく項目を開く。
始まったら、その行を浮かせて描き、指の位置から「どれの前か」を求める。計算はWebと同じ関数を使う。
行の位置は、各行の配置の通知で集める。
指が表示範囲の上端か下端から48px以内にある間は、引き出しをその方向へスクロールする。
並べ替え専用のライブラリーは足さない。カテゴリと配下の2階層と、0.5秒とどまる規則を、既製の一覧の部品では表せないためである。

## Risks / Trade-offs

- アプリの引き出しは、横に払うと閉じる。長押しのあとのドラッグと取り合うおそれがある → ドラッグの間は、引き出しのジェスチャーを止める。エミュレーターで確かめる。
- ジェスチャーは、単体のテストでは一部しか確かめられない → 位置の計算と、とどまる判定を関数に分けて単体で確かめる。画面の動きはエミュレーターで確かめる。
- 左のペインの行はリンクである。ドラッグのあとに誤って開くおそれがある → ドラッグを始めたあとのクリックを1度だけ止める。テストで確かめる。
- 画面が古い一覧を持ったまま動かすと、指定した `before` がもう無いことがある → サーバーは拒否し、画面は一覧を取り直して通知を出す。
- 設定ファイルの読み込みで、ファイルにない項目が後ろへ回る → 仕様に書き、読み込みの説明にも1文足す。

## Migration Plan

- データベースの移行は列を足すだけである。表の作り直しを伴わないので、移行の前の複製は作らない。
- 古いアプリは、新しい順で返る一覧をそのまま表示する。動かす操作を呼ばないだけで、動作は変わらない。
- 戻すときは、前の版に戻す。足した列は、前の版のコードが読まないので残してよい。
