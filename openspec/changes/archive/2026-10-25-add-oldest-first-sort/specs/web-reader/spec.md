# Spec Delta

## ADDED Requirements

### Requirement: 並び順のメニュー

記事の一覧を表示している間、画面は、一覧のペインの上部に並び順のメニューを表示しなければならない（MUST）。
メニューの選択肢は「新しい順」と「古い順」の2つで、メニューを開く前から、いまの並び順が分かるようにする。

#### Scenario: 購読フィードの一覧を開く

- **WHEN** 並び順を変えていない購読フィードXを左のペインで選ぶ
- **THEN** 一覧のペインの上部に並び順のメニューが表示され、いまの並び順は新しい順と読み取れる

#### Scenario: キーボードだけで選ぶ

- **WHEN** 並び順のメニューへキーボードでフォーカスを移し、キーの操作だけで「古い順」を選ぶ
- **THEN** 一覧は古い順に表示される

### Requirement: 並び順のメニューを出さない一覧

イベントの一覧、最近読んだ記事の一覧、検索の結果を表示している間、画面は並び順のメニューを表示してはならない（MUST NOT）。

#### Scenario: イベントのカテゴリを開く

- **WHEN** 左のペインで種別がイベントのカテゴリを選ぶ
- **THEN** 一覧のペインの上部に並び順のメニューは表示されず、イベントは開催日の順に並ぶ

#### Scenario: 最近読んだ記事を開く

- **WHEN** 左のペインで「最近読んだ記事」を選ぶ
- **THEN** 並び順のメニューは表示されず、記事は既読の時刻の新しい順に並ぶ

### Requirement: 並び順の切り替え

利用者が並び順のメニューで並び順を選んだとき、画面は、表示中の項目の一覧を選んだ並び順で先頭から表示し直さなければならない（MUST）。
選んだ並び順は、その項目の並び順としてサーバーに保存する。本文のペインに表示中の記事は変えない。

#### Scenario: 古い順に変える

- **WHEN** 記事Aを開いた状態で、カテゴリBの並び順のメニューから「古い順」を選ぶ
- **THEN** カテゴリBの一覧は最も古い記事から表示され、本文のペインには記事Aが表示されたままである

### Requirement: 並び順の保存の失敗

並び順の保存に失敗したとき、画面は、一覧とメニューを元の並び順に戻し、保存できなかったことを伝えなければならない（MUST）。

#### Scenario: サーバーに届かない

- **WHEN** サーバーに届かない状態で、並び順のメニューから「古い順」を選ぶ
- **THEN** 一覧とメニューは新しい順に戻り、並び順を保存できなかったことが表示される

### Requirement: 項目ごとの並び順に従う表示

左のペインの項目が選ばれたとき、画面は、その項目に保存された並び順で記事の一覧を表示しなければならない（MUST）。
既読を含める切り替えと重要度4以上の切り替えを変えても、並び順は変えない。`j` と `k` のキーによる記事の移動は、表示した並びに従う。

#### Scenario: アプリで変えた並び順

- **WHEN** アプリで購読フィードXを古い順にしたあとで、Webの画面を読み込み直し、購読フィードXを選ぶ
- **THEN** 購読フィードXの一覧は古い順に表示される

#### Scenario: 既読を含める

- **WHEN** 古い順にしたカテゴリAで、既読を含める切り替えを入れる
- **THEN** カテゴリAの未読と既読の記事が、古い順に表示される

#### Scenario: 次の記事へ進む

- **WHEN** 古い順の一覧の1件目を選んだ状態で `j` を押す
- **THEN** 1件目の次に古い記事が選ばれ、その本文が表示される

### Requirement: 古い順の一覧での一括の既読

古い順の一覧で一括の既読を選んだとき、画面は、表示中の項目と絞り込みに当たる未読の記事のうち、一覧を読み込んだ時刻より前に更新されたものを既読にしなければならない（MUST）。
まだ読み込んでいない記事も対象に含める。

#### Scenario: 一部だけを読み込んだ一覧

- **WHEN** 未読が120件あるカテゴリAを古い順で開き、最初の50件だけが読み込まれた状態で、一括の既読を選ぶ
- **THEN** カテゴリAの120件すべてが既読になる

#### Scenario: 読み込んだあとで届いた記事

- **WHEN** 古い順の一覧を読み込み、そのあと新しい記事が作られてから、一括の既読を選ぶ
- **THEN** 新しい記事は未読のまま残る

### Requirement: 古い順の一覧での新しい記事

古い順の一覧を表示している間、画面は、再取得で届いた新しい記事を一覧の末尾に足さなければならない（MUST）。
表示中の本文、選択、一覧のスクロールの位置は変えない。

#### Scenario: 末尾まで読み込んだ一覧

- **WHEN** 古い順の一覧を末尾まで読み込んで記事を読んでいる間に、新しい記事が作られ、60秒が過ぎる
- **THEN** 新しい記事は一覧の末尾に現れ、読んでいる本文と選択は変わらない

#### Scenario: 一部だけを読み込んだ一覧

- **WHEN** 古い順の一覧の最初の50件だけを読み込んでいる間に、新しい記事が作られ、60秒が過ぎる
- **THEN** 読み込んだ50件の並びは変わらず、新しい記事は続きを読み込んだときに末尾へ現れる

### Requirement: 検索の結果と項目の並び順

検索の結果を表示する間、画面は、検索を始める前に選んでいた項目の並び順にかかわらず、最終更新の新しい順に並べなければならない（MUST）。

#### Scenario: 古い順のカテゴリを開いたまま検索する

- **WHEN** 古い順にしたカテゴリAを開いた状態で「電池」を検索する
- **THEN** 検索の結果は、最終更新の新しい順に表示される
