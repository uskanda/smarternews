# Proposal

## Why

記事の一覧は新しい順にしか並ばない。購読フィードを届いた順に読み進めたいときや、たまった記事を古いものから片付けたいときに、末尾までスクロールしてから上へ戻ることになる。
Inoreaderからの乗り換えのために、項目ごとに古い順にも並べられるようにする（#48）。

## What Changes

- 記事の一覧に、並び順の選択として「新しい順」と「古い順」を置く。既定は今と同じ「新しい順」である。
- 並び順は、左のペインの項目ごとに覚える。対象は「未読」「すべて」「スター」「AI生成」「未分類」の固定の項目、カテゴリ、カテゴリの下の「AI生成」、購読フィードである。
- 並び順はサーバーに保存し、Webとアプリで共有する。保存の仕組みは、項目ごとの別の表示の設定（#49の表示形式を見込む）をあとから足せる形にする。
- 古い順でも、並べる時刻は今と同じにする。生成記事は最終更新、配信記事は並びの時刻である。続報で更新された生成記事は、古い順の一覧でも末尾へ移る。
- 一括の既読は、並び順にかかわらず、一覧を読み込んだ時刻までに更新された記事をすべて既読にする。古い順の一覧で、まだ読み込んでいない新しい記事も含める。
- 古い順の一覧を開いている間に届いた記事は、定期的な再取得で末尾に足す。読んでいる記事の位置は変えない。
- Webは一覧のペインの上部に、アプリは一覧の画面の上部に、並び順のメニューを置く。
- イベントの一覧は対象にしない。開催日の順のままにする。最近読んだ記事の一覧と検索の結果も対象にせず、それぞれ既読の時刻の新しい順と、最終更新の新しい順のままにする。
- 設定ファイルの書き出しと読み込みで、項目ごとの並び順を扱う。カテゴリか購読フィードを削除したときは、その項目の並び順の設定も削除する。
- APIは、記事の一覧に古い順の指定を受け付け、一覧を読み込んだ時刻を応答に含める。項目ごとの表示の設定を読み出し、変える操作を足す。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `http-api`: 記事の一覧に並び順の指定を足す。一覧を読み込んだ時刻の提供と、項目ごとの表示の設定の操作を足す
- `settings`: 項目ごとの並び順の保持、カテゴリと購読フィードの削除での設定の削除、設定ファイルでの扱いを足す
- `web-reader`: 一覧のペインの並び順のメニュー、項目ごとの並び順に従う表示、古い順の一覧での一括の既読と新しい記事の扱いを足す
- `mobile-reader`: 一覧の画面の並び順のメニュー、項目ごとの並び順に従う表示、古い順の一覧での一括の既読と新しい記事の扱いを足す

## Impact

- `packages/core`: 移行で、項目ごとの表示の設定の表を足す。記事の一覧の問い合わせに古い順の並びと続きの値を足す。設定ファイルの書き出しと読み込みに、項目ごとの並び順を足す。
- `apps/server`: 項目ごとの表示の設定の読み出しと変更の操作を足す。
- `packages/client`: 項目から表示の設定の鍵を作る処理、並び順を一覧の問い合わせに渡す処理、読んだ記事を一覧に残す処理の並びの向きを足す。
- `apps/web`、`apps/mobile`: 並び順のメニューを足し、一括の既読が使う時刻を応答の値に変える。
- `docs/api.md`: パラメーター、応答の項目、操作、設定ファイルの項目を足す。
- RSSは変えない。LLMも翻訳のAPIも呼ばない。
