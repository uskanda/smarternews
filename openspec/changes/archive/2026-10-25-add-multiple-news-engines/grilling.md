# grilling 記録: add-multiple-news-engines

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 検索先を指定する場所 | `config.yaml` の `newsSearch.engines` に使う検索先を一覧で書く。すべてのトピックのニュース検索がこの一覧を使い、画面とAPIは変えない | 第 1 ラウンド Q1 |
| `maxResultsPerQuery` の数え方 | 検索先ごとに適用する。検索語1つで、検索先の数だけ上限が増える | 第 1 ラウンド Q2 |
| 一方の検索先が失敗したときの扱い | 検索先と検索語の組を1つの取得元として試す。もう一方の結果は候補にし、実行履歴には検索先の名前も残す | 第 1 ラウンド Q3 |
| 候補を見つけた検索先の記録 | 記録しない。候補の種類はニュース検索のまま | 第 1 ラウンド Q4 |
| Bing が返すMSNへの転載 | この変更では扱わない。同じ話題は記事の生成のときに1つにまとまる | 第 1 ラウンド Q5 |
| 今の `engine` の書き方 | 1項目の一覧として読み続ける。`engine` と `engines` を両方書いたら設定の誤りとして起動を止める | 第 2 ラウンド Q6 |
| 何も書かないときの既定値 | Google News だけ。例の設定ファイルに、両方を使う書き方をコメントで示す | 第 2 ラウンド Q7 |
| 空の一覧と重複した一覧 | どちらも設定の誤りとして起動を止める。ニュース検索を止めるときはトピックごとに無効にする | 第 2 ラウンド Q8 |

## 後回しにしたもの

- MSNへの転載を除外すること。転載が目立つようなら、出典名が「on MSN」で終わる結果を除く変更を別に行う。
- 検索先ごとに採用された件数を比べること。必要になったら、候補に検索先を記録する変更を別に行う。
- 利用者のインスタンスの `config.yaml` の書き換え。リポジトリの外にあるので、リリースのあとに利用者が書き換える。
