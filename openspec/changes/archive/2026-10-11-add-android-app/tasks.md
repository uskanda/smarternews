# Tasks

どの作業も、仕様のScenarioに対応する失敗するテストを先に書き、そのテストが通る実装を足す順で進める。
画面のテストは、偽の応答ではなく、実物のAPIに対して動かす。

## 1. 共有する処理と土台

- [x] 1.1 `packages/client` を作り、APIの呼び出し、日時の整形、イベントのまとめ方、読んだ記事を合わせる処理、実行の状態を言葉にする処理を `apps/web` から移す。APIの呼び出しにサーバーのURLを渡せるようにし、そのテストを足す。Webのテストが変更なしで通ることを確かめる
- [x] 1.2 `apps/mobile` を作り、Expo、TypeScript、`expo-router`、Jestを設定する。空の画面のテストが1つ通ることと、`pnpm install` がリポジトリ全体で成功することを確かめる
- [x] 1.3 `apps/mobile` のテストの土台を書く。実物のAPIをJestの中で直接作れるかを試し、作れなければ別のプロセスとして起動する形にする。アプリの側からカテゴリの一覧を取得するテストが通ることを確かめ、選んだ形と理由を `design.md` に記録する
- [x] 1.4 `scripts/` のトークンの変換に、アプリ向けの出力を足す。`DESIGN.md` に、押せる部品の大きさ48dpと、アプリでの使い方の説明を足す。値を変えると `make verify` が失敗することと、`designmd lint DESIGN.md` がエラー0件であることを確かめる
- [x] 1.5 `apps/mobile` に2つの書体を埋め込む設定を書き、アイコンをSVGから作る。アイコンの画像が生成されることを確かめる
- [x] 1.6 `make verify` とCIに、アプリの静的な検査、型の検査、Jestのテストを足す。わざと失敗するテストを置いて `make verify` が失敗することを確かめ、元に戻す
- [x] 1.7 `apps/mobile` 向けに、Expoの公式のスキルを入れる。リポジトリに置くのは `skills-lock.json` だけにし、個人情報の検査と静的な検査が通ることを確かめる
- [x] 1.8 `apps/mobile` のビルドに要るJDK、Android SDK、エミュレーターを、開発用のマシンの利用者の領域へ入れる。空のアプリのAPKを作り、エミュレーターで起動して画面の画像を取れることを確かめる。手順を `design.md` に記録する
