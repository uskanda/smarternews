# Proposal

## Why

記事を読む場所は、机のPCより携帯端末のほうが多い。いまも端末のブラウザーからWebの画面を開けば読める。しかし新着に気づく手段がなく、片手の操作にも向いていない。
最初のchangeで、Androidアプリは同じAPIを使う3本目のchangeとして残してあった。APIとWebの画面がそろったので、ここで作る。

## What Changes

- Androidアプリを `apps/mobile` に作る。Expoを使い、APIだけを呼ぶ。
- 記事の一覧と本文、既読、スター、重要度による絞り込み、一括の既読、イベントの一覧を、片手で扱える形にする。
- サーバーのURLとトークンは、QRコードを読み取るか、手で入力して設定する。トークンは端末の暗号化された保存領域に置く。
- 端末が定期的にサーバーを確かめ、新着の記事を端末の中の通知で知らせる。外部のサービスは使わない。
- アプリから、読み手情報の編集、カテゴリごとの即時の実行、直近の実行の状態の確認ができる。そのほかの設定は、アプリからWebの画面を開いて行う。
- Webの設定の画面に、アプリの接続に使うQRコードを出す操作を足す。
- GitHub Actionsが、リリースのタグごとに署名済みのAPKを作り、GitHub Releasesに添付する。
- APIの呼び出しと、日時やイベントの整形のように画面に依存しない処理を、Webとアプリで共有する。
- `DESIGN.md` の値を、アプリが読める形でも出力する。`PRODUCT.md` の対象の端末にAndroidを足す。

## Capabilities

### New Capabilities

- `mobile-shell`: アプリの土台。サーバーへの接続の設定、トークンの保存、項目の切り替え、配色と書体、失敗の表示、Webの画面を開く操作。
- `mobile-reader`: アプリで読む画面。記事の一覧と本文、既読、スター、絞り込み、一括の既読、イベントの一覧、払う操作。
- `mobile-settings`: アプリの設定の画面。読み手情報の編集、即時の実行と直近の実行の状態、通知の設定、接続の解除。
- `mobile-notifications`: 新着の記事の通知。定期的な確認、通知する記事の選び方、通知を押したときの動き。
- `mobile-distribution`: APKの作り方と配り方。署名、版、作る契機、APKに含めない情報。

### Modified Capabilities

- `web-settings`: アプリの接続に使うQRコードを表示する操作を足す。

## Impact

- 新しい `apps/mobile` と、Webとアプリが共有する処理を置く新しいパッケージ。`apps/web` は、共有する処理をそのパッケージから読む形に改める。
- 依存にExpoとReact Nativeの一式を足す。Webの画面には、QRコードを描くための小さなライブラリーを足す。
- `scripts/` のトークンの出力に、アプリ向けの出力を足す。`make verify` とCIに、アプリの検査とテストを足す。
- GitHub Actionsに、APKを作るワークフローを足す。署名の鍵はGitHubのsecretに置き、リポジトリには入れない。
- APIは変えない。通知の確認も、いまの記事の一覧の操作で足りる。
- `README.md`、`README.ja.md`、`AGENTS.md`、`PRODUCT.md`、`DESIGN.md` を更新する。
