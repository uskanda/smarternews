# Spec Delta

## Purpose

記事をRSS 2.0として出力し、RSSを読む既存のアプリから、カテゴリごと、または全体をまとめて購読できるようにする。
RSSは読み取り専用の出口であり、既読やスターの状態は扱わない。

## ADDED Requirements

### Requirement: カテゴリごとのRSS

カテゴリの識別名を指定したRSSの要求を受けたとき、サーバーはそのカテゴリの記事をRSS 2.0として返さなければならない（MUST）。

#### Scenario: カテゴリを購読する

- **WHEN** 識別名 `security` のカテゴリのRSSを要求する
- **THEN** サーバーは、`channel` のタイトルがカテゴリの名前で、そのカテゴリの記事だけを含むRSS 2.0を返す

### Requirement: 全体のRSS

全体のRSSの要求を受けたとき、サーバーはすべての有効なカテゴリの記事を1つのRSS 2.0として返さなければならない（MUST）。

#### Scenario: すべてをまとめて購読する

- **WHEN** 記事のあるカテゴリが3つある状態で、全体のRSSを要求する
- **THEN** 3つのカテゴリの記事が1つのRSSに含まれ、各項目にカテゴリの名前が付く

### Requirement: 項目の内容

サーバーは、RSSの各項目に、記事のタイトル、主な出典のURL、公開日時、要約、本文、すべての出典へのリンクを含めなければならない（MUST）。

#### Scenario: 出典が2つある記事

- **WHEN** 出典が2つある記事を含むRSSを要求する
- **THEN** その項目の `link` は主な出典のURLで、`content:encoded` には本文のHTMLと2つの出典へのリンクが含まれる

### Requirement: 読み手への影響と未確認の印の出力

記事に読み手への影響または未確認の印があるとき、サーバーはそれらをRSSの項目の本文に含めなければならない（MUST）。

#### Scenario: 未確認の記事

- **WHEN** 未確認の印のある記事を含むRSSを要求する
- **THEN** その項目の本文の先頭に、未確認であることが書かれている

### Requirement: 件数と並び順

サーバーは、RSSに最終更新の新しい順で最大50件の記事を含めなければならない（MUST）。

#### Scenario: 記事が多い

- **WHEN** 記事が80件あるカテゴリのRSSを要求する
- **THEN** 最終更新の新しい50件が、新しい順に含まれる

### Requirement: 更新された記事の再配信

記事が更新されたとき、サーバーはRSSのその項目に、更新前と異なる `guid` と、更新を示す印の付いたタイトルを持たせなければならない（MUST）。

#### Scenario: 続報で更新された記事

- **WHEN** 配信済みの記事が続報で更新されたあとにRSSを要求する
- **THEN** その項目の `guid` は更新前と異なり、タイトルの先頭に更新を示す印が付き、公開日時は更新の時刻になる

### Requirement: 更新のない記事の識別子の安定

記事が更新されていない間、サーバーはその項目の `guid` を変えてはならない（MUST NOT）。

#### Scenario: 2回続けて取得する

- **WHEN** 記事が変わらない状態で、RSSを2回要求する
- **THEN** 2回の応答で、各項目の `guid` は一致する

### Requirement: イベントのRSS

種別がイベントのカテゴリのRSSについて、サーバーは終了したイベントの記事を含めてはならない（MUST NOT）。

#### Scenario: 終了したイベント

- **WHEN** 昨日終了したイベントと明日のイベントの記事がある状態で、RSSを要求する
- **THEN** 明日のイベントの項目だけが含まれ、本文の先頭に開催日時と会場が書かれている

### Requirement: RSS用のトークン

正しいRSS用のトークンを `token` パラメーターに持たないRSSの要求を受けたとき、サーバーはHTTPステータス401を返さなければならない（MUST）。

#### Scenario: トークンがない

- **WHEN** `token` パラメーターなしでRSSを要求する
- **THEN** サーバーはHTTPステータス401を返し、記事を返さない

### Requirement: RSS用のトークンの権限

RSS用のトークンを付けたAPIの要求を受けたとき、サーバーはその要求を拒否しなければならない（MUST）。

#### Scenario: RSS用のトークンで設定を変えようとする

- **WHEN** RSS用のトークンを `Authorization` ヘッダーに付けて、カテゴリの変更を要求する
- **THEN** サーバーはHTTPステータス401を返し、カテゴリは変わらない

### Requirement: 妥当なXML

サーバーは、記事のタイトルや本文にXMLの特殊な文字が含まれていても、妥当なXMLのRSSを返さなければならない（MUST）。

#### Scenario: 特殊な文字を含むタイトル

- **WHEN** タイトルに `<`、`&`、引用符を含む記事があるRSSを要求する
- **THEN** 応答はXMLとして解析でき、解析したタイトルは元のタイトルと一致する

### Requirement: 存在しないカテゴリ

存在しない識別名のRSSの要求を受けたとき、サーバーはHTTPステータス404を返さなければならない（MUST）。

#### Scenario: 識別名の誤り

- **WHEN** 登録されていない識別名のRSSを要求する
- **THEN** サーバーはHTTPステータス404を返す
