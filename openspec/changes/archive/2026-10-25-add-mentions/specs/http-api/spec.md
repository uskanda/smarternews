# Spec Delta

## ADDED Requirements

### Requirement: 記事の詳細での抜き出した名前の提供

記事の詳細の要求を受けたとき、APIは、その記事の抜き出した名前を、名前と種類の組の一覧として返さなければならない（MUST）。
一覧は、保存した順に並べる。抜き出した名前のない記事では、空の一覧を返す。
種類は、人、組織、製品、地名を表す決まった値のいずれかである。

#### Scenario: 名前のある記事

- **WHEN** 種類が組織の名前と種類が人の名前を、この順で抜き出した生成記事の詳細を要求する
- **THEN** 応答の抜き出した名前は2件で、組織の名前、人の名前の順である

#### Scenario: 名前のない記事

- **WHEN** 自動の要約が無効な購読フィードの配信記事の詳細を要求する
- **THEN** 応答の抜き出した名前は空の一覧である

### Requirement: 名前の記事の一覧の操作

APIは、名前を受けて、その名前の記事の一覧を返す操作を提供しなければならない（MUST）。
各記事は、記事の一覧と同じ項目で返す。受けた名前は、同じ名前の判定と同じ規則で正規化してから照らし合わせる。

#### Scenario: 名前で一覧を求める

- **WHEN** 名前として日本銀行を抜き出した生成記事と配信記事が1件ずつある状態で、日本銀行を名前にして操作を呼ぶ
- **THEN** 応答に2件の記事が含まれ、各記事に由来の項目がある

#### Scenario: 全角で名前を渡す

- **WHEN** 名前 `OpenAI` を抜き出した記事がある状態で、全角の `ＯｐｅｎＡＩ` を名前にして操作を呼ぶ
- **THEN** その記事が応答に含まれる

#### Scenario: どの記事にもない名前

- **WHEN** どの記事も抜き出していない名前で操作を呼ぶ
- **THEN** APIは、空の一覧を成功として返す

### Requirement: 名前の記事の一覧の分割

名前の記事の一覧が1回の件数の上限を超えるとき、APIは続きを取得するための値を返さなければならない（MUST）。

#### Scenario: 続きを取得する

- **WHEN** 同じ名前を抜き出した記事が120件ある状態で、1回の件数を50にして一覧を求め、返された値で続きを2回要求する
- **THEN** 50件、50件、20件が重複なく、最終更新の新しい順で返り、最後の応答には続きの値がない

### Requirement: 名前の入力の拒否

空の名前、または正規化したあとで100文字を超える名前で名前の記事の一覧を求められたとき、APIは要求を拒否し、誤っている項目を返さなければならない（MUST）。
空白だけの名前は、空の名前として扱う。

#### Scenario: 空白だけの名前

- **WHEN** 空白だけの名前で名前の記事の一覧の操作を呼ぶ
- **THEN** APIはHTTPステータス400と、名前の項目が誤っていることを返す

#### Scenario: 長すぎる名前

- **WHEN** 101文字の名前で名前の記事の一覧の操作を呼ぶ
- **THEN** APIはHTTPステータス400を返す
