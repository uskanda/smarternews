# Design

## Context

色の値は `DESIGN.md` の先頭にあり、`scripts/design-tokens.ts` がWebのCSSとアプリの値を書き出す。
暗い配色の値は、名前の末尾に `-dark` を付けて持っている。
Webは `prefers-color-scheme` だけで配色を切り替える。アプリは端末の配色の設定だけを読む。
Webのページは、同じ配信元のスクリプトだけを実行できる。ページの中に直接書いたスクリプトは実行されない。

## Goals / Non-Goals

**Goals:**

- 色の値の出どころを `DESIGN.md` の1か所に保ち、3つの配色を同じ仕組みで書き出す。
- Webで、保存した配色を最初の描画より前に適用する。

**Non-Goals:**

- 利用者が色を自由に作ること。
- 配色をサーバーに保存すること。

## Decisions

### いまの暗い配色の値を改名し、「ダーク」を足す

`DESIGN.md` の `-dark` の値を `-darkblue` に改名する。値は変えない。
新しい「ダーク」の値を `-dark` の名前で足す。色相を持たない黒と灰で作る。
候補の値は次のとおりである。`designmd lint` のコントラストの検査に通らない値は、通るまで直す。

| 役割 | 値 |
|---|---|
| `background-dark` | `#121212` |
| `surface-dark` | `#1B1B1B` |
| `on-surface-dark` | `#E8E8E8` |
| `on-surface-muted-dark` | `#A6A6A6` |
| `outline-dark` | `#303030` |
| `outline-strong-dark` | `#757575` |
| `selected-dark` | `#2A2A2A` |
| `primary-dark` | `#A9BEFF` |
| `on-primary-dark` | `#121212` |

印の色（`mark`、`mark-fill`、`warning`、`error`）は、「ダークブルー」の値をそのまま使う。意味を持つ色なので、配色ごとに変えない。
改名せずに「ダーク」を別の名前で足す方式は、`-dark` が「ダークブルー」を指すことになり、読み手が取り違える。

### Webは、根の要素の属性で配色を決める

書き出すCSSは次の形にする。

- `:root` に「ライト」の値を置く。
- `@media (prefers-color-scheme: dark)` の中で、属性のない `:root` に「ダークブルー」の値を置く。
- `:root[data-theme="dark"]` に「ダーク」、`:root[data-theme="darkblue"]` に「ダークブルー」の値を置く。
- `:root[data-theme="light"]` は「ライト」の値のままにし、`color-scheme` だけを明るい側に決める。

「端末に従う」は属性を付けない。保存する値は `light`、`dark`、`darkblue` で、キーは `<smarternews.theme>` とする。「端末に従う」のときはキーを消す。

### 最初の描画より前の適用は、別ファイルの小さなスクリプトで行う

`apps/web/public` に `<theme.js>` を置き、`index.html` の `head` から読み込む。保存した値を読み、根の要素に属性を付けるだけの数行にする。
ページに直接書くスクリプトは、配信の設定で禁止している。同じ配信元の別ファイルなら実行でき、描画より前に動く。
アプリの本体が起動してから属性を付ける方式は、暗い配色を選んだ利用者に、明るい配色が一瞬見える。

### アプリは、配色の選択を1つの保存場所から読む

`apps/mobile/src/theme` に、選択を保存して知らせる小さな保存場所を足す。端末の保存には、すでに使っている `AsyncStorage` を使う。
`useTheme` は、選択と端末の設定から配色を決める。色を使う部品は `useTheme` だけを読んでいるので、部品の側は変えない。
保存した値を読むまでの間は、「端末に従う」で表示する。起動の画面は端末の配色に従うので、切り替わりは小さい。

### 選ぶ操作は、4つの中から1つを選ぶ部品にする

Webは `radiogroup` の役割を持つ部品にし、矢印キーで選べるようにする。アプリは、通知の設定と同じ並びの選択肢にする。

## Risks / Trade-offs

- 色の値を直接書いている箇所があると、新しい配色で読めなくなる → `rg` で16進の色の値を探し、QRコード以外に無いことを確かめる。
- 「ダーク」の候補の値がコントラストの基準に届かない → `designmd lint` の警告を読み、値を直す。候補の値は出発点である。
- このスクリプトを読めないとき → 属性は付かず、画面は「端末に従う」で表示される。画面は使える。

## Migration Plan

- 保存済みのデータはない。配色を選んでいない利用者の表示は、いまと変わらない。
