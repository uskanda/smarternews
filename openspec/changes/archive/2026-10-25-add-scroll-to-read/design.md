# Design

## Context

動機は`proposal.md`のWhyを参照する。決定は`grilling.md`にある。

既読を書き換える処理は `packages/core/src/db/articles.ts` にある。

- `setArticleFlags`: `PATCH /api/v1/articles/:id`。1件ずつの既読の変更で、開いた記事、`m` のキー、アプリの行を払う操作が通る。未読だった行にだけ `read_at` を入れ、`readDuplicatesOf` で重複も既読にする
- `markArticlesRead`: `POST /api/v1/articles/mark-read`。カテゴリなどの範囲と `before` で一括の既読を行う。`read_at` を入れ、重複も既読にし、識別子を返す
- `markArticlesUnread`: `POST /api/v1/articles/mark-unread`。識別子の一覧で未読に戻す

続報で生成記事を書き換える処理は、`is_read = 0`、`read_at = NULL` に戻し、`updated_at` を進める。
一覧の各行の `updatedAt` は、画面がその行を描いたときの版を表す。

Webの記事の一覧は `apps/web/src/reader/ReaderPage.tsx` の `data-list-scroll` の要素で、行を仮想化せずにすべて描く。続きは「さらに読み込む」のボタンで読み込む。
読んだ記事を一覧に残す処理は、`kept` と `mergeKept` が受け持つ。`listKey` が変わるか `refresh` で消える。
アプリの記事の一覧は `apps/mobile/src/reader/ListScreen.tsx` の `FlatList` で、行は仮想化される。イベントの一覧は `SectionList` である。残す処理は `useReaderList.ts` の `session.keep` が受け持つ。
配色の選択は、Webでは `apps/web/src/lib/theme.ts` が `localStorage` へ保存する。アプリでは `apps/mobile/src/theme/store.ts` が `AsyncStorage` へ保存する。キーは `packages/client/src/theme.ts` の `THEME_STORAGE_KEY` で共有する。

## Goals / Non-Goals

**Goals:**

- 既読の時刻（#51）と重複の既読の連動（#58）を、今のサーバーの処理と同じ経路で働かせる。画面からは時刻を送らない。
- 素早く送っても、1行ずつ要求を送らずに済ませる。
- 上端を越えたかどうかの判定と、まとめて送る処理を、Webとアプリで同じ1つの実装にする。

**Non-Goals:**

- 本文の画面のスクロールで既読にすること。対象は記事の一覧だけである。
- 設定をサーバーへ同期すること（第1ラウンドQ4）。
- 一定の時間の表示で既読にすること（第1ラウンドQ2で採らなかった）。
- 移行。データの形は変えない。

## Decisions

### 既読は、識別子と表示した版の組をまとめて送る

`POST /api/v1/articles/mark-read` に、今の範囲の形とは別の本文の形を足す。

```json
{ "articles": [{ "id": 12, "updatedAt": "2026-10-25T09:00:00.000Z" }] }
```

- `articles` があるときは新しい形、ないときは今の範囲の形として検証する。両方の項目を混ぜた本文は400で断る
- 1回に並べられるのは1件以上500件以下。超えると400を返す
- 応答は今と同じ `{ updated, ids }`。`ids` には連動した重複を含める

`packages/core` には `markSeenArticlesRead(db, items, now)` を足す。1つのトランザクションで、各組について次の文を流す。

```sql
UPDATE articles SET is_read = 1, read_at = ? WHERE id = ? AND is_read = 0 AND updated_at <= ? RETURNING id
```

既読にした行では `readDuplicatesOf` を呼ぶ。
存在しない識別子は0行の更新になるだけなので、404にしない。180日の削除で消えた記事が混ざっても、残りは既読になる。
フィルターで隠れた記事の扱いは、1件ずつの既読の変更と同じにする。並べた記事は画面に出ていたものなので、隠れているかどうかは見ない。

採らなかった案は次のとおり。

- 1件ずつ `PATCH /articles/:id` を送る案。素早く30行を送ると30回の要求と30回の未読数の取得になる。続報の版も確かめられない
- 識別子と1つの `before` を送る案。一括の既読と同じ形にできる。ただし、まとめた行のうち最も新しい版より前に続報が届いた記事を既読にしてしまう。組ごとの版なら、その記事だけを残せる
- 新しいパスを作る案。既読の経路が1つのパスに集まっている今の形を崩すだけである

### 上端を越えた行の判定は、前回の位置との差で行う

`packages/client` に、画面の部品に依存しない判定を置く（`packages/client/src/scroll-read.ts`）。

- 入力は、今の行の並び（識別子）と、「全体が上端より上へ出ていない最初の行」の位置である
- 前回の判定で上端より下にあった行のうち、今回は上へ出た行を「越えた行」として返す
- 前回の判定で見ていない行は、上にあっても越えた行にしない

位置だけで判定すると、定期的な再取得で一覧の先頭に足された新しい記事が、見られないまま上端より上に置かれて既読になる。前回との差で判定すれば、この記事は越えた行にならない。
素早く送って1度も表示範囲に入らなかった行も、前回は上端より下にあったので、越えた行になる（第2ラウンドQ3）。

Webでは、一覧の要素の `scroll` を `requestAnimationFrame` で間引いて判定する。行は仮想化していないので、各行の `offsetTop + offsetHeight` と `scrollTop` を比べて、全体が上へ出ていない最初の行を2分探索で求める。
`j` の追随で一覧が送られたときも `scroll` が起きるので、同じ判定に入る。

アプリでは、`FlatList` の `onViewableItemsChanged` で、少しでも見えている最初の行の位置を受け取る。行は仮想化されるので、位置ではなく並びの順で判定する。
`viewabilityConfig` は `itemVisiblePercentThreshold: 0` にして、下の端だけ見えている行も「見えている」と扱う。

採らなかった案は `IntersectionObserver` で行ごとに見張る案である。1回の描画で表示範囲を飛び越えた行は交差の変化が起きず、素早いスクロールを取りこぼす。

### 対象は、未読で、利用者が未読に戻していない行だけにする

越えた行のうち、次の行は送らない。

- すでに既読の行
- 今の一覧の表示の間に、利用者が未読に戻した行。Webの `setRead`、アプリの `useReaderList` の `setRead` で、未読への変更を受けた識別子を除外の集合に入れる。集合は、残す処理と同じく `listKey` が変わるか更新で消す

除外しないと、未読に戻した記事が、次に送った時点でまた既読になる。最近読んだ記事の一覧（#51）から戻した記事も、この一覧はもともと対象外なので、ここでは問題にならない。
除外は一覧を読み直すまで続け、更新か別の項目への移動で解く（第3ラウンドQ2）。

### 送る前に画面を先に変え、まとめて送る

越えた行は、その場で既読の見た目にし、`kept` と `session.keep` で一覧に残す。記事の詳細のキャッシュも既読にする。
送る処理は `packages/client` の `createReadQueue` にまとめる。時計と待ち時間の仕組みは差し替えられるようにして、テストで動かす。

- 越えた行が来てから1秒、新しい行が来なければ送る
- たまった行が100件に達したら、すぐに送る
- 一覧を離れるときは、待たずに送る。Webでは、`listKey` が変わるとき、`pagehide` のとき、`visibilitychange` で隠れたときである。アプリでは、別の一覧へ移るときと、`AppState` が背面に移るときである
- Webで `pagehide` のときは、`fetch` の `keepalive` を付けて送る。`packages/client` の `request` に `keepalive` を渡せるようにする

応答が来たら、未読数と最近読んだ記事の一覧を取り直す。
失敗したら、その組の行を未読の見た目に戻し、「スクロールした記事を既読にできませんでした」とやり直す操作を、Webでは `shell/toast.tsx`、アプリでは `ui/toast.tsx` で出す。やり直すと、同じ組をもう一度送る。
成功のときは知らせを出さない（第2ラウンドQ4）。

### 末尾の余白は、一覧の表示範囲の高さにする

設定が有効なときだけ、一覧の末尾に、一覧の表示範囲と同じ高さの空の要素を置く。これで最後の行も上端より上へ出せる（第2ラウンドQ2）。

- Webでは、「さらに読み込む」のボタンの下に置く。高さは `ResizeObserver` で一覧の要素の `clientHeight` に合わせる
- アプリでは、`ListFooterComponent` の下に置く。高さは `FlatList` の `onLayout` で受け取る。余白のぶん末尾が遠くなるので、`onEndReachedThreshold` を余白の高さだけ足した値（表示範囲の1.5倍）にして、続きの読み込みの時機を今と同じにする

### 対象にしない一覧

最近読んだ記事の一覧、検索の結果の画面、イベントの一覧では、判定を動かさない。末尾の余白も置かない。

- 最近読んだ記事の一覧は、誤って既読にした記事を未読に戻す場所である。送っただけで既読に戻ると、戻す操作が働かない
- 検索の結果の画面は、一括の既読も出さない（「検索の結果での一括の既読の無効」）。探すために送った行を既読にしない
- イベントの一覧は、開催日の順に先の予定を眺める画面である。読み飛ばしの意味が違う

第3ラウンドQ1で、この3つを対象にしないと決めた。

### 設定は端末に保存し、配色の選択と同じ区画に置く

保存のキーは `packages/client` に `SCROLL_READ_STORAGE_KEY = "smarternews.scrollRead"` として置き、Webとアプリで共有する。有効のときは `"on"` を保存し、無効のときはキーを消す。読めない値は無効とする。

- Webは `apps/web/src/lib/scroll-read.ts` を足す。`theme.ts` と同じく `useSyncExternalStore` で購読し、`localStorage` が使えないときは無効にする
- アプリは `apps/mobile/src/settings/scroll-read.ts` を足す。`theme/store.ts` と同じく、起動時に1度読む。読み終わるまでは無効として扱う
- 接続の解除では消さない。配色の選択と同じく、端末の設定であってサーバーの設定ではないからである

設定の画面では、今の「配色」の区画を「この端末の設定」の区画に置き換える。

- Webでは、区画の見出しを「この端末の設定」にし、配色の選択の操作と、チェックボックス「スクロールした記事を既読にする」を並べる。区画の説明には、この区画の設定をこのブラウザーだけに保存することを書く。配色の選択の操作には、今と同じく `aria-describedby` でこの説明を付ける
- アプリでは、`Section` の題を「この端末の設定」にし、配色の `Choice` と、`Toggle` の「スクロールした記事を既読にする」を並べる。説明には、この端末だけに保存することを書く
- 区画の位置は、今の配色の区画の位置のままにする
- アプリの「通知」の区画は動かさない（第3ラウンドQ3）。通知の設定も端末ごとに保存しているが、移すのは配色の選択だけにして、変える範囲を狭く保つ

## Risks / Trade-offs

- 見出しを読まずに一気に送ると、多くの記事が既読になる → 既定は無効で、利用者が選んだときだけ動く。誤った既読は最近読んだ記事の一覧から戻せる
- 送る前にタブを閉じると、既読の要求は届かないことがある → `keepalive` で送る。届かなかった記事は未読のまま残るだけで、既読の時刻は食い違わない
- Webで行の位置を毎回測ると、長い一覧で重くなる → `requestAnimationFrame` で間引き、2分探索で最初の行だけを求める。前回の位置より前の行は測り直さない
- アプリの仮想化で、描いていない行の位置は分からない → 並びの順で判定するので、位置は要らない。速く払っても、最初に見えている行の順番が進めば、その前の行はすべて越えた行になる
- 続報で更新された記事を、古い版のまま既読にしてしまう → 組ごとの `updatedAt` で、サーバーが新しい版を既読にしない
- Webの設定の画面のテストは、区画の名前「配色」で探している → 区画の名前を変えるのに合わせて、テストの探し方を直す。配色の選択の操作の名前「配色」は変えない

## Migration Plan

移行はない。サーバーと画面を同じ版で出す。
古いアプリは新しい本文の形を送らないので、そのまま動く。新しいアプリが古いサーバーにつないだときは400になり、行が未読の見た目に戻って失敗が表示される。自宅の1台で同時に入れ替えるので、この組み合わせは長く続かない。
戻すときは、前の版のサーバーと画面に戻す。保存した設定のキーは、前の版では読まれずに残るだけである。
