# Proposal

## Why

配信記事の本文の画像は、利用者の端末が取得先のサイトから直接読み込んでいる。
取得先には、端末のアドレスと、記事を開いた事実と時刻が伝わる。
また、端末が暗号化せずに要求しないよう、`http:` の画像は保存のときに取り除いている。
サーバーが画像を中継すれば、取得先に伝わるのはサーバーからの要求だけになり、`http:` の画像も安全に表示できる（#66）。

## What Changes

- サーバーに画像の中継を足す。画面とアプリが表示する画像は、すべてサーバーの中継を通して読み込む。無効にする設定は置かない。
- 中継は、表示のたびに取得先から画像を取得して返し、ディスクに置く。置く期間の既定は7日、合計の上限の既定は1GBで、どちらも `config.yaml` で変えられる。上限を超えたら古い画像から消す。
- 中継の取得には、今の取得の制限（方式とアドレスの制限、リダイレクト先の検査、時間の上限、User-Agent）を適用する。1枚の上限は10MBとする。画像の形式でない応答とSVGは拒否する。robots.txtは適用しない。
- 中継のURLには、サーバーが署名を付ける。署名の合わないURLは中継しない。署名に期限は設けない。署名の鍵は、サーバーが初めて起動したときに作り、データのディレクトリに保存する。
- APIは、配信記事の内容を返すときに、画像のURLを中継のURLに書き換える。保存する内容には元のURLを残す。
- 中継のURLは、トークンなしで受け付ける。`img` の要素はトークンのヘッダーを送れないため、署名で守る。
- **BREAKING**（振る舞い）: 配信記事の内容の `http:` の画像を、保存のときに取り除かない。
- **BREAKING**（振る舞い）: 画面のContent-Security-Policyで、画像の読み込みを同じオリジンだけに絞る。他のサイトの画像を直接読み込まなくなる。
- アプリは、中継のURLの画像だけを読み込む。`http:` の画像も、中継を通して表示する。
- 画像を取得できないとき、画面とアプリは画像の説明の文字（`alt`）を出す。これは今の振る舞いのまま変えない。

## Capabilities

### New Capabilities

- `image-proxy`: サーバーによる画像の中継。署名の検査、署名の鍵の生成、取得の制限、ディスクに置く期間と量、取得先への要求での情報の秘匿

### Modified Capabilities

- `web-shell`: 画像の読み込みの制限を、同じオリジンだけを許すContent-Security-Policyに変える
- `feed-subscriptions`: 内容の変換で、`http:` の画像を取り除かずに残す
- `http-api`: 配信記事の内容の画像のURLを中継のURLに書き換えることと、中継のURLをトークンなしで受け付けることを足す
- `mobile-reader`: 暗号化されていない画像を読み込まない要件を除き、中継のURLの画像だけを読み込む要件を足す

## Impact

- `packages/core`: 取得の処理に、画像を取得する経路を足す。画像の中継、署名、ディスクへの保存と削除を足す。`config.yaml` のスキーマに、置く期間と量の設定を足す。内容の変換で `http:` の画像を残す。Markdownの表示で、画像は中継のURLのものだけを読み込む。
- `apps/server`: 中継の入口を足す。APIの記事の応答で画像のURLを書き換える。署名の鍵を起動時に作る。Content-Security-Policyの `img-src` を変える。置いた画像の削除を定期的に動かす。
- `packages/client`、`apps/web`、`apps/mobile`: 中継のURLをサーバーのURLで解決して読み込む。アプリは、中継のURL以外の画像を読み込まない。
- `docs/`: 中継の入口と、`config.yaml` の設定を書く。`examples/config.yaml` に設定の例を足す。
- データのディレクトリに、署名の鍵のファイルと、置いた画像のディレクトリが増える。
- LLMは呼ばない。翻訳のAPIに送る文字数も変わらない。
- 全文の取得（#52）、表示形式のサムネイル（#49）、ニュースレター（#62）の画像も、この中継を通す。
