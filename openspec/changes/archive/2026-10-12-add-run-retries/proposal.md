# Proposal

## Why

実行が失敗すると、そのカテゴリは次の定時まで記事が作られない。失敗が一時的な原因でも同じである。
サーバーが実行の途中で止まると、実行中の1件に加えて、順番を待っていた実行もすべて「失敗」になる。再起動しても再開されない。
失敗した実行を、回数を限ってやり直す。止まったサーバーが起動したときは、待っていた実行を再開する。

## What Changes

- 定時の実行が「失敗」で終わったとき、サーバーは時間を置いてやり直す。やり直しは2回までとし、1回目は10分後、2回目は30分後に行う。
- やり直しの回数は `config.yaml` で0回から3回の範囲で変えられる。0回にすると、やり直さない。
- 「一部失敗」と「上限で停止」の実行は、やり直さない。手動の実行も、やり直さない。
- 起動のとき、順番を待っていた実行は、順番待ちへ戻して再開する。回数には数えない。
- 起動のとき、実行中のまま残っていた実行は、いまと同じく「失敗」にする。定時の実行であれば、1回分として数えたうえで、すぐにやり直す。
- やり直しを待つ間に、同じカテゴリの次の定時の実行が始まったら、やり直しを取りやめる。
- やり直しは、実行履歴に別の行として記録する。何回目のやり直しか、元の実行はどれかを持つ。
- Webの実行履歴の画面に、やり直しであること、やり直しの予定の時刻、上限に達したことを表示する。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `runs`: 失敗した実行のやり直し、回数の上限、取りやめの条件を足す。中断された実行の後始末を、再開とやり直しを含む内容に変える
- `http-api`: 実行の、やり直しの回数、元の実行、予定の時刻を返す項目を足す
- `web-runs`: やり直しの表示を足す

## Impact

- `packages/core`: 移行で実行履歴の表に列を足す。やり直しの予定と実行、起動のときの再開、設定の項目を足す。
- `apps/server`: 起動のときの後始末を変える。やり直しを定期的に確かめる。
- `apps/web`: 実行履歴の画面の表示を変える。
- `docs/api.md`、`docs/providers.md`、`examples/config.example.yaml`、`README.md`、`README.ja.md`: やり直しの説明と設定を足す。
- LLMの利用枠は、失敗が続くカテゴリで最大3回分を使う。やり直しも、実行あたりと1日あたりの上限に従う。
