## ADDED Requirements

### Requirement: 止まった上限の種類の記録

実行が「上限で停止」で終わったとき、サーバーはその実行履歴に、止まった上限の種類を記録しなければならない（MUST）。
種類は、実行あたりの呼び出しの上限、1日あたりの呼び出しの上限、月の予算のいずれかとする。

#### Scenario: 実行あたりの上限で止まる

- **WHEN** 実行あたりの呼び出しの上限に達して、実行が「上限で停止」で終わる
- **THEN** その実行履歴の止まった上限の種類は、実行あたりの呼び出しの上限である

#### Scenario: 月の予算で止まる

- **WHEN** 予算の期間の合計が月の予算に達して、実行が「上限で停止」で終わる
- **THEN** その実行履歴の止まった上限の種類は、月の予算である

#### Scenario: 上限で止まらない実行

- **WHEN** 実行が「成功」で終わる
- **THEN** その実行履歴の止まった上限の種類は空である

## MODIFIED Requirements

### Requirement: やり直しと上限

やり直しの実行も、実行あたりの呼び出しの上限、1日あたりの呼び出しの上限、月の予算に従わなければならない（MUST）。

#### Scenario: 上限に達した日のやり直し

- **WHEN** その日の呼び出し回数が1日の上限に達した状態で、やり直しが始まる
- **THEN** やり直しは「上限で停止」で終わり、それ以上はやり直されない

#### Scenario: 予算に達した期間のやり直し

- **WHEN** 予算の期間の合計が月の予算に達した状態で、`anthropic` のプロバイダーを使うやり直しが始まる
- **THEN** やり直しは「上限で停止」で終わり、それ以上はやり直されない
