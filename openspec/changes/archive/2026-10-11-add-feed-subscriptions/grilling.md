# grilling 記録: add-feed-subscriptions

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 一覧の混ぜ方 | カテゴリを選ぶと生成記事と配信記事を混ぜて表示する。カテゴリの下に「AI生成」と各購読フィードを並べる。上段の「未読」「すべて」「スター」も両方を混ぜ、全カテゴリの生成記事だけを見る「AI生成」を上段に足す | 第1ラウンド Q1（A） |
| 配信記事の本文 | 段落、見出し、リスト、リンクなどの書式つきで表示し、画像も表示する。元のページを取りに行く全文の表示は入れない | 第1ラウンド Q2（B） |
| AIの収集との関係 | 購読フィードはそのまま読むだけにし、トピックの候補には使わない | 第1ラウンド Q3（A） |
| カテゴリとの関係 | カテゴリに属さない購読フィードも許し、左の一覧に「未分類」を出す | 第1ラウンド Q4（B） |
| OPMLの読み込み | フォルダーの名前とカテゴリの名前を突き合わせ、なければトピックのないニュースのカテゴリを作る。入れ子は最上位のフォルダーにまとめる。購読済みのURLは飛ばし、何も削除しない | 第1ラウンド Q5 |
| OPMLの書き出し | カテゴリをフォルダーにして、購読フィードだけを書き出す。トピックのフィードは含めない | 第1ラウンド Q5 |
| OPMLの操作の場所 | Webの設定、API、コマンド | 第1ラウンド Q5 |
| 設定ファイルの範囲 | 設定ファイルにも、購読フィード、取得周期、ストップワードを含める | 第1ラウンド Q5（A） |
| 取得周期 | 基本の値を全体設定に置き、既定は30分。購読フィードごとに上書きでき、範囲は5分から24時間。購読フィードごとに一時停止できる | 第1ラウンド Q6 |
| 失敗が続くとき | 取得の間隔を自動で延ばす。最大は24時間 | 第1ラウンド Q6 |
| 手動の取得 | 設定の画面に「いま取得」を置く | 第1ラウンド Q6 |
| 取得の失敗の見せ方 | 実行履歴には載せず、設定の画面の購読フィードごとに、最後の取得、最後の成功、直近の失敗の理由を出す | 第1ラウンド Q6（A） |
| ストップワードの適用先 | 配信記事だけ。生成記事には適用しない | 第1ラウンド Q7（A） |
| ストップワードの指定 | 全体で1つの一覧。語ごとに「タイトルだけ」か「タイトルと内容」を選ぶ。部分一致で、大文字と小文字、全角と半角を区別しない。正規表現は使わない | 第1ラウンド Q8（A） |
| 隠した記事の扱い | 削除せずに持ち、語を外すと戻る。語を足すと保存済みの記事にも適用する。未読数に数えない。スターのある記事は隠さない。設定の画面に語ごとの隠している件数を出す | 第1ラウンド Q8（A） |
| 購読した直後の記事 | 配信されている記事をすべて未読にする | 第1ラウンド Q9（A） |
| 配信記事の保存期間 | スターのない配信記事は90日で削除し、スターのある配信記事は残す | 第1ラウンド Q10（A） |
| アプリの範囲 | 読む側だけ対応する。購読フィードの追加と編集、OPML、ストップワードはWebの設定だけに置く | 第1ラウンド Q11（A） |
| 配信記事の通知 | 通知しない。通知の設定の文言を「AI生成のすべての新着」に直す | 第1ラウンド Q11（A） |
| 画像の読み込み方 | 読む端末が配信元のサイトから直接読み込む。HTTPSの画像だけを出し、遷移元のURLは送らない。動画と埋め込みの枠は表示しない | 第2ラウンド Q12（A） |
| 一覧の行の画像 | 出さない。画像は本文にだけ出す | 第2ラウンド Q13（A） |
| 「未分類」の出し方 | カテゴリのない購読フィードが1つ以上あるときだけ、カテゴリの並びの最後に出す。下には各購読フィードだけを並べる | 第2ラウンド Q14（A） |
| フォルダーのないフィード | OPMLでフォルダーのないフィードは、カテゴリなしで登録する | 第2ラウンド Q14（A） |
| 属せるカテゴリの種別 | 購読フィードが属せるのは、種別がニュースのカテゴリだけ | 第2ラウンド Q14（A） |
| トピックのないカテゴリ | 作れる。定時の実行をしない | 第2ラウンド Q14（A） |
| カテゴリの削除 | そのカテゴリの購読フィードは削除せず、カテゴリなしに移す | 第2ラウンド Q14（A） |
| LLMの呼び出し | 購読フィードの取得、保存、非表示の判定はプログラムで行い、LLMを呼ばない | 第1ラウンドの前提（会話中に確認） |
| RSSの出力 | smarternewsが出すRSSに配信記事を含めない | 第1ラウンドの前提（会話中に確認） |
| 取得の作法 | 取得先の制限、ホストごとの間隔、User-Agentを適用する。変更のないフィードは本文を受け取らない取得にする | 第1ラウンドの前提（会話中に確認） |
| 配信記事の重要度 | 持たない。重要度4以上の絞り込みでは生成記事だけが残る | 第1ラウンドの前提（会話中に確認） |
| 一覧の並び | 公開日時の新しい順。日時がない記事と未来の日時の記事は、取得した時刻で並べる | 第1ラウンドの前提（会話中に確認） |
| 内容の書き換え | 配信元があとで内容を書き換えても、既読の記事を未読に戻さない | 第1ラウンドの前提（会話中に確認） |
| 購読フィードの追加 | その場で1回取得し、フィードでなければ登録を断る。サイトのURLが入力されたときは、ページが指定するフィードを探す。同じURLの二重登録は断る | 第1ラウンドの前提（会話中に確認） |
| 購読フィードの削除 | その配信記事を、スターのあるものも含めて削除する。確認の表示に件数を出す | 第1ラウンドの前提（会話中に確認） |
| 古い項目の扱い | 取得のとき、保存期間の90日より古い項目は保存しない | 第2ラウンドの仮置き（会話中に確認） |

## 後回しにしたもの

- 画像をサーバーが代わりに取得して端末へ渡す方式（第2ラウンドのQ12のB）
- 一覧の行の小さな画像（第2ラウンドのQ13のB）
- カテゴリごと、購読フィードごとのストップワード（第1ラウンドのQ8のB）
- 生成記事と候補へのストップワードの適用（第1ラウンドのQ7のBとC）
- アプリからの購読フィードの追加と、購読フィードごとの通知（第1ラウンドのQ11のBとC）
- 元のページを取得して全文を表示する機能
- 記事の検索
