# grilling 記録: add-settings-shortcuts

質問と回答は、#118のissueのコメントで行った。質問は5つで、利用者はすべてに推奨の案（A）を選んだ。そのあと、計画を `/ok` で承認した。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 「ほかの設定」のリンク先の形 | A：ハッシュで指定する（`/settings/feeds#feed-12`）。開いたら、その行の編集を開き、そこまでスクロールする。ダイアログで保存していない切り替えは捨て、編集の欄は保存してある値から始める | 第1ラウンド Q1 |
| 設定の各行に置く、記事の一覧へのリンクの形 | A：「いま取得」「編集」「削除」の並びの先頭に、文字のリンク「記事の一覧」を置く。読み上げ用の名前は「〈フィード名〉の記事の一覧」。編集の欄を開いている間は、ボタンと一緒に隠れる | 第1ラウンド Q2 |
| 設定の画面の先頭に置く区画へのリンクの形 | A：見出しの下に横に並べ、幅が足りなければ折り返す。スクロールすると一緒に流れる。見た目はふつうのリンク（primary の色と下線）。ハッシュで開いたときのスクロールは、読み込みのあとにする | 第1ラウンド Q3 |
| 主となるボタンが3つある問題を扱うか | A：この変更で扱い、/settings の3つ（カテゴリの追加、読み手情報の保存、全体設定の保存）をすべて secondary にする。/settings/feeds の主ボタンは扱わない | 第1ラウンド Q4 |
| OpenSpecの記録の残し方 | A：新しい変更 `add-settings-shortcuts` を作り、web-settings と web-reader の spec の差分に要件とシナリオを足す | 第1ラウンド Q5 |
| 計画 | #118のissueに示した計画のとおりに進める | 計画の承認（`/ok`） |
