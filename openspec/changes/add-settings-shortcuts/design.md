# Design

## Context

購読フィードの設定のダイアログは `apps/web/src/reader/FeedOptionsDialog.tsx` にあり、3つの切り替えと「保存する」「やめる」を持つ。
add-feed-from-category（#79）で、このダイアログは3つの切り替えだけにすると決めた。
購読フィードの設定の画面は `apps/web/src/settings/FeedsPage.tsx` である。
各行の `FeedRow` は「いま取得」「編集」「削除」を並べ、「編集」を選ぶと行の中で `EditFeed` の欄を開く。`EditFeed` は開いたときに最初の入力欄へフォーカスを移す。
設定の画面は `apps/web/src/settings/SettingsPage.tsx` で、9つの区画が1ページに並ぶ。
プロバイダーの区画にだけ `id="providers"` があり、`useScrollToHash` が `/settings#providers` で開いたときにその区画までスクロールする。月の予算の警告がこのアドレスへリンクしている。

## Goals / Non-Goals

**Goals:**

- ダイアログから、購読フィードの残りの設定へ1回の操作で移れるようにする。
- 購読フィードの設定の画面の行から、その購読フィードの記事の一覧へ移れるようにする。
- 設定の画面で、目当ての区画へ1回の操作で移れるようにする。
- 設定の画面を、`DESIGN.md` の規則に合わせる。主となるボタンは、1画面に1つまでとする。

**Non-Goals:**

- ダイアログに名前や取得周期などを足すこと。#79の決定のまま、3つの切り替えだけにする。
- 購読フィードの設定の画面の主となるボタンの重なり。issueが挙げていないため扱わない。
- 区画のリンクを画面の上に固定すること。スクロールと一緒に流れる形を、会話で選んだ。

## Decisions

### 行の指定はアドレスのハッシュで行う

ダイアログの「ほかの設定」は `/settings/feeds#feed-<id>-edit` へのリンクにする。設定の画面の `/settings#providers` と同じ、ハッシュの形にそろえるためである。
別案のパラメーター（`?edit=12`）は、同じ画面に2つの仕組みができるので採らない。

計画の時点では `#feed-<id>` を使うつもりだった。その後、show-feed-fetch-stateがmainに入った。
この変更は、記事の一覧の上部の知らせから `/settings/feeds#feed-<id>` へリンクし、行の名前にフォーカスを移す動きを定めた。
同じアドレスで編集を開くと、その動きと食い違う。そこで、編集を開くアドレスには `-edit` を付けて分ける。`#feed-<id>` は行を示し、`#feed-<id>-edit` は行を示して編集も開く。

`FeedRow` の `<li>` に `id="feed-<id>"` を付ける。`FeedsPage` はアドレスのハッシュを読み、`-edit` の付いた行に `initiallyEditing` を渡す。`FeedRow` は、編集の欄を開いた状態から始める。
一覧を読み込んだあと、`FeedsPage` は行までスクロールする。`-edit` のときは編集の欄の最初の入力欄に、ないときは行の名前に、フォーカスを移す。一覧は読み込みのあとに描くので、行が出た時点のハッシュで決まる。

ダイアログのリンクは、選ぶとダイアログを閉じてから移る。値は保存しない。編集の欄は購読フィードの保存してある値から始まるので、保存していない切り替えは自然に捨てられる。

### スクロールの部品を共通にする

`SettingsPage.tsx` の中の `useScrollToHash` を `<apps/web/src/ui/useScrollToHash.ts>` に移し、2つの画面で使う。
引数の `ready` が真になってから、ハッシュの名前の要素へスクロールする。購読フィードの設定の画面では、一覧を読み込み終えたときに真にする。
設定の画面では、設定とプロバイダーの両方を読み込み終えたときに真にする。読み手情報と全体設定は、設定を読み込むまで表示されない。プロバイダーの区画は、読み込むと縦に伸び、下の区画の位置が変わる。
同じ区画のリンクを2回選んでも移れるように、ハッシュに加えてアドレスの `key` の変化でもスクロールする。

### 区画のリンク

設定の画面の `<header>` の見出しの下に、`<nav aria-label="設定の区画">` を置き、9つのリンクを `flex flex-wrap` で並べる。
見た目は、この画面のほかのリンクと同じ `tap text-primary underline underline-offset-4` にする。
各区画に、`categories`、`feeds`、`term-highlights`、`reader`、`global`、`device`、`settings-file`、`providers`、`tokens` のidを付ける。`providers` はいまのidのままにし、月の予算の警告のリンクを変えない。

### 行の「記事の一覧」

「いま取得」「編集」「削除」の並びの先頭に、`/f/<id>` へのリンク「記事の一覧」を置く。読み上げ用の名前は「〈名前〉の記事の一覧」とし、ボタンの「〈名前〉をいま取得」などにそろえる。
フィードの名前そのものをリンクにする案は、選ぶと何が起きるのかが見た目から分からないので採らない。
リンクはボタンの並びの中に置くので、編集の欄を開いている間は、ボタンと一緒に隠れる。

### 主となるボタンを外す

設定の画面の3つのボタンから `variant="primary"` を外し、ほかと同じ `secondary` にする。区画のリンクを足しても1画面であることは変わらず、特定の区画のボタンだけを目立たせる根拠もないためである。

## Risks / Trade-offs

- ［購読フィードの設定の画面を開いたまま、ハッシュだけを変えても、行の編集は開かない］→ `initiallyEditing` を読むのは、行を最初に描いたときだけである。ダイアログのリンクは別の画面から移るので、行は新しく描かれる。画面の中にハッシュを変えるリンクはないため、これで足りる。
- ［プロバイダーの読み込みに失敗すると、区画へのスクロールが待たされる］→ 失敗も読み込みの終わりとして扱い、`isPending` が偽になったら動く。
- ［主となるボタンがなくなり、保存のボタンが目立たなくなる］→ 区画ごとに保存のボタンが1つずつで、ほかに紛らわしい操作はない。`DESIGN.md` の規則に合わせることを優先する。
