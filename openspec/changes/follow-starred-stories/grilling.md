# grilling 記録: follow-starred-stories

GitHubのissueの227番のコメントで、1ラウンドの質問（Q1〜Q5）に答えてもらった記録である。
issueは、2026-11-13のWeb UIの監査の項目F-05である。続報を結び付ける相手は直近14日に更新した記事だけで、スターを付けた話題の続きが3週間後に出ても、前の記事とつながらない新しい記事になる。前の記事へのリンクは出るが、後の記事へのリンクはない。

この変更は、変更 `show-followup-changes` のQ4で後回しにした「この記事を参照するその後の記事の表示」も扱う。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 集約に渡すスター付きの記事 | A：スター付きの記事から後の記事をたどり、いちばん新しい記事を代わりに渡す。話題の連なりは1本のままにする | 第1ラウンド Q1 |
| 「続報」に数える範囲 | A：連なりを後ろにたどった全部。続報の続報も含め、新しい順に最大20件 | 第1ラウンド Q2 |
| 書き直しも通知するか | A：スター付きの記事そのものが72時間以内の続報で書き直されたときも、重要度にかかわらず通知する | 第1ラウンド Q3 |
| 一覧の行の印を出す条件 | A：未読の続報があるときだけ出す。読めば消える | 第1ラウンド Q4 |
| その後の記事を出す記事 | A：後の記事があるすべての生成記事に「この話題のその後の記事」を出す | 第1ラウンド Q5 |
| 計画の承認 | 上の答えに沿った計画を変更なしで承認 | issueへの返答（`/ok`） |

## 質問の前に示した前提

質問の前に、次の点は質問せずに決めると示した。利用者は異を唱えずに計画を承認した。

| 決定 | 選択 |
|---|---|
| 表示を変える画面 | Webだけ。Androidアプリは通知だけを変える（`show-followup-changes` のQ5と同じ分け方） |
| 集約に足すカテゴリの種類 | ニュースだけ。イベントは今のまま、終わっていない記事を渡す |
| 足す記事の範囲 | スター付きで更新から90日以内のものを、更新の新しい順に20件まで。14日以内の記事と重なる分は1件として数える |
| 通知の設定が「出さない」のとき | 通知しない |
| 通知の設定が「重要度5だけ」のとき | 要約の項目 `followsStarred` と一覧の絞り込み `starredStory` を足し、アプリはその条件でもう1回問い合わせて結果を合わせる |
| 保持期限 | 180日のままにする。90日より長いので、連なりの途中の記事は消えない |

## 選ばなかった案

- スター付きの記事そのものを常に集約に渡す案（Q1のB）。同じ話題の記事が2件渡り、連なりが枝分かれする
- 後の記事がないスター付きの記事だけを渡す案（Q1のC）。後の記事が14日を過ぎると話題が途切れる
- スター付きの記事を直接指す記事だけを続報に数える案（Q2のB）。2回目以降の続報が数えられない
- 新しい記事になった続報だけを通知する案（Q3のB）
- 続報が1件でもあれば印を出し続ける案（Q4のB）。新しい進展と見分けられない
- その後の記事をスター付きの記事にだけ出す案（Q5のB）。スターを外すと既存のリンクが消える
