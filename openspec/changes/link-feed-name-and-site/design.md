# Design

## Context

- APIの `Feed` は `siteUrl` を返しており、Webの `useFeeds` で使える。保存するときにhttpとhttpsに限っている（`packages/core/src/sources/feed.ts` の `siteLink`）。サイトのURLは、最初の取得が成功するまで空である。
- 本文の画面（`ArticleView`）の購読フィードの名前は `span` である。同じ画面の「ほかに配信した購読フィード」は、`listPathOf` で作った一覧の道へのリンクにしている。
- 今の一覧と画面の幅を知っているのは `ReaderPage` である。
- 購読フィードの一覧の上部の1段目には、一覧の名前の場所を残すためにボタンを足さない方針がある。

## Goals / Non-Goals

**Goals:**

- 本文から1回の操作で、配信元の購読フィードの未読の一覧へ移れること。
- 一覧と設定の画面から、購読フィードのサイトを開けること。

**Non-Goals:**

- APIとデータベースの変更。
- Androidアプリ。
- サイトのURLの推測。

## Decisions

- **道は `ReaderPage` が作る。** `ArticleView` に `feedListPath(article)` を渡し、リンクにしないときは `null` を返させる。`ReaderPage` は、`listPathOf({ type: "feed", feedId })` で一覧の道を作り、広い画面では `/<記事>` を付けて本文を残し、狭い画面では一覧の道だけを返す。`?read=1` は付けず、左のペインから開いたときと同じ未読の一覧にする。
- **リンクにしない場合。** 開いている一覧がその購読フィードのとき、購読フィードがまだ届いていないとき（名前が空のリンクを避ける）、記事に購読フィードがないときは `null` にする。`feedListPath` を渡さない呼び出し元では、今と同じ文字のままになる。
- **「サイトを開く」は新しいタブのリンク。** `target="_blank" rel="noopener noreferrer"` を付け、「元のページを開く」とそろえる。一覧の上部では2段目の「購読フィードの設定」の隣に、設定の行では「記事の一覧」の隣に置く。設定の行では、ほかの操作と同じく読み上げ名に購読フィード名を入れる。
- **`siteUrl` が空なら出さない。** URLはhttpとhttpsに限って保存しているので、Web側で検査は足さない。

## Risks / Trade-offs

- 広い画面で名前を押すと、開いた記事は既読なので、切り替えた未読の一覧に本文の記事の行は出ない。左のペインから開いた一覧と同じ内容を優先した（Q1のA）。
- Webのフィード（ページを監視する種類）では、サイトのURLに監視しているページのURLが入る。そのページを開くことになるが、配信元を開くという目的には合う。
