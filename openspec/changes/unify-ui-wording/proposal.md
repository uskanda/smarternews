# Proposal

## Why

2026-11-06のWeb UIの監査（U-14、#121）で、画面の文言の食い違いが見つかった。購読フィードの画面の説明は「AIによる要約はしない」と書くが、同じ画面には「自動で要約する」の切り替えがある。同じ操作が画面によって「登録を解除」と「削除」に分かれ、保存のボタンの名前は3通りある。「更新」は一覧の再取得と続報の印の両方に使われ、「フィードを追加」「フィードの設定」は用語集の「購読フィード」と合っていない。呼び名が変わると、利用者には別の操作に見える。

## What Changes

- 購読フィードの画面の説明の後ろの1文を、要約と翻訳は選んだ購読フィードの記事だけに行う、という文に差し替える。文面はdesign.mdに書く。
- 購読フィードの登録の解除を、左のペインのメニューと設定の画面の両方で「登録を解除」の言葉にそろえる。確認のダイアログ、ボタン、知らせも同じ言葉にする。フィルターも一緒に消えることを伝える文は、消えるのがフィルターなので「削除」の語のまま残す。
- 保存のボタンの名前を、すべて「保存する」にする。保存したあとの知らせの文は変えない。
- 一覧を取り直すボタン（記事の一覧と注釈の一覧）の名前を、キー操作の一覧の `r` の説明と同じ「読み直す」にする。続報の印「更新」、本文の更新の回数、実行履歴の「更新」の列は残す。
- カテゴリの一覧の「フィードを追加」と購読フィードの一覧の「フィードの設定」を、「購読フィードを追加」「購読フィードの設定」にする。設定の画面の追加のボタンも「購読フィードを追加」にする。「選んだフィードを追加」と「このページを追加」は残す。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `web-shell`：「メニューからの登録解除」の場面で、確認のダイアログで選ぶ操作の名前を「削除」から「登録の解除」に直す。

## Impact

- `apps/web/src`の画面の文言と、それを名前で探すテスト。
- 進行中の変更`add-feed-from-category`のproposal、design、tasks、web-readerの差分の要件。ここに書かれた「フィードを追加」「フィードの設定」を直す。
- サーバー、API、Androidアプリには影響しない。
