# Proposal

## Why

配信記事だけを集めた一覧がない。
生成記事を読み終えたあと、購読フィードの未読だけを続けて読もうとしても、カテゴリの一覧では生成記事と混ざるので、購読フィードを1つずつ開くことになる（Issue #128）。
APIは、すでに配信記事だけの一覧と一括の既読に応じる。足りないのは、それを開く項目である。

## What Changes

- 左のペイン（Web）と引き出し（Android）の上段に、固定の項目「購読フィード」を足す。位置は「AI生成」のすぐ下で、未読の配信記事の数を付ける。
- 「購読フィード」の一覧は、全カテゴリと「未分類」の配信記事だけを並べる。未読だけを表示し、既読も表示する切り替え、並び順のメニュー、一括の既読を持つ。重要度4以上の切り替えは出さない。
- 一括の既読は配信記事だけを既読にし、終えても別の項目へ移らない。
- 「購読フィード」の並び順を、ほかの項目と同じく表示の設定として保存し、設定ファイルに書き出す。
- 記事の一覧と一括の既読のAPIは変えない。LLMは呼ばない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `web-reader`：上段の項目の並びに「購読フィード」を足し、その一覧と、一括の既読のあとに移らないことの要件を足す。
- `web-shell`：動かせない項目に「購読フィード」を足す。
- `mobile-shell`：引き出しの上段の項目の並びと、動かせない項目に「購読フィード」を足す。
- `mobile-reader`：上段の「購読フィード」の一覧と、一括の既読のあとに移らないことの要件を足す。
- `http-api`：表示の設定を持つ固定の項目に「購読フィード」を足す。
- `settings`：並び順を保存する固定の項目と、設定ファイルで指す固定の項目に「購読フィード」を足す。

## Impact

- `packages/client/src/nav.ts`：項目の種類、ラベル、未読数、キー、一覧の絞り込み、一括の既読の範囲
- `packages/core/src/api.ts`：表示の設定の対象と、設定ファイルの `list`
- `packages/core/src/db/migrations/031_list_views_feeds.sql`（新規）：並び順の表の作り直し
- `apps/web`：`/feeds` のルート、一覧の見出し、重要度の切り替えの除外
- `apps/mobile`：一覧の見出し、重要度の切り替えの除外。引き出しは共有のモデルから出る
- `docs/api.md`：表示の設定と `listViews` の説明
- 記事の一覧、件数、一括の既読のAPI：変えない
