# Proposal

## Why

購読フィードの取得の失敗、更新の停止、一時停止は、Webの設定の画面でしか見えない。
失敗している購読フィードの一覧を開いても「ここに出す記事はありません」としか表示されず、左のペインの項目にも印がない。利用者は、記事が来ない理由に気づけない（issueの117番、Web UIの監査のU-10）。

## What Changes

- 購読フィードの一覧の上部に、取得の状態を1行で出す。取得の失敗は理由と「いま取得」を、更新の停止は「いま取得」を並べる。一時停止は操作のボタンを置かない。どの行にも、設定の画面のその購読フィードの行へのリンクを、文の中に置く。状態が重なったときは、失敗、更新の停止、一時停止の順に強い1つだけを出す。
- 左のペインの購読フィードの行に、状態を形と読み上げ名で示すアイコンを置く。折りたたんだカテゴリと「未分類」の行には、下の購読フィードの中でいちばん強い状態のアイコンを出す。
- 設定の購読フィードの画面を `/settings/feeds#feed-<識別子>` で開いたとき、その行までスクロールし、行の名前にフォーカスを移す。
- `DESIGN.md` の `banner-error` の決まりを直す。ボタンは1つのままとし、原因を直す画面へのリンクを文の中に置いてよいことにする。`nav` の節に、状態のアイコンの決まりを足す。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `web-reader`: 購読フィードの一覧の上部の取得の状態の行と、左のペインの状態の印を足す。折りたたんだカテゴリの行の印を、折りたたみの要件に足す
- `web-settings`: 即時の取得の操作の要件に、行を指定して画面を開けることを足す

## Impact

- `packages/client`: 状態の判定（`feedState`、`strongestFeedState`、`FEED_STATE_LABEL`）を足す。`buildNav` の項目とグループに状態を持たせる。
- `apps/web`: 一覧の上部の行（`FeedStatusBanner`）と、左のペインのアイコンを足す。設定の画面の行の識別子とフォーカス、「いま取得」の共通の処理（`useFetchFeedNow`）も足す。
- `DESIGN.md`: `banner-error` と `nav` の決まりを直す。
- APIとサーバー、Androidアプリは変えない。
