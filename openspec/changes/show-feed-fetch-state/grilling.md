# grilling 記録: show-feed-fetch-state

GitHubのissueの117番のコメントで、1ラウンドの質問（Q1〜Q6）に答えた記録である。
issueは、購読フィードの取得の失敗、更新の停止、一時停止が設定の画面でしか見えないという、Web UIの監査の項目（U-10）である。
失敗している購読フィードの一覧を開いても「ここに出す記事はありません」としか表示されず、左のペインの項目にも印がない。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 一覧の上部に出す状態の範囲 | 3つとも出す。取得の失敗は `banner-error`、更新の停止と一時停止は `banner-warning` にする。文言は設定の画面の印と同じにし、失敗の行には `feedErrorLabel` で訳した理由も書く。重なったときは、失敗、更新の停止、一時停止の順に強い1行だけを出す。一時停止の行には「いま取得」を置かず、設定へのリンクだけを置く（B） | 第1ラウンド Q1 |
| 失敗の行の操作と `DESIGN.md` | `DESIGN.md` を直す。操作のボタンは「いま取得」の1つのままにし、設定へのリンクは文の中に置いてよいことにする（A） | 第1ラウンド Q2 |
| 設定へのリンクの行き先 | `/settings/feeds#feed-<id>` を開き、その行までスクロールして、行の見出しにフォーカスを移す。行には id を付ける（B） | 第1ラウンド Q3 |
| 左のペインの印の形 | 名前の右、未読数の前に小さなアイコンを置く。失敗は `error` の色の警告の形、更新の停止は `warning` の色、一時停止は `on-surface-muted` の色の一時停止の形にし、読み上げ名と `title` を付ける。`DESIGN.md` の `nav` の節に決まりを足す（A） | 第1ラウンド Q4 |
| 折りたたんだカテゴリの行の印 | 折りたたんでいるときだけ、下のフィードの中でいちばん強い状態の印をカテゴリの行に出す。判定は `packages/client` に置き、テストを書く（A） | 第1ラウンド Q5 |
| Androidアプリ | Webだけを直す。状態の判定は `packages/client` に置き、アプリからも使えるようにする（A） | 第1ラウンド Q6 |

## 計画で決めたこと

承認を求めた計画（issueのコメント）で、次を決めた。利用者は変更なしで承認した。

| 決定 | 選択 |
|---|---|
| 判定の置き場所 | `packages/client` の `feedState` と、グループのいちばん強い状態。`buildNav` は、フィードの項目に `state`、グループに `childState` を持たせる |
| 一覧の上部の行の場所 | 見出しの部分のすぐ下。「ここに出す記事はありません」の表示はそのまま残し、並べて出す |
| 「いま取得」の処理 | 設定の画面と同じ処理を1つの `useFetchFeedNow` にまとめ、両方の画面から使う |
| 更新の停止の行の操作 | 失敗の行と同じく「いま取得」と設定へのリンクを置く |
