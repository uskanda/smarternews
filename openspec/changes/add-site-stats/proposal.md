# Proposal

## Why

候補と出典はサイト名を持つが、画面に出るのは、トピックごとの「よく除外されるサイト」の上位3つだけで、操作はない（issue #229）。
毎回除外されるサイトの候補も、毎回判定のタスクに送っている。出典によくなるサイトを購読フィードに誘う導線もない。
カテゴリの画面で、サイトごとの成績を見て、サイトを候補から除いたり、そのサイトのフィードを購読したりできるようにする。
除いたサイトの候補は判定の前に除外するので、LLMの呼び出しが減る。

## What Changes

- 候補に、URLのホスト名を保存する。ホスト名は小文字にし、先頭の `www.` だけを取る。`blog.example.org` と `example.org` は別のサイトとする。
- Googleニュースの検索結果は、各項目の出典サイトのURL（`<source url>`）を取り込む。転送用のURLを解決できなかった候補は、そのURLのホスト名で数え、除外する。
- 移行のとき、保存済みの候補にURLからホスト名を入れる。転送用のURLのまま解決できていない候補は、ホスト名を不明（空）にする。
- カテゴリごとに、候補から除くサイトの一覧を持つ。収集の直後、日付の確認より前に、一覧のサイトの候補を除外する。除外した候補は理由の種類 `blocked-site`（「除外したサイト」）で保存し、既読にする。フィード、ニュース検索、LLM検索のすべての候補が対象である。
- APIに、カテゴリの出典のサイトの成績を返す操作と、サイトを除外する操作、除外をやめる操作を足す。
- トピックの成績の「よく除外されるサイト」を、サイト名ではなくホスト名で数える。除外の内訳に「サイトの除外」の件数を足す。**BREAKING**：`topRejectedSites` の各項目の `siteName` を `host` に変える。
- Webのカテゴリの画面に「出典のサイト」の区画を足す。直近30日の、サイトごとの候補、採用、除外、記事、開いた記事、スター、外れを、候補の多い順に並べる。各行に「このサイトを候補から除く」と「このサイトのフィードを探す」を置く。除外中のサイトは区画の先頭に並べ、「除外をやめる」で戻せる。
- 「このサイトのフィードを探す」は、カテゴリの画面のままダイアログで購読フィードの追加の欄を開き、`https://ホスト名/` でフィードを探し始める。
- Androidアプリは変えない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `sources`: Googleニュースの出典サイトのURLの取り込みと、候補のホスト名の要件を足す
- `article-pipeline`: 除外したサイトの候補を判定の前に除外する要件と、移行のときのホスト名の要件を足す
- `http-api`: 出典のサイトの成績、サイトの除外とその取り消しの操作を足す。トピックの成績のサイトの除外の件数と、ホスト名で数える要件を足す
- `web-settings`: カテゴリの画面の「出典のサイト」の区画と、そこからの除外、取り消し、フィードの探索の要件を足す。トピックの成績にサイトの除外の件数を出す要件を足す

## Impact

- `packages/core`：データベースの移行（候補の表の作り直しと、除外の一覧の表）、ホスト名の関数、理由の種類、ニュース検索の取り込み、実行の処理、集計、APIの型。
- `apps/server`：3つの経路。
- `packages/client`：3つの呼び出し。
- `apps/web`：カテゴリの画面の区画、購読フィードの追加の欄の初期値、トピックの成績の内訳。
- `docs/api.md`：新しい操作と、トピックの成績の変わった項目。
- LLM：新しい呼び出しはない。除外したサイトの候補は判定のタスクにもページの取得にも送らないので、呼び出しは減る。
- Androidアプリはトピックの成績を使っていないので、`topRejectedSites` の変更の影響はない。
