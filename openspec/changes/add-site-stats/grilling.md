# grilling 記録: add-site-stats

GitHubのissueの229番のコメントで、1ラウンドの質問（Q1〜Q8）に答えた記録である。
issueは、カテゴリの画面に「出典のサイト」の区画を足す提案である。区画には、直近30日のサイトごとの成績を並べる。サイトを候補から除く操作と、そのサイトのフィードを探す操作も置く。
利用者は8つの問いすべてに推奨の案（A）で答えた。そのあと、計画を変更なしで承認した。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 除外を適用する範囲 | カテゴリごとに除外する。除外の一覧もカテゴリの画面で管理する（A） | 第1ラウンド Q1 |
| Googleの未解決リンクのホスト名 | 収集時に source の url 属性のホスト名を記録し、未解決の候補はそれで集計・除外する。保存済みの未解決の候補は、ホスト名が不明の1行にまとめる（A） | 第1ラウンド Q2 |
| ホスト名のそろえ方 | URLのホスト名を小文字にし、先頭の www. だけを取る。www. 以外の部分が違うホスト名は別のサイトとする（A） | 第1ラウンド Q3 |
| 除外する候補の範囲と順序 | フィード、ニュース検索、LLM検索のすべての候補に適用する。収集の直後、日付の確認より前に除外し、理由の種類 blocked-site で保存して既読にする（A） | 第1ラウンド Q4 |
| トピックの「よく除外されるサイト」 | 残し、集計をサイト名からホスト名に変える。除外の内訳に「サイトの除外」の件数を足す（A） | 第1ラウンド Q5 |
| 区画の並びと除外の取り消し | 直近30日に候補のあったサイトを候補の多い順に並べる。除外中のサイトは区画の先頭に別の一覧で示し、「除外をやめる」で戻せるようにする。確認のダイアログは出さない（A） | 第1ラウンド Q6 |
| 「フィードを探す」の行き先 | カテゴリの画面のままダイアログで購読フィードの追加の欄を開く。URLは https://ホスト名/ を入れて発見を始め、カテゴリはニュースのカテゴリならそのカテゴリ、イベントのカテゴリなら「なし」を選ぶ（A） | 第1ラウンド Q7 |
| 対象の画面 | Webの画面だけに入れる。APIは足すが、Androidアプリは変えない（A） | 第1ラウンド Q8 |

## 計画で決めたこと

承認を求めた計画（issueのコメント）で、次を決めた。利用者は変更なしで承認した。

| 決定 | 選択 |
|---|---|
| 移行 | 移行（承認時は032、mainとの取り込みで `038_site_hosts.sql` に番号を改めた）で candidates を作り直す。ホスト名の列 `site_host` を足し、理由の種類の CHECK に `blocked-site` を加える。除外の一覧の表 `blocked_sites`（category_id、host、created_at）を作る |
| 保存済みの候補のホスト名 | URL から求めて埋める。news.google.com のまま解決できていない候補は空文字（不明）にする |
| ホスト名の関数 | `siteHost(url)` を足し、LLM検索のサイト名もこの関数に置き換える |
| 理由の文 | 「除外したサイト」と "site blocked in this category" |
| 候補の出典サイトのURL | 候補の型に任意の項目として足す。ニュース検索は RSS の `<source url>` 属性を取り込む |
| 集計 | `siteStats(db, categoryId, now)`。候補、採用、除外、記事、開いた記事、スター、外れをホスト名ごとに数える。記事は candidates.article_id でたどる |
| API | `GET /categories/:id/site-stats`、`PUT` と `DELETE` の `/categories/:id/blocked-sites/:host`。ホスト名はサーバーでもそろえる |
| 画面 | カテゴリの画面に `SiteStats.tsx` の区画を足す。`TopicStats.tsx` の内訳にサイトの除外の件数を出す |
