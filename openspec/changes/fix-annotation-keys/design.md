# Design

## Context

動機はproposal.mdのWhyを参照する。
記事の一覧は、開いている一覧の種類から絞り込みを作り、その絞り込みをキーにキャッシュを読む。
注釈の画面と、一覧の種類が決まらない画面では、絞り込みが空になる。空の絞り込みは「すべて」の一覧のキーと同じなので、取得を止めても「すべて」のキャッシュの行が一覧として読まれる。
注釈の画面で外しているキーは `j` と `k` だけで、`s`・`m`・`o`・`Space` は、この行に働く。

## Goals / Non-Goals

**Goals:**
- 記事の一覧を持たない画面で記事のキーを押しても、ほかの一覧の記事が変わらないようにする。
- 注釈の画面の `Space`・`Shift+Space` を、注釈の一覧の移動につなぐ。

**Non-Goals:**
- 狭い画面の本文の末尾の前後の記事のリンクは変えない（grilling.md）。
- 記事を開いているときの `s`・`m`・`o` の動きは変えない。

## Decisions

- **取得した行を空にする。** 注釈の画面と、検索でも名前の記事でもなく一覧の種類が決まらない画面では、取得した行も、既読にしたあと残しておいた行も一覧に入れない。
  - 代わりに、キャッシュのキーを分ける案を考えた。採らなかった。行を読まない理由がキーに隠れ、絞り込みの形が変わると同じ不具合が戻る。
- **一覧のキーに注釈の画面であることを含める。** これで「すべて」と同じキーにならないので、最後に開いた記事も引き継がれない。
- **注釈の一覧の移動は、refのpropで渡す。** 注釈の一覧が描くたびに、自分の移動の処理をrefに入れる。記事の画面の `Space` の処理は、注釈の画面ではこのrefを呼ぶ。
  - 代わりに、注釈の一覧が自分で `Space` を受ける案を考えた。採らなかった。本文の端かどうかは本文のペインを持つ記事の画面が知っている。

## Risks / Trade-offs

- ［一覧の種類を読み込んでいる間も一覧が空になる］→ その間は取得も止めているので、表示されていた行はもともとほかの一覧のキャッシュである。読み込みが終われば正しい行が出る。
