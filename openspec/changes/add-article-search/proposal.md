# Proposal

## Why

収集した記事を語で探す手段がない。一覧は、カテゴリ、購読フィード、重要度でしか絞り込めない。
GitHubのissueの47番は、Inoreaderの「Search in feeds」に当たる全文検索を求めている。
読んだ記事をあとで探し直すことと、ある話題の記事を由来にかかわらず集めて読むことが、この変更でできるようになる。

## What Changes

- 生成記事と配信記事の両方を、語で検索できるようにする。イベントの記事も対象にする。
- 照合する欄は、タイトル、訳したタイトル、要約、本文、生成記事の読み手への影響、イベントの会場とする。出典のURLは照合しない。
- 空白で区切った語をすべて含む記事を返す。引用符の完全一致と語の除外は入れない。
- 大文字と小文字、全角と半角の違いを無視する。規則はストップワードの照合と同じにする。ひらがなとカタカナは区別する。
- 照合にはSQLiteのFTS5の `trigram` を使う。2文字以下の語は `LIKE` で照合し、1文字の語も受け付ける。
- 結果は新しい順に並べる。既読の記事を含め、ストップワードで隠した配信記事は含めない。
- APIに記事の検索の操作を足す。カテゴリ、購読フィード、未読だけで絞り込める。
- Webは左のペインの上に検索欄を置き、`/` のキーで検索欄へ移れるようにする。結果の画面は、検索語を含むURLを持つ。
- アプリは引き出しの上に検索欄を置く。
- 結果の画面に、カテゴリと購読フィードで絞り込む操作と、未読だけの表示への切り替えを置く。既定は既読を含む表示とする。
- 結果の一覧のタイトルと抜粋、開いた記事の本文で、一致した語を強調する。語の色付け（#54）とは見た目を分ける。
- 結果の画面では、一括の既読を使えないようにする。
- 検索の保存は今回入れない。注釈（#55）の欄の照合は、#55を実装するときに足す。

## Capabilities

### New Capabilities

- `article-search`: 検索の対象の記事と欄、語の正規化と照合、結果の並びと除外、検索の索引の保ち方

### Modified Capabilities

- `http-api`: 記事の検索の操作を足す
- `web-shell`: 左のペインの上の検索欄と、`/` のキーで検索欄へ移る操作を足す
- `web-reader`: 検索の結果の画面、結果の絞り込み、一致した語の強調、結果の画面での一括の既読の無効を足す
- `mobile-shell`: 引き出しの上の検索欄を足す
- `mobile-reader`: 検索の結果の画面、結果の絞り込み、一致した語の強調、結果の画面での一括の既読の無効を足す

## Impact

- `packages/core`: 移行で、FTS5の検索の表と、記事の表の変更に追従するトリガーを足す。語の正規化と一致の範囲を求める処理を、Nodeの機能に依存しない形で足す。検索の問い合わせとAPIのスキーマを足す。
- `apps/server`: 検索の操作の経路を足す。データベースを開くときに、正規化の関数をSQLiteへ登録する。
- `packages/client`: 検索のAPIの呼び出しと、一致した語の強調に使う範囲の計算を足す。
- `apps/web`: 検索欄、結果の画面、`/` のキー、強調の表示を足す。`Shell.tsx` のキーの一覧に `/` を足す。
- `apps/mobile`: 引き出しの検索欄、結果の画面、強調の表示を足す。
- `DESIGN.md`: 検索で一致した語の強調の色を足し、`pnpm run tokens` でCSSに反映する。
- `docs/api.md`: 検索の操作を足す。
- LLMは呼ばない。検索はすべてプログラムで行う。
- データベースの大きさは、検索の表の分だけ増える。保存期間（生成記事は180日、配信記事は購読フィードの保存期間）を過ぎた記事は、表からも消える。
