# grilling 記録: wait-full-content-before-translation

GitHubのissueの186番のコメントで、1ラウンドの質問（Q1）に答えた記録である。
issueは、翻訳と全文の取得を両方有効にした購読フィードで、全文を待つ記事を開くと「翻訳できませんでした」になるという、Web UIの監査の項目（B-04）である。
画面は全文の取得と翻訳を同時に送り、全文が届くと2つ目の翻訳を送る。サーバーは、進行中の1つ目の翻訳の結果を2つ目にも返す。1つ目は、保存の前に元の文が変わったことを見つけて失敗する。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 直す場所と、サーバーでの扱い | 画面とサーバーの両方を直す。画面は、全文を待つ間と取得中は本文の翻訳を求めない。サーバーは、保存の前に元の文が変わっていたら、新しい文で一度だけ翻訳し直す（A） | 第1ラウンド Q1 |

## 計画で決めたこと

承認を求めた計画（issueのコメント）で、次を決めた。利用者は変更なしで承認した。

| 決定 | 選択 |
|---|---|
| サーバーのやり直しの回数 | 1回まで。2回目も元の文が変わっていたら、今までどおり `unavailable` で失敗し、何も保存しない |
| やり直しの場所 | 記事ごとに共有している進行中の処理の中で行う。途中で届いた2つ目の依頼も、新しい文の訳を受け取る |
| 読み直した記事に訳がそろっていたとき | ほかの依頼が保存した本文の訳と題の訳があれば、その訳をそのまま返す |
| 画面で待つ条件 | 全文の取得中のとき。または、記事が全文を待っていて、取得の依頼に応答がなかったのではないとき |
| 待つのをやめるとき | 全文が届いたとき、取得に失敗したとき、依頼に応答がなかったとき。届いた場合は全文を、それ以外は配信された内容を翻訳する |
| 待つ間の表示 | 「翻訳しています。」を出さず、「全文を取得しています。」だけにする |
| 題の翻訳 | 本文と一緒に待つ。サーバーは題と本文を一度に翻訳する |
| Androidアプリ | 変えない。サーバーの修正で失敗の表示は出なくなる |

## 後回しにしたもの
