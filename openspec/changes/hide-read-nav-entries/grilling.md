# grilling 記録: hide-read-nav-entries

GitHubのissueの130番のコメントで、1ラウンドの質問（Q1〜Q5）に答えた記録である。
issueは、左のペインで未読のない項目を隠せないという、Web UIの監査の項目（R-09）である。
購読フィードが数十あると、左のペインの大半を未読0の項目が占め、Shift+JとShift+Kも未読0の項目を通る。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 隠す対象にする項目 | カテゴリ、「未分類」、カテゴリの下の「AI生成」と購読フィードのうち、未読が0のものだけを隠す。上の段は隠さない。未読が0のカテゴリは、下の項目ごと隠す（A） | 第1ラウンド Q1 |
| 取得に問題のある購読フィードの扱い | 取得の失敗と更新の停止の印がある購読フィードは、未読が0でも隠さない。その親のカテゴリも残す。一時停止は隠す（B） | 第1ラウンド Q2 |
| 切り替えを置く場所 | 設定の「この端末の設定」にチェックボックスを1つ置くだけにする（A） | 第1ラウンド Q3 |
| Androidのドロワー | 今回はWebの左のペインだけを対象にする。隠す判定は `packages/client` に置く（A） | 第1ラウンド Q4 |
| 開いている項目と、件数を読み込むまでの表示 | 開いている項目は隠さず、それが購読フィードか「AI生成」なら親のカテゴリも残す。件数を読み込むまでは何も隠さない（A） | 第1ラウンド Q5 |

## 計画で決めたこと

承認を求めた計画（issueのコメント）で、次を決めた。利用者は変更なしで承認した。

| 決定 | 選択 |
|---|---|
| 判定の置き場所 | `packages/client` の純粋な関数 `hideEmptyEntries(model, { current, counted })`。グループの `childState` は、隠す前の子から計算した値のままにする |
| 保存のキー | `smarternews.nav.hideRead`。オンは `"on"`、オフは値を保存しない。初めはオフ |
| 隠したあとの model を使う箇所 | 左のペインの描画、ドラッグ、項目のメニューの「上へ」「下へ」、Shift+JとShift+K。開いている項目は、隠す前の model から決める |
| すべて既読にしたあとの移り先 | `nextTarget` は、もともと未読0の項目を飛ばすので変えない |
| キー操作の一覧の説明 | Shift+JとShift+Kの説明は変えない |
