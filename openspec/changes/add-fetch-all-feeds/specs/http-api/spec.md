# Spec Delta

## ADDED Requirements

### Requirement: 一括の即時の取得の操作

APIは、すべての有効な購読フィードの即時の取得を求める操作を提供しなければならない（MUST）。
応答は、取得の終わりを待たずに返す。応答は、取得を求めた購読フィードの件数、Retry-Afterの待ちで飛ばした件数、求めの時刻を含む。

#### Scenario: 一括で取得を求める

- **WHEN** 有効な購読フィードが2つある状態で、一括の即時の取得を要求する
- **THEN** APIは、求めた件数として2、飛ばした件数として0をすぐに返し、そのあと2つの購読フィードの新しい項目が配信記事として保存される

#### Scenario: Retry-Afterで待つものを飛ばす

- **WHEN** 有効な購読フィードが2つあり、その1つがRetry-Afterの示す時刻を待っている状態で、一括の即時の取得を要求する
- **THEN** APIは、求めた件数として1、飛ばした件数として1を返す

#### Scenario: 対象がない

- **WHEN** 購読フィードがすべて無効の状態で、一括の即時の取得を要求する
- **THEN** APIは、求めた件数として0を返し、どの購読フィードへの要求も発生しない

### Requirement: 取得の求めの時刻の提供

購読フィードを返すとき、APIは、一括の即時の取得を求められてまだ取得していない購読フィードに、その求めの時刻（`fetchRequestedAt`）を含めなければならない（MUST）。
取得を待っていない購読フィードでは、この値は空である。

#### Scenario: 取得を待っている購読フィード

- **WHEN** 一括の即時の取得を要求し、ある購読フィードの取得が終わる前に、購読フィードの一覧を要求する
- **THEN** その購読フィードは、求めの時刻とともに返り、次の取得の時刻は求めの時刻である

#### Scenario: 取得が終わった購読フィード

- **WHEN** 一括の即時の取得で取得が終わったあとに、購読フィードの一覧を要求する
- **THEN** その購読フィードの求めの時刻は空で、取得の成功と失敗のどちらでも同じである
