# Spec Delta

## ADDED Requirements

### Requirement: 一括の即時の取得

一括の即時の取得を受けたとき、サーバーは、取得周期と、失敗で延びた間隔を待たずに、有効な購読フィードを取得しなければならない（MUST）。

#### Scenario: 取得周期の途中の購読フィード

- **WHEN** 前回の取得から1分しか過ぎていない有効な購読フィードが2つある状態で、一括の即時の取得を要求する
- **THEN** サーバーは2つとも取得し、新しい項目が配信記事として保存される

#### Scenario: 失敗で間隔が延びた購読フィード

- **WHEN** 取得に3回続けて失敗し、次の取得が4時間後になっている購読フィードがある状態で、一括の即時の取得を要求する
- **THEN** サーバーは、4時間を待たずにその購読フィードを取得する

### Requirement: 一括の即時の取得でのRetry-Afterの尊重

一括の即時の取得を受けたとき、サーバーは、Retry-Afterの示す時刻が来ていない購読フィードを取得してはならない（MUST NOT）。

#### Scenario: Retry-Afterで待っている購読フィード

- **WHEN** 取得がRetry-Afterの「18000」（5時間）を付けた429で失敗してから1時間後に、一括の即時の取得を要求する
- **THEN** その購読フィードへの要求は発生せず、ほかの有効な購読フィードは取得される

#### Scenario: Retry-Afterの時刻が過ぎた購読フィード

- **WHEN** Retry-Afterの示す時刻が過ぎたあとで、一括の即時の取得を要求する
- **THEN** サーバーはその購読フィードを取得する

### Requirement: 一括の即時の取得での無効な購読フィードの除外

一括の即時の取得を受けたとき、サーバーは、無効にされた購読フィードを取得してはならない（MUST NOT）。

#### Scenario: 一時停止中の購読フィード

- **WHEN** 有効な購読フィードと無効な購読フィードが1つずつある状態で、一括の即時の取得を要求する
- **THEN** 有効な購読フィードだけが取得され、無効な購読フィードへの要求は発生しない

#### Scenario: 取得を待つ間に一時停止する

- **WHEN** 一括の即時の取得を要求し、ある購読フィードの取得が始まる前に、その購読フィードを無効にする
- **THEN** その購読フィードへの要求は発生せず、あとで有効に戻しても、取得周期が過ぎるまで取得されない

### Requirement: 一括の即時の取得の直列化

一括の即時の取得を進める間、サーバーは、同時に2つ以上の購読フィードを取得してはならない（MUST NOT）。

#### Scenario: 3つの購読フィードを一括で取得する

- **WHEN** 有効な購読フィードが3つある状態で、一括の即時の取得を要求する
- **THEN** 1つの取得が終わってから次の取得が始まり、3つとも取得される

#### Scenario: 取得の途中に要求が来る

- **WHEN** ある購読フィードの定期的な取得の途中に、一括の即時の取得を要求する
- **THEN** 進行中の取得が終わってから、残りの購読フィードが続けて取得され、2つの取得は重ならない

### Requirement: 一括の即時の取得のあとの取得周期

一括の即時の取得で購読フィードを取得し終えたとき、サーバーは、その取得の時刻から数えた取得周期で次の取得を予定しなければならない（MUST）。

#### Scenario: 取得のあとの次の取得

- **WHEN** 取得周期が30分の購読フィードを、一括の即時の取得で取得する
- **THEN** その購読フィードの次の取得は、その取得の30分後に予定され、それまで定期的な取得は発生しない

### Requirement: 再起動をまたぐ一括の即時の取得

一括の即時の取得を受けてから取得し終えるまでの間に再起動したとき、サーバーは、起動のあとに、まだ取得していない購読フィードを取得しなければならない（MUST）。

#### Scenario: 取得の前に再起動する

- **WHEN** 一括の即時の取得を要求し、購読フィードの取得が始まる前にサーバーを再起動する
- **THEN** 起動のあと、サーバーは取得周期を待たずにその購読フィードを取得する
