# grilling 記録: add-fetch-all-feeds

Issue #131「すべての購読フィードをいま取得する」で、計画についての質問に答えてもらった。
Issueは2026-11-06のWeb UIの監査の項目（R-11）で、「有効な購読フィードの次の取得の時刻を、今にそろえる。取得の直列化と、ホストごとの間隔は守る」と方向を示している。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 操作を置く場所 | B：設定の購読フィードの画面と、左のペインの両方に置く | Issue #131 第1ラウンド Q1 |
| Retry-Afterで待っている購読フィードの扱い | A：取得周期と、失敗で延びた間隔は待たない。Retry-Afterで待っている購読フィードだけは飛ばす | Issue #131 第1ラウンド Q2 |
| 取得の終わりの知らせ方 | B：サーバーはすぐに応答する。画面は終わるまでボタンを`取得中…`にして数秒ごとに状態を読み直し、終わったら失敗の件数を知らせ、未読の数と記事の一覧を読み直す | Issue #131 第1ラウンド Q3 |
| 「今にそろえる」の持ち方 | A：購読フィードの表に取得の求めの時刻の列を足し、次の取得の時刻の計算に使う | Issue #131 第1ラウンド Q4 |
| 左のペインの位置 | 「カテゴリ」の見出しの行の右端に、小さいボタン「いま取得」を置く。読み上げ用の名前は「すべての購読フィードをいま取得」にする | 計画の承認（Issue #131への返答 `/ok`） |
| 設定の画面の位置 | 一覧の見出しの下の、「問題のある購読フィードを先頭に並べる」の行に、ボタン「すべていま取得」を置く | 計画の承認（Issue #131への返答 `/ok`） |
| 対象 | 有効で、Retry-Afterの待ちの中にない購読フィード。一時停止中のものは含めない。対象が0件のときは、取得を始めずに「取得する購読フィードはありません」と知らせる | 計画の承認（Issue #131への返答 `/ok`） |
| Androidアプリ | 対象の外にする。Androidアプリには、購読フィードごとの「いま取得」もない | 計画の承認（Issue #131への返答 `/ok`） |
| キーボードのキー | 足さない | 計画の承認（Issue #131への返答 `/ok`） |

## 後回しにしたもの

- Androidアプリに、購読フィードごとの「いま取得」と一括の取得を足すこと。アプリにまだ無い機能で、別のIssueで扱う
- 一括の取得のキーボードのキー
