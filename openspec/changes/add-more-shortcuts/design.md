# Design

## Context

キー操作は `apps/web/src/lib/keys.ts` の `useHotkeys` が受け付ける。
`useHotkeys` は、押されたキーの `event.key` をそのまま操作の表から引く。
`Ctrl`、`Meta`、`Alt` を押している間と、入力欄にフォーカスがある間は何もしない。
`Shift` は見ていないため、`Shift+A` と `a` を区別するには `event.key` の大文字に頼るしかない。
`Space` と `Shift+Space` は、どちらも `event.key` が `" "` になり、区別できない。

呼び出し元は2か所ある。
`apps/web/src/shell/Shell.tsx` は `?` を受け付け、`apps/web/src/reader/ReaderPage.tsx` は `j`、`k`、`s`、`m`、`o` を受け付ける。
どちらも `window` に別々の `keydown` の受け手を登録する。
`?` で開く一覧の中身は、`Shell.tsx` の `KEYS` の配列である。

左のペインの項目は、`packages/client/src/nav.ts` の `buildNav` が作るモデルから描く。
上部の4つの項目（`views`）のあとに、カテゴリごとのまとまり（`groups`）が並び、まとまりはカテゴリの項目と配下の項目（`children`）を持つ。
折りたたみの状態は、Webだけがブラウザーに保存している（`apps/web/src/lib/collapsed.ts`）。
一括の既読のあとに次の項目へ移る処理は、同じモデルを `packages/client/src/order.ts` の `nextTarget` でたどる。

一括の既読、一覧の更新、既読を含める切り替えは、`ReaderPage.tsx` のボタンとチェックボックスにある。
本文のペインは、`ReaderPage.tsx` の中のスクロールする `div` である。

## Goals / Non-Goals

**Goals:**

- 足すキーが、同じ操作のボタンやチェックボックスと同じ処理を呼ぶ。キーのための別の処理を作らない。
- `g` に続くキーを、どの呼び出し元の受け手から見ても同じ規則で扱う。`g r` の `r` が一覧の再取得として働かない。
- 項目の順のたどり方を、描画から切り離した関数にして、単体のテストで確かめられるようにする。

**Non-Goals:**

- キー操作を1か所の表へ集める作り直し。今の `useHotkeys` を呼び出し元ごとに使う形は変えない。
- サーバー、API、アプリの変更。
- `/`（#47）と `w`（#52）。それぞれの変更が `KEYS` と受け手に足す。

## Decisions

### キーの名前を `keys.ts` で組み立てる

`useHotkeys` は、`event.key` をそのまま引く代わりに、次の規則で組み立てた名前を引く。

- 英字1文字は、`Shift` を押していれば `Shift+A` のように大文字で、押していなければ小文字で表す。Caps Lockで `event.key` が大文字でも、`Shift` を押していなければ小文字として扱う。
- `event.key` が `" "` のときは `Space`、`Shift` を押していれば `Shift+Space` とする。
- それ以外のキーは `event.key` のままとする。`?` はこれまでどおり `?` で引ける。

`event.key` の大文字だけで `Shift+A` を見分けると、Caps Lockを入れた利用者が `a` を押しただけで一括の既読が起きる。
`event.code` で引く案もあるが、配列の違うキーボードで `?` の位置がずれるため採らない。
Caps Lockのときに `j` と `k` が今は働かない点も、この規則で直る。

### `g` に続くキーは、`keys.ts` のモジュールに1つだけ状態を持つ

`useHotkeys` に渡す表は、`"g a"` のように空白で区切った2つのキーの並びも受け付ける。
`keys.ts` は、`g` を待っている状態と、その期限を、モジュールの中に1つだけ持つ。
すべての呼び出し元の受け手は、この状態を見てから自分の表を引く。

1. 待っている状態で期限の前にキーが来たら、`"g <キー>"` の名前をすべての呼び出し元の表から探し、見つかれば実行する。見つからなくても、そのキーは使い切り、1つのキーとしては実行しない。状態は消す。
2. 待っている状態でないときに `g` が押され、どれかの表に `g` で始まる並びがあれば、待っている状態に入る。期限は1秒後にする。
3. それ以外は、これまでどおり1つのキーとして自分の表を引く。

受け手を1つにまとめる作り直しはNon-Goalsに置いたため、状態の共有で済ませる。
呼び出し元ごとに状態を持つと、`Shell.tsx` が `g r` を処理したあと、`ReaderPage.tsx` の受け手が `r` を一覧の再取得として実行してしまう。
受け手の実行順に頼らないよう、`g` を待っている間のキーは、どの受け手でも1つのキーとして扱わない。

期限の判定には、テストで進められる時計を使う。
画面はすでに `useApp()` の `now` という差し替えられる時計を持つため、それを `useHotkeys` に渡すか、`keys.ts` が受け取れるようにする。

### `Space` は、ボタンにフォーカスがあるときに働かせない

`Space` は、フォーカスのあるボタンを押すキーでもある。
`useHotkeys` が `Space` を受け取って `preventDefault` すると、利用者はボタンを `Space` で押せなくなり、キーボードだけでの操作の要件を満たさない。
`keys.ts` は、フォーカスのある要素が、`Space` で押せる部品のときは、`Space` と `Shift+Space` を受け取らない。
対象は `button`、`summary`、`role` が `button`、`menuitem`、`checkbox`、`switch`、`tab` の要素である。
チェックボックスなどの `input` は、入力欄の判定ですでに除いている。
リンクは `Space` で押せないため、記事の一覧の行にフォーカスがあっても本文を送る。

### 本文の送りの量と、端の判定

`Space` は、本文のペインの表示範囲の高さから1行分を引いた量だけ送る。
ブラウザーの `Space` のスクロールと同じく、前の画面の最後の行を残して、読んでいた位置を見失わないようにするためである。
1行分は、本文の書体の行の高さとし、値は `DESIGN.md` の本文の書体から取る。

末尾の判定は「スクロールの位置と表示範囲の高さの和が、内容の高さから1px以内」とする。
位置の小数の誤差があっても、末尾で送ろうとする動きを避ける。
本文がペインに収まるときは、最初から末尾にいるため、`Space` はすぐに次の記事へ移る。

末尾や先頭で記事を移るときは、`j` と `k` が呼ぶ `move` を同じ向きで呼ぶ。
そのため、記事の一覧の追随も、`j` と `k` を押したときと同じに働く。
本文が表示されていないときも `move` を呼ぶ。選ぶ記事は、`j` または `k` を押したときと同じになる。

### 一括の既読、一覧の再取得、既読を含める切り替えは、ボタンと同じ関数を呼ぶ

`Shift+A` は `markAllRead` を呼ぶ。ボタンを出す条件（`canMarkAll`）が偽のときは、キーを表に入れない。
`r` は更新のボタンと同じ `refresh` を呼ぶ。購読フィードの取得のAPIは呼ばない。
`u` は、既読を含めるチェックボックスと同じく `toggleParam("read", "1", !includeRead)` を呼ぶ。チェックボックスを出す条件（`readToggle`）が偽のときは、キーを表に入れない。
切り替えはURLのパラメーターに残るため、保存のしかたは今の切り替えと変わらない。

### 項目の順は `packages/client/src/order.ts` の関数でたどる

`order.ts` に、次または前の項目を返す関数を足す。引数は、モデル、いまの項目、向き、折りたたみの判定である。
たどる順は、`views` を上から、続いて各まとまりのカテゴリの項目と、折りたたんでいなければ配下の項目である。
「設定」と「実行履歴」はモデルに入っていないため、たどる対象に入らない。

いまの項目は、表示している項目のうち、`isOnList` が真になるものとする。
折りたたんだカテゴリの配下の一覧を開いているときは、そのカテゴリの項目をいまの項目とみなす。
左のペインがその行を強調している（`holdsCurrent`）のと同じ扱いで、利用者が見ている位置から動く。
どの項目にも当たらないときは、`Shift+J` で最初の項目、`Shift+K` で最後の項目を返す。
端では何も返さず、画面は移らない。`j` と `k` が一覧の端で止まるのと同じ扱いである。

アプリは今回このキーを使わないが、項目のモデルは共有の処理に置く規則のため、`packages/client` に置く。
Webの `Shell.tsx` は、`Nav` と同じく `buildNav` でモデルを作り、`useCollapsed` で折りたたみを判定して、この関数を呼ぶ。

### `g` に続くキーの行き先

- `g a` は「すべて」（`/all`）を開く。「全体」に当たる項目のうち、既読を含めて全カテゴリの記事を並べる項目である。
- `g s` は「スター」（`/starred`）を開く。
- `g e` は、左のペインのまとまりを上から見て、最初に現れる種別がイベントのカテゴリを開く。種別がイベントのカテゴリは複数ありうるため、左のペインでの並びで1つに決める。
- `g r` は「最近読んだ記事」を開く。

これらは `Shell.tsx` の `useHotkeys` に置く。設定の画面と実行履歴の画面からも移れるようにするためである。

### `g r` は #51 の項目に依存する

「最近読んだ記事」の項目は、同じ時期に計画している#51の変更（add-recently-read）が、項目のモデルに足す。
この変更の実装が#51より先になったときは、`g r` を表に入れず、`KEYS` にも載せない。
#51の項目が入ったあとに、`g r` を足す。この作業はtasksの最後の節に置く。
#51が先に入っていれば、同じ節をこの変更の中で行う。
仕様は「当たる項目が左のペインにないとき、画面は何も開かない」と書いているため、どちらの順でも仕様と矛盾しない。

### キー操作の一覧の載せ方

`KEYS` の配列に、次の行を足す。`?` の一覧は、配列の順で表示する。
`Space` と `Shift+Space`、`Shift+J` と `Shift+K` は、`j` と `k` に合わせて1行ずつ分ける。

- `Shift+A`：表示中の一覧を一括で既読にする
- `Shift+J`、`Shift+K`：左のペインの次の項目、前の項目
- `Space`、`Shift+Space`：本文を1画面分送る、戻す。端なら次の記事、前の記事
- `r`：一覧を読み直す
- `u`：既読も表示するかを切り替える
- `g a`、`g s`、`g e`、`g r`：「すべて」「スター」、イベントのカテゴリ、「最近読んだ記事」へ移る

## Risks / Trade-offs

- `g` を押したあと1秒の間、`s` や `m` が働かない → 仕様のとおり、対応のないキーは使い切る。`g` を押し間違えても、記事のスターや既読は変わらない。
- ブラウザーの拡張機能が、同じキーを先に受け取る → `keydown` を `window` で受け取る今の作りを変えない。衝突するキーは、利用者が拡張機能の側で外す。
- 狭い画面で `Shift+J` を押すと一覧は変わるが、左のペインは閉じたままである → 一覧の見出しが項目の名前を出すため、利用者は移った先を見分けられる。左のペインを開く操作は足さない。
- `Space` で送る量が本文の書体に依存する → 行の高さを `DESIGN.md` の値から取り、書体を変えたときに追従させる。

## Migration Plan

画面だけの変更で、データの移行はない。戻すときは、この変更の版より前の画面を配信し直せばよい。

## Open Questions

- `g a` の行き先を「すべて」とした。grillingの答えは「全体」で、「未読」（全カテゴリの未読）を指す可能性も残る。Inoreaderの `g a` は「すべての記事」へ移るため、「すべて」を推奨として仕様に書いた。利用者の確認は実装の前に取る。
- `g e` の行き先を「左のペインで最初に並ぶ、種別がイベントのカテゴリ」とした。左のペインに「イベント」という1つの項目はなく、種別がイベントのカテゴリは複数ありうる。押すたびに次のイベントのカテゴリへ移る案もある。利用者の確認は実装の前に取る。
