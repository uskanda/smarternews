# Proposal

## Why

Webの画面のキー操作は、`j`、`k`、`s`、`m`、`o`、`?` と、項目のメニューを開く `Shift+F10` しかない。
一括の既読、次の項目への移動、本文の送り、一覧の再取得は、マウスかTabキーでボタンまでたどる必要がある。
Inoreaderから乗り換えた利用者が、同じキーで同じ操作をできるようにする（#53）。

## What Changes

- `Shift+A` で、表示中の一覧を一括で既読にする。ボタンで選んだときと同じく、取り消しの手段を出す。
- `Shift+J` と `Shift+K` で、左のペインに表示している次と前の項目を開く。折りたたんだカテゴリの下の項目は飛ばす。
- `Space` で本文を1画面分送り、本文の末尾なら次の記事へ移る。`Shift+Space` で1画面分戻し、本文の先頭なら前の記事へ移る。
- `r` で、件数と表示中の一覧をサーバーから読み直す。購読フィードの即時の取得は始めない。
- `u` で、表示中の項目の未読だけの表示と、既読を含む表示を切り替える。保存のしかたは、今の切り替えの操作と変えない。
- `g` に続けて `a` で「未読」、`s` で「スター」、`e` でイベントのカテゴリ、`r` で「最近読んだ記事」を開く。`g e` は押すたびに、左のペインの並びで次のイベントのカテゴリへ移り、最後の次は最初へ戻る。`g` から1秒のうちに次のキーが来なければ何もしない。
- `?` で開くキー操作の一覧に、足したキーを載せる。
- 割り当ては、衝突しない限りInoreaderと同じキーにする。利用者による割り当ての変更、アプリの物理キーボード、`n` と `p` は対象にしない。
- `/`（検索欄へ移る、#47）と `w`（全文の取得、#52）は、それぞれの変更で足す。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `web-shell`: キー操作の要件を足す。一括の既読、項目の移動、本文の送り、一覧の再取得、既読を含む表示の切り替え、`g` に続くキーでの移動である。今ある `s`、`m`、`o` の要件は変えない

## Impact

- `apps/web/src/lib/keys.ts`: `Shift` 付きのキー、`Space` と `Shift+Space`、`g` に続く2つ目のキーを見分けられるようにする。
- `apps/web/src/shell/Shell.tsx`: 項目の移動と `g` に続くキーを受け付け、キー操作の一覧（`KEYS`）に足したキーを載せる。
- `apps/web/src/reader/ReaderPage.tsx`: 一括の既読、本文の送り、一覧の再取得、既読を含む表示の切り替えを受け付ける。
- `g r` は、「最近読んだ記事」の項目を足す変更（#51）に依存する。
- サーバー、API、アプリに変更はない。
