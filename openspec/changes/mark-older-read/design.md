# Design

## Context

「すべて既読にする」（`ReaderPage.tsx` の `markAllRead`）は、一覧の最初のページを読んだ時刻 `asOf` を `before` として、対象の項目と「重要度4以上だけ」の絞り込みとともに `markRead` へ送る。
サーバーの `markArticlesRead` は、`updated_at < before` の未読を既読にする。`updated_at` は、配信記事では配信元の公開時刻（日付がないか未来なら取得した時刻）、生成記事では最後に更新された時刻である。

一覧の見出しの行には「すべて既読にする」と「読み直す」が並ぶ。幅のあるボタンを3つ目に置くと、一覧の名前の場所がなくなる。
メニューの前例は、並び順のメニュー（`SortMenu.tsx`）である。

## Goals / Non-Goals

**Goals:**

- 1日、3日、1週間より古い未読だけを、画面から既読にできるようにする。
- 「すべて既読にする」と `Shift+A` の動きを変えない。

**Non-Goals:**

- Androidアプリでの期間を選んだ一括の既読。
- APIとサーバーの変更。
- キーボードのショートカットの追加。

## Decisions

### 送る時刻

期間を選んだときの `before` は、「いまの時刻から期間を引いた時刻」と `asOf` の早いほうにする。
一覧を長く開いたままにすると、いまから期間を引いた時刻が `asOf` より後になることがある。そのときに、一覧を読み込んだあとに届いて画面に出ていない記事を既読にしないためである。
「いま」は画面の時計（`useApp().now`）で決める。

### 処理の分け方

`markAllRead` を、`before`、移るかどうか、0件のときの文面を受け取る関数に分ける。
「すべて既読にする」は、これまでどおり `asOf` を送り、設定に従って次の項目へ移る。
期間を選んだときは、上の時刻を送り、次の項目へは移らない。古い分を片付けて直近の分を読む、という目的に反するからである。
0件のときは「1日より古い未読はありません」のように知らせ、取り消しは出さない。取り消すものがないためである。

### メニューの部品

`MarkOlderMenu.tsx` を新しく作る。開く、閉じる、キー操作は並び順のメニューと同じ形にし、項目は `role="menuitem"` にする。
ボタンは「▾」だけを見せ、`aria-label="期間を選んで既読にする"` と `aria-haspopup="menu"` を持つ。
「すべて既読にする」とのあいだは詰め、2つで1つの操作に見えるようにする。
メニューは見出しの行の右端に出るので、ボタンの右端にそろえて開く。

## Risks / Trade-offs

- 細いボタンは見つけにくい。「すべて既読にする」に接して置き、読み上げの名前を付けることで補う。
- 一括の既読の処理を分けることで、既存の動きを変えてしまうおそれがある。既存の一括の既読と次の項目への移動のテストを、そのまま通すことで防ぐ。
