# Design

## Context

ダイアログ `AddFeedDialog` は、開いているカテゴリを必ず受け取り、そのidを追加の欄 `AddFeedForm` の `categoryId` に渡す。
`AddFeedForm` は `categoryId` を省くと「なし（未分類）」から始まる。設定の画面の追加の欄がこの使い方である。
`ReaderPage` は、`view === "category"` でニュースのカテゴリのときだけ、切り替えの並びの中にダイアログのボタンを置く。

## Goals / Non-Goals

**Goals:**

- カテゴリの一覧と同じ部品で、2つの一覧にもボタンを出す。

**Non-Goals:**

- 個々の購読フィードの一覧への追加のボタン。そこには「購読フィードの設定」がある。
- Androidアプリでの追加。

## Decisions

### `AddFeedDialog` のカテゴリを省けるようにする

`category` を省けるようにし、省いたときは `AddFeedForm` に `categoryId` を渡さない。
2つの一覧のための別のダイアログを作る案は、ボタンとダイアログが2か所に分かれるので採らない。

### ボタンを出す条件に2つの一覧を足す

`ReaderPage` の条件に `view === "feeds"` と `view === "uncategorized"` を足す。位置はカテゴリの一覧と同じで、切り替えの並びの中である。
ニュースのカテゴリの一覧と同じく、カテゴリ（`categories.data`）を読めてから出す。ダイアログのカテゴリの選択肢に使うためである。

### 進行中の変更 `add-feed-from-category` の差分を直す

その差分の「カテゴリの一覧の追加の操作」は、「カテゴリ以外の一覧には表示しない」と書いている。この変更の要件と食い違うので、その文を「この変更で表示する一覧を除く」意味に直し、「操作を出さない一覧」のシナリオは「未読」の一覧のままにする。
進行中の変更をほかの変更から直すのは、`unify-ui-wording` と同じやり方である。

## Risks / Trade-offs

- 2つの変更の差分が、同じ画面の同じ操作を書く。`add-feed-from-category` の文を直し、2つを同時に閉じても食い違わないようにする。
