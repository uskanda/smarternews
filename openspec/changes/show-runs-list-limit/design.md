# Design

## Context

Webの実行履歴の画面は、`useRuns` で実行の一覧のAPIを `limit: 100` で呼ぶ。
APIは新しい順に最大100件を返し、続きの値は返さない。画面は返った行をそのまま表に並べる。
カテゴリで絞り込むと、APIの `category` で絞った100件が返る。

## Goals / Non-Goals

**Goals:**

- 一覧が上限で切れている可能性を、利用者が画面から分かるようにする。
- 絞り込みなしのときは、古い実行を見る手段（カテゴリでの絞り込み）を示す。

**Non-Goals:**

- 続きの読み込み。APIに続きの値を足す必要があり、規模が合わない。
- カテゴリの画面とAndroidのアプリの変更。

## Decisions

### 上限の定数

`queries.ts` に `RUNS_LIMIT = 100` を書き出し、`useRuns` のAPIの呼び出しと、画面の判定と文面の両方で使う。
値が二重に書かれて食い違うことを防ぐ。

### 注記を出す条件

返った件数が `RUNS_LIMIT` 以上のときに出す。
記録がちょうど100件のときも出るが、害は小さい。101件を取って判定する案は、APIへの要求と表示の件数がずれるので採らない。

### 文面

絞り込みの有無で文面を分ける。絞り込み中は、すでに絞り込んでいるので、絞り込みを勧める文を出さない。
注記は表の下に、補足の色（`text-on-surface-muted`）で1行出す。

## Risks / Trade-offs

- ちょうど100件のときにも「100件だけ」と出る。古い実行がないのに注記が出るが、誤解の害は小さい。
- 絞り込み中に100件を超えた古い実行は、画面からは見られないままである。続きの読み込みを足すまでの制限として残る。
