# grilling 記録: show-runs-list-limit

Issue #204「実行履歴は新しい100件で切れ、切れていることも表示しない」の計画の記録である。
対話でのgrillingは省いた。このrunは無人で、計画の段階でも質問は出していない。どの判断もIssueの文面と既存の実装から決まるためである。
計画には「前提にした判断」として判断を並べ、変えたいものがあれば承認の返答に書いてもらう形にした。
利用者は、変更を書かずに計画を承認した（`/ok`）。

## 決定

| 決定 | 選択 | 出典 |

| 注記を出す条件 | 返った件数が上限の100件に達したとき。ちょうど100件のときも出す。101件を取って判定はしない | Issue #204の計画 前提2（`/ok`で承認） |

| 絞り込みなしの文面 | 新しい100件だけを表示していることと、カテゴリで絞り込むとそれより古い実行が出ることを書く | Issue #204の計画 変えること（`/ok`で承認） |
| 上限の値の置き場所 | `apps/web/src/api/queries.ts`に定数として書き出し、`useRuns`と画面の両方で使う | Issue #204の計画 変えること（`/ok`で承認） |

| 計画の承認 | 上の判断に沿った計画を、変更なしで承認 | Issue #204への返答（`/ok`） |
