# Design

## Context

`SearchBox` は、結果の画面にいる間は検索語を表示し、別の一覧へ移っても値を残す。`Shell` の `/` のキーの処理は、広い画面では `#article-search` に `focus()` を呼ぶだけで、狭い画面ではペインのダイアログを開く。ダイアログは、RadixのFocusScopeで最初の欄である検索欄にフォーカスを置き、そのとき欄の文字を選ぶ（`select: true`）。ペインがすでに開いているときの `/` は、`setNavOpen(true)` が何も変えないため、何も起きない。

狭い画面のペインはダイアログで、閉じると中身ごと外れる。開き直すたびに検索欄は作り直され、結果の画面の外では空になる。前の語が残るのは、広い画面だけである。

## Goals / Non-Goals

**Goals:**
- `/` で検索欄へ移ったとき、欄の文字をすべて選ぶ。広い画面と狭い画面の両方で。
- 検索欄のプレースホルダーの色をトークンで指定する。

**Non-Goals:**
- 検索欄の値の持ち方を変えること（grilling.md）。
- クリック・Tab・「項目」のボタンで欄へ入ったときの動きを変えること。

## Decisions

### 広い画面と開いているペインでは、`/` が欄へ移して選ぶ

`/` のキーの処理は、広い画面か、ペインが開いているときに、`#article-search` に `focus()` と `select()` を呼ぶ。狭い画面のペインは開いている間だけ描かれるため、`#article-search` は1つしかない。

### `/` で開くペインは、Radixの動きのままにする

ペインを開くと、Radixが検索欄へフォーカスを移して文字を選ぶ。`/` で開いたときにも選ばれるので、手を加えない。

代わりの案：`/` で開いたことをrefに覚え、`onOpenAutoFocus` で欄を選ぶ（承認された計画の案）。実装の前のテストで、Radixがすでに選んでいることがわかった。計画は「項目」のボタンで開いたときを今のままにするとしており、その今の動きも全選択である。足す処理が要らないため採らない。

### プレースホルダーの色

検索欄の `className` に `placeholder:text-on-surface-muted` を足す。Webでプレースホルダーを持つ欄はこの検索欄だけなので、共通の部品にはしない。

## Risks / Trade-offs

- Radixの版が上がり、開いたときに文字を選ばなくなるおそれがある。→ 狭い画面で `/` を押したときに選ばれることをテストで確かめる。
