# grilling 記録: use-subscriptions-as-topic-sources

Issue #223（購読フィードの配信記事をトピックの候補に使う）で、計画についての質問に答えてもらった。
質問は第1ラウンドの6問で、利用者はすべて推奨どおりに答えた。続けて示した計画も、そのまま承認された。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| まとめた配信記事を一覧に残すか | A：一覧はいまのままにする。配信記事と生成記事の本文の画面に、互いへのリンクだけを出す | Issue #223 第1ラウンド Q1 |
| 実行あたりの件数の上限 | A：config.yamlの `limits` に1つ足す。既定は60件（判定2回分）で、新しい順に取る | Issue #223 第1ラウンド Q2 |
| 配信記事の候補のトピック | A：カテゴリの有効なトピックすべてに結び付ける。judgeの入出力は変えない | Issue #223 第1ラウンド Q3 |
| 書く処理に渡す本文 | A：ほかの候補と同じく元のページを取得する。取れないときは、抜粋の代わりに配信された内容を使う | Issue #223 第1ラウンド Q4 |
| 候補の由来の値 | A：新しい値 `subscription` を足し、実行の詳細に「購読フィード」と出す | Issue #223 第1ラウンド Q5 |

計画で示した前提は次のとおり。

- 対象は、有効なニュースのカテゴリに属し、設定を有効にした購読フィードの配信記事である。対象期間内に保存したもので、重複とフィルターで隠したものは除く。
- 設定を有効にする前に保存した記事も、期間内なら対象にする。
- 判定済みのURLは、件数の上限をかける前に除く。判定済みの記事が毎回の枠を埋めないようにするためである。
- 既定は無効とする。設定を有効にしない限り、いまの動きは変わらない。

## 選ばなかった案

- まとめた配信記事を、全体とカテゴリの一覧から隠す案（Q1 B）。一覧の件数と未読数の計算に条件が増え、読み始めた記事があとから消える
- まとめた時点で配信記事を既読にする案（Q1 C）。利用者が読んでいない記事を既読にしてしまう
- 上限を30件にする案（Q2 B）と、購読フィードごとに上限を持つ案（Q2 C）
- judgeの出力に、合うトピックのIDを足す案（Q3 B）。タスクの定義、プロンプト、トピックの試しに影響が広がる
- ページを取得せず、配信された内容だけで書く案（Q4 B）。要約の材料が薄くなる
- 由来をトピックのフィードと同じ `feed` にする案（Q5 B）。出どころが分からなくなる
- リンクをWebの本文の画面にだけ出す案（Q6 B）

## 見直した既存の決定

- add-feed-subscriptionsの第1ラウンドQ3は「購読フィードはそのまま読むだけにし、トピックの候補には使わない」と決めた。当時は、フィルター、重複の除去、配信記事をLLMに渡す処理がなかった。いまはどれもある。既定を無効にするので、設定しない限り当時の動きは変わらない
