# Proposal

## Why

生成記事の候補は、トピックに書いたフィードのURL、ニュース検索、LLM検索からしか入らない。
購読しているサイトを集約もさせるには、トピックごとにURLを書き写す必要がある。実行は、トピックとURLの組ごとにフィードを取得し直す。
`PRODUCT.md` が挙げる「同じ話題が配信元の数だけ並ぶ」状態が、購読フィードの側に残っている。
いまは、フィルター、重複の除去、配信記事をLLMに渡す処理がそろっている。そのため、購読フィードを候補に使わないとしたadd-feed-subscriptionsの決定を、既定を無効にしたうえで見直す。

## What Changes

- 購読フィードごとに「トピックの取得元にする」の設定を足す。既定は無効で、ニュースのカテゴリに属する購読フィードでだけ有効にできる。
- 実行は、設定を有効にした購読フィードの配信記事のうち、対象期間内に保存したものを、そのカテゴリの候補に加える。重複とフィルターで隠した配信記事、判定済みのURLは加えない。
- 1回の実行で加える配信記事の数に上限を設ける。config.yamlの `limits` に項目を足し、既定は60件とする。新しい順に取る。
- 配信記事の候補は、カテゴリの有効なトピックすべてに結び付けて判定に渡す。候補の由来は新しい値 `subscription` とする。
- 書く処理は、ページを取れないとき、抜粋の代わりに配信された内容を使う。
- 採用した配信記事に、まとめた先の生成記事を記録する。記事の詳細は、互いへの参照を返す。
- Webの購読フィードの設定に切り替えを足す。Webの実行の詳細とトピックの集計で、`subscription` を「購読フィード」と表示する。
- WebとAndroidアプリの本文の画面に、配信記事と生成記事の互いへのリンクを出す。
- 設定ファイルの書き出しと読み込みで、この設定を扱う。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `sources`: 購読フィードの配信記事からの収集、件数の上限、ページを取れないときの本文を足す。
- `feed-subscriptions`: 「トピックの取得元にする」の設定と、まとめた先の生成記事の記録を足す。
- `http-api`: 購読フィードの設定の受け付けと、記事の詳細での互いへの参照を足す。
- `settings`: 設定ファイルでの「トピックの取得元にする」の扱いを足す。
- `web-settings`: 購読フィードの設定の画面に切り替えを足す。
- `web-runs`: 候補の由来としての購読フィードの表示を足す。
- `web-reader`: 本文の画面に、互いへのリンクを足す。
- `mobile-reader`: 本文の画面に、互いへのリンクを足す。

## Impact

- `packages/core`：マイグレーション（`feeds`、`articles`、`candidates` の列とCHECK制約）、`api.ts` のスキーマ、`config.ts` の `limits`、購読フィードの保存、設定ファイル、実行の処理、トピックの集計。
- `apps/server`：購読フィードのAPIと記事の詳細のAPI。`docs/api.md` と `examples/` の設定の例。
- `apps/web`：購読フィードの設定、実行の詳細、トピックの集計、本文の画面。
- `apps/mobile`：本文の画面。
- LLMの呼び出し：有効にした購読フィードがあるカテゴリでは、判定が配信記事30件につき1回増える。上限の既定では、1回の実行で2回までである。
