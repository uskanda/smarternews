## ADDED Requirements

### Requirement: 購読フィードの配信記事からの収集

カテゴリに「トピックの取得元にする」を有効にした購読フィードがあるとき、クローラーは、その購読フィードの配信記事のうち対象期間内に保存したものを、そのカテゴリの候補にしなければならない（MUST）。
候補のURLは配信記事の元のページのURLを正規化したものとし、公開日時のない配信記事は保存した時刻を公開日時とする。
設定を有効化する前の配信記事も、保存が対象期間内なら候補とする。

#### Scenario: 有効にした購読フィードの配信記事

- **WHEN** 対象期間が24時間のニュースのカテゴリで、「トピックの取得元にする」を有効にした購読フィードが、3時間前と3日前に保存した配信記事を持つ状態で実行する
- **THEN** 3時間前に保存した配信記事だけが候補になる

#### Scenario: 無効のままの購読フィード

- **WHEN** 購読フィードの「トピックの取得元にする」が無効で、その購読フィードが1時間前に保存した配信記事を持つ状態で、そのカテゴリを実行する
- **THEN** その配信記事は候補にならず、実行は設定を足す前と同じ候補を判定する

### Requirement: 隠した配信記事を候補にしないこと

重複として隠した配信記事と、フィルターで隠した配信記事について、クローラーは候補にしてはならない（MUST NOT）。

#### Scenario: 重複とフィルター

- **WHEN** 購読フィードの「トピックの取得元にする」が有効で、その購読フィードが、重複として隠した配信記事、フィルターで隠した配信記事、どちらでもない配信記事を持つ状態で実行する
- **THEN** どちらでもない配信記事だけが候補になる

### Requirement: 配信記事の候補のトピック

配信記事を候補にしたとき、クローラーは、その候補にカテゴリの有効なトピックすべてを記録しなければならない（MUST）。
同じURLがトピックの取得元からも得られたとき、候補は1件にまとまる。

#### Scenario: 2つのトピックのあるカテゴリ

- **WHEN** 有効なトピックが2つあるカテゴリで、配信記事が候補になる
- **THEN** 候補には2つのトピックが記録され、由来は購読フィードになる

#### Scenario: トピックのフィードと同じURL

- **WHEN** トピックAのフィードと、「トピックの取得元にする」を有効にした購読フィードの両方から、同じURLが得られる
- **THEN** 候補は1件にまとまる

### Requirement: 配信記事の候補の件数の上限

1回の実行で配信記事から加える候補の数が設定の上限を超えるとき、クローラーは新しく保存した配信記事から上限の数だけを候補にしなければならない（MUST）。
判定済みのURLは、上限を数える前に除く。上限の既定は60件とする。

#### Scenario: 上限を超える配信記事

- **WHEN** 上限が2件の設定で、対象期間内の配信記事が3件ある状態で実行する
- **THEN** 新しく保存した2件だけが候補になり、残りの1件は次の実行で候補になる

#### Scenario: 判定済みの記事が枠を埋めない

- **WHEN** 上限が2件の設定で、対象期間内の配信記事のうち新しい2件が前回の実行で判定済みである
- **THEN** 残りの判定していない配信記事が候補になる

### Requirement: ページを取れない配信記事の本文

記事にすると決まった配信記事の候補のページを取得できないとき、クローラーは、抜粋の代わりに配信された内容を本文の生成に渡さなければならない（MUST）。

#### Scenario: ページが応答しない

- **WHEN** 記事にすると決まった配信記事の候補のページが、取得に失敗する
- **THEN** 本文の生成には、その配信記事の配信された内容が渡される
