# grilling 記録: mark-selected-row

GitHubのissueの115番のコメントで、1ラウンドの質問（Q1〜Q4）に答えた記録である。
issueは、2026-11-06のWeb UIの監査の項目U-08である。選択中の行が淡い地の色だけで示され、行をクリックしたあとにキーで移るとフォーカスの枠と選択の位置がずれる。未読と既読は太さと色だけで示し、読み上げでは区別できない。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 選択中の行の形の目印 | 行の右端に、上から下まで `primary` の3pxの縦線を引く。フォーカスの枠（2px）とは太さで見分ける。左端は重要度の印の場所なので使わない（A） | 第1ラウンド Q1 |
| 目印を付ける一覧の範囲 | 記事・イベント・注釈の3つの一覧に、形の目印とフォーカスの移動を入れる。未読の読み上げは記事とイベントの行に入れる。navとAndroidアプリには手を入れない（A） | 第1ラウンド Q2 |
| キーで移ったときにフォーカスを移す条件 | フォーカスが一覧の中にあったときだけ、選んだ行のリンクへ移す。本文やページ全体にフォーカスがあるときはそのままにする。スクロールは今の動きに任せ、フォーカスは `preventScroll` で移す（A） | 第1ラウンド Q3 |
| 未読と既読の読み上げ | 未読の行だけ、見出しの前に `sr-only` で `未読。` を足す。`重要度N。` より前に置く。既読の行には何も足さない（A） | 第1ラウンド Q4 |

## 計画で決めたこと

承認を求めた計画（issueのコメント）で、次を決めた。利用者は変更なしで承認した。

| 決定 | 選択 |
|---|---|
| 順序 | DESIGN.mdの `selected` と `list-row` の説明を先に変え、そのあとでコードを変える |
| 線の描き方 | 選択中の `li` の中に、`aria-hidden` の要素を右端へ絶対配置で置く。行の幅や折り返しを変えないためである。3つの一覧で同じものを1か所にまとめる |
| Spaceでの移動 | 本文の末尾でSpaceを押して次の記事へ移るときも、j/kと同じ条件でフォーカスを移す |
