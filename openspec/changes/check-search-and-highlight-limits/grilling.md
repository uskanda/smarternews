# grilling 記録: check-search-and-highlight-limits

Issue #103（検索の語とハイライトの長さの上限を、画面で確かめていない）で、計画についての質問に答えてもらった。
質問は1ラウンドで6つある。利用者はすべて推奨（A）を選び、続く計画を `/ok` で承認した。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 直す範囲 | A：Webだけを直す。確かめる関数は `packages/client` に置き、Androidアプリの検索欄は別のissueにする | Issue #103 第1ラウンド Q1 |
| 検索欄で上限を超えたとき | A：送らずに、検索欄の下に理由を出す。入力は残し、結果の画面へは移らない。直して押し直せば消える | Issue #103 第1ラウンド Q2 |
| ハイライトで上限を超えたとき | A：ボタンは今のまま出す。押したとき（`h` キーと右クリックのメニューも）は送らず、知らせで理由を出す。「メモを書く」ではダイアログを開かない | Issue #103 第1ラウンド Q3 |
| 理由の文 | A：検索は `検索の語は200文字以内にしてください。`、ハイライトは `ハイライトする文字列は5000文字以内にしてください。選ぶ範囲を狭めてください。` | Issue #103 第1ラウンド Q4 |
| 長すぎる語の付いたURL | A：検索を送らず、結果の画面に理由を出す。「再試行」は出さない | Issue #103 第1ラウンド Q5 |
| OpenSpecの変更 | A：OpenSpecの変更を作り、それから実装する | Issue #103 第1ラウンド Q6 |
| 計画の承認 | 上の6つの答えに沿った計画を承認 | Issue #103への返答（`/ok`） |

## 選ばなかった案

- 検索欄にmaxLengthを付ける案。貼り付けた語が黙って切られ、絵文字を2文字に数えるのでサーバーの数え方と合わない
- 結果の画面へ移ってから理由を出す案。直すために左のペインへ戻らなければならない
- 上限を超える選択でメニューのボタンを押せなくする案と、出さない案。入口ごとに別の扱いが要り、出さない案は理由が分からない
- Androidアプリの検索欄も一緒に直す案。変更がAndroidアプリの画面とテストまで広がる
