# Design

## Context

動機は `proposal.md` のWhyに書いた。

- サーバーは、検索の語を前後の空白を除いてから `charCount` で数える。絵文字のような、UTF-16で2単位を使う文字も1文字である（`packages/core/src/search/text.ts`）。
- ハイライトの引用は、zodの `.max` で数える。空白を除かず、UTF-16の長さで数える（`packages/core/src/api.ts`）。
- 画面の確かめは `packages/client/src/messages.ts` に置き、サーバーの拒否と同じ文を `describeProblem` で作る決まりである。今の `checkText` はUTF-16の長さで数えるので、検索の語には合わない。
- ハイライトを付ける入口は3つある。選んだ文字列のメニュー、右クリックのメニュー、`h` キーである。どれも `Annotations.tsx` の `add` を呼ぶ。「メモを書く」は、ダイアログを開いてから `add` を呼ぶ。

## Goals / Non-Goals

**Goals:**

- 送っても必ず断られる語と範囲を、送る前に止め、直し方の分かる理由を出す。
- 画面の数え方を、サーバーの数え方とそろえる。

**Non-Goals:**

- Androidアプリの検索欄（別のissueにする。grilling.md）。
- メモの長さ。メモの入力欄は、すでにmaxLengthで5000文字に限っている。
- サーバーの上限や数え方を変えること。

## Decisions

### 確かめる関数は `packages/client` に2つ置く

`checkSearchWords(text)` と `checkHighlightQuote(quote)` を `messages.ts` に足す。どちらも、超えたときは理由の文を、超えなければnullを返す。
上限の定数と `charCount` は `@smarternews/core/api` から読み込み、サーバーと同じ値と数え方を使う。
文は `describeProblem` のtoo_bigで作る。ハイライトでは、何を直すかが分かるように、範囲を狭める指示の1文を足す（grilling.md Q4）。
`checkText` を数え方の引数で広げる案は採らない。数え方が2つの関数で違い、引数で切り替えると呼ぶ側で取り違えやすい。

### 検索欄は送る前に止める

`SearchBox` の `submit` で確かめ、超えたら理由を状態に持って、検索欄の下に出す。検索欄は `aria-invalid` にし、理由の要素を `aria-describedby` で結ぶ。
見た目は `Field` の誤りの文（`type-label-sm text-error`）と枠の色にそろえる。
理由は、語を変えたときに消す。押し直して通ったときも消える。

### 結果の画面は検索を止めて理由を出す

`ReaderPage` は、`words` が長すぎるとき、`useArticleSearch` を止める（`enabled` をfalseにする）。
理由は `ErrorNotice` で出す。`ErrorNotice` に決まった文を渡す `message` を足し、`onRetry` は渡さない。誤りの役割（`role="alert"`）と見た目を、ほかの失敗と共有するためである。
このとき、読み込み中の表示と、一致する記事がないときの表示は出さない。

### ハイライトは `add` の手前の1か所で確かめる

`Annotations.tsx` に、確かめてから進む関数を1つ置く。3つの入口と「メモを書く」は、どれもこれを通る。
超えたら `toast` で理由を出し、送らない。「メモを書く」では `setWritingFor` を呼ばない。選んだ範囲は消さない。狭め直すときの手がかりにするためである。

### 仕様は要件を足す形で書く

計画では、既存の要件「検索の開始」「検索の結果の画面」「ハイライトの操作」に場面を足すとした。
「ハイライトの操作」は付けたハイライトを押したときの要件であり、新しく付ける操作は扱っていない。
また、1つの要件に1つの振る舞いを書く決まりがある。そこで、上限を超えたときの振る舞いを、それぞれ新しい要件として足した。振る舞いの中身は計画のとおりである。

## Risks / Trade-offs

- サーバーの上限や数え方が変わると、画面とずれる。→ 定数と `charCount` をサーバーと同じ場所から読み込む。空白と絵文字の数え方の違いは、関数のテストで固定する。
- 長すぎる語のURLでは、見出しに200文字を超える語がそのまま出る。→ 今と同じ扱いで、表示が長くなるだけで害はない。手を入れない。
