## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 文字参照の表の出どころ | A：`entities` を `packages/core` の依存に足し、その表で解く。名前の大文字と小文字は区別する | 第1ラウンド Q1 |
| フィードの大きさの上限 | A：`config.yaml` に `fetch.feedMaxBytes` を足し、既定を10MBにする | 第1ラウンド Q2 |
| 略称 `IST` の読み方 | A：表に入れない。その項目は公開日時なしのままにする | 第1ラウンド Q3 |
| guidをURLに使う条件 | A：`http(s)` のURLの形で、`isPermaLink="false"` でないguidだけを使う | 第1ラウンド Q4 |
| 時差のない日時の読み方 | 全体設定のタイムゾーンで読む。Webページの購読フィードの日時と同じ扱い | 計画の承認（コメント6952737010）で確認 |
| 読む略称の一覧 | `JST`、`KST`、`CET`、`CEST`、`BST`、`WET`、`WEST`、`EET`、`EEST`、`MSK`、`HKT`、`SGT`、`AEST`、`AEDT`、`NZST`、`NZDT` | 計画の承認で確認 |
| Atomのenclosureの位置 | RSSのenclosureと同じく、添付の先頭に足す | 計画の承認で確認 |
| フィードの上限を使う取得 | 購読フィードの取得、トピックのフィードとニュース検索、フィードの探索。Webページの購読フィードと全文の取得は `fetch.maxBytes` のまま | 計画の承認で確認 |
| `Fetcher` の分け方 | 分けない。`get` に呼び出しごとの上限を渡す。ホストごとの間隔は1つの勘定のまま | 計画の承認で確認 |
| ページの公開日時（`extract.ts`） | Issueの範囲の外なので変えない | 計画の承認で確認 |
