# grilling 記録: add-relevance-sort

Issue #60「関連度での並び」の計画の記録である。
問いはIssueのコメントで2ラウンド出し、利用者は全問に答えた。第1ラウンドは、最初に出した4問を、コードを調べて分かった事実とともに出し直したものである。
そのあと、答えに沿った計画を出し、利用者は直す箇所を挙げずに承認した（`/ok`）。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 対象の記事 | 生成記事と配信記事の両方。2種類が混ざる一覧でも関連度順を選べる | 第1ラウンド Q1（C） |
| 配信記事の関連度の根拠 | 利用者の行動（購読フィードごとの、開いた割合とスターを付けた割合）と、色付けの語への一致の両方。LLMは呼ばない | 第1ラウンド Q2（A） |
| 新しさの扱い | 古い記事を上に出し続けない。関連度に、時刻が古くなるほど小さくなる重みを掛ける | 第1ラウンド Q3（A） |
| 選ぶ場所 | 並び順のメニュー（#48）に「関連度順」を足し、項目ごとに保存する。並びが固定の一覧には出さない | 第1ラウンド Q4（A） |
| 関連度で動かす最大の時間 | 48時間。関連度が最も高い記事を、最も低い記事より48時間新しい記事として並べる | 第2ラウンド Q5（C） |
| 生成記事と配信記事の尺度 | 両方を0から1にそろえる。重要度1は0、重要度5は1とし、配信記事も最大で重要度5と同じ扱いになれる | 第2ラウンド Q6（A） |
| 配信記事の値の配分 | 行動0.5、語の一致0.5 | 第2ラウンド Q7（A） |
| 重みの形と続きの取得 | 指数的に減る重み。並びの値（時刻＋関連度を換算した時間）を記事ごとに持ち、索引を張る。続きの値は `[並びの値, id, "relevance"]` | 第2ラウンド Q8（A） |
| 値を計算する時点 | 語の一致は記事の保存時と語の変更時に調べて保存する。行動の値は1日1回スケジュールで計算し直す | 第2ラウンド Q9（A） |
| 行動の値の数え方 | 直近30日に保存した記事のうち、開いたかスターを付けた記事の割合。最も割合の高いフィードを1として比べる。記事が10件未満のフィードは全フィードの平均の値にする | 第2ラウンド Q10（A） |
| 語を照合する文字列 | 見出し（翻訳した見出しを含む）と要約。1語でも一致すれば1、なければ0 | 第2ラウンド Q11（A） |
| 選択肢を出す場所と見せ方 | 「新しい順」「古い順」と同じメニューで選ぶ。APIは `order=relevance`、設定ファイルは `sort: relevance`。値や理由は画面に出さない | 第2ラウンド Q12（A） |
| 計画の承認 | 上の決定に沿った計画（移行032、`rank_at` の仮想の生成列、スケジューラーでの1日1回の計算、起動直後の計算を含む）を、変更なしで承認 | Issue #60への返答（`/ok`） |
