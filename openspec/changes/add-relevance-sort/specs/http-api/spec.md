# Spec Delta

## ADDED Requirements

### Requirement: 関連度順の一覧

関連度順を指定した記事の一覧の要求を受けたとき、APIは、記事の時刻に関連度ぶんの時間を足した並びの値の大きい順に記事を返さなければならない（MUST）。
記事の時刻は、新しい順の一覧と同じ時刻である。関連度は0から1の値で、関連度1の記事は48時間新しい記事として並ぶ。
生成記事の関連度は、重要度1を0、重要度5を1とする等間隔の値である。
配信記事の関連度は、購読フィードの行動の値と、色付けの語への一致（一致すれば1、なければ0）を、半分ずつ合わせた値である。
APIは、関連度を求めるためにLLMを呼んではならない。

#### Scenario: 重要度の高い生成記事を上に出す

- **WHEN** 重要度5で最終更新が24時間前の生成記事Aと、重要度1で最終更新が1時間前の生成記事Bがあり、関連度順を指定して一覧を要求する
- **THEN** 記事Aが記事Bより前に返る

#### Scenario: 古くなれば上に居続けない

- **WHEN** 重要度5で最終更新が3日前の生成記事Aと、重要度1で最終更新が1時間前の生成記事Bがあり、関連度順を指定して一覧を要求する
- **THEN** 記事Bが記事Aより前に返る

#### Scenario: 語に一致する配信記事

- **WHEN** 同じ購読フィードに、時刻が同じで、見出しが色付けの語に一致する配信記事Aと、一致しない配信記事Bがあり、関連度順を指定して一覧を要求する
- **THEN** 記事Aが記事Bより前に返る

#### Scenario: 生成記事と配信記事が混ざる

- **WHEN** 最終更新が10時間前で重要度5の生成記事Aと、並びの時刻が1時間前で、行動の値が0で語に一致しない配信記事Bがあるカテゴリについて、関連度順を指定して一覧を要求する
- **THEN** 記事Aが記事Bより前に返る

### Requirement: 関連度順の一覧の分割

関連度順の一覧が1回の件数の上限を超えるとき、APIは、関連度順のまま続きを取得するための値を返さなければならない（MUST）。
新しい順と古い順の一覧で返された続きの値を関連度順の要求に付けたとき、または関連度順の続きの値をほかの並び順の要求に付けたとき、APIは、入力が不正であることを示す応答を返す。

#### Scenario: 関連度順で続きを取得する

- **WHEN** 記事が120件あり、関連度順を指定して1回の件数を50にした一覧を要求し、返された値で続きを2回要求する
- **THEN** 50件、50件、20件が重複なく、関連度順で返り、最後の応答には続きの値がない

#### Scenario: 並び順の違う続きの値

- **WHEN** 新しい順の一覧で返された続きの値を、関連度順を指定した一覧の要求に付ける
- **THEN** APIは、入力が不正であることを示す応答を返す

### Requirement: 関連度順を受け付けない一覧

イベントの一覧または最近読んだ記事の一覧で関連度順を指定されたとき、APIは、入力が不正であることを示す応答を返さなければならない（MUST）。

#### Scenario: イベントの一覧で関連度順を指定する

- **WHEN** 種別にイベントを指定し、関連度順も指定して一覧を要求する
- **THEN** APIは、入力が不正であることを示す応答を返す

#### Scenario: 最近読んだ記事の一覧で関連度順を指定する

- **WHEN** 最近読んだ記事の一覧を、関連度順を指定して要求する
- **THEN** APIは、入力が不正であることを示す応答を返す

### Requirement: 関連度順の一覧での一括の既読

関連度順の一覧を読み込んだ時刻を一括の既読の時刻に指定したとき、APIは、読み込んだ件数にかかわらず、その時刻までに更新された対象の未読の記事を既読にしなければならない（MUST）。

#### Scenario: 関連度順の最初の50件だけを読み込む

- **WHEN** 未読が120件あるカテゴリを、関連度順、1回の件数50で要求し、続きを取得しないまま、応答の時刻を指定してそのカテゴリの一括の既読を要求する
- **THEN** 120件すべてが既読になる

### Requirement: 関連度順の表示の設定

APIは、項目ごとの表示の設定の並び順として、新しい順と古い順に加えて関連度順を受け付けなければならない（MUST）。
関連度順を保存できるようにする更新は、それまでに保存した並び順を変えてはならない。

#### Scenario: カテゴリを関連度順にする

- **WHEN** カテゴリAの並び順を関連度順に変え、表示の設定を読み出す
- **THEN** カテゴリAの並び順は関連度順として返る

#### Scenario: 更新の前に保存した並び順

- **WHEN** 「未読」と購読フィードXを古い順にしたサーバーを、関連度順を保存できる版へ更新する
- **THEN** その2つの項目は古い順のままである

### Requirement: 行動の値の計算

サーバーは、購読フィードごとの行動の値を、起動の直後と、そのあと1日に1回、計算し直さなければならない（MUST）。
行動の値は、直近30日に保存したその購読フィードの記事のうち、開いたかスターを付けた記事の割合を、割合が最も高い購読フィードを1として比べた0から1の値である。
フィルターで隠した記事と、隠した重複の記事は数えない。
数える記事が10件未満の購読フィードには、10件以上ある購読フィードの値の平均を使う。10件以上ある購読フィードがないか、どの記事も開かれずスターもないときは、どの購読フィードも0である。
新しく登録した購読フィードは、次に計算し直すまで、10件未満の購読フィードと同じ値を使う。

#### Scenario: よく開く購読フィード

- **WHEN** 直近30日に、購読フィードXの記事20件のうち10件を開き、購読フィードYの記事20件のうち5件を開いた状態で、行動の値を計算し直す
- **THEN** Xの行動の値は1、Yの行動の値は0.5になる

#### Scenario: 記事の少ない購読フィード

- **WHEN** 前の状態に加えて、直近30日の記事が3件の購読フィードZがあり、行動の値を計算し直す
- **THEN** Zの行動の値は、XとYの平均の0.75になる

#### Scenario: 記録がない

- **WHEN** どの記事も開かれず、スターもない状態で、行動の値を計算し直す
- **THEN** どの購読フィードの行動の値も0になる

#### Scenario: 計算し直すまで並びは変わらない

- **WHEN** 関連度順の一覧を読み込んだあとで、配信記事を開き、続きを要求する
- **THEN** 続きの記事は、最初に読み込んだときと同じ並びの値で返り、重複も欠落もない
