# Design

## Context

左のペインの項目は、`packages/client/src/nav.ts` の1つのモデル（`NavModel`）から描く。
Webの画面は、隠す前のモデル（`full`）と、未読のない項目を隠したモデル（`shown`）の両方を持つ。
キー操作は `apps/web/src/lib/keys.ts` の `useHotkeys` に表で登録し、`g` に続くキーは、表に `"g x"` の形で足すだけで働く。
狭い画面の左のペインの中でも `g` の組は受け取る。
`data-hotkeys="off"` を付けたダイアログの中では、1文字のキーが背後の一覧へ届かない。

## Goals / Non-Goals

**Goals:**

- 名前の一部を打って、カテゴリか購読フィードの一覧へ少ないキーで移る。
- 候補の作り方と絞り込みを、画面を持たない純粋な関数へ置き、テストで決める。

**Non-Goals:**

- Androidアプリの同じ操作。
- 固定の項目（「未読」など）とカテゴリの下の「AI生成」を候補にすること。
- あいまい一致。

## Decisions

### 候補の作り方

`order.ts` に `jumpCandidates(model, query)` を足す。隠す前のモデルを受け取り、各グループの見出し（カテゴリか「未分類」）と、その下の購読フィードを左のペインの順に並べる。
カテゴリの下の「AI生成」は除く。購読フィードの候補は、属するグループの名前を持つ。
無効のカテゴリは `buildNav` の段階で除かれているので、追加の処理は要らない。

### 絞り込み

名前と入力を `normalize("NFKC").toLowerCase()` でそろえ、入力を空白で語に分けて、すべての語を含む候補だけを残す。
入力が空白だけのときは、すべての候補を返す。
購読フィードの候補は自分の名前だけで比べ、属するカテゴリの名前では当てない。カテゴリの名前で当てると、カテゴリ名を打ったときに配下の購読フィードがすべて残り、目的のカテゴリが埋もれる。

### ダイアログ

`JumpDialog.tsx` を新しく置き、`@radix-ui/react-dialog` で作る。依存は足さない。
入力欄は `role="combobox"`、候補の一覧は `role="listbox"`、各候補は `role="option"` にする。
選んでいる候補は `aria-activedescendant` と `aria-selected` で伝え、見た目では背景の色と太字で示す。
選ぶ位置は入力が変わるたびに先頭へ戻し、`↑` と `↓` は端で止める。
Enterは、日本語入力の変換中（`isComposing`）なら何もしない。
候補を開くと、ダイアログを閉じ、`react-router` で移り、フォーカスを `#content` へ移す。閉じるときにRadixが元の要素へフォーカスを戻すので、`onCloseAutoFocus` でそれを止める。

### Shellへの組み込み

`KEYS` の `g r` の次に `g u` を足し、`useHotkeys` の表に `"g u"` を足す。
狭い画面では、開いたあとに左のペインも閉じる。
移動は `react-router` を通るので、設定の未保存の確認がそのまま働く。

## Risks / Trade-offs

- `u` の単独のキーは「既読も表示するかを切り替える」である。`g` の直後の `u` は組として使い切られるので、両方が働くことはない。
- 購読フィードが数百件あると、空の入力で全件を描く。個人用で件数は限られるので、仮想化はしない。
