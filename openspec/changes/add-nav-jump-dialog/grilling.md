# grilling 記録: add-nav-jump-dialog

Issue #221「名前を打って項目へ移る操作」の計画の記録である。
計画の段階で、質問は出していない。どの判断もIssueの文面か既存の規約から決まるためで、計画に「前提にした判断」として6つを並べ、変えたいものがあれば `/ok` に続けて書いてもらう形にした。
利用者は、変更を書かずに `/ok` だけで計画を承認した。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 候補の範囲 | カテゴリ（「未分類」を含む）と購読フィードだけ。固定の項目には `g a` などがある。カテゴリの下の「AI生成」は、どのカテゴリでも同じ名前なので名前で選べない | Issue #221の計画 前提1（`/ok` で承認） |
| 隠れている項目 | 候補に入れる。折りたたんだカテゴリの下の購読フィードも、未読のない項目を隠す設定で隠している項目も入る。`g e` も隠す前のモデルを使っている | Issue #221の計画 前提2（`/ok` で承認） |
| 絞り込みの方式 | 部分一致。NFKCと小文字にそろえて比べる。空白で区切った語は、すべてを含む候補だけを残す。トピックの重複の判定と同じ比べ方 | Issue #221の計画 前提3（`/ok` で承認） |
| 候補の並び | 左のペインの順。打つたびに順が入れ替わらない | Issue #221の計画 前提4（`/ok` で承認） |
| マウスや指での操作からの入口 | 足さない。Issueはキー操作の不足を挙げており、左のペインはクリックで選べる | Issue #221の計画 前提5（`/ok` で承認） |
| 無効のカテゴリ | 候補に入れない。左のペインに出ない | Issue #221の計画 前提6（`/ok` で承認） |
| キー | `g` に続けて `u`。ダイアログは「項目へ移る」 | Issue #221の本文 |
| 開いたあと | ダイアログを閉じ、フォーカスを内容へ移す。狭い画面の左のペインも閉じる | Issue #221の計画 |
| 計画の承認 | 上の判断に沿った計画を、変更なしで承認 | Issue #221への返答（`/ok`） |
