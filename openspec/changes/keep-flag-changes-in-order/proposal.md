# Proposal

## Why

Webの画面で既読やスターを変えると、画面には押した時点で反映する。ところが、その時点で実行中だった一覧の取得の応答は、変更の前のサーバーの値を持っている。その応答が届くと、変更が古い値で上書きされる。「すべて」の一覧で`s`を押してすぐに`m`を押すと、一覧の行と本文の表示が最大60秒食い違う。記事を開いた直後に届く一覧でも、開いて既読にした行が未読に見える。
同じ記事への変更を続けて送ると、要求は別々の接続で送られ、サーバーに届く順序が入れ替わる場合がある。そのときは、最後に押した値がサーバーに残らない。

## What Changes

- 既読とスターを変えたとき、実行中の記事の一覧と、その記事の取得を取り消す。取り消した取得は、変更がすべて終わったあとに取得し直す。
- 変更のあとの再取得（件数、スターの一覧、最近読んだ記事など）は、最後の変更が終わったときにまとめて出す。
- 一覧の最初の読み込みと、次のページの読み込みは取り消さない。届いた内容に変更を当て直す。
- 同じ記事への変更は、前の要求の応答を待ってから送る。別の記事への変更は待たせない。
- アプリ（`apps/mobile`）は変えない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

なし。web-readerの「スターの切り替え」「開いた記事の既読化」の要求は変わらず、その実現の不具合を直す変更である。要求は変わらないので、`.openspec.yaml`に`skip_specs: true`を置く。

## Impact

- `apps/web/src/api/queries.ts`の`useArticleFlags`
- `apps/web/src/testing/harness.tsx`に、指定した要求の応答を止めておく手段を足す
- `apps/web/src/reader/reader.test.tsx`のテスト
- APIとサーバーは変わらない
