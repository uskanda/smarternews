# grilling 記録: scale-web-text-with-font-size

Issue #122（文字の拡大と狭い幅での表示の崩れ）について、計画への質問に答えてもらった。
書体の大きさをpxで指定しているため、ブラウザーの文字の大きさの設定は画面に反映されない。390px幅で文字を200%にすると、記事の一覧の見出しと引き出しの項目の名前は欠けるおそれがある。

## 前提（質問にしなかったもの）

- DESIGN.mdの値はpxのまま残し、Web向けの書き出しだけをremに換算する（16pxを1remとする）。Androidアプリの定数は変えない。
- `sizes.ts` の行の高さはpxの数なので、Spaceで本文を送る量は、実行時の文字の大きさに合わせて計算し直す。
- 間隔（`xs` から `2xl`）と指で押す部品の高さ（44px）は、pxのまま残す。
- 画面の崩れを自動で確かめる道具はリポジトリに無い。書き出しはテストで確かめる。画面は、390px幅と文字200%の条件のブラウザーを使い、手で確かめる。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 文字の大きさに追従させる範囲 | B：書体をremにし、ペインの数を切り替える幅もemにする（68.75emと45em）。ペインの幅はpxのまま | Issue #122 第1ラウンド Q1 |
| 見出しとボタンを2行に分ける条件 | A：見出しに6文字ほどの幅が残らないときだけ、ボタンを次の行へ送る | Issue #122 第1ラウンド Q2 |
| 引き出しの幅 | A：80vwと12.5rem（既定の文字で200px）の小さいほう | Issue #122 第1ラウンド Q3 |
| 計画の承認 | 上の3つの答えに沿った計画を承認 | Issue #122への返答（`/ok`） |
