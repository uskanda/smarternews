# smarternews

[English](README.md)

smarternewsは、1人の読み手のためのセルフホスト型ニュース収集サーバーである。
追いたい話題をキーワードか文章で登録すると、サーバーがスケジュールに従って関連するページを集める。
同じ話題のページは1つの記事にまとめ、出典へのリンクを付ける。記事はHTTPのAPIとRSSで読める。

RSSを読むアプリとしても使える。RSSやAtomのフィードを購読すると、配信された記事が、LLMの書いた記事と並んで表示される。

判定と文章の生成はLLMが受け持ち、それ以外はプログラムが受け持つ。
取得、重複の排除、スケジュール、RSSの生成はLLMを呼ばない。購読フィードの取得と記事の保存も、LLMを呼ばない。
LLMを呼ぶのは、トピックの解釈、Webの検索、候補の判定、話題ごとの集約、記事の執筆、配信記事の要約、配信記事の翻訳の7つのタスクだけである。要約と翻訳は、利用者が選んだ購読フィードの記事だけに行う。
どのタスクも入力の形と出力のJSON Schemaが決まっているので、プロバイダーを差し替えられる。

## 状態

このリポジトリには、サーバー（クローラー、API、RSS）、読むことと設定のためのWebの画面、読むためのAndroidアプリがある。
3つとも同じAPIを使う。RSSを読める任意のアプリでも購読できる。

## 必要なもの

- LinuxまたはmacOS、Node.js 24以降、pnpm。
- LLMのプロバイダー。既定は [Claude Code](https://claude.com/claude-code) の `claude` コマンドで、サーバーを動かすユーザーで導入とログインを済ませておく。OllamaやLM StudioのようなOpenAI互換のサーバーも使える。設定は [docs/providers.md](docs/providers.md) にある。

サーバーはNodeでTypeScriptを直接実行するので、ビルドは要らない。ビルドするのはWebの画面だけで、コマンド1つで済む。

## 使い始める

```bash
git clone https://github.com/uskanda/smarternews.git
cd smarternews
pnpm install
pnpm build    # Webの画面をビルドする。APIとRSSだけを使うなら省ける

# 例のカテゴリを読み込む。あとで自分の内容に置き換える。
node apps/server/src/main.ts import examples/settings.example.yaml

# カテゴリを1つ、いますぐ実行する。LLMを数回呼び、結果を1行で表示する。
node apps/server/src/main.ts run developer-tools

# API、RSS、スケジュールを起動する。
node apps/server/src/main.ts serve
```

`run` コマンドはサーバーなしで動く。サーバーの起動後は、APIの `POST /api/v1/categories/:id/runs` で実行を始める。こうすると実行はサーバーの待ち行列に入り、1つずつ進む。

サーバーの既定の待ち受けは `127.0.0.1:8787` である。ブラウザーで `http://127.0.0.1:8787/` を開いてAPIのトークンを貼り付けるか、別の端末から次のようにAPIを呼ぶ。

```bash
API=http://127.0.0.1:8787
TOKEN=$(node apps/server/src/main.ts token api)
FEED_TOKEN=$(node apps/server/src/main.ts token feed)

curl -s "$API/api/v1/health"
curl -s -H "Authorization: Bearer $TOKEN" "$API/api/v1/articles?unread=true"
curl -s "$API/rss/all.xml?token=$FEED_TOKEN"
```

## Webの画面

3つのペインで記事を読む。左は項目とカテゴリ、中央は記事の一覧、右は本文である。狭い画面では1ペインずつ表示する。配色は、設定の画面で「端末に従う」「ライト」「ダーク」「ダークブルー」の4つから選ぶ。既定は「端末に従う」で、端末が明るい配色のとき「ライト」、暗い配色のとき「ダークブルー」で表示する。選んだ配色はブラウザーに保存する。左と中央のペインは、境目をドラッグすると幅を変えられる。境目にフォーカスして矢印キーでも変えられ、ダブルクリックで元の幅に戻る。幅はブラウザーに保存する。

- 記事を開くと既読になる。「すべて既読にする」は一覧の記事をまとめて既読にし、10秒以内なら取り消せる。
- 重要度4と5の記事には一覧で印が付き、切り替えでその記事だけに絞れる。
- 種別がイベントのカテゴリは、開催日ごとの一覧で表示する。
- 購読フィードのあるカテゴリは、名前の下に「AI生成」と各フィードが並ぶ。「AI生成」は、LLMが書いた記事だけの一覧である。上段の「AI生成」は全カテゴリを対象にする。カテゴリのないフィードは「未分類」に入る。
- 左のペインのカテゴリと購読フィードは、ドラッグで並べ替えられる。購読フィードは、別のカテゴリの上に0.5秒とどまってから離すと、そのカテゴリへ移る。
- カテゴリと購読フィードを右クリックすると、上下へ動かすメニューが開く。購読フィードのメニューからは、登録の解除もできる。キーボードでは `Shift+F10` で同じメニューが開く。
- 並び順はサーバーに保存する。Androidアプリ、設定ファイル、OPMLも同じ順になる。
- 「すべて既読にする」のあとは、下にある未読ありの次の項目が開く。カテゴリからは次のカテゴリへ、購読フィードからは次の購読フィードへ移る。この動きは、全体設定の切り替えで止められる。
- 設定の画面で、カテゴリ、トピック、購読フィード、フィルター、読み手情報、全体設定を編集できる。設定ファイルとOPMLの読み書きもできる。
- 実行履歴で、実行ごとに集めた数、失敗の内容、除外した候補とその理由を確かめられる。
- 左のペインの上の検索欄で、既読を含む記事を語で探せる。一致した語は、一覧と本文で強調する。結果はカテゴリ、購読フィード、未読だけで絞り込める。結果の画面のURLは検索語を含む。

キー操作は次のとおり。`j` と `k` で次と前の記事、`s` でスター、`m` で既読の切り替え、`o` で主な出典を開く。`w` で配信記事の全文を取得し、全文のある記事では配信された内容と切り替える。`Shift+F10` でカテゴリと購読フィードのメニューを開く。`/` で検索欄へ移る。`?` で一覧を出す。`j` と `k` で選んだ記事が一覧の表示範囲から外れると、一覧が1画面分進む。

画面の言葉は日本語である。記事は、設定した出力言語で書かれる。新しい版のChromeで確かめてあり、2024年以降のFirefoxとSafariでも動く想定である。

トークンはブラウザーの保存領域に置く。設定の画面の「このブラウザーからトークンを消す」で消せる。画面そのものを開発するときは、サーバーを動かしたまま `pnpm --filter @smarternews/web dev` を実行する。

## Androidアプリ

Androidアプリは、携帯端末で読むためのものである。Webの画面と同じ一覧と記事を表示し、記事を開くと既読にし、新着の記事を通知で知らせる。配色は、アプリの設定の画面で同じ4つから選び、端末に保存する。
項目の一覧では、カテゴリと購読フィードを長押しのあとにドラッグすると、並べ替えられる。
APKは [リリースのページ](https://github.com/uskanda/smarternews/releases) から取得して端末に入れる。入れるとき、その入手元からの導入を許可するかをAndroidが1度たずねる。APKには、サーバーの宛先とトークンのどちらも入っていない。

接続するには、PCでWebの設定の画面を開き、「アプリ接続用のQRコードを表示する」を押して、アプリの最初の画面から読み取る。サーバーのURLとトークンを入力しても接続できる。
トークンは、端末の暗号化された保存領域に置く。端末からサーバーへ届く必要があるので、Tailscaleなどを使う。

- 記事を左右に払うと、次の記事と前の記事へ移る。一覧の行は、左へ払うと開かないまま既読になる。行を長く押すと、スターと出典の操作を選べる。
- 配信記事の画面の上部のボタンで全文を取得する。全文のある記事では、このボタンで配信された内容と切り替える。
- 左から出る引き出しに、Webの画面と同じ項目、カテゴリ、購読フィードが、未読数つきで並ぶ。
- 設定の画面では、読み手情報の編集、カテゴリの即時の実行、直近の実行の結果の確認ができる。カテゴリ、トピック、購読フィード、フィルターの編集はWebの画面で行い、設定の画面からブラウザーで開ける。
- 画面の言葉は日本語で、表示は縦向きに固定する。

通知は端末の中で作る。アプリを閉じている間、端末がときどきサーバーに新着をたずねる。間隔は15分以上で、時刻はAndroidが決める。
そのため、通知は記事ができてからしばらく遅れることがある。端末の省電力の設定で、さらに遅れることもある。アプリを開けば、いつでも最新の状態が表示される。
通知のサービスへは何も送らない。既定では重要度5の記事だけを通知し、設定の画面で「AI生成のすべての新着」と「出さない」を選べる。購読フィードの記事は通知しない。

アプリが通信する相手は、接続したサーバーだけである。例外は、購読フィードの記事の画像で、配信元のサイトから読み込む。QRコードの読み取りにはGoogleのML Kitを使う。ML Kitは読み取りの利用の統計を送る仕組みを持つので、送信を担う部分をビルドから外してある。
出典を開くと、ブラウザーがそのサイトと通信する。

APKを自分で作るには、JDK 17とAndroid SDKが要る。

```bash
cd apps/mobile
pnpm exec expo prebuild --platform android --clean
cd android && ./gradlew assembleRelease
```

署名の鍵がないときは、試すためのデバッグ用の鍵で署名される。[.github/workflows/android.yml](.github/workflows/android.yml) のワークフローは、リポジトリのsecretに置いた鍵で署名し、リリースごとにAPKを添付する。鍵の置き方は、そのファイルの先頭に書いてある。
鍵の控えは、安全な場所に取っておくこと。Androidは、入っているアプリと同じ鍵で署名されたAPKだけを更新として受け付ける。鍵をなくすと、アプリを消してから入れ直すことになる。

## 設定するもの

設定は2つのファイルにあり、どちらもリポジトリの外に置く。

設定ファイルには読みたい内容を書く。カテゴリ、トピック、購読フィード、フィルター、読み手情報、出力言語、タイムゾーンである。
書式は [examples/settings.example.yaml](examples/settings.example.yaml) を見る。
`import` で読み込み、`export` で現在の設定を書き出せるので、設定の控えとしても使える。同じ内容をAPIからも変更できる。

`~/.config/smarternews/config.yaml` にはサーバーの動かし方を書く。待ち受けの宛先、プロバイダー、各種の上限である。
すべての項目は省略できる。項目と既定値は [examples/config.example.yaml](examples/config.example.yaml) にある。

### カテゴリとトピック

カテゴリはトピックをまとめる単位で、スケジュールとRSSをカテゴリごとに持つ。種別は次の2つである。

- `news` は、直近の `windowHours`（既定は24）時間に公開されたページを集める。
- `event` は、今後 `windowDays`（既定は7）日以内に開催されるイベントを集め、日時、会場、料金、申込の要否を保存する。

トピックはキーワードか文章で書く。トピックを登録したときと文章を変えたときに、LLMが検索語と判定基準を1度だけ作る。
取得元はトピックごとに選ぶ。

| 取得元 | 内容 |
|---|---|
| `feeds` | 登録したRSSまたはAtomのフィードを読む |
| `newsSearch` | トピックの検索語でニュース検索を引く |
| `llmSearch` | LLMにWebを検索させる。地域のイベントのように、フィードとニュース検索で見つからない話題に使う |

関連する話題のうちどこまでを記事にするかは、`minImportance`（1から5）と `maxArticlesPerRun` で決まる。
記事にしなかった候補は理由とともに30日間残り、`GET /api/v1/runs/:id/candidates` で一覧できる。

### 購読フィード

購読フィードは、配信された内容をそのまま読むためのものである。サーバーが決まった間隔で取得し、項目ごとに、配信元のタイトルと内容のままの記事として保存する。
ここではLLMを使わないので、購読を増やしてもLLMの呼び出しは増えない。増えるのは、購読フィードで自動の要約か翻訳を有効にしたときだけである。トピックの `feeds` とは別のもので、そちらはLLMが記事を書くための材料である。

Webの「設定」の「購読フィードを設定する」から追加する。フィードのURLか、サイトのURLを入力する。サイトのURLのときは、そのページが案内しているフィードをサーバーが探す。
フィードは、種別が `news` のカテゴリ1つに入れるか、どのカテゴリにも入れない。

- 基本の取得周期は30分で、5分から24時間の範囲で変えられる。フィードごとに、周期の指定と一時停止ができる。
- フィードの追加と編集の「自動で要約する」を入れると、そのあとに届く記事をLLMが要約する。既定は無効で、入れる前に保存した記事は要約しない。記事はすぐ保存されて読める。要約は少し遅れて届き、内容の上に「AIによる要約」として表示する。要約が届く前に読んだ記事は、要約しない。
- 要約のために、サーバーは記事のページを取得して本文をLLMに渡す。取得の作法は、実行のときと同じである。全文を取得しない購読フィードでは、取得した本文を保存しない。ページを読めないときは、配信された内容だけで要約し、そのことを表示する。配信された内容が200文字に満たないときは、要約を作らない。
- フィードの追加と編集の「全文を取得する」を入れると、そのあとに届く各記事の元のページを取得し、本文を全文として保存する。既定は無効である。記事の画面では、配信された内容の位置に全文を表示し、元のページから取得した全文であることを示す。配信された内容へ切り替えることもできる。
- 全文の取得は、記事の保存のあとに1件ずつ行う。`robots.txt` とホストごとの間隔に従い、LLMは呼ばない。取得の前に読んだ記事は取得しない。失敗した記事は自動では取得し直さず、記事の画面に理由を表示する。
- 設定にかかわらず、記事の画面から1件の全文を取得できる。Webの画面では「全文を取得」のボタンか `w` のキー、Androidアプリでは上部のボタンを使う。配信された内容より短い本文は、購読の案内のようなものとみなして保存しない。全文のある記事は、ページを取得し直さずに全文から要約し、翻訳でも全文を訳す。全文はRSSに載せない。
- フィードの追加と編集の「翻訳する」を入れると、その購読フィードの記事を出力言語へ翻訳する。既定は無効である。一覧には訳したタイトルを表示する。本文は、段落ごとに、訳の下に原文を小さな文字で並べる。原文は消さない。フィルターは原文に対して判定する。
- 翻訳のために、その購読フィードの記事のタイトルと本文を、Googleの翻訳のAPIか、設定したLLMのプロバイダーへ送る。ほかの内容は送らない。タイトルは記事が届いたときに、APIだけで翻訳する。本文は、記事を初めて開いたときに、先頭から2万文字までを翻訳する。「翻訳する」を入れる前に保存した記事は、開いたときに翻訳する。
- 取得の失敗は、理由とともにフィードの一覧に表示する。実行履歴には載せない。失敗が続く間は、待つ時間を2倍ずつ延ばす。上限は24時間である。
- 購読した時点で配信されている項目は、すべて未読の記事になる。90日より前の項目は取り込まない。
- 購読フィードの記事にも、スターと既読を使える。スターのない記事は90日で削除する。
- 内容は、段落、見出し、リスト、引用、強調、コード、リンク、画像だけを残す。スクリプトと埋め込みの枠は取り除く。
- カテゴリを削除しても、そのフィードは消えない。記事とともに「未分類」へ移る。

内容の中の画像は、読む端末が配信元のサイトから読み込む。HTTPSの画像だけを読み込み、遷移元のURLは送らない。
配信元には、端末のアドレスと読んだ時刻が伝わる。LLMが書いた記事では、画像を読み込まない。

購読の一覧をほかのアプリと受け渡すには、OPMLを使う。Webの画面のほか、2つのコマンドで読み書きできる。

```bash
node apps/server/src/main.ts opml-import feeds.opml
node apps/server/src/main.ts opml-export > feeds.opml
```

フォルダーは、同じ名前のカテゴリになる。ないカテゴリは、トピックなしで作る。トピックのないカテゴリは、スケジュールの時刻になっても実行しない。
読み込みでは、購読済みのフィードを飛ばし、何も削除しない。

### フィルター

フィルターは、購読フィードの記事を一覧から隠す。
隠すフィルターは、すべての条件に合う記事を隠す。適用する範囲は、全体、カテゴリ、購読フィードから選ぶ。
残すフィルターは、カテゴリか購読フィードに置き、その範囲の残すフィルターのどれにも合わない記事を隠す。
条件は、タイトル、内容、著者、URLのどれかを照合する。照合の方法は、部分一致か正規表現である。
大文字と小文字、全角と半角は区別しない。訳した文章には照合しない。
設定の画面では、フィルターごとに隠している件数と記事を確かめられる。保存の前に、隠れる件数も確かめられる。
隠した記事は消さずに持ち、フィルターを無効にするか削除すると一覧に戻る。
スターのある記事と、LLMが書いた記事は隠さない。

以前のストップワードは、サーバーの更新のときに、全体の隠すフィルターへ移る。
`stopWords` の鍵を持つ設定ファイルも、同じように読み込める。

### 購読フィードをまたぐ重複の除去

複数の購読フィードが同じ記事を配信したとき、全体とカテゴリの一覧には1件だけを並べる。
ほかの購読フィードが7日以内に配信した記事と、URLかタイトルが同じなら、重複とみなす。
URLの追跡用のパラメーターと、タイトルの大文字と小文字、全角と半角、空白、記号の違いは無視する。
10文字未満のタイトルはURLだけで比べ、同じ購読フィードの記事同士は比べない。
先に届いた記事を一覧に残し、元のページを開く操作の下に、ほかに配信した購読フィードの名前を並べる。名前を押すと、その購読フィードの同じ記事を開く。
重複の記事も、それぞれの購読フィードの一覧と未読の件数には出る。
残した記事を読むと、重複の記事も既読になる。
重複の記事は、届いたときに要約もタイトルの翻訳もしない。判定にLLMは使わない。

重複の除去は既定で有効である。全体設定で無効にすると、重複の記事もすべての一覧に並ぶ。有効に戻すと、同じ記事がまた隠れる。

### 読み手情報

`readerInfo` は、記事を読む人について自由に書く文章である。LLMはこれを関連と重要度の判定に使い、読み手への影響を1文で記事に付ける。
空にすると、記事にその1文は付かない。

## RSSとAPI

| URL | 内容 |
|---|---|
| `/rss/all.xml?token=<RSS用のトークン>` | 有効なカテゴリすべての、LLMが書いた記事の新しい50件 |
| `/rss/<カテゴリの識別名>.xml?token=<RSS用のトークン>` | 1つのカテゴリの、最終更新の新しい50件 |
| `/api/v1/...` | そのほかの操作。[docs/api.md](docs/api.md) を見る |

RSS用のトークンでできるのはRSSの取得だけである。APIのトークンはすべての読み書きができるので、URLには書かない。

このRSSに載るのは、LLMが書いた記事だけである。購読フィードの記事は載せない。ほかのサイトが配信した内容を、サーバーから配り直さないためである。

72時間以内に続報が出ると、サーバーは記事を書き直して未読に戻す。
RSSでは、新しい `guid` と、タイトルの先頭の印を付けて配信し直す。一度表示した項目の変更を無視するアプリが多いためである。

### 翻訳

Googleの翻訳のAPIを使うには、APIキーをサーバーの環境変数に置き、その変数の名前を `config.yaml` に書く。APIキーそのものは、smarternewsのどのファイルにも書かない。

```yaml
translation:
  google:
    apiKeyEnv: GOOGLE_TRANSLATE_API_KEY
  monthlyChars: 450000
```

サーバーは、APIに送った文字数を月ごとに数え、`monthlyChars` を超える分は送らない。課金のない範囲に収めるためで、既定の値は50万文字より低くしてある。
上限に達した月の残りと、APIキーがないとき、APIが失敗したときは、LLMの `translate` のタスクが翻訳する。LLMが翻訳するのは、開いた記事だけである。
今月の文字数と上限は、購読フィードの設定の画面に表示する。詳しくは [docs/providers.md](docs/providers.md) に書いてある。APIキーをサービスに渡す方法は [examples/smarternews.service](examples/smarternews.service) にある。

## 常駐させる

[examples/smarternews.service](examples/smarternews.service) はsystemdのユーザー単位のサービスの雛形である。導入のコマンドは先頭のコメントにある。

データベースの形が変わる版に上げたときは、起動の前に、データベースのファイルの複製を同じ場所に作る。名前は `db.sqlite.before-<番号>` である。
新しい版で問題がなければ、複製は消してよい。

データベースの記事は、サーバーを通してだけ書き換える。検索の索引は、サーバーが登録する関数を呼ぶトリガーで保つ。
`sqlite3` のコマンドなど、ほかの接続からはデータベースを読めるが、記事を書き換えると失敗する。

他の端末から読むには、`config.yaml` の `listen` を、その端末から届く宛先に変える。たとえばそのマシンのTailscaleの宛先である。
サーバーはTLSを持たず、認証は固定のトークン1つなので、閉じたネットワークの中で使う。外部のネットワークへは公開しない。

## 他のサイトへの配慮

- すべての要求に、製品名、版、このリポジトリのURLを含む `User-Agent` を付ける。`config.yaml` で変更できる。
- 記事のページを取得する前に `robots.txt` を確かめ、禁じられたページは取得しない。`robots.txt` を読めなかったサイトは、取得を禁じているものとして扱う。
- 同じホストへの要求は1秒以上空ける。1回の実行で取得する記事のページは20までとする。どちらも設定で変えられる。
- ページを取得するのは、記事にすると決めた話題だけである。関連なしと判定した候補のページは取得しない。`llmSearch` では、LLMが挙げたページの実在を確かめるために1度取得する。
- 記事に載せるのは、LLMが書いた要約と出典へのリンクである。読んだページの本文は転載せず、手元の写しは30日で消す。
- 購読フィードの取得は、最短でも5分おきで、既定は30分おきである。前回の応答の `ETag` と `Last-Modified` を送るので、変更のないフィードは本文なしの応答で済む。配信された内容は利用者本人にだけ表示し、配り直さない。

ニュース検索は、既定でGoogle NewsのRSS出力を使う。Bing NewsのRSS出力へ切り替えることもできる。
どちらも、個人がRSSを読むアプリで使う非商用の利用だけを認めている。ほかの用途で使う前に、各社の利用条件を確かめること。

## 取得しない宛先

クローラーが取得するURLは、フィード、検索の結果、LLMの出力から来る。その中には、同じネットワークの機器や、同じマシンのほかのサービスを指すものも混ざる。
そのため、クローラーは `http` と `https` のURLだけを取得する。宛先のアドレスが、ループバック、プライベート、リンクローカル、共有アドレス空間（`100.64.0.0/10`）の範囲にあるときは、要求を送らない。
ホスト名は、接続するときに解決されたアドレスで確かめる。リダイレクト先も同じように確かめ、5回を超えたら取得をやめる。

自分のネットワークに置いたフィードを読むには、そのホストを `config.yaml` に書く。

```yaml
fetch:
  allowPrivateHosts: [feeds.home.example]
```

拒否した取得は、ほかの取得の失敗と同じように記録する。実行履歴で、URLと理由を確かめられる。
LLMのプロバイダーへの呼び出しは制限しない。その宛先は、利用者が自分で決めたものだからである。

## 失敗した実行のやり直し

定時の実行が「失敗」で終わると、サーバーは時間を置いてそのカテゴリをもう1度実行する。1回目のやり直しは失敗の10分後に、2回目は30分後に始まる。
やり直しの回数は、`config.yaml` の `limits.runRetries` で0回から3回の範囲に変えられる。既定は2回である。3回目は、失敗の90分後に始まる。0回にすると、やり直さない。
「一部失敗」と「上限で停止」の実行は、やり直さない。手動の実行も、やり直さない。

やり直しは、実行履歴に別の行として残る。何回目のやり直しかを表示し、元の定時の実行へ移れる。
やり直しは、失敗した実行で判定済みになったページと、すでに作った記事を扱わない。
次のどれかに当たると、サーバーはやり直しを取りやめる。同じカテゴリの次の定時の実行が順番待ちに入った。カテゴリが無効になった。有効なトピックがなくなった。
失敗した実行の詳細は、やり直しの予定の時刻か、予定がない理由を表示する。

やり直しの予定は保存するので、サーバーを再起動しても残る。停止中に予定の時刻を過ぎたやり直しは、起動のあとに始まる。
起動のとき、順番を待っていた実行は、元の順のまま再開する。6時間より長く待っていた実行は、再開せずに「失敗」にする。
実行中のまま止まった実行は「失敗」にする。それが定時の実行であれば、1回分として数えたうえで、すぐにやり直す。

## LLMの呼び出しの上限

1回の実行は、呼び出しが `llmCallsPerRun`（既定は40）回に達すると止まる。
その日の呼び出しが `llmCallsPerDay`（既定は300）回に達したあとは、どの実行もLLMを呼ばない。
止まる前に完成した記事は残り、次の実行が残りを続ける。当日の呼び出し回数は `GET /api/v1/providers` で分かる。

配信記事の要約は、これとは別に数える。その日の要約が `summariesPerDay`（既定は100）回に達すると、翌日まで要約しない。翌日は、待っている記事を新しい順に要約する。
要約は `llmCallsPerDay` に数えず、実行の呼び出しは `summariesPerDay` に数えない。
`summarize` のタスクは、`config.yaml` の `tasks` で割り当てなければ、`fast` という名前のプロバイダーで動く。詳しくは [docs/providers.md](docs/providers.md) に書いてある。

やり直しも、ほかの実行と同じく2つの上限に従う。やり直しが2回のとき、失敗が続くカテゴリは、定時の時刻1つにつき最大3回分の呼び出しを使う。

LLMでの翻訳は `llmCallsPerDay` に数える。上限に達した日は、LLMでの翻訳が要る記事を原文のまま表示し、やり直すボタンを出す。

## 開発

```bash
make verify    # lint、型検査、テスト、画面のビルド、個人情報の検査
```

要件と設計は [openspec/](openspec/) に日本語で書いてある。画面の前提と見た目の値は [PRODUCT.md](PRODUCT.md) と [DESIGN.md](DESIGN.md) にあり、Webの画面とAndroidアプリの両方が使う。テストは実際のLLMと外部のサイトを呼ばず、偽のプロバイダーと記録済みの応答で動く。
Androidアプリのテストは、テスト用のプロセスがループバックで配る実物のAPIに対して、Jestで動かす。`make verify` はAPKを作らない。
